Сборка из исходного кода#

Примечание

Если вам нужно только установить NumPy, рекомендуем готовые бинарные пакеты. Подробнее см. «Установка».

Для сборки NumPy из исходного кода сначала необходимо установить системные зависимости (компиляторы, библиотеки BLAS/LAPACK и т. д.), а затем запустить сборку. Её можно выполнять для локальной установки NumPy, разработки самого NumPy или создания распространяемых двоичных пакетов. При этом может потребоваться настроить отдельные параметры процесса. В руководстве рассмотрены все эти задачи. Кроме того, в нём объясняется устройство сборки NumPy и приведены ссылки на актуальную документацию по сборке и упаковке Python, относящуюся к этим вопросам.

Системные зависимости #

Для скорости NumPy использует компилируемый код. Поэтому для сборки нужны компиляторы и другие системные зависимости, не относящиеся к Python и PyPI.

Примечание

Если вы используете Conda, то можете пропустить шаги в этом разделе — за исключением установки компиляторов для Windows или Инструментов разработчика Apple для macOS.Все остальные зависимости будут установлены автоматически командой mamba env create -f environment.yml.

Если вы хотите использовать системный Python и pip, вам потребуется:

  • Компиляторы C и C++ (обычно GCC).

  • Файлы заголовков Python (обычно пакет с именем python3-dev или python3-devel)

  • Библиотеки BLAS и LAPACK. По умолчанию в NumPy используется OpenBLAS; другие варианты — Apple Accelerate, MKL, ATLAS и эталонные реализации BLAS и LAPACK Netlib (Reference).

  • pkg-config для обнаружения зависимостей.

  • Компилятор Fortran нужен только для запуска тестов f2py. Инструкции ниже включают его установку, но этот шаг можно спокойно пропустить.

Чтобы установить зависимости для сборки NumPy, выполните:

sudo apt install -y gcc g++ gfortran libopenblas-dev liblapack-dev pkg-config python3-pip python3-dev

Другой вариант:

sudo apt build-dep numpy

Эта команда устанавливает все, что необходимо для создания NumPy, с тем преимуществом, что новые зависимости или обновления требуемых версий обрабатываются менеджерами пакетов.

Чтобы установить зависимости для сборки NumPy, выполните:

sudo dnf install gcc-gfortran python3-devel openblas-devel lapack-devel pkgconfig

Другой вариант:

sudo dnf builddep numpy

Эта команда устанавливает все, что необходимо для создания NumPy, с тем преимуществом, что новые зависимости или обновления требуемых версий обрабатываются менеджерами пакетов.

Чтобы установить зависимости для сборки NumPy, выполните:

sudo yum install gcc-gfortran python3-devel openblas-devel lapack-devel pkgconfig

Другой вариант:

sudo yum-builddep numpy

Эта команда устанавливает все, что необходимо для создания NumPy, с тем преимуществом, что новые зависимости или обновления требуемых версий обрабатываются менеджерами пакетов.

Чтобы установить зависимости для сборки NumPy, выполните:

sudo pacman -S gcc-fortran openblas pkgconf

Установите Apple Developer Tools. Простой способ сделать это: откройте окно терминала и введите команду:

xcode-select --install

и следуйте подсказкам. Apple Developer Tools включает Git, компиляторы Clang C/C++ и другие необходимые средства разработки.

Не используйте системный Python macOS. Установите Python с помощью установщика python.org либо менеджера пакетов, например Homebrew, MacPorts или Fink.

На macOS >=13.3 самым простым вариантом сборки является использование Accelerate, который уже установлен и будет автоматически использоваться по умолчанию.

В старых версиях macOS нужна другая библиотека BLAS, скорее всего OpenBLAS, а также pkg-config для её обнаружения. Проще всего установить их через Homebrew:

brew install openblas pkg-config gfortran

Собирать NumPy в Windows немного сложнее, чем в macOS и Linux, поскольку нужно настроить компиляторы. Сначала установите Microsoft Visual Studio: подойдёт Community Edition 2019 или более новая версия (см. сайт загрузки Visual Studio). Это необходимо для установки универсальной среды выполнения C для Windows (UCRT). Рекомендуется UCRT версии >= 10.0.22621.0.

Установщик MSVC не добавляет компиляторы в системный PATH, а каталог установки может меняться. Для его поиска в комплект MSVC входит утилита командной строки vswhere.exe. Чтобы компиляторы C/C++ стали доступны в используемой оболочке, запустите файл .bat для нужной разрядности и архитектуры (например, vcvars64.bat для 64-битных процессоров Intel).

Подробные инструкции см. в разделе «Использование набора инструментов Microsoft C++ из командной строки».

Если вам не нужен f2py, достаточно только MSVC. Для настройки компилятора Fortran (необходимо для f2py) см. F2PY и Windows .

Примечание

Чтобы компиляторы обнаруживались, они должны быть доступны через системный путь поиска: переменная окружения PATH должна содержать каталог с их исполняемыми файлами. Исключение — MSVC, который обнаруживается автоматически тогда и только тогда, когда в PATH нет других компиляторов. Сборку можно запускать из любой оболочки, например PowerShell, cmd или Git Bash.

Предупреждение

Создание среды conda может завершиться неудачей из-за устаревшего компилятора Fortran. В таком случае удалите запись compilers из environment.yml и повторите попытку. Компилятор Fortran нужно установить согласно документации F2PY для Windows.

В Windows на ARM64 выбор компиляторов для сборки NumPy ограничен. GCC и gfortran пока не поддерживаются. Сейчас сборка NumPy для Windows на ARM64 поддерживается с наборами инструментов MSVC и LLVM.

Сначала установите Microsoft Visual Studio: подойдёт Community Edition 2022 (см. сайт загрузки Visual Studio). Убедитесь, что установлены компоненты Visual Studio, необходимые для сборки NumPy на WoA и перечисленные здесь.

Установщик MSVC не добавляет компиляторы в системный PATH; каталог установки также может меняться. Определить его помогает поставляемая с MSVC утилита vswhere.exe. Чтобы компиляторы C/C++ стали доступны в оболочке, запустите файл .bat для нужных разрядности и архитектуры; например, для процессоров ARM64 — vcvarsarm64.bat.

Подробные инструкции см. в разделе «Использование набора инструментов Microsoft C++ из командной строки».

Если вам не нужен f2py, достаточно только MSVC. Для настройки компилятора Fortran (необходимо для f2py) см. F2PY и Windows .

Предупреждение

В настоящее время среда Conda еще официально не поддерживается на Windows на ARM64 . Настоящий подход использует Virtualenv для построения NumPy из исходного кода на Windows на ARM64.

Сборка NumPy из исходного кода#

Если вам нужно лишь один раз установить NumPy из исходного кода без дальнейшей разработки, для сборки и установки рекомендуется pip. В остальных случаях рекомендуется conda.

Примечание

Если conda ещё не установлена, рекомендуем Miniforge, хотя подойдёт любой вариант conda.

Сборка из исходного кода для использования NumPy#

В среде conda для запуска сборки NumPy из исходного кода по-прежнему используется pip. Важно всегда передавать флаг --no-build-isolation команде pip install, чтобы при сборке не использовался пакет wheel numpy из PyPI. Для этого сначала установите остальные зависимости сборки в среду conda:

# Either install all NumPy dev dependencies into a fresh conda environment
mamba env create -f environment.yml

# Or, install only the required build dependencies
mamba install python numpy cython compilers openblas meson-python pkg-config

# To build the latest stable release:
pip install numpy --no-build-isolation --no-binary numpy

# To build a development version, you need a local clone of the NumPy git repository:
git clone https://github.com/numpy/numpy.git
cd numpy
git submodule update --init
pip install . --no-build-isolation

Сборка из исходного кода для разработки NumPy#

Чтобы собрать NumPy из исходного кода для работы над самим проектом, сначала клонируйте репозиторий NumPy:

git clone https://github.com/numpy/numpy.git
cd numpy
git submodule update --init

Затем вы хотите сделать следующее:

  1. Создание специализированной среды разработки (виртуальная среда или конда-среда).

  2. Установите все нужные зависимости: для сборки, тестирования и документации, а также необязательные,

  3. Соберите NumPy через интерфейс разработчика spin.

Шаг (3) всегда одинаков; шаги (1) и (2) различаются для conda и виртуальных окружений:

Чтобы создать среду разработки numpy-dev со всеми обязательными и необязательными зависимостями, выполните:

mamba env create -f environment.yml
mamba activate numpy-dev

Примечание

Есть много инструментов управления виртуальными окружениями: venv, virtualenv/virtualenvwrapper, pyenv/pyenv-virtualenv, Poetry, PDM, Hatch и другие. Здесь мы используем базовый инструмент venv из стандартной библиотеки Python. Можно выбрать любой другой: достаточно активированного окружения Python.

Создайте и активируйте виртуальное окружение в новом каталоге venv. Точная команда активации зависит от ОС и оболочки; см. «Как работают виртуальные окружения» в документации venv.

python -m venv venv
source venv/bin/activate

python -m venv venv
source venv/bin/activate

python -m venv venv
.\venv\Scripts\activate

python -m venv venv
.\venv\Scripts\activate

Примечание

Сборке NumPy с функциями BLAS и LAPACK требуется библиотека OpenBLAS во время выполнения. В Windows на ARM64 зависимость от OpenBLAS можно настроить через pkg-config. Инструкции по сборке OpenBLAS для Windows на ARM64 приведены здесь.

Затем установите зависимости уровня Python с PyPI:

python -m pip install -r requirements/build_requirements.txt

Чтобы создать NumPy в активированной среде разработки, запустите:

spin build

Это позволит установить NumPy внутри репозитория (по умолчанию в каталоге build-install). Затем вы можете запустить тесты (spin test), перейти в IPython (spin ipython) или предпринять другие шаги по разработке, такие как создание документации html или запуск бенчмарков. Интерфейс spin является самодокументирующимся, поэтому см. spin --help и spin <subcommand> --help для подробного руководства.

Предупреждение

В активированной среде conda в Windows могут быть заданы переменные окружения AR, LD и LDFLAGS, из-за которых сборка завершится ошибкой. Эти переменные нужны только для flang; перед сборкой их можно безопасно удалить из окружения.

Поддержка IDE и редактируемые установки

Мы рекомендуем работать над NumPy через интерфейс spin, но у него есть ограничение: из-за нестандартного каталога установки среда IDE не распознаёт NumPy, установленный через spin, автоматически — например, при запуске скрипта кнопкой Run или визуальной установке точек останова. Для этого лучше подходит сборка в исходном каталоге, или редактируемая установка.

Редактируемые установки поддерживаются. Важно: в одном клоне репозитория можно использовать либо редактируемую установку, либо spin , но не оба способа одновременно. При редактируемой установке запускайте pytest и другие инструменты разработки напрямую, без spin.

Чтобы использовать редактируемую установку, начните с чистого репозитория (выполните git clean -xdf, если ранее собирали с помощью spin) и правильно установите все зависимости, как описано выше на этой странице. Затем выполните:

# Note: the --no-build-isolation is important!
pip install -e . --no-build-isolation

# To run the tests for, e.g., the `numpy.linalg` module:
pytest numpy/linalg

  • Примечание: параметр --no-build-isolation важен!
  • Запуск тестов, например, для модуля `numpy.linalg`:

При изменении кода NumPy, в том числе компилируемого, не нужно вручную пересобирать или переустанавливать пакет. NumPy автоматически пересобирается при каждом импорте интерпретатором Python. Подробности этого механизма см. в документации meson-python по редактируемым установкам.

После запуска git clean -xdf, удаляющего собранные модули расширения, не забудьте также удалить NumPy командой pip uninstall numpy.

Предупреждение

Обратите внимание, что редактируемые установки являются принципиально неполными установками.Единственной их гарантией является то, что import numpy работает - поэтому они подходят для работы над самим NumPy, а также для работы над чистыми пакетами Python, которые зависят от NumPy. Заголовки, точки входа и другие подобные вещи могут быть недоступны из редактируемой установки.
