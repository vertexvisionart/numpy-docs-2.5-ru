Настройка и использование среды разработки #

Рекомендуемая настройка среды разработки#

В NumPy есть части на C и Cython, требующие компиляции. Установите нужные компиляторы и заголовки разработки Python — см. Сборка из исходного кода. Начиная с 2.0 для сборки NumPy нужны компиляторы с поддержкой C11 и C++17.

Наличие компилируемого кода также означает, что для импорта NumPy из исходников разрабатываемой версии нужны дополнительные действия, описанные ниже. Далее в этой главе предполагается, что вы настроили репозиторий Git согласно разделу «Работа с исходным кодом scikit-image».

Примечание

Если не удаётся собрать NumPy из исходного кода или настроить локальную среду разработки, попробуйте GitHub Codespaces. Он позволяет создать подходящее окружение прямо в браузере, сократив необходимость локальной установки средств разработки и решения конфликтов зависимостей.

Если у вас хорошее подключение к интернету и нужна временная среда, начать работу над NumPy зачастую быстрее в Codespaces. Инструкции по началу работы см. в документации Codespaces. При создании codespace для репозитория numpy/numpy подходит стандартная двухъядерная машина; четырёхъядерная собирает код и работает немного быстрее, но вдвое сокращает доступное число бесплатных часов. После запуска codespace выполните conda activate numpy-dev — и среда разработки полностью готова. Далее можно следовать соответствующим разделам документации NumPy, чтобы собирать код, тестировать, разрабатывать, писать документацию и вносить изменения в NumPy.

Использование виртуальных сред #

Часто спрашивают: «Как установить разрабатываемую версию NumPy параллельно со стабильным выпуском, который я использую для работы или исследований?»

Простой способ — установить выпущенную версию в site-packages через pip или conda, а версию разработки настроить в виртуальном окружении.

Если вы используете conda, мы рекомендуем создать отдельную виртуальную среду для разработки numpy, используя файл environment.yml в корне репозитория (это создаст среду и установит все зависимости разработки одновременно):

$ conda env create -f environment.yml  # `mamba` works too for this command
$ conda activate numpy-dev
Комментарии к примеру на русском
  • В этой команде также можно использовать `mamba`

Если вы установили Python другим способом, кроме conda, сначала установите virtualenv (при необходимости используйте virtualenvwrapper ), затем создайте виртуальную среду (здесь с именем numpy-dev), активируйте ее и установите все зависимости проекта с помощью:

$ virtualenv numpy-dev
$ source numpy-dev/bin/activate # activate virtual environment
$ python -m pip install -r requirements/all_requirements.txt
Комментарии к примеру на русском
  • Активируем виртуальное окружение

Чтобы активировать виртуальное окружение, выполните source numpy-dev/bin/activate. Команда deactivate выходит из него и возвращает прежнее окружение оболочки.

Тестирование сборки #

Перед запуском тестов установите необходимые для них зависимости:

$ python -m pip install -r requirements/test_requirements.txt
$ python -m pip install asv # only for running benchmarks
Комментарии к примеру на русском
  • Только для запуска тестов производительности

Чтобы собрать версию NumPy для разработки, запустить тесты, открыть интерактивную оболочку с правильно настроенными путями импорта Python и выполнить другие подобные задачи, используйте утилиту spin. Для запуска тестов выполните одну из команд:

$ spin test -v
$ spin test numpy/random  # to run the tests in a specific module
$ spin test -v -t numpy/_core/tests/test_nditer.py::test_iter_c_order
$ spin test -p auto # to run tests in parallel threads using pytest-run-parallel
Комментарии к примеру на русском
  • Для запуска тестов конкретного модуля
  • Для запуска тестов в параллельных потоках через pytest-run-parallel

Сначала собирается NumPy, поэтому первый запуск может занять несколько минут.

Для измерения производительности можно также использовать spin bench. Дополнительные параметры командной строки см. в spin --help.

Примечание

Если приведенные выше команды приводят к RuntimeError: Cannot parse version 0+untagged.xxxxx, запустите git pull upstream main --tags.

Дополнительные аргументы передаются pytest после отдельного разделителя --. Например, чтобы передать флаг --pdb при запуске тестового метода, выполните:

$ spin test -t numpy/tests/test_scripts.py::test_f2py -- --pdb

Также можно выбирать имена тестов с помощью операторов Python, передавая pytest аргумент -k:

$ spin test -v -t numpy/_core/tests/test_multiarray.py -- -k "MatMul and not vector"

Чтобы запустить doctest — проверить правильность примеров кода в документации, — используйте команду spin check-docs. Она опирается на пакет scipy-docs, дополняющий возможности пакета doctest стандартной библиотеки. Установите scipy-doctest и выполните одну из команд:

$ spin check-docs -v
$ spin check-docs numpy/linalg
$ spin check-docs -v -- -k 'det and not slogdet'

Примечание

Помните, что все тесты NumPy должны пройти до фиксации изменений.

Примечание

Некоторые тесты в наборе тестов требуют большого объема памяти и пропускаются, если в вашей системе ее недостаточно.

Тестирование #

Помимо использования spin, существуют различные способы запуска тестов. Внутри интерпретатора тесты могут выполняться следующим образом:

>>> np.test()  
>>> np.test('full')   # Also run tests marked as slow
>>> np.test('full', verbose=2)   # Additionally print test name/file

An example of a successful test :
``4686 passed, 362 skipped, 9 xfailed, 5 warnings in 213.99 seconds``
Комментарии к примеру на русском
  • Также запускаем тесты, помеченные как медленные
  • Дополнительно выводим имя и файл теста

Или аналогичный способ из командной строки:

$ python -c "import numpy as np; np.test()"

Тесты можно запускать и командой pytest numpy, но тогда плагин NumPy не обнаруживается, что вызывает странные побочные эффекты.

Полезно запускать отдельные файлы тестов: это намного быстрее, чем запускать весь набор тестов или тесты целого модуля (например, np.random.test()). Для этого выполните:

$ python path_to_testfile/test_file.py

Можно передать и дополнительные аргументы, например --pdb: он запускает отладчик Python при сбое теста или возникновении исключения.

Также поддерживается запуск тестов с tox . Например, для сборки NumPy и запуска тестового набора с Python 3.9 используют:

$ tox -e py39

Подробнее см. Рекомендации по тестированию.

Примечание: не запускайте тесты из корневого каталога вашего numpy git repo без spin, что приведет к странным ошибкам в тесте.

Запуск проверок типов#

Для изменений, затрагивающих статические объявления типов, также выполняется spin. Вызов выглядит следующим образом:

$ spin mypy

Ищет в каталоге typing/tests наборы операций для проверки несовместимости типов.

Запуск линтинга #

Линт-проверку можно выполнять для вновь добавляемых строк кода Python.

Установите все зависимые пакеты с помощью pip:

$ python -m pip install -r requirements/linter_requirements.txt

Чтобы выполнить проверки линтером перед коммитом нового кода, запустите:

$ spin lint

Если ошибок нет, вывод будет выглядеть так:

$ spin lint

Повторная сборка и очистка рабочего каталога#

После изменения компилируемого кода NumPy можно пересобрать той же командой: пересоберутся только изменённые файлы. Для полной сборки, которая иногда необходима, сначала нужно очистить рабочую область. Стандартный способ сделать это (внимание: все незафиксированные файлы будут удалены!):

$ git clean -xdf

Чтобы отбросить все изменения и вернуться к последнему коммиту в репозитории, используйте один из следующих способов:

$ git checkout .
$ git reset --hard

Отладка#

Другой частый вопрос: «Как отлаживать код C внутри NumPy?». Сначала убедитесь, что в системе установлен gdb с поддержкой Python (в Linux она часто включена по умолчанию). Чтобы проверить настройку, посмотрите, какая версия Python работает внутри gdb:

(gdb) python
>import sys
>print(sys.version_info)
>end
sys.version_info(major=3, minor=7, micro=0, releaselevel='final', serial=0)

Большинство сборок Python не содержит отладочных символов и компилируется с включённой оптимизацией. Для удобства отладки рекомендуется использовать отладочную сборку Python; см. Расширенные средства отладки.

Для отладки NumPy также необходимо собрать в отладочном режиме. Используйте тип сборки debug и отключите оптимизацию, чтобы при компиляции объектных файлов использовался флаг -O0. Обратите внимание: перед сборкой командой spin build NumPy НЕ должен быть установлен в вашем окружении.

Чтобы при сборке сгенерировать отладочную информацию на уровне исходного кода, выполните:

$ spin build --clean -- -Dbuildtype=debug -Ddisable-optimization=true

Примечание

При использовании окружения conda учитывайте, что conda автоматически задаёт CFLAGS и CXXFLAGS, по умолчанию включающие флаг -O2. Чтобы убрать эти настройки, можно выполнить unset CFLAGS && unset CXXFLAGS или переопределить их в начале команды spin: CFLAGS="-O0 -g" CXXFLAGS="-O0 -g". Для постоянного управления этими переменными можно создать файл env_vars.sh в каталоге <path-to-conda-envs>/numpy-dev/etc/conda/activate.d и экспортировать в нём переменные CFLAGS и CXXFLAGS. Подробные инструкции: https://conda.io/projects/conda/en/latest/user-guide/tasks/manage-environments.html#saving-environment-variables.

Затем напишите сценарий Python, вызывающий код C, выполнение которого нужно отладить. Например, mytest.py:

import numpy as np
x = np.arange(5)
np.empty_like(x)

Учтите, что тестовый файл должен находиться вне вашего клона репозитория NumPy. Теперь можно выполнить:

$ spin gdb /path/to/mytest.py

Если вы используете набор инструментов clang:

$ spin lldb /path/to/mytest.py

А потом в отладчике:

(gdb) break array_empty_like
(gdb) run

аналог lldb:

(lldb) breakpoint set --name array_empty_like
(lldb) run

Теперь выполнение остановится в соответствующей функции C, и вы сможете пошагово выполнять её как обычно. Доступен ряд полезных команд для Python. Например, py-list показывает текущую позицию в коде Python, а py-bt — стек вызовов Python. Подробнее см. DebuggingWithGdb. Вот несколько часто используемых команд:

  • list: вывести код указанной функции или строки.

  • next: выполнить следующий шаг программы, не заходя внутрь вызываемых подпрограмм.

  • step: в оригинале описано продолжение выполнения отлаживаемой программы после сигнала или точки останова. Примечание переводчика: это описание команды continue. Команда step выполняет программу до перехода к другой строке исходного кода, заходя внутрь вызываемых функций.

  • print: вывести значение выражения EXP.

Для полноценной отладки Python скрипт python-gdb.py из поставки Python должен находиться по пути, доступному gdb. Если Python установлен через системный менеджер пакетов, скорее всего, дополнительных действий не требуется. Если Python собран из исходного кода, обычно нужно создать в домашнем каталоге файл .gdbinit, указывающий gdb расположение Python. Например, для Python, установленного через pyenv, нужен файл .gdbinit следующего содержания:

add-auto-load-safe-path ~/.pyenv

Настоятельно рекомендуется собрать NumPy с Python, созданным с поддержкой отладки (в дистрибутивах Linux, обычно упаковываемых как python-dbg).

Знакомство с кодом и начало работы#

Чтобы лучше понять кодовую базу, выберите то, что хотите изменить, и начните читать код, разбираясь в его работе. Если возникают сомнения, задавайте вопросы в списке рассылки. Неидеальные запросы на включение изменений — это нормально: сообщество всегда радо помочь. Проект развивается силами добровольцев, поэтому что-то иногда упускают. Если ответа нет примерно две–четыре недели, вполне уместно напомнить о себе.

Выберите что-нибудь в NumPy, что вас раздражает или сбивает с толку, поэкспериментируйте с кодом, поучаствуйте в обсуждениях или изучите справочную документацию, чтобы попробовать это исправить. Постепенно всё встанет на свои места, и вскоре вы будете хорошо понимать проект в целом. Удачи!
