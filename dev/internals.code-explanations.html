Модель памяти#

Один из основных принципов ndarray: массив рассматривается как участок памяти, начинающийся по определённому адресу. Интерпретация этой памяти зависит от сведений о шагах. Для каждого измерения \(N\)-мерного массива целое число — шаг — задаёт, сколько байтов нужно пропустить для перехода к следующему элементу вдоль этого измерения. При обходе массива нужно учитывать шаги, кроме случая, когда массив занимает один сегмент памяти. Написать код с поддержкой шагов несложно: нужно использовать указатели char*, поскольку шаги выражаются в байтах. Шаги не обязательно кратны размеру элемента. Также помните: если число измерений равно 0, то есть массив нульмерный (иногда называемый rank-0), переменные strides и dimensions равны NULL.

Помимо структурных сведений в полях strides и dimensions объекта PyArrayObject, флаги содержат важную информацию о доступе к данным. NPY_ARRAY_ALIGNED установлен, если память выровнена по границе, подходящей типу данных. Даже непрерывный участок памяти не гарантирует безопасного разыменования указателя на элемент конкретного типа: для этого нужен NPY_ARRAY_ALIGNED. На одних платформах невыровненный доступ работает, на других, например Solaris, вызывает bus error. Перед записью также нужно проверить NPY_ARRAY_WRITEABLE. Указатель может вести в область только для чтения. Запись без флага NPY_ARRAY_WRITEABLE иногда лишь нарушает правила использования, а иногда приводит к аварийному завершению программы, например если данные отображены из файла только для чтения.

Инкапсуляция типов данных#

См. также

Объекты типа данных (dtype)

Тип данных — важная абстракция ndarray. Операции обращаются к нему за основными средствами работы с массивом. Они представлены списком указателей на функции, на который ссылается поле f структуры PyArray_Descr. Поэтому новый тип данных можно добавить, предоставив структуру PyArray_Descr с подходящими указателями на функции в поле f. Для встроенных типов есть оптимизации в обход этого механизма, но смысл абстракции — возможность добавлять новые типы.

Встроенный тип данных void позволяет использовать в качестве элементов массива произвольные структурированные типы с одним или несколькими полями. Поле — это другой объект типа данных вместе со смещением внутри текущего структурированного типа. Для поддержки произвольно вложенных полей у типа void есть несколько рекурсивных реализаций доступа к данным. Часто используется обход элементов словаря с выполнением операции согласно объекту типа данных, находящемуся по заданному смещению. Смещения могут быть произвольными числами, поэтому необходимо учитывать возможность невыровненного расположения данных и при необходимости обрабатывать её.

N-мерные итераторы#

См. также

Обход массивов

В коде NumPy часто требуется обойти все элементы произвольного N-мерного массива с заданными шагами по памяти. Универсальный N-мерный цикл представлен абстракцией объекта итератора. Чтобы написать такой цикл, достаточно создать итератор для ndarray, работать с полем dataptr его структуры и вызывать макрос PyArray_ITER_NEXT для перехода к следующему элементу. Элемент next всегда выбирается в порядке обхода C. Макрос отдельно обрабатывает простые частные случаи: массивы, непрерывно расположенные в порядке C, а также одномерные и двумерные массивы.

В общем случае объект итератора хранит счётчики координат по всем осям. При переходе к следующему элементу проверка начинается с последней оси. Если её счётчик ещё меньше размера этой оси минус один — эта граница вычислена и сохранена заранее, — счётчик увеличивается на один, к полю dataptr прибавляется шаг по этой оси, и макрос завершает работу. Если достигнут конец оси, её счётчик сбрасывается в ноль, а dataptr возвращается к началу этой оси: из указателя вычитается шаг, умноженный на размер оси минус один. Это смещение также вычислено заранее и хранится в поле backstrides итератора. После переноса макрос продолжает работу: локальный индекс оси уменьшается, и та же проверка выполняется для предпоследней оси, затем при необходимости для предыдущих. Так поле dataptr корректно изменяется и для массивов с произвольными шагами. Примечание переводчика: в исходном описании увеличение счётчика упоминается дважды. В реализации PyArray_ITER_NEXT для NumPy 2.5 сначала проверяется текущее значение, а увеличивается оно только внутри соответствующей ветви условия.

Поле coordinates структуры PyArrayIterObject хранит текущие N-мерные координаты. Если исходный массив непрерывно расположен в памяти в порядке C, подсчёт координат пропускается. Поле index структуры PyArrayIterObject отслеживает текущий плоский индекс итератора; его обновляет макрос PyArray_ITER_NEXT.

Трансляция массивов (broadcasting)#

См. также

Трансляция массивов (согласование форм)

В Numeric, предшественнике NumPy, трансляция массивов была реализована несколькими строками кода глубоко внутри ufuncobject.c. В NumPy она выделена в отдельную абстракцию, применимую в разных местах. Трансляцию выполняет функция PyArray_Broadcast. Ей нужно передать PyArrayMultiIterObject или двоично эквивалентный объект. PyArrayMultiIterObject хранит число измерений после трансляции, размер каждого измерения и общее число элементов результата. Он также хранит число участвующих массивов и указатель на итератор для каждого из них.

Функция PyArray_Broadcast принимает уже созданные итераторы и определяет общую форму после трансляции в каждом измерении. Чтобы одновременно создать итераторы и выполнить согласование форм, используйте PyArray_MultiIterNew. Затем итераторы настраиваются так, словно каждый обходит массив общей формы. Для этого изменяются число измерений итератора и его форма по осям. Одновременно корректируются шаги итератора. Трансляция изменяет только исходные оси длины 1 или добавляет такие оси. Для них шаг устанавливается в 0, поэтому указатель на данные не перемещается, когда итератор проходит расширенную ось.

В Numeric трансляция массивов всегда реализовывалась с помощью нулевых шагов для расширяемых измерений. NumPy делает это точно так же. Существенное отличие в том, что массив шагов теперь хранится в PyArrayIterObject, итераторы, участвующие в трансляции, — в PyArrayMultiIterObject, а вызов PyArray_Broadcast реализует общие правила трансляции массивов.

Скаляры массивов#

См. также

Скаляры

Скаляры массива предлагают иерархию типов Python, которая обеспечивает взаимно однозначное соответствие между типом данных, хранящимся в массиве, и типом Python, который возвращается при извлечении элемента из массива. Исключение из этого правила сделано для массивов объектов. Массивы объектов представляют собой разнородные коллекции произвольных объектов Python. Когда вы выбираете элемент из массива объектов, вы получаете исходный объект Python (а не скаляр массива объектов, который существует, но редко используется для практических целей).

Скаляры NumPy предоставляют те же методы и атрибуты, что и массивы, чтобы один и тот же код мог работать с любым числом измерений, включая ноль. Скаляры NumPy доступны только для чтения (неизменяемы), за исключением скаляра void: в него можно записывать, чтобы присваивание значений полям структурированного массива работало естественным образом (a[0]['f1'] = value).

Индексация #

См. также

Индексация ndarray, Функции индексации

При любой индексации Python arr[index] сначала подготавливается индекс и определяется его тип. Поддерживаются следующие типы индексов:

  • целое число

  • newaxis

  • срез

  • Ellipsis

  • целочисленные массивы или объекты, подобные массивам (расширенная индексация)

  • логический индекс (один логический массив); если в индексе несколько логических массивов или форма не совпадает в точности, логический массив вместо этого преобразуется в целочисленный.

  • 0-d булевые (и также целые); 0-d булевые массивы являются особым случаем, который должен обрабатываться в расширенном индексационном коде. Они сигнализируют о том, что булевой массив 0-d должен интерпретироваться как целочисленный массив.

Также учитывается особый случай скалярного массива, означающий, что целочисленный массив был интерпретирован как целочисленный индекс. Это важно, поскольку индексирование целочисленным массивом требует создания копии, но это требование не учитывается при возврате скаляра (когда целочисленные индексы заданы для всех осей). Подготовленный индекс гарантированно корректен, за исключением значений за пределами допустимых границ и ошибок трансляции массивов при расширенной индексации. В частности, к неполным индексам добавляется Ellipsis, например при индексировании двумерного массива одним целым числом.

Следующий шаг зависит от найденного типа индекса. Если все измерения индексируются целыми числами, возвращается или задаётся скаляр. Единственный логический индексирующий массив обрабатывается специализированными функциями. Если индексы содержат Ellipsis или срез, но не расширенную индексацию, всегда создаётся представление исходного массива с заново вычисленными шагами и смещением в памяти. Его можно вернуть либо при присваивании заполнить с помощью PyArray_CopyObject. Функция PyArray_CopyObject может также вызываться для временных массивов в других ветвях, чтобы поддерживать сложные присваивания для массивов с объектным dtype.

Расширенное индексирование#

Самый сложный случай — расширенная индексация, которая может сочетаться с обычной индексацией, создающей представления. Здесь целочисленные индексы относятся к индексации через представления. Прежде чем разбираться в реализации, стоит ознакомиться с тонкостями такого индексирования. В коде расширенной индексации есть три ветви и один особый случай:

  • Имеется один массив индексов, который, как и массив присваиваемых значений, допускает простой обход. Например, оба массива могут быть непрерывно расположены в памяти. Кроме того, массив индексов должен иметь тип intp, а массив значений при присваивании — нужный тип. Это исключительно оптимизированный путь выполнения.

  • Имеются только целочисленные индексы-массивы, поэтому подмассива нет.

  • Здесь смешаны индексация с созданием представлений и расширенная индексация. Первая задаёт набор подмассивов, которые объединяются посредством второй. Например, arr[[1, 2, 3], :] создаётся вертикальным объединением подмассивов arr[1, :], arr[2, :] и arr[3, :].

  • Подмассив есть, но содержит ровно один элемент. Этот случай можно обработать как отсутствие подмассива, но при подготовке нужна осторожность.

Выбор случая, проверка трансляции массивов и определение необходимой перестановки осей выполняются в PyArray_MapIterNew. После настройки возможны два случая. Если подмассива нет или в нём один элемент, отдельный обход подмассива не нужен: готовится итератор для всех массивов индексов, а также массива результата или присваиваемых значений. Если подмассив есть, готовятся три итератора: для массивов индексов; для массива результата или значений без его подмассива; и для подмассивов исходного массива и массива результата/присваивания. Первые два итератора дают указатели на начала подмассивов или позволяют вычислить их, после чего обход подмассива можно запустить заново.

Если расширенные индексы расположены рядом, может понадобиться перестановка осей. Её выполняет PyArray_MapIterSwapAxes, которую должен вызвать вызывающий код, если только PyArray_MapIterNew не поручено выделить результирующий массив.

После подготовки получение и присваивание элементов относительно просты, хотя нужно учитывать разные режимы обхода. При получении элементов допустимость индексов проверяется заранее, кроме случая с единственным индексным массивом. В этом случае ради оптимизации проверка выполняется непосредственно во внутреннем цикле.

Универсальные функции #

См. также

Универсальные функции (ufunc), Основы универсальных функций (ufunc)

Универсальные функции — вызываемые объекты, принимающие \(N\) входов и формирующие \(M\) выходов. Они оборачивают базовые одномерные циклы поэлементной обработки в удобные функции, автоматически выполняющие трансляцию массивов, проверку типов, приведение типов через буфер и обработку выходных аргументов. Новые универсальные функции обычно создают на C, хотя их можно создавать и из функций Python (frompyfunc). Пользователь должен предоставить одномерный цикл, который получает входные скалярные значения и помещает скалярные результаты в соответствующие выходные позиции, как описано в разделе о реализации.

Настройка#

Каждое вычисление ufunc связано с накладными расходами на его подготовку. Поэтому, хотя сами вычисления универсальной функции очень быстры, для небольших массивов можно написать код под конкретный массив и тип, который окажется быстрее. В частности, многократные вычисления универсальными функциями над нульмерными массивами медленнее других решений на Python. Неявно импортируемый модуль scalarmath как раз обеспечивает для скаляров NumPy поведение, похожее на вычисления универсальными функциями, со значительно меньшими накладными расходами.

Вызов ufunc требует ряда подготовительных действий. Полученная при подготовке информация хранится в объекте цикла — структуре C, которая могла бы стать объектом Python, но не инициализируется как таковой, поскольку используется только внутри реализации. Структура объекта цикла позволяет использовать его с PyArray_Broadcast, чтобы выполнять трансляцию массивов (согласование форм) так же, как в других частях кода.

Сначала из глобального словаря, отдельного для каждого потока, извлекаются текущий размер буфера, маска ошибок и связанный с ней объект ошибки. Маска ошибок определяет действия при обнаружении ошибки. Аппаратные флаги ошибок проверяются лишь после выполнения каждого одномерного цикла. Поэтому, если входные и выходные массивы непрерывно расположены в памяти и имеют нужный тип, так что достаточно одного одномерного цикла, флаги могут проверяться лишь после обработки всех элементов массива. Поиск значений в отдельном для потока словаре требует времени, но этими затратами можно пренебречь для всех массивов, кроме очень маленьких.

После проверки глобальных переменных текущего потока анализируются входные данные, чтобы определить порядок выполнения универсальной функции; при необходимости создаются входные и выходные массивы. Входные данные, не являющиеся массивами, преобразуются в массивы (при необходимости с использованием контекста). При этом отмечается, какие входные данные являются скалярами и потому преобразуются в нульмерные массивы.

Затем по типам входных массивов выбирается подходящий одномерный цикл из доступных для ufunc. Сигнатура типов входных данных сопоставляется с имеющимися сигнатурами. Сигнатуры встроенных типов хранятся в поле ufunc.types структуры ufunc. Сигнатуры пользовательских типов хранятся в связном списке сведений о функциях; его головной элемент хранится как CObject в словаре userloops с ключом, равным номеру типа данных. В качестве ключа берётся первый пользовательский тип в списке аргументов. Поиск продолжается до сигнатуры, к которой можно безопасно привести все входные массивы; скалярные аргументы, не участвующие в определении типа результата, игнорируются. Поэтому «меньшие» типы должны предшествовать «большим» при хранении сигнатур. Если одномерный цикл не найден, сообщается об ошибке. Иначе argument_list обновляется найденной сигнатурой на случай необходимости приведения типов, а также для задания выходных типов, ожидаемых одномерным циклом.

Если у универсальной функции два входа и один выход, а второй вход — массив Object, выполняется особая проверка. Возвращается NotImplemented, если второй вход не является ndarray, имеет атрибут __array_priority__ и специальный метод __r{op}__. Тем самым Python получает указание дать другому объекту возможность выполнить операцию вместо общих вычислений над массивом объектов. Это позволяет, например, разреженным матрицам переопределять одномерный цикл оператора умножения.

Для входных массивов меньше заданного размера буфера копируются все массивы, не расположенные непрерывно, неправильно выровненные или имеющие несистемный порядок байтов. Это обеспечивает обработку малых массивов одним циклом. Затем создаются итераторы всех входных массивов, а их формы согласуются по правилам трансляции.

Затем выходные аргументы (если они есть) обрабатываются и строятся недостающие возвращаемые массивы. Если какой-либо предоставленный выходной массив не имеет правильного типа (или неправильно выровнен) и меньше размера буфера, то создается новый выходной массив со специальным установленным флагом NPY_ARRAY_WRITEBACKIFCOPY. В конце функции вызывается PyArray_ResolveWritebackIfCopy, чтобы ее содержимое было скопировано обратно в выходной массив. Затем обрабатываются итераторы для выходных аргументов.

Наконец, выбирается способ выполнения циклов, чтобы объединить все элементы входных массивов в выходные массивы нужного типа. Возможны один цикл (для непрерывно расположенных в памяти и выровненных данных нужного типа), обход с шагами (для данных, расположенных не непрерывно, но выровненных и нужного типа) и цикл с буферизацией (при невыровненных данных или неподходящем типе). В соответствии с выбранным способом цикл настраивается и выполняется.

Вызов функции#

В этом разделе описываются подготовка и выполнение основного вычислительного цикла универсальной функции для каждого из трёх режимов. Если при компиляции определён NPY_ALLOW_THREADS, перед вызовом циклов глобальная блокировка интерпретатора Python (GIL) освобождается, если не используются объектные массивы. При необходимости обработки ошибок GIL захватывается снова. Аппаратные флаги ошибок проверяются только после завершения одномерного цикла.

Один цикл #

Это самый простой случай. Универсальная функция выполняется единственным вызовом базового одномерного цикла. Это возможно, только если входные и выходные данные выровнены и имеют нужный тип (включая порядок байтов), а шаги всех массивов постоянны: массивы либо непрерывно расположены в памяти, либо нульмерные, либо одномерные. Тогда одномерный вычислительный цикл вызывается один раз для обработки всего массива. Аппаратные флаги ошибок проверяются лишь после завершения всего вычисления.

Цикл обхода с шагом#

Если входные и выходные массивы выровнены и имеют правильный тип, но шаги неоднородны (данные расположены в памяти не непрерывно, а массив имеет не менее двух измерений), для вычисления применяется вторая структура циклов. Все итераторы входных и выходных аргументов преобразуются так, чтобы обходить все измерения, кроме самого большого. Внутренний цикл выполняет базовый одномерный вычислительный цикл, а внешний — обычный цикл по преобразованным итераторам. После завершения каждого одномерного цикла проверяются аппаратные флаги ошибок.

Цикл с буферизацией#

Этот код обрабатывает случаи, когда входные и/или выходные массивы не выровнены либо их тип данных, включая порядок байтов, отличается от ожидаемого базовым одномерным циклом. Также предполагается, что массивы не расположены в памяти непрерывно. Работа похожа на обход с шагом, но внутренний одномерный цикл изменён: входные данные предварительно обрабатываются, а выходные — обрабатываются после вычисления блоками размера bufsize, где bufsize задаётся пользователем. Базовый вычислительный цикл вызывается для данных, скопированных при необходимости. Подготовка и сам цикл в этом случае значительно сложнее, поскольку нужно учитывать:

  • выделение памяти временных буферов

  • определение необходимости буферизации входных и выходных данных при невыровненном размещении и/или неподходящем типе данных

  • копирование и, возможно, преобразование данных для любых входов или выходов, для которых необходимы буферы.

  • особая обработка массивов Object для правильного управления счётчиками ссылок при копировании и/или приведении типов.

  • разбиение внутреннего одномерного цикла на блоки размером bufsize (с возможным остатком).

Флаги аппаратных ошибок проверяются в конце каждого 1-D цикла.

Заключительная обработка результата#

Универсальные функции позволяют работать с другими классами, подобными массивам, так, чтобы результат сохранял класс входов. Механизм следующий: если среди входов есть объекты, отличные от ndarray и определяющие метод __array_wrap__, класс с наибольшим значением __array_priority__ задаёт тип всех выходов, кроме явно переданных выходных массивов. Метод __array_wrap__ входного массива вызывается с ndarray, полученным из универсальной функции. Поддерживаются два варианта вызова __array_wrap__. Сначала передаются ndarray и кортеж контекста (ufunc, arguments, output argument number). Если возникает TypeError, метод вызывается повторно только с ndarray в качестве единственного аргумента.

Методы #

Три метода универсальных функций требуют вычислений, подобных обычному вызову ufunc: ufunc.reduce, ufunc.accumulate и ufunc.reduceat. У каждого после подготовки выполняется цикл. Возможны четыре варианта: без элементов, с одним элементом, с заданными шагами и с буферизацией. Это те же основные варианты, что и при обычном вызове, кроме особых случаев пустого входного массива и массива из одного элемента.

Настройка#

Функция подготовки всех трёх методов — construct_reduce. Она создаёт объект цикла свёртки и заполняет его параметрами для выполнения цикла. Методы работают только с универсальными функциями с двумя входами и одним выходом. Поэтому базовый одномерный цикл выбирается для сигнатуры [otype, otype, otype], где otype — запрошенный тип данных свёртки. Затем из глобального хранилища текущего потока извлекаются размер буфера и настройки обработки ошибок. Для небольших невыровненных массивов или массивов неподходящего типа создаётся копия, позволяющая использовать код без буферизации. Далее выбирается стратегия обхода: для массива из нуля или одного элемента — простой цикл; для выровненного массива нужного типа — цикл с шагами; в остальных случаях — цикл с буферизацией. После этого задаются параметры цикла и создаётся возвращаемый массив. Его форма зависит от метода: reduce, accumulate или reduceat. Если выходной массив уже задан, его форма проверяется. Если он не удовлетворяет требованиям к непрерывному расположению в порядке C, выравниванию или типу данных, создаётся временная копия с флагом NPY_ARRAY_WRITEBACKIFCOPY. Так методы работают с массивом подходящего устройства, а при завершении функции вызов PyArray_ResolveWritebackIfCopy копирует результат обратно в настоящий выходной массив. Наконец, настраиваются итераторы для обхода нужной оси, определяемой переданным аргументом axis, и функция подготовки возвращает управление вычисляющей функции.

Reduce#

Все методы универсальных функций используют одни и те же базовые одномерные вычислительные циклы. Их входные и выходные аргументы настраиваются так, чтобы выполнить нужную свёртку. Например, работа reduce основана на том, что при вызове одномерного цикла выход и второй вход указывают на одну и ту же позицию памяти и оба имеют нулевой шаг. Первый вход указывает на входной массив, а его шаг равен соответствующему шагу массива вдоль выбранной оси. Таким образом, выполняется операция

\begin{align*} o & = & i[0] \\ o & = & i[k]\textrm{<op>}o\quad k=1\ldots N \end{align*}

где \(N+1\) — число элементов входного массива \(i\), \(o\) — результат, а \(i[k]\) — элемент с номером \(k^{\textrm{th}}\) массива \(i\) вдоль выбранной оси. Для массивов с более чем одним измерением эта базовая операция повторяется: свёртка выполняется для каждого одномерного подмассива вдоль выбранной оси. Этот обход выполняется итератором, из которого исключено выбранное измерение.

В циклах с буферизацией данные нужно скопировать и привести к нужному типу до вызова функции цикла: она ожидает выровненные данные правильного типа и порядка байтов. Перед каждым вызовом для блока размером не больше заданного пользователем bufsize буферизованный цикл выполняет такое копирование и приведение.

Accumulate#

Метод accumulate очень похож на reduce: выход и второй вход указывают на выходные данные. Отличие в том, что второй вход указывает на память на один шаг позади текущего выходного указателя. Поэтому выполняется операция

\begin{align*} o[0] & = & i[0] \\ o[k] & = & i[k]\textrm{<op>}o[k-1]\quad k=1\ldots N. \end{align*}

Результат имеет ту же форму, что и входные данные. Каждый одномерный цикл обрабатывает \(N\) элементов, когда длина выбранной оси равна \(N+1\). Циклы с буферизацией также копируют и приводят данные перед вызовом базового одномерного вычислительного цикла.

Reduceat#

Функция reduceat обобщает reduce и accumulate. Она выполняет reduce по диапазонам входного массива, заданным индексами. Перед вычислениями проверяется, не превышают ли значения дополнительного аргумента indices границы входного массива по выбранной оси. Реализация похожа на код reduce, повторённый для каждого элемента indices. Первый входной указатель, передаваемый базовому одномерному вычислительному циклу, указывает на позицию входного массива, заданную массивом индексов. Выходной и второй входной указатели этого цикла указывают на одну и ту же область памяти. Длина одномерного цикла равна разности следующего и текущего индексов; для последнего индекса следующим считается длина массива по выбранной оси. Таким образом, одномерный цикл выполняет reduce по заданным диапазонам индексов.

Невыровненные данные или несовпадение типа внутреннего цикла с типом входных и/или выходных данных обрабатываются через буферизацию. Перед вызовом базовой одномерной функции данные копируются во временный буфер и при необходимости приводятся к нужному типу. Размер временных буферов в элементах не превышает настраиваемого пользователем предела. Поэтому внешний цикл должен вызывать базовый одномерный вычислительный цикл столько раз, сколько нужно для обработки всех данных порциями не больше буфера.
