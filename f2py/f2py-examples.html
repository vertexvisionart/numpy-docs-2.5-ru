Примеры F2PY #

Ниже приведены примеры использования F2PY. Список не исчерпывающий, но может служить отправной точкой при создании обёрток для собственного кода.

Примечание

Примеры лучше всего искать в трекере ошибок NumPy или тестах f2py. Дополнительные примеры приведены в разделе Сокращение шаблонного кода и шаблонизация.

Пошаговый пример F2PY: простой модуль расширения#

Создание исходного кода простого модуля расширения#

Рассмотрим следующую подпрограмму, содержащуюся в файле с именем add.f.

C
      SUBROUTINE ZADD(A,B,C,N)
C
      DOUBLE COMPLEX A(*)
      DOUBLE COMPLEX B(*)
      DOUBLE COMPLEX C(*)
      INTEGER N
      DO 20 J = 1, N
         C(J) = A(J)+B(J)
 20   CONTINUE
      END

Эта подпрограмма просто складывает элементы двух массивов, непрерывно расположенных в памяти, и помещает результат в третий. Память для всех трёх массивов должна выделить вызывающая подпрограмма. f2py может автоматически сгенерировать простейший интерфейс к этой подпрограмме:

python -m numpy.f2py -m add add.f

Эта команда создаст в текущем каталоге файл addmodule.c с исходным кодом модуля расширения. После компиляции модуль можно использовать из Python, как любой другой модуль расширения. Примечание переводчика: оригинал называет addmodule.c модулем расширения; точнее, это исходный файл C, который ещё требуется скомпилировать.

Создание скомпилированного модуля расширения #

Можно также поручить f2py скомпилировать add.f вместе с созданным кодом модуля расширения. В результате останется только файл разделяемой библиотеки расширения, который можно импортировать из Python:

python -m numpy.f2py -c -m add add.f

Эта команда создаёт модуль расширения Python, совместимый с вашей платформой. Затем его можно импортировать в Python. Модуль будет содержать метод для каждой подпрограммы из add. Строка документации каждого метода описывает, как его вызывать:

>>> import add
>>> print(add.zadd.__doc__)
zadd(a,b,c,n)

Wrapper for ``zadd``.

Parameters
----------
a : input rank-1 array('D') with bounds (*)
b : input rank-1 array('D') with bounds (*)
c : input rank-1 array('D') with bounds (*)
n : input int

Улучшение базового интерфейса#

Стандартный интерфейс почти буквально переносит код Fortran в Python. Аргументы-массивы Fortran преобразуются в массивы NumPy, а целочисленный аргумент должен соответствовать целому числу C. Интерфейс пытается привести аргументы к нужным типам и формам и выдаёт ошибку, если это невозможно. Однако f2py не знает назначения аргументов: что C — выходной массив, а n должен соответствовать размерам массивов. Поэтому некорректный вызов функции может аварийно завершить Python. Например:

>>> add.zadd([1, 2, 3], [1, 2], [3, 4], 1000)

приведёт к аварийному завершению программы в большинстве систем. Внутри списки преобразуются в массивы, но базовой функции add затем указывается обходить данные далеко за границами выделенной памяти.

Для настройки интерфейса f2py поддерживает директивы, задаваемые в файле сигнатур. Обычно лучше начать с интерфейсов, которые f2py генерирует в этом файле и которые соответствуют поведению по умолчанию. Чтобы f2py создал файл интерфейса, используйте параметр -h:

python -m numpy.f2py -h add.pyf -m add add.f

Эта команда создает файл add.pyf в текущем каталоге. Раздел этого файла, соответствующий zadd:

subroutine zadd(a,b,c,n) ! in :add:add.f
   double complex dimension(*) :: a
   double complex dimension(*) :: b
   double complex dimension(*) :: c
   integer :: n
end subroutine zadd
Комментарии к примеру на русском
  • В :add:add.f

Директивы intent и код проверок позволяют значительно улучшить интерфейс: метод модуля Python становится удобнее в использовании и устойчивее к некорректным входным данным.

subroutine zadd(a,b,c,n) ! in :add:add.f
   double complex dimension(n) :: a
   double complex dimension(n) :: b
   double complex intent(out),dimension(n) :: c
   integer intent(hide),depend(a) :: n=len(a)
end subroutine zadd
Комментарии к примеру на русском
  • В :add:add.f

Директива intent(out) сообщает f2py, что c — выходная переменная, которую интерфейс должен создать перед передачей в базовый код. Директива intent(hide) запрещает пользователю задавать переменную n: вместо этого она определяется по размеру a. Директива depend(a) сообщает f2py, что значение n зависит от входа a, чтобы n не создавалась до создания a.

После изменения add.pyf новый файл модуля Python можно сгенерировать путем компиляции add.f и add.pyf:

python -m numpy.f2py -c add.pyf add.f

Докстринг нового интерфейса:

>>> import add
>>> print(add.zadd.__doc__)
c = zadd(a,b)

Wrapper for ``zadd``.

Parameters
----------
a : input rank-1 array('D') with bounds (n)
b : input rank-1 array('D') with bounds (n)

Returns
-------
c : rank-1 array('D') with bounds (n)

Теперь функцию можно вызывать гораздо более надёжным способом:

>>> add.zadd([1, 2, 3], [4, 5, 6])
array([5.+0.j, 7.+0.j, 9.+0.j])

Обратите внимание на автоматическое преобразование в правильный формат, который произошел.

Вставка директив в исходный код Fortran#

Надёжный интерфейс предыдущего раздела можно создать автоматически, записав директивы переменных специальными комментариями в исходном коде Fortran.

Примечание

Для проектов, где активно разрабатывается код Fortran, это может быть предпочтительным.

Таким образом, если изменить исходный код следующим образом:

C
      SUBROUTINE ZADD(A,B,C,N)
C
CF2PY INTENT(OUT) :: C
CF2PY INTENT(HIDE) :: N
CF2PY DOUBLE COMPLEX :: A(N)
CF2PY DOUBLE COMPLEX :: B(N)
CF2PY DOUBLE COMPLEX :: C(N)
      DOUBLE COMPLEX A(*)
      DOUBLE COMPLEX B(*)
      DOUBLE COMPLEX C(*)
      INTEGER N
      DO 20 J = 1, N
         C(J) = A(J) + B(J)
 20   CONTINUE
      END

Затем можно скомпилировать модуль расширения, используя:

python -m numpy.f2py -c -m add add.f

Сигнатура функции add.zadd точно совпадает с созданной ранее. Если бы исходный код содержал A(N) вместо A(*) и аналогичные изменения для B и C, почти тот же интерфейс можно было бы получить строкой комментария INTENT(OUT) :: C в исходном коде. Отличие лишь в том, что N был бы необязательным входным аргументом со стандартным значением, равным длине A.

Пример фильтрации#

В этом примере показана функция, которая фильтрует двумерный массив чисел двойной точности с плавающей запятой, используя фиксированный фильтр усреднения. Преимущество использования Фортрана для индексации многомерных массивов должно быть ясно из этого примера.

C
      SUBROUTINE DFILTER2D(A,B,M,N)
C
      DOUBLE PRECISION A(M,N)
      DOUBLE PRECISION B(M,N)
      INTEGER N, M
CF2PY INTENT(OUT) :: B
CF2PY INTENT(HIDE) :: N
CF2PY INTENT(HIDE) :: M
      DO 20 I = 2,M-1
         DO 40 J = 2,N-1
            B(I,J) = A(I,J) +
     &           (A(I-1,J)+A(I+1,J) +
     &           A(I,J-1)+A(I,J+1) )*0.5D0 +
     &           (A(I-1,J-1) + A(I-1,J+1) +
     &           A(I+1,J-1) + A(I+1,J+1))*0.25D0
 40      CONTINUE
 20   CONTINUE
      END

Этот код можно скомпилировать и скомпоновать в модуль расширения filter следующим образом:

python -m numpy.f2py -c -m filter filter.f

В текущем каталоге будет создан модуль расширения с методом dfilter2d, возвращающим отфильтрованные входные данные.

Пример аргумента depends#

Рассмотрим следующий код, сохраненный в файле myroutine.f90:

subroutine s(n, m, c, x)
	implicit none
  	integer, intent(in) :: n, m
  	real(kind=8), intent(out), dimension(n,m) :: x
  	real(kind=8), intent(in) :: c(:)

	x = 0.0d0
	x(1, 1) = c(1)

end subroutine s

Обернув это с помощью python -m numpy.f2py -c myroutine.f90 -m myroutine, мы можем сделать в Python следующее:

>>> import numpy as np
>>> import myroutine
>>> x = myroutine.s(2, 3, np.array([5, 6, 7]))
>>> x
array([[5., 0., 0.],
   [0., 0., 0.]])

Теперь сначала создадим файл сигнатур этой подпрограммы, вместо того чтобы сразу генерировать модуль расширения. Это обычный подход при многоэтапном создании расширений. В данном случае после выполнения

python -m numpy.f2py myroutine.f90 -m myroutine -h myroutine.pyf

создаётся следующий файл сигнатур:

!    -*- f90 -*-
! Note: the context of this file is case sensitive.

python module myroutine ! in 
    interface  ! in :myroutine
        subroutine s(n,m,c,x) ! in :myroutine:myroutine.f90
            integer intent(in) :: n
            integer intent(in) :: m
            real(kind=8) dimension(:),intent(in) :: c
            real(kind=8) dimension(n,m),intent(out),depend(m,n) :: x
        end subroutine s
    end interface 
end python module myroutine

python module myroutine ! in

            integer intent(in) :: n
            integer intent(in) :: m
            real(kind=8) dimension(:),intent(in) :: c
            real(kind=8) dimension(n,m),intent(out) :: x
        end subroutine s
    end interface
