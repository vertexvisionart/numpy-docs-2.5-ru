Файл сигнатур#

Файл определения интерфейса .pyf позволяет точно настроить взаимодействие Python и Fortran. Синтаксис файлов сигнатур (файлов .pyf) основан на спецификации языка Fortran 90/95. Поддерживаются почти все стандартные конструкции Fortran в свободном и фиксированном формате; напомним, что Fortran 77 — подмножество Fortran 90/95. F2PY добавляет расширения к спецификации Fortran 90/95, которые помогают проектировать более естественный для Python интерфейс с Fortran.

Файлы сигнатур могут содержать произвольный код Fortran, поэтому любой код Fortran 90/95 можно рассматривать как файл сигнатур. F2PY без предупреждения игнорирует конструкции, не относящиеся к созданию интерфейса. Это также означает, что F2PY не обнаруживает синтаксические ошибки: они выявляются лишь при сборке библиотеки.

Примечание

В настоящее время F2PY может не справляться с некоторыми корректными конструкциями Fortran. В таком случае поищите возможные обходные решения или обсуждаемые подходы в системе отслеживания задач NumPy на GitHub.

Содержимое файлов сигнатур в целом чувствительно к регистру. При анализе кода Fortran для создания файла сигнатур F2PY автоматически переводит символы в нижний регистр, кроме многострочных блоков и случая с параметром --no-lower.

Синтаксис файлов сигнатур#

Блок модуля Python#

Файл сигнатур может содержать один (рекомендуется) или несколько блоков python module. Блок python module описывает содержимое модуля расширения Python/C <modulename>module.c, генерируемого F2PY.

Предупреждение

Исключение: если <modulename> содержит подстроку __user__, соответствующий блок python module описывает сигнатуры функций обратного вызова (см. «Аргументы обратного вызова»).

Блок python module имеет следующую структуру:

python module <modulename>
  [<usercode statement>]...
  [
  interface
    <usercode statement>
    <Fortran block data signatures>
    <Fortran/C routine signatures>
  end [interface]
  ]...
  [
  interface
    module <F90 modulename>
      [<F90 module data type declarations>]
      [<F90 module routine signatures>]
    end [module [<F90 modulename>]]
  end [interface]
  ]...
end [python module [<modulename>]]

Скобки [] обозначают необязательную часть, а точки ... — одно или несколько повторений предыдущей части. Поэтому []... означает ноль или более повторений.

Сигнатуры подпрограмм Fortran/C#

Сигнатура подпрограммы Fortran имеет следующую структуру:

[<typespec>] function | subroutine <routine name> \
              [ ( [<arguments>] ) ] [ result ( <entityname> ) ]
  [<argument/variable type declarations>]
  [<argument/variable attribute statements>]
  [<use statements>]
  [<common block statements>]
  [<other statements>]
end [ function | subroutine [<routine name>] ]

По сигнатуре процедуры Fortran F2PY создаёт функцию расширения Python/C со следующей сигнатурой:

def <routine name>(<required arguments>[,<optional arguments>]):
     ...
     return <return variables>

Сигнатура блока данных Fortran имеет следующую структуру:

block data [ <block data name> ]
  [<variable type declarations>]
  [<variable attribute statements>]
  [<use statements>]
  [<common block statements>]
  [<include statements>]
end [ block data [<block data name>] ]

Объявления типов#

Часть <argument/variable type declaration> определяется следующим образом:

<typespec> [ [<attrspec>] :: ] <entitydecl>

где

<typespec> := byte | character [<charselector>]
           | complex [<kindselector>] | real [<kindselector>]
           | double complex | double precision
           | integer [<kindselector>] | logical [<kindselector>]

<charselector> := * <charlen>
               | ( [len=] <len> [ , [kind=] <kind>] )
               | ( kind= <kind> [ , len= <len> ] )
<kindselector> := * <intlen> | ( [kind=] <kind> )

<entitydecl> := <name> [ [ * <charlen> ] [ ( <arrayspec> ) ]
                      | [ ( <arrayspec> ) ] * <charlen> ]
                     | [ / <init_expr> / | = <init_expr> ] \
                       [ , <entitydecl> ]

и

  • <attrspec> — список атрибутов, разделённых запятыми;

  • <arrayspec> — это разделённый запятой список границ измерений;

  • <init_expr> - это C выражение ;

  • Значение <intlen> может быть отрицательным целым числом в спецификации типа integer. В таком случае integer*<negintlen> обозначает беззнаковые целые числа C;

Если у аргумента нет <argument type declaration>, его тип определяется по имени согласно правилам implicit.

Операторы#

Инструкции атрибутов#

<argument/variable attribute statement> аналогичен <argument/variable type declaration>, но без <typespec>.

Оператор атрибута не может содержать другие атрибуты, а <entitydecl> может быть только списком имён. Подробнее о допустимых атрибутах F2PY см. Атрибуты.

Инструкции USE#

  • Часть <use statement> определяется следующим образом:

    use <modulename> [ , <rename_list> | , ONLY : <only_list> ]

    где

    <rename_list> := <local_name> => <use_name> [ , <rename_list> ]

  • В настоящее время F2PY использует операторы use только для связывания модулей обратного вызова и аргументов external — функций обратного вызова. См. «Аргументы обратного вызова».

Операторы блоков COMMON#

  • Часть <common block statement> определяется следующим образом:

    common / <common name> / <shortentitydecl>

    где

    <shortentitydecl> := <name> [ ( <arrayspec> ) ] [ , <shortentitydecl> ]

  • Если блок python module содержит два или более блоков common с одинаковым именем, добавляются переменные из дополнительных объявлений. Типы переменных в <shortentitydecl> определяются с помощью <argument type declarations>. Обратите внимание, что соответствующий <argument type declarations> может содержать спецификации массива; тогда их не нужно указывать в <shortentitydecl>.

Другие инструкции#

  • Часть <other statement> относится к любым другим конструкциям языка Fortran, которые не описаны выше. F2PY игнорирует большинство из них, за исключением следующего:

    • операторы call и вызовы функций, переданных в аргументах external (см. подробнее о внешних аргументах);

    • Инструкции include
      include '<filename>'
include "<filename>"

      Если файла <filename> нет, инструкция include игнорируется. Иначе файл <filename> включается в файл сигнатур. Инструкции include можно использовать в любой части файла сигнатур, в том числе вне блоков сигнатур подпрограмм Fortran/C.

    • Инструкции implicit
      implicit none
implicit <list of implicit maps>

      где

      <implicit map> := <typespec> ( <list of letters or range of letters> )

      Если переменная не определена с помощью <variable type declaration>, её тип определяется неявными правилами по первой букве имени. Правила по умолчанию таковы:

      implicit real (a-h,o-z,$_), integer (i-m)
    • Инструкции entry
      entry <entry name> [([<arguments>])]

      F2PY создаёт обёртки для всех точек входа, используя сигнатуру блока подпрограммы.

      Примечание

      Оператор entry описывает сигнатуру произвольной подпрограммы или функции, позволяя F2PY создавать несколько обёрток по одной сигнатуре блока процедуры. Есть ограничения: fortranname использовать нельзя; callstatement и callprotoargument можно использовать, только если они допустимы для всех процедур entry, и т. д.

Операторы F2PY#

Кроме того, F2PY вводит следующие операторы:

threadsafe

Помещает вызов функции Fortran/C внутрь блока Py_BEGIN_ALLOW_THREADS .. Py_END_ALLOW_THREADS.

callstatement <C-expr|multi-line block>

Заменяет созданную F2PY инструкцию вызова функции Fortran/C на <C-expr|multi-line block>. Функция Fortran/C, для которой создаётся обёртка, доступна как (*f2py_func).

Чтобы вызвать исключение, задайте f2py_success = 0 в <C-expr|multi-line block>.

callprotoargument <C-typespecs>

При использовании оператора callstatement F2PY может не генерировать правильные прототипы для функций Fortran/C (поскольку <C-expr> может содержать вызовы функций, а F2PY не имеет возможности определить, какой прототип должен быть правильным).

Этот оператор позволяет явно задать аргументы соответствующего прототипа:

extern <return type> FUNC_F(<routine name>,<ROUTINE NAME>)(<callprotoargument>);
fortranname [<actual Fortran/C routine name>]

F2PY позволяет использовать произвольный <routine name> для заданной функции Fortran/C. Затем это утверждение используется для <actual Fortran/C routine name>.

Если оператор fortranname используется без <actual Fortran/C routine name>, создается фиктивная оболочка.

usercode <multi-line block>

При использовании внутри блока python module указанный код C вставляется в генерируемый исходный код C/API непосредственно перед определениями функций-обёрток.

Здесь можно определить произвольные функции С, которые будут использоваться для инициализации необязательных аргументов.

Например, если usercode используется дважды внутри блока python module, то после определения внешних процедур вставляется второй многострочный блок.

При использовании внутри <routine signature> данный код C будет вставлен в соответствующую функцию-оболочку сразу после объявления переменных, но перед любыми операторами C. Таким образом, продолжение usercode может содержать как объявления, так и операторы C.

При использовании внутри первого блока interface указанный код C вставляется в конец функции инициализации модуля расширения. Так можно изменять словарь модуля расширения, например определять дополнительные переменные.

pymethoddef <multiline block>

Многострочный блок, вставляемый в определение массива PyMethodDef с методами модуля. Он должен содержать разделённый запятыми список массивов C (подробности см. в документации Python «Расширение и встраивание»). Инструкцию pymethoddef можно использовать только внутри блока python module.

Атрибуты#

Следующие атрибуты могут быть использованы F2PY.

optional

Соответствующий аргумент переносится в конец списка <optional arguments>. Значение по умолчанию для необязательного аргумента можно задать через <init_expr> (см. entitydecl и его определение).

Примечание

  • Значение по умолчанию должно быть дано в качестве действительного выражения C.

  • Всякий раз, когда используется <init_expr>, атрибут optional устанавливается автоматически F2PY.

  • У необязательного аргумента-массива размеры всех измерений должны быть определены.

required

Аргумент с этим атрибутом считается обязательным. Это поведение по умолчанию. required следует указывать только для отключения автоматического назначения optional при использовании <init_expr>.

Если в качестве требуемого аргумента используется объект Python None, то аргумент рассматривается как необязательный. То есть в случае аргументов массива выделяется память. Если задан <init_expr>, то проводится соответствующая инициализация.

dimension(<arrayspec>)

Соответствующая переменная рассматривается как массив с размерами, приведенными в <arrayspec>.

intent(<intentspec>)

Задаёт назначение (intent) соответствующего аргумента. <intentspec> — список следующих ключей через запятую:

  • in

    Соответствующий аргумент считается доступным только для ввода. Это означает, что значение аргумента передается функции Fortran/C и ожидается, что функция не изменит значение этого аргумента.

  • inout

    Соответствующий аргумент помечается как входной/выходной либо выходной с изменением на месте. Аргументы intent(inout) могут быть только массивами NumPy, непрерывно расположенными в памяти в порядке Fortran или C и имеющими подходящие тип и размер. Непрерывность в порядке C соответствует обычному понятию непрерывности в NumPy и применяется только при указании intent(c). По умолчанию F2PY предполагает непрерывное расположение в порядке Fortran.

    Примечание

    Использовать intent(inout) обычно не рекомендуется: это может приводить к неожиданным результатам. Например, скалярные аргументы с intent(inout) считаются объектами массивов, чтобы изменения на месте имели эффект. Вместо этого используйте intent(in,out).

    См. также атрибут intent(inplace).

  • inplace

    Соответствующий аргумент считается входным/выходным либо выходным аргументом с изменением на месте. Аргументы intent(inplace) должны быть массивами NumPy подходящего размера. Если размер не подходит или массив не расположен непрерывно в памяти, подпрограмме передаётся исправленная копия с флагом NPY_ARRAY_WRITEBACKIFCOPY, чтобы при выходе результат был скопирован обратно в исходный массив.

    Примечание

    Поскольку возможно создание копий, intent(inplace) может работать медленнее, чем ожидается. Этот вариант предпочтительнее inout, но уступает in,out.

  • out

    Соответствующим аргументом считается возвращаемая переменная. Он прилагается к списку <returned variables>. Использование intent(out) устанавливает intent(hide) автоматически, если не указаны также intent(in) или intent(inout).

    По умолчанию возвращаемые многомерные массивы непрерывно расположены в памяти в порядке Fortran. При атрибуте intent(c) используется непрерывное расположение в порядке C.

  • hide

    Соответствующий аргумент удаляется из списка обязательных или необязательных аргументов. Обычно intent(hide) используется вместе с intent(out) или когда <init_expr> полностью определяет значение аргумента, как в следующем примере:

    integer intent(hide),depend(a) :: n = len(a)
real intent(in),dimension(n) :: a
  • c

    Аргумент обрабатывается как скаляр или массив C. Скаляр передаётся функции C по значению; напомним, что скалярные аргументы Fortran фактически передаются как указатели C. Для массивов предполагается, что обёртка интерпретирует многомерные массивы как непрерывно расположенные в памяти в порядке C.

    Для одномерных массивов не нужно использовать intent(c) независимо от того, написана ли оборачиваемая функция на Fortran или C. Для одномерных массивов условия непрерывного расположения в памяти в порядке Fortran и C совпадают.

    Если intent(c) используется как инструкция без списка объявлений сущностей, F2PY добавляет атрибут intent(c) ко всем аргументам.

    Кроме того, при обертывании функций C необходимо использовать атрибут intent(c) для <routine name>, чтобы отключить макросы F_FUNC(..,..), характерные для Fortran.

  • cache

    Соответствующий аргумент считается неинициализированной рабочей памятью. Проверки непрерывности в порядке Fortran или C не выполняются. intent(cache) имеет смысл только для аргументов-массивов, в том числе вместе с атрибутами intent(hide) или optional.

  • copy

    Гарантирует сохранение исходного содержимого аргумента intent(in). Обычно используется с атрибутом intent(in,out). F2PY создает дополнительный аргумент overwrite_<argument name> со значением по умолчанию 0 .

  • overwrite

    Это указывает на то, что исходное содержимое аргумента intent(in) может быть изменено функцией Fortran/C. F2PY создает дополнительный аргумент overwrite_<argument name> со значением по умолчанию 1 .

  • out=<new name>

    Заменяет возвращенное имя на <new name> в строке __doc__ функции обертки.

  • callback

    Создаёт внешнюю функцию для вызова функций Python из Fortran. intent(callback) нужно указать перед соответствующим оператором external. Если аргумент отсутствует в списке аргументов, он добавляется в обёртку Python, но только путём инициализации внешней функции.

    Примечание

    Используйте intent(callback), если код Fortran/C предполагает, что пользователь реализовал функцию с заданным прототипом и скомпоновал её с исполняемым файлом. Не используйте intent(callback), если функция указана в списке аргументов подпрограммы Fortran.

    Если заданы атрибуты intent(hide) или optional и функция-обёртка вызывается без аргумента обратного вызова в списке аргументов, функция обратного вызова ищется в пространстве имён модуля расширения, созданного F2PY. Пользователь может задать её как атрибут этого модуля.

  • aux

    Определяет вспомогательную переменную C в функции-обёртке, сгенерированной F2PY. Полезно для сохранения значений параметров, чтобы использовать их в выражениях инициализации других переменных.

    Примечание

    intent(aux) неявно включает intent(c).

Применяются следующие правила:

  • Если ни один из intent(in | inout | out | hide) не указан, предполагается intent(in).

    • intent(in,inout) — это intent(in);

    • intent(in,hide) или intent(inout,hide) — это intent(hide) ;

    • intent(out) - это intent(out,hide), если не указаны intent(in) или intent(inout).

  • При использовании intent(copy) или intent(overwrite) вводится дополнительный необязательный аргумент overwrite_<argument name> со значением по умолчанию 0 или 1 соответственно.

    • intent(inout,inplace) — это intent(inplace);

    • intent(in,inplace) — это intent(inplace);

    • intent(hide) отключает optional и required.

check([<C-booleanexpr>])

Выполняет проверку согласованности аргументов, оценивая <C-booleanexpr>; если <C-booleanexpr> возвращает 0, возникает исключение.

Примечание

Если check(..) не используется, F2PY автоматически создаёт несколько стандартных проверок (например, для аргумента-массива проверяются правильность формы и размера). Используйте check(), чтобы отключить проверки, создаваемые F2PY.

depend([<names>])

Это означает, что соответствующий аргумент зависит от значений переменных в списке <names>. Например, <init_expr> может использовать значения других аргументов. Используя информацию, предоставляемую атрибутами depend(..), F2PY гарантирует, что аргументы инициализируются в правильном порядке. Если атрибут depend(..) не используется, F2PY автоматически определяет отношения зависимости. Используйте depend(), чтобы отключить отношения зависимости, генерируемые F2PY.

Изменяя зависимости, первоначально созданные F2PY, следите, чтобы не нарушить зависимости других связанных переменных. Также остерегайтесь циклических зависимостей. F2PY обнаруживает их при создании обёрток и сообщает об этом.

allocatable

Соответствующая переменная — массив Fortran 90 с атрибутом allocatable, объявленный как данные модуля Fortran 90.

external

Соответствующий аргумент — функция пользователя. Сигнатура этой функции обратного вызова может быть определена

  • в модульном блоке __user__,

  • или посредством демонстрационного вызова (либо настоящего, если файл сигнатур является полноценным кодом Fortran) в блоке <other statements>.

Например, из следующего кода F2PY генерирует:

external cb_sub, cb_fun
integer n
real a(n),r
call cb_sub(a,n)
r = cb_fun(4)

следующие сигнатуры обратного вызова:

subroutine cb_sub(a,n)
    real dimension(n) :: a
    integer optional,check(len(a)>=n),depend(a) :: n=len(a)
end subroutine cb_sub
function cb_fun(e_4_e) result (r)
    integer :: e_4_e
    real :: r
end function cb_fun

Соответствующие функции Python, предоставляемые пользователем:

def cb_sub(a,[n]):
    ...
    return
def cb_fun(e_4_e):
    ...
    return r

См. также атрибут intent(callback).

parameter

Это указывает на то, что соответствующая переменная является параметром и должна иметь фиксированное значение. F2PY заменяет все встречающиеся параметры соответствующими значениями.

Расширения #

F2PY директивы #

Директивы F2PY позволяют использовать конструкции файлов сигнатур прямо в исходном коде Fortran 77/90. Благодаря этому промежуточный файл сигнатур почти всегда можно не создавать, применяя F2PY непосредственно к исходному коду Fortran.

Директивы F2PY имеют следующую форму:

<comment char>f2py ...

где допустимые символы комментариев для кода Fortran в фиксированном и свободном формате — cC*!# и ! соответственно. Всё после <comment char>f2py компилятор игнорирует, а F2PY читает как обычную строку кода Fortran, не являющуюся комментарием:

Примечание

Когда F2PY находит строку с директивой F2PY, директива сначала заменяется 5 пробелами, а затем строка перечитывается.

Для кодов Фортрана фиксированного формата <comment char>, конечно, должен находиться в первом столбце файла. Для кодов Fortran свободного формата директивы F2PY могут появляться в любом месте файла.

C-выражения #

Выражения C используются в следующих частях файлов сигнатур:

  • <init_expr> для инициализации переменных;

  • <C-booleanexpr> атрибута check;

  • <arrayspec> атрибута dimension;

  • оператор callstatement; здесь также можно использовать многострочный блок C.

Выражение C может содержать:

  • стандартные конструкции C;

  • функции из math.h и Python.h;

  • переменные из списка аргументов, предположительно инициализированные ранее в соответствии с заданными отношениями зависимости;

  • Следующие макросы CPP:

    f2py_rank(<name>)

    Возвращает ранг массива <name>.

    f2py_shape(<name>, <n>)

    Возвращает <n>-е измерение массива <name>.

    f2py_len(<name>)

    Возвращает длину массива <name>.

    f2py_size(<name>)

    Возвращает размер массива <name>.

    f2py_itemsize(<name>)

    Возвращает размер элемента (itemsize) массива <name>.

    f2py_slen(<name>)

    Возвращает длину строки <name>.

Для инициализации массива <array name> F2PY генерирует цикл по всем индексам и измерениям, который выполняет следующий псевдооператор:

<array name>(_i[0],_i[1],...) = <init_expr>;

где _i[<i>] обозначает индекс вдоль измерения <i>, принимающий значения от 0 до shape(<array name>,<i>)-1.

Например, функция myrange(n), сгенерированная по следующей сигнатуре

subroutine myrange(a,n)
  fortranname        ! myrange is a dummy wrapper
  integer intent(in) :: n
  real*8 intent(c,out),dimension(n),depend(n) :: a = _i[0]
end subroutine myrange

Это эквивалентно numpy.arange(n,dtype=float).

Предупреждение

При разборе кода Fortran F2PY может переводить в нижний регистр и выражения C; см. параметр --[no]-lower.

Многострочные блоки#

Многострочный блок начинается с ''' (трёх одинарных кавычек) и заканчивается ''' на строго последующей строке. Такие блоки допустимы только в файлах .pyf. Содержимое может быть произвольным, кроме ''', и не подвергается преобразованиям, например переводу в нижний регистр.

Сейчас многострочные блоки можно использовать в следующих конструкциях:

  • как выражение C оператора callstatement;

  • как спецификацию типов C для инструкции callprotoargument;

  • как блок кода C оператора usercode;

  • в виде списка C-массивов pymethoddef-заявления;

  • как строку документации.

Расширенный char-selector#

F2PY расширяет спецификацию char-selector, которую можно использовать в файле сигнатур или директиве F2PY, следующим образом:

<extended-charselector> := <charselector>
                        | (f2py_len= <len>)

Описание использования см. в разделе «Строки символов».
