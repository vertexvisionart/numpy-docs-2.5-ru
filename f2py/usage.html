Использование F2PY#

Эта страница содержит справочник по всем параметрам командной строки команды f2py, а также по внутренним функциям модуля numpy.f2py.

Использование f2py в качестве инструмента командной строки #

При запуске из командной строки f2py имеет три основных режима, определяемых использованием параметров -c и -h.

1. Создание файла сигнатур#

Для сканирования исходного кода Fortran и создания файла сигнатур используйте

f2py -h <filename.pyf> <options> <fortran files>   \
  [[ only: <fortran functions>  : ]                \
    [ skip: <fortran functions>  : ]]...           \
  [<fortran files> ...]

Примечание

Исходный файл Фортрана может содержать множество подпрограмм, и часто нет необходимости разрешать использование всех подпрограмм из Python. В таких случаях либо укажите, какие подпрограммы следует обернуть (в части only: .. :), либо какие подпрограммы F2PY должен игнорировать (в части skip: .. :).

В F2PY нет концепции «пофайлового» списка skip или only, поэтому, если функции перечислены в only, никакие другие функции не будут взяты из каких-либо других файлов.

Если в качестве <filename.pyf> указано stdout, сигнатуры записываются в стандартный вывод, а не в файл.

Среди других вариантов (см. ниже) в этом режиме можно использовать следующие:

--overwrite-signature

Перезаписывает существующий файл сигнатур.

2. Создание модуля расширения#

Чтобы создать модуль расширения, используйте

f2py -m <modulename> <options> <fortran files>   \
  [[ only: <fortran functions>  : ]              \
    [ skip: <fortran functions>  : ]]...          \
  [<fortran files> ...]

Созданный модуль расширения сохраняется как <modulename>module.c в текущем каталоге.

Здесь <fortran files> также может содержать файлы сигнатур. Среди других опций (см. ниже) в этом режиме можно использовать следующие опции:

--debug-capi

Добавляет отладочные средства в модуль расширения. При его использовании в стандартный вывод записывается диагностическая информация об обёртке, например значения переменных, выполненные шаги и т. д.

-include'<includefile>'

Добавляет директиву препроцессора C #include в исходный код модуля расширения. <includefile> следует задавать в одном из следующих форматов:

"filename.ext"
<filename.ext>

Оператор include вставляется непосредственно перед функцией-оболочкой. Эта функция позволяет использовать произвольные функции C (определенные в <includefile>) в оболочках, сгенерированных F2PY.

Примечание

Этот параметр объявлен устаревшим. Используйте инструкцию usercode, чтобы задавать фрагменты кода C непосредственно в файлах сигнатур.

--[no-]wrap-functions

Создавать обёртки в виде подпрограмм Fortran для функций Fortran. По умолчанию используется --wrap-functions: это обеспечивает максимальную переносимость и независимость от компилятора.

--[no-]freethreading-compatible

Создаёт модуль с указанием, требуется ли ему GIL. Для обратной совместимости по умолчанию используется --no-freethreading-compatible. Перед передачей --freethreading-compatible проверьте оборачиваемый код Fortran на потокобезопасность: f2py сам этого не анализирует.

--include-paths "<path1>:<path2>..."

Искать подключаемые заголовочные файлы в заданных каталогах.

Примечание

Пути следует разделять системным разделителем pathsep: : в Linux/macOS и ; в Windows. В CMake этому соответствует использование $<SEMICOLON>.

3.Создание модуля #

Чтобы создать модуль расширения, используйте

f2py -c <options> <fortran files>       \
  [[ only: <fortran functions>  : ]     \
    [ skip: <fortran functions>  : ]]... \
  [ <fortran/c source files> ] [ <.o, .a, .so files> ]

Если <fortran files> включает файл сигнатур, создаётся исходный код модуля расширения, компилируются все исходники Fortran и C, затем объектные файлы и библиотеки компонуются в модуль <modulename>.so, сохраняемый в текущем каталоге.

Если <fortran files> не содержит файла сигнатур, перед сборкой модуля расширения все исходные файлы Fortran сканируются для извлечения сигнатур процедур.

Предупреждение

distutils удалён. Для настройки meson используйте переменные окружения или файлы конфигурации native files. Подробнее см. FAQ.

Помимо других параметров (см. ниже) и параметров предыдущих режимов доступны следующие.

Примечание

Изменено в версии 2.5.0: механизм сборки distutils удалён.

Общие флаги сборки:

--backend <backend_type>

Устаревший вариант, поддерживается только meson.

--f77flags=<string>

Задать флаги компилятора F77

--f90flags=<string>

Задать флаги компилятора F90

--debug

Компиляция с отладочной информацией

-l<libname>

Подключить библиотеку <libname> при компоновке.

-D<macro>[=<defn=1>]

Определите макрос <macro> как <defn>.

-U<macro>

Определить макрос <macro>

-I<dir>

Добавляет каталог <dir> в список каталогов поиска включаемых файлов.

-L<dir>

Добавляет каталог <dir> в список каталогов поиска для -l.

--dep <dependency>

Задаёт зависимость Meson для модуля. Для нескольких зависимостей параметр можно повторить; зависимости сохраняются в списке для дальнейшей обработки. Например, --dep lapack --dep scalapack добавит “lapack” и “scalapack” в список зависимостей и удалит соответствующие аргументы из argv. Получится список [“lapack”, “scalapack”].

Примечание

Параметр f2py -c необходимо использовать либо с существующим файлом .pyf (и файлами исходного кода, объектными файлами или библиотеками), либо вместе с параметром -m <modulename> (и файлами исходного кода, объектными файлами или библиотеками). Используйте один из следующих вариантов:

f2py -c -m fib1 fib1.f

Или

f2py -m fib1 fib1.f -h fib1.pyf
f2py -c fib1.pyf fib1.f

Подробнее см. раздел документации Python Сборка расширений C и C++.

При сборке модуля расширения с компиляторами Fortran, не основанными на GCC, может потребоваться сочетание следующих макросов:

-DPREPEND_FORTRAN
-DNO_APPEND_FORTRAN
-DUPPERCASE_FORTRAN

Для измерения производительности интерфейсов, сгенерированных F2PY, используйте -DF2PY_REPORT_ATEXIT. При завершении Python будет выведен отчёт с различными замерами времени. Возможность работает не на всех платформах; сейчас поддерживается только Linux.

Чтобы узнать, копирует ли интерфейс, сгенерированный F2PY, аргументы-массивы, используйте -DF2PY_REPORT_ON_ARRAY_COPY=<int>. Если размер аргумента-массива превышает <int>, сообщение о копировании выводится в stderr.

Другие варианты #

-m <modulename>

Наименование модуля расширения. По умолчанию untitled.

Предупреждение

Не используйте этот параметр при использовании файла сигнатур (*.pyf).

Изменено в версии 1.26.3: Параметр -m игнорируется, если передан файл pyf.

--[no-]lower

Преобразовывать [не преобразовывать] символы в <fortran files> в нижний регистр. По умолчанию --lower используется с флагом -h, а --no-lower — без флага -h.

-include<header>

Добавляет заголовки в обёртку на C. Можно передавать несколько раз; каждый раз создаётся директива #include <header>. Аргумент следует заключать в одинарные кавычки и указывать без пробелов, например '-include<stdbool.h>'.

--build-dir <dirname>

Все файлы, генерируемые F2PY, создаются в <dirname>. По умолчанию используется tempfile.mkdtemp().

--f2cmap <filename>

Загружает из заданного файла спецификации соответствия Fortran и C для KIND.

--quiet

Запуск без лишнего вывода.

--verbose

Запуск с более подробным выводом.

--skip-empty-wrappers

Не создавать файлы обёрток, если входные данные этого не требуют. Флаг обратной совместимости восстанавливает поведение до версии 1.22.4.

-v

Вывести версию F2PY и завершить работу.

Выполните f2py без каких-либо опций, чтобы получить обновленный список доступных опций.

numpy.f2py.get_include()[source]#

Возвращает каталог с файлами fortranobject.c и .h.

Модули расширения Python, построенные с помощью кода, генерируемого f2py, должны использовать fortranobject.c в качестве исходного файла и включать заголовок fortranobject.h. Эта функция может использоваться для получения каталога, содержащего оба этих файла.

Возвращаемые значения:
include_pathstr

Абсолютный путь к каталогу, содержащему fortranobject.c и fortranobject.h.

См. также

numpy.get_include

функция, возвращающая каталог заголовочных файлов NumPy

Примечания

Добавлено в версии 1.21.1.

Если ваша система сборки не предоставляет специальной поддержки f2py, сборка расширения Python с файлом сигнатур .pyf состоит из двух этапов. Для модуля mymod:

  • Шаг 1: выполните python -m numpy.f2py mymod.pyf --quiet. Будут созданы файлы mymodmodule.c и, при необходимости, mymod-f2pywrappers.f рядом с mymod.pyf.

  • Шаг 2: соберите модуль расширения Python. Для этого потребуются следующие исходные файлы:

    • mymodmodule.c

    • mymod-f2pywrappers.f (если он был сгенерирован на шаге 1)

    • fortranobject.c

numpy.f2py.run_main(comline_list)[source]#

Эквивалент запуска:

f2py <args>

где <args>=string.join(<list>,' '), но из Python. Если не используется -h, функция возвращает словарь сведений о созданных модулях и их зависимостях от исходных файлов.

С этой функцией нельзя строить модули расширения, то есть использовать -c не разрешается. Используйте вместо этого команду compile.

Примеры

Команду f2py -m scalar scalar.f можно выполнить из Python следующим образом.

>>> import numpy.f2py
>>> r = numpy.f2py.run_main(['-m','scalar','doc/source/f2py/scalar.f'])
Reading fortran codes...
        Reading file 'doc/source/f2py/scalar.f' (format:fix,strict)
Post-processing...
        Block: scalar
                        Block: FOO
Building modules...
        Building module "scalar"...
        Wrote C/API module "scalar" to file "./scalarmodule.c"
>>> print(r)
{'scalar': {'h': ['/home/users/pearu/src_cvs/f2py/src/fortranobject.h'],
	 'csrc': ['./scalarmodule.c', 
                  '/home/users/pearu/src_cvs/f2py/src/fortranobject.c']}}

Использование f2py с Meson #

Meson - это современная система сборки, рекомендуемая для создания модулей расширения Python, особенно начиная с Python 3.12 и NumPy 2.x. Meson обеспечивает надежный и удобный способ создания расширений Fortran с f2py.

Чтобы создать расширение Fortran с использованием f2py и Meson, вы можете использовать custom_target Meson для вызова f2py и создания модуля расширения. Следующий минимальный пример демонстрирует, как это сделать:

Этот пример показывает сборку расширения add из файлов add.f и add.pyf, описанных в разделе Примеры F2PY. Файл .pyf нужен не всегда: во многих случаях f2py самостоятельно определяет аннотации.

Структура проекта:

f2py_examples/
  meson.build
  add.f
  add.pyf (optional)
  __init__.py  (can be empty)

Пример meson.build:

project('f2py_examples', 'fortran')

py = import('python').find_installation()

# List your Fortran source files
sources = files('add.pyf', 'add.f')

# Build the extension by invoking f2py via a custom target
add_mod = custom_target(
  'add_extension',
  input: sources,
  output: ['add' + py.extension_suffix()],
  command: [
    py.full_path(), '-m', 'numpy.f2py',
    '-c', 'add.pyf', 'add.f',
    '-m', 'add'
  ],
  build_by_default: true
)

# Install into site-packages under the f2py_examples package
install_subdir('.', install_dir: join_paths(py.site_packages_dir(), 'f2py_examples'),
               strip_directory: false,
               exclude_files: ['meson.build'])

# Also install the built extension (place it beside __init__.py)
install_data(add_mod, install_dir: join_paths(py.site_packages_dir(), 'f2py_examples'))
Комментарии к примеру на русском
  • Перечислите исходные файлы Fortran
  • Собираем расширение вызовом f2py через пользовательскую цель
  • Устанавливаем в site-packages внутри пакета f2py_examples
  • Также устанавливаем собранное расширение рядом с __init__.py

Подробности и расширенные варианты использования см. в руководстве по сборке с Meson в пользовательской документации. Практические примеры можно найти в файлах сборки Meson проекта SciPy: scipy/scipy
