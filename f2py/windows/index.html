F2PY и Windows #

Предупреждение

Поддержка F2PY для Windows не всегда соответствует поддержке Linux.

Примечание

В документации SciPy есть сведения о системных зависимостях, которые хорошо протестированы и для работы с Fortran.

Вообще говоря, при работе с F2PY в Windows есть две проблемы:

  • отсутствие активно разрабатываемых компиляторов FOSS Fortran;

  • проблемы компоновки, связанные с библиотекой времени выполнения C при сборке расширений Python на C.

Целью этого раздела является создание рекомендаций по разработке и расширению модулей Fortran для Python напрямую через F2PY в Windows.

В настоящее время поддерживаются следующие наборы инструментов:

  • Компиляторы C/C++/Fortran из Mingw-w64

  • Компиляторы Intel

  • Clang-cl + Flang

  • MSVC + Flang

Обзор #

С точки зрения пользователя наиболее совместимая с UNIX среда разработки в Windows обеспечивается эмуляцией — через подсистему Windows для Linux (WSL) или Docker. Традиционная виртуализация, например VirtualBox, также подходит для разработки инструментов UNIX в Windows.

В самой Windows поддержка обычно ограничена коммерческими компиляторами. Однако по состоянию на 2022 год большинство таких компиляторов предлагает бесплатные варианты, достаточные для обычного использования. Кроме того, возможности Fortran, поддерживаемые f2py (частично Fortran 2003), часто не требуют самых новых инструментов. Для конечного пользователя варианты в порядке предпочтительности кратко таковы:

Классические компиляторы Intel (коммерческие)

Они активно поддерживаются, однако могут действовать лицензионные ограничения. Подробнее см. F2PY и Intel Fortran в Windows.

Подходит для обычной разработки собственных программ Windows на основе MSVC.

MSYS2 (FOSS)

Совместно с проектом mingw-w64 наборы инструментов gfortran и gcc позволяют собирать программы непосредственно для Windows.

Подсистема Windows для Linux

Предполагая использование gfortran, это может быть использовано для кросс-компиляции приложений Windows, но значительно сложнее.

Conda

Поддержка компиляторов GNU в Windows при использовании conda предоставляется каналом conda-forge.

Компиляторы PGI (коммерческие)

Больше не поддерживается, но пригоден для использования при наличии лицензии. Работает непосредственно в Windows, однако заменён на Nvidia HPC SDK, у которого нет нативной поддержки Windows.

Cygwin (FOSS)

Можно использовать и для gfortran. Однако слой совместимости с POSIX API в Cygwin предназначен для компиляции программ UNIX под Windows, а не для создания нативных программ Windows. Поэтому необходима кросс-компиляция.

Intel oneAPI

Новые компиляторы Intel (ifx, icx) основаны на LLVM и подходят для нативной компиляции. Лицензионные требования могут быть обременительными.

Classic Flang (FOSS)

На основе компиляторов PGI была создана «классическая», или старая версия Flang. Её можно собрать из исходного кода и использовать непосредственно в системе. LLVM Flang пока не поддерживает Windows (по состоянию на 30.01.2022).

LFortran (свободное ПО с открытым исходным кодом)

Один из двух компиляторов на основе LLVM. По состоянию на 30 января 2022 года ещё не компилирует все конструкции Fortran, поддерживаемые F2PY, но использует MSVC для нативной компоновки.

PowerShell и MSVC#

MSVC устанавливается либо в составе Visual Studio, либо с помощью более лёгкого (предпочтительного) пакета Build Tools for Visual Studio с выбранным компонентом Desktop development with C++.

Примечание

Это может занять значительное количество времени, так как включает в себя загрузку около 2 ГБ и требует перезапуска.

Полученное окружение можно использовать из обычной командной строки. Однако удобнее работать в PowerShell для разработчика с профилем Windows Terminal. Для этого добавьте следующий блок в раздел profiles->list JSON-файла конфигурации Windows Terminal (см. Settings->Open JSON file):

{
"name": "Developer PowerShell for VS 2019",
"commandline": "powershell.exe -noe -c \"$vsPath = (Join-Path ${env:ProgramFiles(x86)} -ChildPath 'Microsoft Visual Studio\\2019\\BuildTools'); Import-Module (Join-Path $vsPath 'Common7\\Tools\\Microsoft.VisualStudio.DevShell.dll'); Enter-VsDevShell -VsInstallPath $vsPath -SkipAutomaticLocation\"",
"icon": "ms-appx:///ProfileIcons/{61c54bbd-c2c6-5271-96e7-009a87ff44bf}.png"
}

Теперь тестирование набора инструментов компилятора может выглядеть так:

 # New Windows Developer Powershell instance / tab
 # or
 $vsPath = (Join-Path ${env:ProgramFiles(x86)} -ChildPath 'Microsoft Visual Studio\\2019\\BuildTools');
 Import-Module (Join-Path $vsPath 'Common7\\Tools\\Microsoft.VisualStudio.DevShell.dll');
 Enter-VsDevShell -VsInstallPath $vsPath -SkipAutomaticLocation
 **********************************************************************
 ** Visual Studio 2019 Developer PowerShell v16.11.9
 ** Copyright (c) 2021 Microsoft Corporation
 **********************************************************************
 cd $HOME
 echo "#include<stdio.h>" > blah.cpp; echo 'int main(){printf("Hi");return 1;}' >> blah.cpp
 cl blah.cpp
.\blah.exe
 # Hi
 rm blah.cpp

Пути Python из Microsoft Store#

Рассматриваемая здесь версия Python для MS Windows устанавливается по пути, зависящему от хеша, поэтому заранее он неизвестен. Этот путь нужно добавить в переменную PATH.

$Env:Path += ";$env:LOCALAPPDATA\packages\pythonsoftwarefoundation.python.3.10_qbz5n2kfra8p0\localcache\local-packages\python310\scripts"
