Даты, время и временные интервалы#

Начиная с NumPy 1.7, основные типы данных массивов включают встроенную поддержку даты и времени. Соответствующий тип называется datetime64, поскольку имя datetime уже занято в стандартной библиотеке Python.

Соглашения и допущения datetime64#

Как и в классе Python date, даты выражаются в григорианском календаре, неограниченно продолженном в прошлое и будущее. [1] В отличие от Python date, поддерживающего только годы с 1 по 9999 н. э., datetime64 допускает и даты до нашей эры. Для них используется астрономическая нумерация лет: 2 год до н. э. имеет номер −1, 1 год до н. э. — 0, а 1 год н. э. — 1.

Моменты времени, например 16:23:32.234, представляются числом часов, минут, секунд и долей секунды от полуночи: 00:00:00.000 — полночь, 12:00:00.000 — полдень и т. д. Каждый календарный день содержит ровно 86400 секунд. Это «наивное» время без явного учёта часовых поясов или конкретных шкал времени: UT1, UTC, TAI и т. д. [2]

[1]

Календарь, полученный распространением григорианского календаря на даты до его официального введения 15 октября 1582 года, называется пролептическим григорианским календарём

[2]

Предположение о 86400 секундах в календарных сутках неверно для UTC — современной шкалы гражданского времени. Из-за секунд координации сутки изредка могут длиться 86401 или 86399 секунд. Для шкалы TAI, напротив, предположение о 86400 секундах в сутках верно. Поддержка TAI и преобразования TAI в UTC с учётом секунд координации предложена, но ещё не реализована. См. также раздел Недостатки ниже.

Основы работы с датой и временем#

Самый простой способ создать дату и время — передать строку в формате даты или даты и времени ISO 8601. Также можно передать целое число, задающее смещение относительно эпохи Unix (00:00:00 UTC 1 января 1970 года). Единица внутреннего хранения автоматически определяется по виду строки: это может быть единица даты или единица времени. Единицы даты — годы (‘Y’), месяцы (‘M’), недели (‘W’) и дни (‘D’); единицы времени — часы (‘h’), минуты (‘m’), секунды (‘s’), миллисекунды (‘ms’) и другие единицы на основе секунды с приставками СИ. Тип datetime64 также принимает строку “NAT” в любом сочетании регистров для значения “Not A Time” («не время»). Строка “now” возвращает текущее время UTC. По умолчанию используется точность до секунд (‘s’), но можно указать другую единицу, например ‘M’, ‘D’ или ‘h’, чтобы усечь результат до этой точности. Более мелкие единицы, например ‘ms’ и ‘ns’, поддерживаются, но дробная часть будет нулевой: фактическая точность ограничена целыми секундами. Строка “today” возвращает текущую дату UTC с точностью до дня. Для неё поддерживаются те же обозначения точности, что и для now.

Пример

Простая дата ISO:

>>> import numpy as np

>>> np.datetime64('2005-02-25')
np.datetime64('2005-02-25')

Из целого числа и единицы времени: один год после начала эпохи UNIX:

>>> np.datetime64(1, 'Y')
np.datetime64('1971')

Использование месяцев как единицы измерения:

>>> np.datetime64('2005-02')
np.datetime64('2005-02')

Указываем только месяц, но принудительно задаём единицу «дни»:

>>> np.datetime64('2005-02', 'D')
np.datetime64('2005-02-01')

Из даты и времени:

>>> np.datetime64('2005-02-25T03:30')
np.datetime64('2005-02-25T03:30')

NAT (не время):

>>> np.datetime64('nat', 'D')
np.datetime64('NaT', 'D')

Текущее время в UTC, по умолчанию с точностью до секунды:

>>> np.datetime64('now')
np.datetime64('2025-08-05T02:22:14')  # result will depend on the current time
Комментарии к примеру на русском
  • Результат зависит от текущего времени
>>> np.datetime64('now', 'D')
np.datetime64('2025-08-05')

>>> np.datetime64('now', 'ms')
np.datetime64('2025-08-05T02:22:14.000')

Текущая дата:

>>> np.datetime64('today')
np.datetime64('2025-08-05')  # result will depend on the current date
Комментарии к примеру на русском
  • Результат зависит от текущей даты

При создании массива дат и времени из строки по-прежнему можно автоматически выбрать единицу времени по входным данным, используя тип datetime без указания конкретной единицы.

Объявлено устаревшим в версии 2.5: обобщённые единицы timedelta64 объявлены устаревшими в NumPy 2.5 и в будущем будут вызывать ошибку. Теперь для NaT в datetime64 требуется явно указать единицу времени.

Пример

>>> import numpy as np

>>> np.array(['2007-07-13', '2006-01-13', '2010-08-13'], dtype=np.datetime64)
array(['2007-07-13', '2006-01-13', '2010-08-13'], dtype='datetime64[D]')

>>> np.array(['2001-01-01T12:00', '2002-02-03T13:56:03.172'], dtype=np.datetime64)
array(['2001-01-01T12:00:00.000', '2002-02-03T13:56:03.172'],
      dtype='datetime64[ms]')

Массив дат и времени можно создать из целых чисел, представляющих временные метки POSIX в заданных единицах.

Пример

>>> import numpy as np

>>> np.array([0, 1577836800], dtype='datetime64[s]')
array(['1970-01-01T00:00:00', '2020-01-01T00:00:00'],
      dtype='datetime64[s]')

>>> np.array([0, 1577836800000]).astype('datetime64[ms]')
array(['1970-01-01T00:00:00.000', '2020-01-01T00:00:00.000'],
      dtype='datetime64[ms]')

Тип datetime работает со многими распространенными функциями NumPy, например arange можно использовать для создания диапазонов дат.

Пример

Все даты за один месяц:

>>> import numpy as np

>>> np.arange('2005-02', '2005-03', dtype='datetime64[D]')
array(['2005-02-01', '2005-02-02', '2005-02-03', '2005-02-04',
       '2005-02-05', '2005-02-06', '2005-02-07', '2005-02-08',
       '2005-02-09', '2005-02-10', '2005-02-11', '2005-02-12',
       '2005-02-13', '2005-02-14', '2005-02-15', '2005-02-16',
       '2005-02-17', '2005-02-18', '2005-02-19', '2005-02-20',
       '2005-02-21', '2005-02-22', '2005-02-23', '2005-02-24',
       '2005-02-25', '2005-02-26', '2005-02-27', '2005-02-28'],
      dtype='datetime64[D]')

Объект datetime представляет один момент времени. Два значения datetime с разными единицами измерения могут обозначать один и тот же момент. Преобразование из более крупной единицы, например месяцев, в более мелкую, например дни, считается безопасным приведением, поскольку момент времени по-прежнему представлен точно.

Пример

>>> import numpy as np

>>> np.datetime64('2005') == np.datetime64('2005-01-01')
True

>>> np.datetime64('2010-03-14T15') == np.datetime64('2010-03-14T15:00:00.00')
True

Устарело с версии 1.11.0: NumPy не хранит сведения о часовом поясе. Для обратной совместимости datetime64 пока разбирает смещения часовых поясов, преобразуя время в UTC±00:00 (Zulu). Это поведение устарело и в будущем будет вызывать ошибку.

Арифметика дат, времени и временных интервалов#

NumPy позволяет вычитать значения даты и времени, получая число с единицей измерения времени. Поскольку ядро NumPy не содержит системы физических величин, тип данных timedelta64 создан в дополнение к datetime64. Аргументы timedelta64 — число единиц и единица даты или времени: день (D), месяц (M), год (Y), час (h), минута (m) или секунда (s). Тип timedelta64 также принимает вместо числа строку «NAT», обозначающую значение «Not A Time».

Пример

>>> import numpy as np

>>> np.timedelta64(1, 'D')
np.timedelta64(1,'D')

>>> np.timedelta64(4, 'h')
np.timedelta64(4,'h')

>>> np.timedelta64('nAt', 'D')
np.timedelta64('NaT', 'D')

Типы дат и времени (datetime) и временных интервалов (timedelta) совместно обеспечивают простые вычисления с датами и временем.

Пример

>>> import numpy as np

>>> np.datetime64('2009-01-01') - np.datetime64('2008-01-01')
np.timedelta64(366,'D')

>>> np.datetime64('2009') + np.timedelta64(20, 'D')
np.datetime64('2009-01-21')

>>> np.datetime64('2011-06-15T00:00') + np.timedelta64(12, 'h')
np.datetime64('2011-06-15T12:00')

>>> np.timedelta64(1,'W') / np.timedelta64(1,'D')
7.0

>>> np.timedelta64(1,'W') % np.timedelta64(10,'D')
np.timedelta64(7,'D')

>>> np.datetime64('nat', 'D') - np.datetime64('2009-01-01')
np.timedelta64('NaT','D')

>>> np.datetime64('2009-01-01') + np.timedelta64('nat', 'D')
np.datetime64('NaT', 'D')

Две единицы timedelta — ‘Y’ (годы) и ‘M’ (месяцы) — обрабатываются особо, поскольку их длительность зависит от того, когда они используются. День timedelta равен 24 часам, а месяцы и годы нельзя напрямую преобразовать в дни без небезопасного приведения ‘unsafe’.

Метод numpy.ndarray.astype позволяет небезопасно преобразовывать месяцы и годы в дни. Для этого используются средние значения по 400-летнему циклу високосных лет.

Пример

>>> import numpy as np

>>> a = np.timedelta64(1, 'Y')

>>> np.timedelta64(a, 'M')
numpy.timedelta64(12,'M')

>>> np.timedelta64(a, 'D')
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
TypeError: Cannot cast NumPy timedelta64 scalar from metadata [Y] to [D] according to the rule 'same_kind'

Единицы даты и времени#

Типы Datetime и Timedelta поддерживают множество единиц времени, а также неопределённые единицы, которые выбираются по входным данным. Неопределённые единицы объявлены устаревшими в NumPy 2.5; в будущем их использование будет вызывать ошибку. Рекомендации приведены ниже в разделе Переход с устаревших неопределённых единиц.

Дата и время всегда хранятся с началом отсчёта 1970-01-01T00:00. Поэтому поддерживаемые даты образуют симметричный интервал относительно этого момента; в таблице ниже он обозначен как «диапазон времени».

Ширина представимого диапазона равна диапазону 64-битного целого числа, умноженному на длительность единицы даты или времени. Например, для ‘W’ (неделя) диапазон ровно в 7 раз шире, чем для ‘D’ (день), а для ‘D’ — ровно в 24 раза шире, чем для ‘h’ (час).

Преобразование datetime и timedelta в объект Python#

NumPy следует строгому протоколу при преобразовании datetime64 и/или timedelta64 в объекты Python (e.g, tuple, list, datetime.datetime).

Протокол описан в следующей таблице:

Устарело с версии 2.5: Использование timedelta64 без указания единиц измерения (generic) устарело в NumPy 2.5 и в будущем будет вызывать ошибку.

Пример

>>> import numpy as np

>>> type(np.datetime64('NaT', 'D').item())
<class 'NoneType'>

>>> type(np.timedelta64('NaT', 'D').item())
<class 'NoneType'>

>>> type(np.timedelta64(123, 'ns').item())
<class 'int'>

>>> type(np.datetime64('2025-01-01T12:00:00.123456').item())
<class 'datetime.datetime'>

>>> type(np.timedelta64(10, 'D').item())
<class 'datetime.timedelta'>

При преобразовании datetime64 и/или timedelta64 с указанием типов Python int, float и str возвращаются скаляры NumPy: np.str_ для str, np.int64 для int и np.float64 для float. Примечание переводчика: в оригинале порядок соответствий возвращаемых типов ошибочен; здесь указаны проверенные соответствия.

Пример

>>> import numpy as np

>>> type(np.timedelta64(1, 'D').astype(int))
<class 'numpy.int64'>

>>> type(np.datetime64('2025-01-01T12:00:00.123456').astype(float))
<class 'numpy.float64'>

>>> type(np.timedelta64(123, 'ns').astype(str))
<class 'numpy.str_'>

Работа с рабочими днями#

Для задач, в которых допустимы лишь определённые дни недели, NumPy предоставляет набор функций busday (business day — рабочий день).

По умолчанию функции busday считают рабочими только дни с понедельника по пятницу. Реализация использует weekmask — маску недели из семи логических флагов рабочих дней. Можно задать собственную маску с другим набором рабочих дней.

Функции busday дополнительно могут проверять список праздничных дат — конкретных дней, которые не считаются рабочими.

Функция busday_offset позволяет применять смещения в рабочих днях к значениям datetime с единицей ‘D’ (день).

Пример

>>> import numpy as np

>>> np.busday_offset('2011-06-23', 1)
np.datetime64('2011-06-24')

>>> np.busday_offset('2011-06-23', 2)
np.datetime64('2011-06-27')

Если дата приходится на выходной или праздник, busday_offset сначала переносит её на рабочий день по заданному правилу, затем применяет смещение. Правило по умолчанию — «raise»: оно просто вызывает исключение. Чаще всего используются «forward» и «backward».

Пример

>>> import numpy as np

>>> np.busday_offset('2011-06-25', 2)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ValueError: Non-business day date in busday_offset

>>> np.busday_offset('2011-06-25', 0, roll='forward')
np.datetime64('2011-06-27')

>>> np.busday_offset('2011-06-25', 2, roll='forward')
np.datetime64('2011-06-29')

>>> np.busday_offset('2011-06-25', 0, roll='backward')
np.datetime64('2011-06-24')

>>> np.busday_offset('2011-06-25', 2, roll='backward')
np.datetime64('2011-06-28')

В некоторых случаях для нужного результата требуется правильно подобрать параметры roll и offset.

Пример

Первый рабочий день на дату или после нее:

>>> import numpy as np

>>> np.busday_offset('2011-03-20', 0, roll='forward')
np.datetime64('2011-03-21')
>>> np.busday_offset('2011-03-22', 0, roll='forward')
np.datetime64('2011-03-22')

Первый рабочий день строго после даты:

>>> np.busday_offset('2011-03-20', 1, roll='backward')
np.datetime64('2011-03-21')
>>> np.busday_offset('2011-03-22', 1, roll='backward')
np.datetime64('2011-03-23')

Функция также полезна для вычисления особых дат, например праздников. В Канаде и США День матери приходится на второе воскресенье мая; его дату можно вычислить с помощью собственной маски дней недели.

Пример

>>> import numpy as np

>>> np.busday_offset('2012-05', 1, roll='forward', weekmask='Sun')
np.datetime64('2012-05-13')

Для быстрой обработки множества рабочих дат с одной и той же маской недели и набором праздников предусмотрен объект busdaycalendar, хранящий необходимые данные в оптимизированном виде.

np.is_busday():#

Чтобы проверить, является ли дата datetime64 рабочим днём, используйте is_busday.

Пример

>>> import numpy as np

>>> np.is_busday(np.datetime64('2011-07-15'))  # a Friday
True
>>> np.is_busday(np.datetime64('2011-07-16')) # a Saturday
False
>>> np.is_busday(np.datetime64('2011-07-16'), weekmask="Sat Sun")
True
>>> a = np.arange(np.datetime64('2011-07-11'), np.datetime64('2011-07-18'))
>>> np.is_busday(a)
array([ True,  True,  True,  True,  True, False, False])
Комментарии к примеру на русском
  • Пятница
  • Суббота

np.busday_count():#

Чтобы узнать число рабочих дней в заданном диапазоне дат datetime64, используйте busday_count:

Пример

>>> import numpy as np

>>> np.busday_count(np.datetime64('2011-07-11'), np.datetime64('2011-07-18'))
5
>>> np.busday_count(np.datetime64('2011-07-18'), np.datetime64('2011-07-11'))
-5

Если у вас есть массив значений datetime64 с точностью до дня и вы хотите подсчитать, сколько из них являются рабочими днями, можно сделать следующее:

Пример

>>> import numpy as np

>>> a = np.arange(np.datetime64('2011-07-11'), np.datetime64('2011-07-18'))
>>> np.count_nonzero(np.is_busday(a))
5

Пользовательские маски рабочих дней недели#

Ниже приведены примеры пользовательских значений weekmask. Все они задают стандартный для busday набор рабочих дней: с понедельника по пятницу.

Некоторые примеры:

# Positional sequences; positions are Monday through Sunday.
# Length of the sequence must be exactly 7.
weekmask = [1, 1, 1, 1, 1, 0, 0]
# list or other sequence; 0 == invalid day, 1 == valid day
weekmask = "1111100"
# string '0' == invalid day, '1' == valid day

# string abbreviations from this list: Mon Tue Wed Thu Fri Sat Sun
weekmask = "Mon Tue Wed Thu Fri"
# any amount of whitespace is allowed; abbreviations are case-sensitive.
weekmask = "MonTue Wed  Thu\tFri"
Комментарии к примеру на русском
  • Последовательности с позициями от понедельника до воскресенья.
  • Длина последовательности должна быть ровно 7.
  • Список или другая последовательность: 0 — нерабочий день, 1 — рабочий
  • В строке: «0» — нерабочий день, «1» — рабочий
  • Строковые сокращения из списка: Mon Tue Wed Thu Fri Sat Sun
  • Допускается любое число пробельных символов; регистр сокращений важен.

Недостатки Datetime64#

Предположение о ровно 86400 секундах в каждых сутках делает datetime64 в основном совместимым с семантикой datetime Python и времени POSIX. Поэтому им свойственны одни и те же известные недостатки относительно шкалы UTC и определения исторического времени. Краткий неполный обзор приведён ниже.

  • Невозможно разобрать корректные временные метки UTC, приходящиеся на добавленную секунду координации.

    Пример

    В момент «2016-12-31 23:59:60 UTC» была добавочная секунда, поэтому «2016-12-31 23:59:60.450 UTC» — корректная временная метка, которую datetime64 не может разобрать:

    >>> import numpy as np

    >>> np.datetime64("2016-12-31 23:59:60.450")
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ValueError: Seconds out of range in datetime string "2016-12-31 23:59:60.450"

  • Вычисления timedelta64 между двумя датами UTC могут отличаться от правильного результата на целое число секунд СИ.

    Пример

    Вычислите количество секунд SI между «2021-01-01 12:56:23.423 UTC» и «2001-01-01 00:00:00.000 UTC»:

    >>> import numpy as np

    >>> (
...   np.datetime64("2021-01-01 12:56:23.423")
...   - np.datetime64("2001-01-01")
... ) / np.timedelta64(1, "s")
631198583.423

    Однако правильный ответ — 631198588.423 секунд СИ, поскольку между 2001 и 2021 годами было добавлено 5 секунд координации.

  • Вычисления timedelta64 для дат в прошлом не дают значения в секундах СИ, вопреки возможным ожиданиям.

    Пример

    Вычислим число секунд между «000-01-01 UT» и «1600-01-01 UT», где UT — всемирное время:

    >>> import numpy as np

    >>> a = np.datetime64("0000-01-01", "us")
>>> b = np.datetime64("1600-01-01", "us")
>>> b - a
numpy.timedelta64(50491123200000000,'us')

    Вычисленный результат, 50491123200 секунд, получен умножением числа прошедших дней (584388) на 86400 секунд; это число секунд по часам, синхронизированным с вращением Земли. Точное значение в секундах СИ можно лишь оценить, например по данным статьи Measurement of the Earth’s rotation: 720 BC to AD 2015 («Измерение вращения Земли: от 720 года до н. э. до 2015 года н. э.»), 2016, Royal Society’s Proceedings A 472, Stephenson et al.. Разумная оценка составляет 50491112870 ± 90 секунд, что отличается от вычисленного результата на 10330 секунд.

Переход от устаревшего использования неуказанных единиц измерения (generic)#

Начиная с NumPy 2.5 использование timedelta64 без указания единиц измерения (generic) устарело и в будущем будет вызывать ошибку. В этом разделе объясняется, как обновить код, использующий timedelta64 и datetime64 без указания единиц измерения, чтобы избежать будущих ошибок.

Простейший способ — заменить общую единицу времени конкретной: «D» для дней, «h» для часов, «m» для минут, «s» для секунд и т. д. Выбор зависит от контекста кода и требуемой точности.

Пример

>>> import numpy as np

>>> # Old code using generic units of timedelta64
>>> np.timedelta64(5, "s") + 1
DeprecationWarning: The 'generic' unit for NumPy timedelta is deprecated, and will raise an error in the future. This includes implicit conversion of bare integers (e.g. `+ 1`).Please use a specific unit instead.
Комментарии к примеру на русском
  • Старый код с неопределёнными единицами timedelta64
>>> # Updated code using a specific time unit
>>> np.timedelta64(5, "s") + np.timedelta64(1, "s")
np.timedelta64(6,'s')
Комментарии к примеру на русском
  • Обновлённый код с конкретной единицей времени

При сравнении объектов timedelta64 обязательно используйте одну и ту же единицу времени для обоих операндов, даже если они представляют 0.

>>> np.timedelta64(0, "s") == 0
DeprecationWarning: The 'generic' unit for NumPy timedelta is deprecated, and will raise an error in the future. This includes implicit conversion of bare integers (e.g. `== 0`).Please use a specific unit instead.
np.True_

>>> np.timedelta64(0, "s") == np.timedelta64(0, "s")
np.True_

При использовании numpy.testing.assert_allclose для сравнения объектов timedelta64 задавайте конкретную единицу времени также для параметра atol.

>>> arr = np.ones(5, dtype='m8[s]')
>>> np.testing.assert_allclose(arr, np.timedelta64(1, "s"), atol=np.timedelta64(0, "s"))

Ранее datetime64 позволял использовать NaT без единицы времени. Поскольку использование неопределённых единиц объявлено устаревшим, для NaT теперь требуется явно указывать единицу времени, как и в других операциях с датами и временными интервалами.

>>> np.datetime64("NAT")
DeprecationWarning: The 'generic' unit for NumPy timedelta is deprecated, and will raise an error in the future. This includes implicit conversion of bare integers (e.g. `+ 1`).Please use a specific unit instead.

>>> np.datetime64("NAT", "D")
np.datetime64('NaT', 'D')
