Протокол интерфейса массива #

Примечание

На этой странице описан API NumPy для доступа к содержимому массивов NumPy из других расширений на C. PEP 3118 — The Revised Buffer Protocol («Пересмотренный буферный протокол») — вводит аналогичный стандартизированный API для любых модулей расширения. Поддержка буферных массивов в Cython использует API PEP 3118; см. учебное руководство Cython по NumPy.

Версия :

3

Интерфейс массивов, иногда называемый протоколом массивов, создан в 2005 году, чтобы объекты Python, подобные массивам, могли по возможности разумно использовать буферы данных друг друга. Интерфейс однородных N-мерных массивов — стандартный механизм совместного использования памяти массивов и сведений о ней. Он имеет стороны Python и C, представленные двумя атрибутами. Объекты, которые должны рассматриваться прикладным кодом как N-мерные массивы, должны поддерживать хотя бы один атрибут. Код, желающий работать с такими массивами, должен искать хотя бы один из этих атрибутов и соответствующим образом использовать полученные сведения.

Этот интерфейс описывает однородные массивы в том смысле, что каждый элемент массива имеет один и тот же «тип». Этот тип может быть очень простым или может быть довольно произвольной и сложной C-подобной структурой.

Интерфейс можно использовать двумя способами: из Python и из C. Каждый вариант предоставляется отдельным атрибутом.

На стороне Python#

В этом варианте интерфейса у объекта есть атрибут __array_interface__.

object.__array_interface__#

Словарь из 3 обязательных и 5 необязательных элементов. Если необязательные ключи отсутствуют, для них используются значения по умолчанию.

Ключи:

shape (обязательно)

Кортеж размеров массива по каждому измерению. Каждый элемент — целое число Python (int). Эти числа могут быть больше, чем вмещают платформенные int или long (тип int в Python соответствует long в C). Код, использующий этот атрибут, должен учитывать это: выдавать ошибку при возможном переполнении либо использовать тип C long long для размеров.

typestr (обязательно)

Строка с базовым типом однородного массива. Она состоит из трёх частей: символа порядка байтов (< — little-endian, > — big-endian, | — порядок несущественен), символьного кода базового типа и целого числа байтов, занимаемых этим типом.

Основные символьные коды типов:

t

Битовое поле (следующее целое число дает количество битов в битовом поле).

b

Логический тип (целочисленный тип, допускающий только значения True или False)

i

Целое число

u

Беззнаковое целое число

f

Числа с плавающей точкой

c

Комплексные числа с плавающей точкой

m

Интервал времени

M

Дата и время

O

Объект: память содержит указатель на PyObject

S

Строка — последовательность char фиксированной длины

U

Unicode (последовательность фиксированной длины Py_UCS4)

V

Другой тип (void *: каждый элемент — участок памяти фиксированного размера)
descr (необязательно)

Список кортежей, дающий более подробное описание структуры памяти для каждого элемента однородного массива. Каждый кортеж в списке состоит из двух или трех элементов. Обычно этот атрибут используется, когда typestr равен V[0-9]+ , но это не является обязательным требованием. Единственное требование состоит в том, чтобы количество байтов, представленных в ключе typestr , было таким же, как общее количество байтов, представленных здесь. Идея состоит в том, чтобы поддержать описания C-подобных структур, составляющих элементы массива. Элементами каждого кортежа в списке являются

  1. Строка с именем этой части типа данных. Также допускается кортеж ('full name', 'basic_name'), где basic_name — допустимое имя переменной Python, соответствующее полному имени поля.

  2. Строка описания базового типа, как в typestr, либо другой список для вложенных структурированных типов.

  3. Необязательный кортеж формы, указывающий, сколько раз следует повторить эту часть структуры. Если это не указано, повторы не предполагаются. С помощью этого общего интерфейса можно описать очень сложные структуры. Однако обратите внимание, что каждый элемент массива по-прежнему имеет тот же тип данных. Ниже приведены некоторые примеры использования этого интерфейса.

По умолчанию: [('', typestr)]

данные

Кортеж из двух элементов, первый из которых — целое число Python, указывающее на область памяти с содержимым массива.

Примечание

При преобразовании из C/C++ через PyLong_From* или высокоуровневые связывания, такие как Cython или pybind11, обязательно используйте целое число достаточно большой битности.

Этот указатель должен указывать на первый элемент данных (другими словами, любое смещение всегда игнорируется в этом случае).Вторая запись в кортеже является флагом только для чтения (истинное означает, что область данных только для чтения).

Этот атрибут также может быть объектом, предоставляющим буферный интерфейс для совместного доступа к данным. Если значение этого ключа — None, память предоставляется через буферный интерфейс самого объекта. В этом случае ключ offset позволяет указать начало данных в буфере. Чтобы область памяти оставалась доступной, новый объект должен сохранять ссылку на объект, предоставляющий интерфейс массива.

Примечание

Если это поле не задано, используется «скалярный» путь обработки, который мы можем удалить в будущем, поскольку нам неизвестно о его пользователях. В этом случае NumPy помещает исходный объект в массив как скаляр.

Изменено в версии 2.4: до NumPy 2.4 указатель NULL обрабатывался по недокументированному «скалярному» пути и потому обычно не принимался, а в некоторых случаях приводил к аварийному завершению. Начиная с NumPy 2.4 NULL принимается, но NumPy выделяет для массива новый блок памяти размером 1 байт.

strides (необязательно)

Либо None для массива, непрерывно расположенного в памяти в порядке C, либо кортеж шагов в байтах для перехода к следующему элементу по соответствующему измерению. Каждый шаг должен быть целым числом Python int. Как и значения формы, шаги могут превышать диапазон типов C int или long. Вызывающий код должен учитывать это: выдавать ошибку или использовать long long в C. Значение по умолчанию None означает непрерывный буфер в порядке C, где быстрее всего меняется последний индекс. Например, для элементов по 8 байт и формы (10, 20, 30) кортеж шагов по умолчанию равен (4800, 240, 8).

По умолчанию: None (непрерывное расположение в памяти в порядке C)

mask (необязательно)

None или объект с интерфейсом массива. Элементы маски интерпретируются как истинные или ложные значения, указывающие допустимость элементов этого массива. Его форма должна быть “broadcastable” (согласуемой по правилам трансляции) с формой исходного массива.

По умолчанию: None (все значения массива допустимы)

offset (необязательно)

Целочисленное смещение в области данных массива. Допустимо только когда data равен None или возвращает объект memoryview.

по умолчанию : 0 .

version (обязательно)

Целое число с версией интерфейса (для этой версии — 3). Не используйте его для отклонения объектов, предоставляющих будущие версии интерфейса.

Доступ к структуре C#

Такой подход к интерфейсу массива обеспечивает более быстрый доступ: достаточно одного обращения к атрибуту и чётко определённой структуры C.

object.__array_struct__#

Объект PyCapsule, поле pointer которого содержит указатель на заполненную структуру PyArrayInterface. Память структуры выделяется динамически, а PyCapsule создаётся с подходящим деструктором, поэтому после завершения работы с объектом, возвращённым этим атрибутом, достаточно применить к нему Py_DECREF. Кроме того, нужно либо скопировать данные, либо удерживать ссылку на объект, предоставляющий атрибут, чтобы данные не были освобождены. Объекты с интерфейсом __array_struct__ также не должны перевыделять свою память, пока на них ссылаются другие объекты.

Структура PyArrayInterface определяется в numpy/ndarrayobject.h как:

typedef struct {
  int two;              /* contains the integer 2 -- simple sanity check */
  int nd;               /* number of dimensions */
  char typekind;        /* kind in array --- character code of typestr */
  int itemsize;         /* size of each element */
  int flags;            /* flags indicating how the data should be interpreted */
                        /*   must set ARR_HAS_DESCR bit to validate descr */
  Py_ssize_t *shape;    /* A length-nd array of shape information */
  Py_ssize_t *strides;  /* A length-nd array of stride information */
  void *data;           /* A pointer to the first element of the array */
  PyObject *descr;      /* NULL or data-description (same as descr key
                                of __array_interface__) -- must set ARR_HAS_DESCR
                                flag or this will be ignored. */
} PyArrayInterface;

Поле flags может содержать пять битов, определяющих интерпретацию данных, и один бит, определяющий интерпретацию интерфейса. Биты данных: NPY_ARRAY_C_CONTIGUOUS (0x1), NPY_ARRAY_F_CONTIGUOUS (0x2), NPY_ARRAY_ALIGNED (0x100), NPY_ARRAY_NOTSWAPPED (0x200) и NPY_ARRAY_WRITEABLE (0x400). Ещё один флаг, NPY_ARR_HAS_DESCR (0x800), указывает, есть ли в структуре поле arrdescr. Обращаться к этому полю можно только при установленном флаге.

NPY_ARR_HAS_DESCR#

Новое с 16 июня 2006 года:

Раньше большинство реализаций использовали член desc самого PyCObject (теперь PyCapsule) для хранения указателя на объект, предоставляющий интерфейс. Не путайте его с членом descr структуры PyArrayInterface выше: это разные вещи. Теперь это явная часть интерфейса. Обязательно увеличьте счётчик ссылок объекта и вызовите PyCapsule_SetContext перед возвратом PyCapsule, а также настройте деструктор для уменьшения счётчика этой ссылки.

Примечание

__array_struct__ считается устаревшим и не рекомендуется для нового кода. Вместо него используйте буферный протокол или протокол DLPack через numpy.from_dlpack.

Примеры описания типов#

Для наглядности приведём примеры описаний типов и соответствующих записей descr в __array_interface__. Благодарим Scott Gilbert за эти примеры:

Во всех случаях ключ «descr» необязателен, но предоставляет дополнительные сведения, которые могут быть важны для различных приложений:

* Float data
    typestr == '>f4'
    descr == [('','>f4')]

* Complex double
    typestr == '>c8'
    descr == [('real','>f4'), ('imag','>f4')]

* RGB Pixel data
    typestr == '|V3'
    descr == [('r','|u1'), ('g','|u1'), ('b','|u1')]

* Mixed endian (weird but could happen).
    typestr == '|V8' (or '>u8')
    descr == [('big','>i4'), ('little','<i4')]

* Nested structure
    struct {
        int ival;
        struct {
            unsigned short sval;
            unsigned char bval;
            unsigned char cval;
        } sub;
    }
    typestr == '|V8' (or '<u8' if you want)
    descr == [('ival','<i4'), ('sub', [('sval','<u2'), ('bval','|u1'), ('cval','|u1') ]) ]

* Nested array
    struct {
        int ival;
        double data[16*4];
    }
    typestr == '|V516'
    descr == [('ival','>i4'), ('data','>f8',(16,4))]

* Padded structure
    struct {
        int ival;
        double dval;
    }
    typestr == '|V16'
    descr == [('ival','>i4'),('','|V4'),('dval','>f8')]

Следует понимать, что любой структурированный тип может быть описан с помощью этого интерфейса.

Отличия от интерфейса массива версии 2#

Интерфейс версии 2 был очень похож. Различия были в основном эстетическими. В частности:

  1. В структуре PyArrayInterface не было поля descr в конце и, соответственно, флага ARR_HAS_DESCR.

  2. Назначение поля context объекта PyCapsule (ранее — поля desc объекта PyCObject), возвращаемого из __array_struct__, не было определено. Обычно оно содержало объект, предоставляющий массив, чтобы сохранять ссылку на него и освобождать её при уничтожении объекта C. Теперь явно требуется, чтобы это поле каким-либо способом удерживало ссылку на объект — владелец данных.

    Примечание

    До августа 2020 года в нем говорилось:

    Теперь это должен быть кортеж, первым элементом которого является строка с «PyArrayInterface Version #», а вторым элементом — объект, представляющий массив.

    От этого решения отказались почти сразу после его предложения: <https://mail.python.org/pipermail/numpy-discussion/2006-June/020995.html>. Хотя документация 14 лет утверждала обратное, предполагать, что капсулы __array_interface__ содержат этот кортеж, никогда не было корректно.

  3. Кортеж, возвращаемый __array_interface__['data'], раньше был шестнадцатеричной строкой (теперь это целое число типа int или long).

  4. Атрибута __array_interface__ не было: вместо него каждому ключу словаря __array_interface__, кроме version, соответствовал отдельный атрибут. Поэтому для получения информации на стороне Python требовалось по отдельности обращаться к атрибутам:

    • __array_data__

    • __array_shape__

    • __array_strides__

    • __array_typestr__

    • __array_descr__

    • __array_offset__

    • __array_mask__
