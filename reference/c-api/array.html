Структура массивов и доступ к данным #

Эти макросы имеют доступ к элементам структуры PyArrayObject и определены в ndarraytypes.h. Вводным аргументом, arr , может быть любой PyObject*, который непосредственно интерпретируется как PyArrayObject* (любой экземпляр PyArray_Type и его подтипов).

int PyArray_NDIM(PyArrayObject *arr)#

Количество измерений в массиве.

int PyArray_FLAGS(PyArrayObject *arr)#

Возвращает целое число, представляющее флаги массива.

int PyArray_TYPE(PyArrayObject *arr)#

Возвращает номер встроенного типа элементов массива.

int PyArray_Pack(const PyArray_Descr *descr, void *item, const PyObject *value)#

Добавлено в версии 2.0.

Записывает по адресу item значение типа descr, равное value.

Функция эквивалентна присваиванию одному элементу массива в Python. Возвращает 0 при успехе и -1 с установленной ошибкой при неудаче.

Примечание

Если у descr установлен флаг NPY_NEEDS_INIT, данные должны быть действительными или память обнулена.

int PyArray_SETITEM(PyArrayObject *arr, void *itemptr, PyObject *obj)#

Преобразует obj и помещает его в массив ndarray arr по адресу, указанному itemptr. Возвращает -1 при ошибке и 0 при успехе.

Примечание

Для произвольных объектов Python обычно предпочтительнее PyArray_Pack. Например, Setitem не поддерживает произвольное приведение между разными dtype.

void PyArray_ENABLEFLAGS(PyArrayObject *arr, int flags)#

Включает указанные флаги массива. Эта функция не выполняет проверки и предполагает, что вы знаете, что делаете.

void PyArray_CLEARFLAGS(PyArrayObject *arr, int flags)#

Сбрасывает указанные флаги массива. Функция ничего не проверяет и предполагает, что вы знаете, что делаете.

void *PyArray_DATA(PyArrayObject *arr)#
char *PyArray_BYTES(PyArrayObject *arr)#

Эти два макроса похожи: оба возвращают указатель на буфер данных массива. Результат первого макроса можно и следует присвоить указателю конкретного типа; второй предназначен для общей обработки. Если непрерывное расположение данных в памяти и/или их выравнивание не гарантированы, убедитесь, что понимаете способ доступа к элементам массива, чтобы избежать проблем с памятью и выравниванием.

npy_intp *PyArray_DIMS(PyArrayObject *arr)#

Возвращает указатель на размеры массива по осям (его форму). Число элементов равно числу измерений массива. Для нульмерных массивов может возвращать NULL.

npy_intp *PyArray_SHAPE(PyArrayObject *arr)#

Синоним PyArray_DIMS, названный в соответствии с использованием shape в Python.

npy_intp *PyArray_STRIDES(PyArrayObject *arr)#

Возвращает указатель на шаги массива. Число элементов совпадает с числом измерений массива.

npy_intp PyArray_DIM(PyArrayObject *arr, int n)#

Возвращает размер измерения n\(^{\textrm{th}}\).

npy_intp PyArray_STRIDE(PyArrayObject *arr, int n)#

Возвращает шаг вдоль измерения n\(^{\textrm{th}}\).

npy_intp PyArray_ITEMSIZE(PyArrayObject *arr)#

Возвращает размер одного элемента массива в байтах (itemsize).

В старом API, объявленном устаревшим в версии 1.7, эта функция возвращала тип int.

npy_intp PyArray_SIZE(PyArrayObject *arr)#

Возвращает общий размер (по количеству элементов) массива.

npy_intp PyArray_Size(PyObject *obj)#

Возвращает 0, если obj не относится к ndarray или его подклассу. Иначе возвращает общее число элементов массива. Более безопасный вариант PyArray_SIZE(obj).

npy_intp PyArray_NBYTES(PyArrayObject *arr)#

Возвращает общее количество байтов, использованных массивом.

PyObject *PyArray_BASE(PyArrayObject *arr)#

Это возвращает базовый объект массива. В большинстве случаев это означает объект, которому принадлежит память, на которую указывает массив.

Если вы создаёте массив через C API и предоставляете собственную память, используйте функцию PyArray_SetBaseObject, чтобы установить base на объект, владеющий этой памятью.

Если установлен флаг NPY_ARRAY_WRITEBACKIFCOPY, свойство имеет другой смысл: base — массив, в который текущий массив будет скопирован при завершении работы с копией. Такое двойное назначение свойства base, вероятно, изменится в одной из будущих версий NumPy.

PyArray_Descr *PyArray_DESCR(PyArrayObject *arr)#

Возвращает заимствованную ссылку на свойство dtype массива.

PyArray_Descr *PyArray_DTYPE(PyArrayObject *arr)#

Синоним PyArray_DESCR, названный в соответствии с использованием dtype в Python.

PyObject *PyArray_GETITEM(PyArrayObject *arr, void *itemptr)#

Получает из ndarray arr по адресу itemptr объект встроенного типа Python. При ошибке возвращает NULL.

numpy.ndarray.item идентичен PyArray_GETITEM.

int PyArray_FinalizeFunc(PyArrayObject *arr, PyObject *obj)#

Функция, на которую указывает PyCapsule __array_finalize__. Первый аргумент — вновь созданный объект подтипа. Второй аргумент, если не NULL, — «родительский» массив, если массив создан срезом или другой операцией с явно определяемым родителем. Функция может выполнять любые действия. При ошибке она должна возвращать -1, иначе — 0.

Доступ к данным #

Эти функции и макросы дают простой доступ к элементам ndarray из C и работают со всеми массивами. Однако будьте осторожны, если данные имеют немашинный порядок байтов, не выровнены или недоступны для записи. Учитывайте состояние флагов, если только вы точно не знаете, что делаете, либо заранее не обеспечили доступность записи, выравнивание и машинный порядок байтов с помощью PyArray_FromAny. Для обработки всех видов массивов полезна функция copyswap каждого типа: она позволяет работать с массивами, не отвечающими этим требованиям. Некоторые платформы, например Solaris, аварийно завершают работу при разыменовании невыровненного указателя. Другие, например x86 Linux, лишь медленнее обрабатывают невыровненные данные.

void *PyArray_GetPtr(PyArrayObject *aobj, npy_intp *ind)#

Возвращает указатель на данные массива ndarray aobj по N-мерному индексу, заданному массивом C ind (длина которого должна быть не меньше aobj->nd). При необходимости возвращённый указатель можно привести к указателю на тип данных этого ndarray.

void *PyArray_GETPTR1(PyArrayObject *obj, npy_intp i)#
void *PyArray_GETPTR2(PyArrayObject *obj, npy_intp i, npy_intp j)#
void *PyArray_GETPTR3(PyArrayObject *obj, npy_intp i, npy_intp j, npy_intp k)#
void *PyArray_GETPTR4(PyArrayObject *obj, npy_intp i, npy_intp j, npy_intp k, npy_intp l)#

Быстрый встроенный доступ к элементу по заданным координатам в ndarray obj, который должен иметь соответственно 1, 2, 3 или 4 измерения; это не проверяется. Координаты i, j, k и l могут быть любыми целыми, но интерпретируются как npy_intp. Возвращаемый указатель может потребоваться привести к типу данных ndarray.

Создание массивов #

С нуля #

PyObject *PyArray_NewFromDescr(PyTypeObject *subtype, PyArray_Descr *descr, int nd, npy_intp const *dims, npy_intp const *strides, void *data, int flags, PyObject *obj)#

Функция забирает владение ссылкой на descr. Проще всего получить такой дескриптор через PyArray_DescrFromType.

Это основная функция создания массивов. Большинство новых массивов создаются с помощью этой гибкой функции.

Возвращаемый объект имеет тип Python subtype, который должен быть подтипом PyArray_Type. У массива nd измерений, описанных в dims. Дескриптор типа данных нового массива — descr.

Если subtype — подкласс массива, а не базовый &PyArray_Type, то obj передаётся методу __array_finalize__ этого подкласса.

Если data равно NULL, выделяется новая неинициализированная память; ненулевой flags может указывать на непрерывное расположение в порядке Fortran. Для инициализации памяти используйте PyArray_FILLWBYTE.

Если data не равен NULL, предполагается, что он указывает на память для массива, а аргумент flags задаёт его новые флаги, за исключением состояния NPY_ARRAY_OWNDATA. Флаг NPY_ARRAY_WRITEBACKIFCOPY нового массива сбрасывается.

Кроме того, если data не равен NULL, можно также передать strides. Если strides равен NULL, шаги вычисляются для непрерывного расположения в порядке C (по умолчанию) или Fortran. Порядок Fortran выбирается, если flags ненулевой при data = NULL либо если flags & NPY_ARRAY_F_CONTIGUOUS ненулевое при ненулевом data. Переданные dims и strides копируются в новые массивы размеров и шагов, память для которых выделяется для нового объекта массива.

PyArray_CheckStrides помогает проверить информацию о шагах, отличную от NULL.

Если передан data, он должен существовать всё время жизни массива. Управлять этим можно через PyArray_SetBaseObject.

PyObject *PyArray_NewLikeArray(PyArrayObject *prototype, NPY_ORDER order, PyArray_Descr *descr, int subok)#

Эта функция забирает владение ссылкой на descr, если он не равен NULL. Она позволяет удобно создать новый массив с формой и расположением данных в памяти, соответствующими существующему массиву, при необходимости изменив расположение и/или тип данных.

Если order равен NPY_ANYORDER, порядок результата — NPY_FORTRANORDER, когда prototype имеет порядок Fortran, и NPY_CORDER в остальных случаях. При order, равном NPY_KEEPORDER, порядок результата соответствует prototype, даже если оси prototype не следуют порядку C или Fortran.

Если descr равен NULL, используется тип данных prototype.

Если subok равен 1, новый массив создаётся с подтипом prototype; иначе создаётся массив базового класса.

PyObject *PyArray_New(PyTypeObject *subtype, int nd, npy_intp const *dims, int type_num, npy_intp const *strides, void *data, int itemsize, int flags, PyObject *obj)#

Аналогично PyArray_NewFromDescr (…), но дескриптор типа данных задаётся параметрами type_num и itemsize, где type_num соответствует встроенному или пользовательскому типу. Если тип имеет фиксированное число байтов, itemsize игнорируется. В противном случае itemsize задаёт размер элемента для данного массива.

Предупреждение

Если данные переданы в PyArray_NewFromDescr или PyArray_New, память под ними нельзя освобождать до удаления нового массива. Если данные принадлежат другому объекту Python, вызовите для него Py_INCREF и установите поле base нового массива в этот объект. Переданные шаги должны соответствовать размерам, itemsize и данным массива.

PyObject *PyArray_SimpleNew(int nd, npy_intp const *dims, int typenum)#

Создаёт новый неинициализированный массив типа typenum. Размеры по каждому из nd измерений задаются целочисленным массивом dims. Память массива не инициализируется, кроме случая typenum равного NPY_OBJECT: тогда каждый элемент устанавливается в NULL. Аргумент typenum позволяет указать любой встроенный тип данных, например NPY_FLOAT или NPY_LONG. При необходимости память массива можно заполнить нулями с помощью PyArray_FILLWBYTE(return_object, 0). Этой функцией нельзя создать массив типа переменного размера, поскольку itemsize не задаётся.

PyObject *PyArray_SimpleNewFromData(int nd, npy_intp const *dims, int typenum, void *data)#

Создаёт массив-обёртку для data по заданному указателю. По умолчанию флаги указывают, что область данных отвечает необходимым требованиям и непрерывно расположена в порядке C. Форма задаётся массивом C dims длины nd, тип данных — typenum. Если данные принадлежат другому объекту Python с подсчётом ссылок, после передачи указателя нужно увеличить счётчик ссылок этого объекта, а член base возвращаемого ndarray должен указывать на объект Python, владеющий данными. Это не позволит освободить переданную память, пока существует возвращённый массив.

PyObject *PyArray_SimpleNewFromDescr(int nd, npy_int const *dims, PyArray_Descr *descr)#

Эта функция забирает владение ссылкой на descr.

Создаёт новый массив с дескриптором типа данных descr и формой, заданной nd и dims.

void PyArray_FILLWBYTE(PyObject *obj, int val)#

Заполняет массив, на который указывает obj (он должен быть экземпляром ndarray или его подкласса), значением val, интерпретируемым как байт. Макрос вызывает memset, поэтому obj должен быть непрерывно расположен в памяти.

PyObject *PyArray_Zeros(int nd, npy_intp const *dims, PyArray_Descr *dtype, int fortran)#

Создаёт новый nd-мерный массив формы dims с типом данных dtype. Если fortran ненулевой, используется порядок Fortran, иначе — порядок C. Память заполняется нулями или объектами 0, если dtype соответствует NPY_OBJECT.

PyObject *PyArray_ZEROS(int nd, npy_intp const *dims, int type_num, int fortran)#

Макрос — аналог PyArray_Zeros, принимающий номер типа вместо объекта типа данных.

PyObject *PyArray_Empty(int nd, npy_intp const *dims, PyArray_Descr *dtype, int fortran)#

Создаёт новый nd-мерный массив формы dims с типом данных dtype. Если fortran не равен нулю, используется порядок Fortran, иначе — порядок C. Данные не инициализируются, кроме типа NPY_OBJECT: в этом случае массив заполняется Py_None.

PyObject *PyArray_EMPTY(int nd, npy_intp const *dims, int typenum, int fortran)#

Макросная форма PyArray_Empty, принимающая номер типа typenum вместо объекта типа данных.

PyObject *PyArray_Arange(double start, double stop, double step, int typenum)#

Создаёт новый одномерный массив с типом данных typenum и значениями от start до stop (не включая верхнюю границу) с шагом step. Эквивалентно arange(start, stop, step, dtype).

PyObject *PyArray_ArangeObj(PyObject *start, PyObject *stop, PyObject *step, PyArray_Descr *descr)#

Создаёт новый одномерный массив с типом данных, определяемым descr, со значениями от start до stop (не включая верхнюю границу) с шагом step. Эквивалентно arange(start, stop, step, typenum).

int PyArray_SetBaseObject(PyArrayObject *arr, PyObject *obj)#

Эта функция принимает владение ссылкой на obj и устанавливает этот объект как свойство base массива arr.

Если вы создаете массив, передавая свой собственный буфер памяти в качестве параметра, вам необходимо установить свойство base массива, чтобы обеспечить соответствующее время жизни буфера памяти.

Возвращаемое значение — 0 в случае успеха и -1 в случае неудачи.

Если переданный объект — массив, функция проходит по цепочке указателей base так, чтобы каждый массив непосредственно ссылался на владельца памяти. После установки base менять его на другое значение нельзя.

Из других объектов #

PyObject *PyArray_FromAny(PyObject *op, PyArray_Descr *dtype, int min_depth, int max_depth, int requirements, PyObject *context)#

Это основная функция для получения массива из op — вложенной последовательности или объекта, предоставляющего интерфейс массива. Параметры позволяют указать требуемый dtype, минимальное (min_depth) и максимальное (max_depth) допустимое число измерений, а также другие requirements к массиву. Функция забирает ссылку на аргумент dtype: он должен быть структурой PyArray_Descr, задающей нужный тип данных, в том числе порядок байтов. Аргумент dtype может быть равен NULL; тогда допустим любой тип данных и порядок байтов. Если NPY_ARRAY_FORCECAST отсутствует в flags, вызов завершается ошибкой, когда тип данных невозможно безопасно получить из объекта. Чтобы использовать NULL для dtype и при этом гарантировать родной порядок байтов массива, используйте PyArray_CheckFromAny. Нулевое значение любого параметра глубины означает, что этот параметр игнорируется. Перечисленные ниже флаги массива можно объединять (например, с помощью |), формируя аргумент requirements. Если ваш код может обрабатывать массивы общего вида (например, с произвольными шагами, изменённым порядком байтов или без выравнивания), requirements может быть равен 0. Если op ещё не является массивом или не предоставляет интерфейс массива, создаётся новый массив, заполняемый из op с помощью протокола последовательности. Значение поля flags нового массива будет равно NPY_ARRAY_DEFAULT. Аргумент context не используется.

NPY_ARRAY_C_CONTIGUOUS

Обеспечить непрерывное расположение возвращаемого массива в памяти в порядке C

NPY_ARRAY_F_CONTIGUOUS

Обеспечить непрерывное расположение возвращаемого массива в памяти в порядке Fortran.

NPY_ARRAY_ALIGNED

Гарантирует правильное выравнивание возвращаемого массива для его типа данных. В выровненном массиве адрес данных и каждый шаг по оси кратны величине выравнивания, заданной дескриптором типа.

NPY_ARRAY_WRITEABLE

Обеспечить возможность записи в возвращаемый массив.

NPY_ARRAY_ENSURECOPY

Гарантирует создание копии op. Без этого флага данные не копируются, если копирования можно избежать.

NPY_ARRAY_ENSUREARRAY

Обеспечивает возврат объекта базового класса ndarray. По умолчанию, если op — экземпляр подкласса ndarray, возвращается экземпляр того же подкласса. При установленном флаге вместо него возвращается объект ndarray.

NPY_ARRAY_FORCECAST

Принудительное приведение к выходному типу, даже если это невозможно сделать безопасно. Без этого флага приведение данных произойдет только в том случае, если это можно сделать безопасно, в противном случае выдается ошибка.

NPY_ARRAY_WRITEBACKIFCOPY

Если op уже является массивом, но не удовлетворяет требованиям, создаётся копия, которая им удовлетворяет. Если установлен этот флаг и требуется копия объекта-массива, у возвращаемой копии устанавливается флаг NPY_ARRAY_WRITEBACKIFCOPY, а op становится доступным только для чтения. Необходимо вызвать PyArray_ResolveWritebackIfCopy, чтобы скопировать содержимое обратно в op; после этого массив op снова станет доступен для записи. Если op изначально недоступен для записи или не является массивом, возникает ошибка.

Можно также добавлять сочетания флагов массива.

PyObject *PyArray_CheckFromAny(PyObject *op, PyArray_Descr *dtype, int min_depth, int max_depth, int requirements, PyObject *context)#

Почти идентична PyArray_FromAny(…), но requirements может содержать NPY_ARRAY_NOTSWAPPED, переопределяющий спецификацию в dtype, и NPY_ARRAY_ELEMENTSTRIDES, требующий выравнивания массива в том смысле, что шаги должны быть кратны размеру элемента.

PyObject *PyArray_FromArray(PyArrayObject *op, PyArray_Descr *newtype, int requirements)#

Частный случай PyArray_FromAny, когда op уже является массивом, но должен иметь определённый тип newtype, включая порядок байтов, или удовлетворять заданным requirements.

PyObject *PyArray_FromStructInterface(PyObject *op)#

Возвращает объект ndarray из объекта Python, который предоставляет атрибут __array_struct__ и соответствует протоколу интерфейса массива. Если объект не содержит этого атрибута, возвращается заимствованная ссылка на Py_NotImplemented.

PyObject *PyArray_FromInterface(PyObject *op)#

Возвращает объект ndarray из объекта Python, предоставляющего атрибут __array_interface__ согласно протоколу интерфейса массивов. Если у объекта нет этого атрибута, возвращается заимствованная ссылка на Py_NotImplemented.

PyObject *PyArray_FromArrayAttr(PyObject *op, PyArray_Descr *dtype, PyObject *context)#

Возвращает объект ndarray из объекта Python, предоставляющего метод __array__. Сторонние реализации __array__ должны принимать именованные аргументы dtype и copy. context не используется.

PyObject *PyArray_ContiguousFromAny(PyObject *op, int typenum, int min_depth, int max_depth)#

Возвращает массив, непрерывно расположенный в памяти в порядке C, выровненный и доступный для записи, из вложенной последовательности или объекта, предоставляющего интерфейс массива, op. Тип с фиксированным размером элемента задаётся кодом typenum, минимальное число измерений — min_depth, максимальное — max_depth. Эквивалентно вызову PyArray_FromAny с требованиями NPY_ARRAY_DEFAULT и полем type_num аргумента типа, установленным в typenum.

PyObject *PyArray_ContiguousFromObject(PyObject *op, int typenum, int min_depth, int max_depth)#

Возвращает выровненный и доступный для записи массив, непрерывно расположенный в памяти в порядке C, из любой вложенной последовательности или объекта, предоставляющего интерфейс массива. Минимальное число измерений задаётся min_depth, максимальное — max_depth. Эквивалентно вызову PyArray_FromAny с требованиями NPY_ARRAY_DEFAULT и NPY_ARRAY_ENSUREARRAY.

PyObject *PyArray_FromObject(PyObject *op, int typenum, int min_depth, int max_depth)#

Возвращает выровненный массив с машинным порядком байтов из любой вложенной последовательности или объекта op, предоставляющего интерфейс массивов. Тип задаётся номером typenum из перечисления. Минимальное число измерений задаётся min_depth, максимальное — max_depth. Это эквивалентно вызову PyArray_FromAny с требованиями BEHAVED.

PyObject *PyArray_EnsureArray(PyObject *op)#

Эта функция забирает владение ссылкой на op и гарантирует, что op будет ndarray базового класса. Скаляры массива обрабатываются отдельно; в остальных случаях вызывается PyArray_FromAny(op, NULL, 0, 0, NPY_ARRAY_ENSUREARRAY, NULL).

PyObject *PyArray_FromString(char *string, npy_intp slen, PyArray_Descr *dtype, npy_intp num, char *sep)#

Создаёт одномерный ndarray одного типа из двоичной или текстовой ASCII-строки string длины slen. Тип создаваемого массива задаёт dtype. При num = -1 копирует всю строку и возвращает массив подходящего размера; иначе num — число элементов, которые нужно скопировать. Если sep равен NULL или пустой строке, вход интерпретируется как байты двоичных данных. Иначе подстроки, разделённые sep, преобразуются в элементы типа dtype. Некоторые типы нельзя читать в текстовом режиме; тогда возникает ошибка. При любой ошибке возвращается NULL.

PyObject *PyArray_FromFile(FILE *fp, PyArray_Descr *dtype, npy_intp num, char *sep)#

Создаёт одномерный ndarray с элементами одного типа из двоичного или текстового файла. fp — указатель на открытый файл, dtype задаёт тип данных создаваемого массива; он должен соответствовать данным файла. Если num равен -1, файл читается до конца и возвращается массив соответствующего размера; иначе num задаёт число читаемых элементов. Если sep равен NULL или пустой строке, файл читается в двоичном режиме. Иначе используется текстовый режим, а sep задаёт разделитель элементов. Некоторые типы массивов нельзя прочитать в текстовом режиме; в таком случае вызывается исключение.

PyObject *PyArray_FromBuffer(PyObject *buf, PyArray_Descr *dtype, npy_intp count, npy_intp offset)#

Создаёт одномерный ndarray одного типа из объекта buf, предоставляющего односегментный буферный протокол либо атрибут __buffer__, возвращающий объект с таким протоколом. Сначала запрашивается доступный для записи буфер, затем — только для чтения. Флаг NPY_ARRAY_WRITEABLE результата отражает полученный доступ. Данные начинаются со смещения offset байт от начала памяти объекта. Тип данных буфера задаёт дескриптор dtype. Если count отрицателен, число элементов определяется по размеру буфера и требуемому размеру элемента; иначе count задаёт число элементов для преобразования из буфера.

int PyArray_CopyInto(PyArrayObject *dest, PyArrayObject *src)#

Копирует данные из исходного массива src в целевой массив dest, при необходимости преобразуя тип данных. Возвращает -1 при ошибке, иначе 0. Форма src должна допускать трансляцию (согласование форм) до формы dest. При копировании NumPy проверяет, перекрываются ли области памяти двух массивов.

int PyArray_CopyObject(PyArrayObject *dest, PyObject *src)#

Присваивает объект src массиву NumPy dest по правилам преобразования в массив. Это почти эквивалентно PyArray_FromAny, но запись выполняется непосредственно в выходной массив. Возвращает 0 при успехе и -1 при ошибке.

PyArrayObject *PyArray_GETCONTIGUOUS(PyObject *op)#

Если op уже непрерывно расположен в памяти в порядке C и удовлетворяет требованиям выравнивания и порядка байтов, возвращается ссылка на него; иначе возвращается копия с этими свойствами. Параметр op должен быть экземпляром ndarray или его подкласса; это не проверяется.

PyObject *PyArray_FROM_O(PyObject *obj)#

Преобразует obj в ndarray. Аргумент может быть вложенной последовательностью или объектом, предоставляющим интерфейс массива. Это макрос для PyArray_FromAny с аргументами NULL, 0, 0, 0. Для его использования код должен обрабатывать любой дескриптор типа данных и любое сочетание флагов данных.

PyObject *PyArray_FROM_OF(PyObject *obj, int requirements)#

Аналог PyArray_FROM_O, но принимает аргумент requirements, задающий обязательные свойства результирующего массива. Можно потребовать NPY_ARRAY_C_CONTIGUOUS, NPY_ARRAY_F_CONTIGUOUS, NPY_ARRAY_ALIGNED, NPY_ARRAY_WRITEABLE, NPY_ARRAY_NOTSWAPPED, NPY_ARRAY_ENSURECOPY, NPY_ARRAY_WRITEBACKIFCOPY, NPY_ARRAY_FORCECAST и NPY_ARRAY_ENSUREARRAY. Также допустимы стандартные комбинации флагов:

PyObject *PyArray_FROM_OT(PyObject *obj, int typenum)#

Аналогичен PyArray_FROM_O, за исключением того, что он может принимать аргумент typenum , указывающий номер типа возвращаемого массива.

PyObject *PyArray_FROM_OTF(PyObject *obj, int typenum, int requirements)#

Сочетание PyArray_FROM_OF и PyArray_FROM_OT, позволяющее передать оба аргумента: typenum и flags.

PyObject *PyArray_FROMANY(PyObject *obj, int typenum, int min, int max, int requirements)#

Аналогично PyArray_FromAny, но тип данных задаётся номером типа. Результат PyArray_DescrFromType (typenum) передаётся напрямую в PyArray_FromAny. Макрос также добавляет NPY_ARRAY_DEFAULT к requirements, если в requirements передан NPY_ARRAY_ENSURECOPY.

PyObject *PyArray_CheckAxis(PyObject *obj, int *axis, int requirements)#

Объединяет логику функций и методов, принимающих именованный аргумент axis= и корректно обрабатывающих None. Входной массив — obj, *axis — преобразованное целое число, где *axis == NPY_RAVEL_AXIS соответствует None, а requirements задаёт требуемые свойства obj. Возвращается преобразованный входной массив, отвечающий требованиям и при необходимости развёрнутый в одномерный. Отрицательные значения *axis преобразуются, затем новый индекс проверяется на соответствие форме obj.

Компиляция для NumPy 1.x и 2.x

NumPy 2.x требует передачи структуры типа PyArray_DescrProto, а не PyArray_Descr. Это необходимо для того, чтобы разрешить изменения. Чтобы код мог запускаться и компилироваться как в 1.x, так и в 2.x, вам необходимо изменить тип вашей структуры на PyArray_DescrProto и добавить:

/* Allow compiling on NumPy 1.x */
#if NPY_ABI_VERSION < 0x02000000
#define PyArray_DescrProto PyArray_Descr
#endif
Комментарии к примеру на русском
  • Если NPY_ABI_VERSION < 0x02000000

для совместимости с 1.x. Кроме того, структура больше не является фактическим дескриптором: обновляется лишь её номер типа. Поэтому после успешной регистрации фактический dtype необходимо получить следующим образом:

int type_num = PyArray_RegisterDataType(&my_descr_proto);
if (type_num < 0) {
    /* error */
}
PyArray_Descr *my_descr = PyArray_DescrFromType(type_num);

С этими двумя изменениями код должен компилироваться и работать как на 1.x, так и на 2.x или более поздней версии.

Если вы всё же выделяете структуру dtype в куче, то в NumPy 2 выделенную память следует освободить, поскольку создаётся копия структуры. Эта структура не является допустимым объектом Python, поэтому не применяйте к ней Py_DECREF.

Переход на новый DType API

Пользователям старого API DType может быть непросто перейти на новый из-за проблем NumPy, вызывающих регрессии. Новые DType могут ограничиться новыми версиями NumPy, но существующие так поступить не могут.

Для перехода на новый API DType используйте слот NPY_DT_legacy_descriptor_proto при регистрации. Он доступен при компиляции с NumPy 2.5 и обеспечивает поддержку NumPy 2.0 и новее. Его также можно включить в собственный код для компиляции с более старыми версиями NumPy.

Регистрирует новый пользовательский тип данных для массивов. Большинство полей его дескриптора должно быть заполнено. Это проверяется не всегда, и ошибки могут привести к сбою сегментации. В частности, поле typeobj структуры dtype должно содержать тип Python с фиксированным размером элемента, соответствующим полю elsize дескриптора dtype. Поле f также должно предоставлять необходимые функции: nonzero, copyswap, copyswapn, getitem, setitem и cast (некоторые функции cast могут быть NULL, если соответствующее преобразование не нужно поддерживать). Во избежание путаницы следует выбрать уникальный символьный код типа, хотя уникальность не проверяется и внутренняя реализация на неё не полагается.

Возвращает номер пользовательского типа, однозначно его идентифицирующий. Затем по этому номеру можно получить указатель на новую структуру через PyArray_DescrFromType. При ошибке возвращается -1. Если этот dtype уже зарегистрирован (проверяется только адрес указателя), возвращается ранее присвоенный номер типа.

Число пользовательских DType, известных NumPy, хранится в NPY_NUMUSERTYPES — статической глобальной переменной, доступной через C API. Доступ к этому символу по своей природе не является потокобезопасным. Если этот API требуется в многопоточном контексте, добавьте собственную блокировку: NumPy не гарантирует потокобезопасного добавления новых типов данных.

Специальные функции для NPY_OBJECT#

Предупреждение

При работе с массивами или буферами объектов NumPy старается заполнить такие буферы значениями None до любого чтения данных. Однако могут существовать пути выполнения, при которых массив инициализируется лишь значениями NULL. Сам NumPy трактует NULL как эквивалент None, но при сборке в режиме отладки может проверять с помощью assert, что значение не равно NULL.

Поскольку инициализация значением None в NumPy пока непоследовательна, пользователи обязаны учитывать возможность значений NULL при работе с буферами, созданными NumPy. Также следует передавать в NumPy полностью инициализированные буферы: в будущем это может стать обязательным требованием.

Планируется обеспечить, чтобы NumPy всегда инициализировал массивы объектов до возможности их чтения. Любое нарушение этого требования будет считаться ошибкой. В будущем пользователи, возможно, смогут полагаться на отсутствие NULL при чтении любого массива, хотя для записи в только что созданные массивы могут сохраниться исключения — например, для выходных массивов в коде ufunc. По состоянию на NumPy 1.23 известны пути выполнения кода, на которых надлежащее заполнение не выполняется.

Флаги массива#

Атрибут flags структуры PyArrayObject содержит важные сведения о памяти массива, на которую указывает поле data. Флаги должны оставаться точными, иначе возможны странные результаты и даже ошибки доступа к памяти (segfault).

Область памяти буфера данных описывают шесть двоичных флагов. Соответствующие константы определены в arrayobject.h и задают позиции битов флагов. Python предоставляет удобный интерфейс через атрибуты и интерфейс наподобие словаря для чтения этих флагов и, когда это допустимо, их установки.

ndarray может ссылаться на самые разные области памяти, поэтому необходимы эти флаги. Получая произвольный PyArrayObject в коде C, нужно учитывать установленные флаги. Чтобы гарантировать свойства массива, например NPY_ARRAY_C_CONTIGUOUS и NPY_ARRAY_BEHAVED, передайте эти требования в PyArray_FromAny.

В NumPy 1.6 и более ранних версиях имена следующих флагов не содержали пространства имён макросов _ARRAY_. Такая форма имён констант объявлена устаревшей в версии 1.7.

Основные флаги массива#

Сегмент данных ndarray не обязательно представляет собой простой непрерывный участок памяти, с которым удобно работать. Он может быть не выровнен по границам машинных слов, что особенно важно на некоторых платформах. Порядок байтов данных может отличаться от машинного. Запись может быть запрещена. Данные могут быть непрерывно расположены в порядке Fortran. Флаги массива описывают эти свойства связанных с ним данных.

NPY_ARRAY_C_CONTIGUOUS#

Область данных находится в непрерывном порядке в стиле C (последний индекс изменяется быстрее всего).

NPY_ARRAY_F_CONTIGUOUS#

Область данных непрерывно расположена в памяти в порядке Fortran: первый индекс меняется быстрее всего.

Примечание

Данные массива могут одновременно быть непрерывно расположены в порядке C и Fortran. Это очевидно для одномерных массивов, но возможно и при большем числе измерений.

Даже у непрерывно расположенного в памяти массива шаг измерения arr.strides[dim] может быть произвольным, если arr.shape[dim] == 1 или массив пуст. Вообще говоря, не гарантируется равенство self.strides[-1] == self.itemsize для порядка C или self.strides[0] == self.itemsize для порядка Fortran. Правильный способ получить itemsize через C API — PyArray_ITEMSIZE(arr).

Область данных содержит копию с подходящими свойствами памяти; её содержимое должно быть записано обратно в исходный массив при вызове PyArray_ResolveWritebackIfCopy.

Этот специальный флаг устанавливается, если массив является копией, созданной из другого массива из-за требований пользователя к флагам в PyArray_FromAny, и пользователь запросил установку этого флага в такой ситуации. Атрибут base тогда указывает на исходный массив, не удовлетворявший требованиям; он переводится в режим только для чтения. PyArray_ResolveWritebackIfCopy копирует содержимое обратно в исходный массив, при необходимости приводя типы, и восстанавливает у него NPY_ARRAY_WRITEABLE. Если исходный массив изначально не имел NPY_ARRAY_WRITEABLE, функция PyArray_FromAny вернула бы ошибку, поскольку выполнение NPY_ARRAY_WRITEBACKIFCOPY было бы невозможно.

PyArray_UpdateFlags (obj, flags) обновит obj->flags для flags, который может быть любым из NPY_ARRAY_C_CONTIGUOUS, NPY_ARRAY_F_CONTIGUOUS, NPY_ARRAY_ALIGNED или NPY_ARRAY_WRITEABLE.

Возвращает истинное значение, если arr непрерывно расположен в памяти в порядке Fortran.

Принимает истинное значение, если arr непрерывно расположен в памяти в порядке Fortran и не непрерывно расположен в порядке C. Для проверки непрерывного расположения в порядке Fortran следует использовать PyArray_IS_F_CONTIGUOUS.

Возвращает истинное значение, если запись в область данных arr разрешена

Возвращает истинное значение, если область данных arr правильно выровнена для данной машины.

Истинно, если область данных arr выровнена, доступна для записи и имеет родной порядок байтов согласно дескриптору.

Возвращает истинное значение, если область данных arr непрерывно расположена в памяти в порядке Fortran и PyArray_ISBEHAVED(arr) имеет истинное значение.

Принимает истинное значение, если данные arr непрерывно расположены в памяти в порядке C, выровнены и используют машинный порядок байтов.

int PyArray_ISFARRAY_RO(const PyArrayObject *arr)#

Возвращает истинное значение, если данные arr непрерывно расположены в памяти в порядке Fortran, выровнены и имеют машинный порядок байтов.

Возвращает истинное значение, если данные arr занимают один непрерывный участок памяти в порядке C или Fortran.

void PyArray_UpdateFlags(PyArrayObject *arr, int flagmask)#

Флаги массива NPY_ARRAY_C_CONTIGUOUS, NPY_ARRAY_ALIGNED и NPY_ARRAY_F_CONTIGUOUS можно вычислить по самому объекту массива. Эта функция выполняет необходимые вычисления и обновляет один или несколько таких флагов arr, указанных в flagmask.

Предупреждение

Важно поддерживать флаги в актуальном состоянии при любых действиях с массивом, способных их изменить; в этом помогает PyArray_UpdateFlags. Последующие вычисления NumPy, опирающиеся на эти флаги, не пересчитывают их заново.

int PyArray_FailUnlessWriteable(PyArrayObject *obj, const char *name)#

Если obj доступен для записи, функция ничего не делает и возвращает 0. Если obj недоступен для записи, устанавливает исключение и возвращает -1. Также она может выполнять служебные действия, например выдавать предупреждения для массивов, которые в будущем станут представлениями. Обязательно вызывайте её перед записью в массив.

name — имя массива для более понятных сообщений об ошибках. Например, это может быть «массив назначения», «выходной массив» или просто «массив».

API-интерфейс ArrayMethod #

Циклы ArrayMethod задуманы как универсальный механизм записи циклов над массивами, включая циклы ufunc и приведения типов. Публичный API определен в заголовке numpy/dtype_api.h. См. PyArrayMethod_Context и PyArrayMethod_Spec для получения документации по структурам C, представленным в API ArrayMethod.

Слоты и определения типов (typedef)#

Используются для определения вида функции, реализованной слотом ArrayMethod. О функциях, которые необходимо реализовать для каждого слота, см. Слоты и определения типов ниже.

NPY_METH_resolve_descriptors#
typedef NPY_CASTING (PyArrayMethod_ResolveDescriptors)(struct PyArrayMethodObject_tag *method, PyArray_DTypeMeta *const *dtypes, PyArray_Descr *const *given_descrs, PyArray_Descr **loop_descrs, npy_intp *view_offset)#

Функция определения дескрипторов операции по дескрипторам операндов. Например, если ufunc с двумя входными и одним выходным операндом вызывается без заданного out в Python API, resolve_descriptors получает дескрипторы двух входных операндов и определяет правильный дескриптор результата на основе выходного DType, заданного для ArrayMethod. Если out задан, дескриптор выходного операнда тоже передаётся и не должен переопределяться.

method — указатель на лежащий в основе цикл приведения типов или ufunc. Возможно, в будущем мы сделаем эту структуру общедоступной, но пока это непрозрачный указатель, не позволяющий исследовать содержимое метода. dtypes — массив длины nargs из указателей PyArray_DTypeMeta; given_descrs — массив длины nargs из экземпляров входных дескрипторов (выходные дескрипторы могут быть NULL, если пользователь не задал выходные данные); loop_descrs — массив дескрипторов длины nargs, который должна заполнить реализация функции разрешения дескрипторов. view_offset пока имеет значение только для приведения типов, и обычно его можно игнорировать. Если приведение не требует никаких операций, это можно обозначить, установив view_offset в 0. При ошибке необходимо установить исключение и вернуть (NPY_CASTING)-1.

NPY_METH_strided_loop#
NPY_METH_contiguous_loop#
NPY_METH_unaligned_strided_loop#
NPY_METH_unaligned_contiguous_loop#

Одномерные циклы с заданным шагом по памяти, реализующие операцию (универсальную функцию или приведение типа). В большинстве случаев достаточно реализовать только универсальный вариант NPY_METH_strided_loop. Дополнительно можно реализовать NPY_METH_contiguous_loop как более простой и быстрый вариант; он используется, когда все входные и выходные массивы непрерывно расположены в памяти.

Для работы с потенциально невыровненными данными NumPy должен уметь копировать их в выровненную память. При реализации нового DType для приведения или копирования его значений необходимо реализовать NPY_METH_unaligned_strided_loop. В отличие от обычных вариантов, этот цикл не должен предполагать, что данные выровнены в памяти. Такие циклы должны копировать каждое значение перед его чтением или записью:

type_in in_value;
type_out out_value
memcpy(&value, in_data, sizeof(type_in));
out_value = in_value;
memcpy(out_data, &out_value, sizeof(type_out)

В то время как обычный цикл может просто использовать:

*(type_out *)out_data = *(type_in)in_data;

Циклы для невыровненных данных сейчас используются только при приведении типов и никогда не выбираются в ufunc: ufunc создают временные копии, обеспечивающие выравнивание входных данных. Если определён NPY_METH_get_loop, эти идентификаторы слотов игнорируются и используется цикл, возвращённый функцией get_loop.

NPY_METH_contiguous_indexed_loop#

Специализированный вариант внутреннего цикла для ускорения распространённых вычислений ufunc.at.

typedef int (PyArrayMethod_StridedLoop)(PyArrayMethod_Context *context, char *const *data, const npy_intp *dimensions, const npy_intp *strides, NpyAuxData *auxdata)#

Реализация цикла ArrayMethod. Каждый из перечисленных выше идентификаторов слотов цикла должен предоставлять реализацию PyArrayMethod_StridedLoop. Структура context содержит контекст операции, в частности дескрипторы входов. data — массив указателей на начала буферов входных и выходных массивов. dimensions задаёт размеры цикла операции. strides — массив длины nargs с шагами каждого входа. Необязательный набор вспомогательных данных auxdata передаётся циклу для включения и отключения дополнительных возможностей, уменьшения повторяющегося кода за счёт общей реализации цикла для похожих ufunc или выделения памяти, сохраняемой между вызовами циклов с шагами.

NPY_METH_get_loop#

Позволяет точнее управлять выбором цикла. Принимает реализацию PyArrayMethod_GetLoop, которая возвращает реализацию цикла с шагами. Если определён NPY_METH_get_loop, остальные идентификаторы слотов циклов, если они заданы, игнорируются.

typedef int (PyArrayMethod_GetLoop)(PyArrayMethod_Context *context, int aligned, int move_references, const npy_intp *strides, PyArrayMethod_StridedLoop **out_loop, NpyAuxData **out_transferdata, NPY_ARRAYMETHOD_FLAGS *flags);#

Выбирает цикл выполнения операции во время работы программы. context задаёт контекст выполнения операции. aligned указывает, выровнен ли доступ к данным цикла: 1 — да, 0 — нет. move_references указывает, нужно ли копировать встроенные в данные ссылки. strides задаёт шаги входного массива. В указатель out_loop необходимо записать указатель на реализацию цикла. Необязательный out_transferdata можно заполнить для передачи операции дополнительного пользовательского контекста. В flags необходимо записать относящиеся к операции флаги ArrayMethod, в частности признак того, что для внутреннего цикла требуется удерживать GIL Python.

NPY_METH_get_reduction_initial#
typedef int (PyArrayMethod_GetReductionInitial)(PyArrayMethod_Context *context, npy_bool reduction_is_empty, char *initial)#

Запрашивает у ArrayMethod начальное значение для свёртки. context — контекст ArrayMethod, используемый преимущественно для доступа к входным дескрипторам. reduction_is_empty указывает, пуста ли свёртка. Для пустой свёртки возвращаемое значение может отличаться: это значение по умолчанию, которое может не совпадать с обычно используемым нейтральным элементом. Например:

  • 0.0 — значение по умолчанию для sum([]). В остальных случаях правильным нейтральным элементом является -0.0, поскольку он сохраняет знак в sum([-0.0]).

  • Для object нейтральный элемент не используется, но возвращаются стандартные значения 0 и 1 для пустых sum([], dtype=np.object_) и prod([], dtype=np.object_). Благодаря этому работает np.sum(np.array(["a", "b"], dtype=np.object_)).

  • -inf или INT_MIN — нейтральные элементы для max, но по крайней мере INT_MIN плохо подходит как значение по умолчанию при отсутствии элементов.

initial — указатель на данные начального значения, которые нужно заполнить. Возвращает -1 при ошибке, 0 при отсутствии начального значения и 1 при успешном заполнении. Если отсутствие начального значения допустимо, ошибка выдаваться не должна: NumPy может вызывать эту функцию даже без строгой необходимости.

Флаги #

enum NPY_ARRAYMETHOD_FLAGS#

Эти флаги позволяют включать и выключать пользовательское поведение во время выполнения для циклов ArrayMethod. Например, если ufunc не может вызвать ошибки с плавающей точкой, то флаг NPY_METH_NO_FLOATINGPOINT_ERRORS должен быть установлен на ufunc при его регистрации.

Указывает, что метод должен удерживать GIL. Если флаг не установлен, GIL освобождается перед вызовом цикла.

enumerator NPY_METH_NO_FLOATINGPOINT_ERRORS#

Указывает, что метод не может вызывать ошибок вычислений с плавающей точкой, поэтому проверку таких ошибок после завершения цикла можно пропустить.

enumerator NPY_METH_SUPPORTS_UNALIGNED#

Указывается, что метод поддерживает невыровненный доступ.

enumerator NPY_METH_IS_REORDERABLE#

Указывает, что результат повторного применения цикла, например при свёртке, не зависит от порядка применения.

enumerator NPY_METH_RUNTIME_FLAGS#

Флаги, которые можно менять во время выполнения.

typedef int (PyArrayMethod_TraverseLoop)(void *traverse_context, const PyArray_Descr *descr, char *data, npy_intp size, npy_intp stride, NpyAuxData *auxdata)#

Цикл обхода одного массива. Аналогичен общей функции цикла с шагом по памяти и предназначен для случаев, когда нужно посетить каждый элемент одного массива.

Сейчас это используется для очистки массивов через функцию обратного вызова NPY_DT_get_clear_loop в API DType и для заполнения нулями через NPY_DT_get_fill_zero_loop. Это особенно полезно для массивов, хранящих встроенные ссылки на объекты Python или данные, размещённые в куче.

descr — дескриптор массива, data — указатель на его буфер, size — число элементов одномерного буфера, stride — шаг по памяти, а auxdata — необязательные дополнительные данные для цикла.

Параметр traverse_context передаётся на случай, если в будущем понадобится состояние интерпретатора или подобные данные. При этом полный контекст с указателями на типы данных, метод и вызывающий объект для функции обхода не имеет смысла. Пока предполагается, что в будущем этот контекст можно будет просто передавать дальше, в том числе для структурированных типов данных.

int PyUFunc_AddPromoter(PyObject *ufunc, PyObject *DType_tuple, PyObject *promoter)#

Сейчас выходные dtype всегда равны NULL, если они не входят в сигнатуру. Это деталь реализации, которая может измениться. Однако в общем случае функциям продвижения типов не нужны выходные dtype. Регистрирует новую функцию продвижения для ufunc. Первый аргумент — ufunc, для которой она регистрируется. Второй — кортеж Python из DType или None длиной, равной суммарному числу входов и выходов ufunc. Последний аргумент — функция продвижения, сохранённая в PyCapsule. Она получает операцию и запрошенные сигнатуры DType и может изменить их для повторного поиска подходящего цикла или функции продвижения.

typedef int (PyArrayMethod_PromoterFunction)(PyObject *ufunc, PyArray_DTypeMeta *const op_dtypes[], PyArray_DTypeMeta *const signature[], PyArray_DTypeMeta *new_op_dtypes[])#

Тип функции повышения типов, которую нужно обернуть в PyCapsule с именем "numpy._ufunc_promoter". Ей передаются операция и запрошенные сигнатуры DType. Функция может изменять сигнатуры для поиска нового цикла или функции повышения типов, способных выполнить операцию после приведения входов к повышенным DType.

Функция повышения типов должна учитывать signature[], если сигнатура задана. При неудаче она должна вернуть -1. Допускается установить исключение Python, но это необязательно: в обоих случаях будет установлено общее исключение, а исходное, если оно есть, включится в цепочку исключений. При успехе функция должна вернуть 0 или 1. Для предотвращения рекурсии NumPy обычно проверяет, что new_op_dtypes отличаются от op_dtypes. Проверка пропускается, если функция возвращает 1: это позволяет добавить новый цикл. При его добавлении new_op_dtypes должны совпадать с op_dtypes.

Изменено в версии 2.5: После 2.5 возврат 1 означает успешную работу механизма продвижения типов с пропуском шага защиты от рекурсии. Прежде всего это позволяет ему добавить в ufunc новый цикл, который теперь должен быть выбран вместо самого механизма продвижения. Обычно механизм должен изменить DType, чтобы помочь найти подходящий цикл.

Проверяет ошибку с плавающей точкой после выполнения операции с плавающей точкой таким образом, чтобы учесть сигнализацию об ошибке, настроенную через numpy.errstate. Принимает имя операции для использования в сообщении об ошибке и целочисленный флаг, который является одним из NPY_FPE_DIVIDEBYZERO, NPY_FPE_OVERFLOW, NPY_FPE_UNDERFLOW, NPY_FPE_INVALID, чтобы указать, какую ошибку проверить.

Возвращает -1 при неудаче, когда установлено исключение, и 0 при успехе.

int PyUFunc_AddWrappingLoop(PyObject *ufunc_obj, PyArray_DTypeMeta *new_dtypes[], PyArray_DTypeMeta *wrapped_dtypes[], PyArrayMethod_TranslateGivenDescriptors *translate_given_descrs, PyArrayMethod_TranslateLoopDescriptors *translate_loop_descrs)#

Позволяет создать достаточно лёгкую обёртку над существующим циклом универсальной функции. В основном это предназначено для единиц измерения. Сейчас есть ограничение: использовать цикл другой универсальной функции нельзя.

typedef int (PyArrayMethod_TranslateGivenDescriptors)(int nin, int nout, PyArray_DTypeMeta *wrapped_dtypes[], PyArray_Descr *given_descrs[], PyArray_Descr *new_descrs[]);#

Функция преобразования заданных дескрипторов, переданных в resolve_descriptors, в дескрипторы для оборачиваемого цикла. Новые дескрипторы ОБЯЗАТЕЛЬНО должны допускать представление тех же данных без копирования со старыми дескрипторами. Значение NULL должно поддерживаться для выходных аргументов и обычно передаваться дальше.

Результат этой функции используется для построения представлений аргументов с преобразованными описаниями dtype, без приведения самих данных. Поэтому механизм в основном полезен для DType, служащих обёрткой над реализацией другого DType. Например, DType с единицами измерения может обернуть существующий DType с плавающей точкой без повторной реализации низкоуровневой логики универсальных функций. В этом примере resolve_descriptors вычисляет единицы измерения результата по единицам измерения входных данных.

typedef int (PyArrayMethod_TranslateLoopDescriptors)(int nin, int nout, PyArray_DTypeMeta *new_dtypes[], PyArray_Descr *given_descrs[], PyArray_Descr *original_descrs[], PyArray_Descr *loop_descrs[]);#

Функция преобразования фактических дескрипторов цикла, возвращённых исходной функцией resolve_descriptors, в дескрипторы для выходного массива. Она должна возвращать типы, допускающие представление без копирования, и не должна изменять их так, чтобы нарушить логику внутреннего цикла. Поддержка NULL не требуется.

Пример цикла-обёртки#

Предположим, вы хотите создать обёртку над реализацией умножения float64 для WrappedDoubleDType. Тогда нужно добавить следующий цикл-обёртку:

PyArray_DTypeMeta *orig_dtypes[3] = {
    &WrappedDoubleDType, &WrappedDoubleDType, &WrappedDoubleDType};
PyArray_DTypeMeta *wrapped_dtypes[3] = {
     &PyArray_Float64DType, &PyArray_Float64DType, &PyArray_Float64DType}

PyObject *mod = PyImport_ImportModule("numpy");
if (mod == NULL) {
    return -1;
}
PyObject *multiply = PyObject_GetAttrString(mod, "multiply");
Py_DECREF(mod);

if (multiply == NULL) {
    return -1;
}

int res = PyUFunc_AddWrappingLoop(
    multiply, orig_dtypes, wrapped_dtypes, &translate_given_descrs
    &translate_loop_descrs);

Py_DECREF(multiply);

Обратите внимание, что для этого также необходимо определить две функции над этим кодом:

static int
translate_given_descrs(int nin, int nout,
                       PyArray_DTypeMeta *NPY_UNUSED(wrapped_dtypes[]),
                       PyArray_Descr *given_descrs[],
                       PyArray_Descr *new_descrs[])
{
    for (int i = 0; i < nin + nout; i++) {
        if (given_descrs[i] == NULL) {
            new_descrs[i] = NULL;
        }
        else {
            new_descrs[i] = PyArray_DescrFromType(NPY_DOUBLE);
        }
    }
    return 0;
}

static int
translate_loop_descrs(int nin, int NPY_UNUSED(nout),
                      PyArray_DTypeMeta *NPY_UNUSED(new_dtypes[]),
                      PyArray_Descr *given_descrs[],
                      PyArray_Descr *original_descrs[],
                      PyArray_Descr *loop_descrs[])
{
    // more complicated parametric DTypes may need to
    // to do additional checking, but we know the wrapped
    // DTypes *have* to be float64 for this example.
    loop_descrs[0] = PyArray_DescrFromType(NPY_FLOAT64);
    Py_INCREF(loop_descrs[0]);
    loop_descrs[1] = PyArray_DescrFromType(NPY_FLOAT64);
    Py_INCREF(loop_descrs[1]);
    loop_descrs[2] = PyArray_DescrFromType(NPY_FLOAT64);
    Py_INCREF(loop_descrs[2]);
}

  • Для более сложных параметризованных DType может понадобиться
  • дополнительная проверка, но в этом примере известно, что обёрнутые
  • DType *обязаны* быть float64.

Сортировка и получение индексов сортировки#

Методы сортировки и получения индексов сортировки для dtype регистрируются через ArrayMethod API: добавьте спецификацию ArrayMethod с именем "sort" или "argsort" соответственно. Для обоих методов нужны nin=1 и nout=1. Сортировка выполняется на месте, поэтому обязательно data[0] == data[1]. Получение индексов сортировки возвращает новый массив индексов, поэтому выход должен иметь тип NPY_INTP.

Передаваемый циклу context содержит поле parameters, которое для этих операций представляет собой структуру PyArrayMethod_SortParameters *. Её поле flags — побитовое ИЛИ значений NPY_SORTKIND, задающих вид сортировки: устойчивую и/или по убыванию. Если цикл с шагом зависит от флагов, удобно определить NPY_METH_get_loop и не задавать остальные слоты циклов.

struct PyArrayMethod_SortParameters#
NPY_SORTKIND flags#

Флаги, передаваемые операции сортировки. Это побитовое ИЛИ значений NPY_SORTKIND, определяющих вид сортировки.

Эти спецификации могут быть зарегистрированы с использованием PyUFunc_AddLoopsFromSpecs вместе с другими циклами ufunc.

PyObject *PyArray_GetField(PyArrayObject *self, PyArray_Descr *dtype, int offset)#

Эквивалентно ndarray.getfield(self, dtype, offset). Функция принимает владение ссылкой на PyArray_Descr и возвращает новый массив типа dtype, используя данные текущего массива со смещением offset байт. Таким образом можно получить поле структурированного массива, а также выбрать отдельные байты или группы байтов массива любого типа. Примечание переводчика: равенство границе тоже допустимо; сумма смещения и размера нового элемента не должна превышать размер исходного элемента.

int PyArray_SetField(PyArrayObject *self, PyArray_Descr *dtype, int offset, PyObject *val)#

Эквивалентно ndarray.setfield(self, val, dtype, offset). Устанавливает значение поля с началом по смещению offset байтов и типом dtype равным val. Изменяет форму self на месте и перевыделяет память для self, если общее число элементов в newshape отличается от прежнего. Если требуется перевыделение памяти, self должен владеть своими данными; должны выполняться условия self->base==NULL и self->weakrefs==NULL. Кроме того, если refcheck не равен 0, другие массивы не должны ссылаться на него. Аргумент fortran не влияет на поведение.

В Python 3.13 и более ранних версиях проверка разрешает перераспределение памяти на месте для объектов с уникальной ссылкой и для объектов со счётчиком ссылок, равным единице. В Python 3.14 и новее требуется уникальность ссылки на массив. Причины различия поведения подробнее описаны в соответствующем разделе «Что нового» в Python 3.14.

Перевыделение памяти массивов на месте часто приводит к фрагментации памяти, поэтому его следует избегать. Если цель — освободить избыточно выделенную память, возможные альтернативы — создать представление или копию только нужных данных либо строить массив за два прохода: сначала с небольшими затратами определить форму, затем выделить память и заполнить массив. Измерьте производительность в своём сценарии, чтобы выбрать оптимальный вариант. Может оказаться, что resize на деле замедляет приложение или увеличивает потребление памяти.

int PyArray_AsCArray(PyObject **op, void *ptr, npy_intp *dims, int nd, PyArray_Descr *typedescr)#

Иногда удобно обращаться к многомерному массиву как к многомерному массиву C, чтобы использовать в алгоритмах синтаксис a[i][j][k]. Эта функция возвращает указатель ptr, имитирующий такой массив C для одно-, двух- и трёхмерных ndarray.

Параметры:

  • op — адрес любого объекта Python. Объект заменяется эквивалентным ndarray с нужными выравниванием и порядком байтов, непрерывно расположенным в памяти в порядке C. Тип данных задают два последних аргумента. Убедитесь, что передача владения ссылкой на входной объект таким способом оправданна.

  • ptr — адрес переменной типа ctype* для одного измерения, ctype** для двух или ctype*** для трёх, где ctype — соответствующий данным тип C. После возврата к ptr можно обращаться как к одно-, двух- или трёхмерному массиву.

  • dims — выходной массив с формой объекта-массива. Его значения задают границы последующих циклов.

  • nd — число измерений массива (1, 2 или 3).

  • typedescr — структура PyArray_Descr, задающая требуемый тип данных, включая порядок байтов. Вызов забирает владение ссылкой на этот параметр.

Примечание

Имитация массива C неполна для двух и трёх измерений. Например, полученные массивы указателей нельзя передавать подпрограммам, ожидающим конкретные статически заданные двумерные или трёхмерные массивы. Для таких функций нужно статически объявить требуемый массив и скопировать в него данные.

PyObject *PyArray_Correlate(PyObject *op1, PyObject *op2, int mode)#

Вычисляет одномерную корреляцию одномерных массивов op1 и op2. Каждая точка результата получается умножением op1 на сдвинутую версию op2 и суммированием. Нужные при сдвиге значения за границами op1 и op2 считаются нулями. Режим определяет число возвращаемых сдвигов: 0 — только сдвиги, не требующие дополнения нулями; 1 — результат размера op1; 2 — все возможные сдвиги с любым ненулевым перекрытием.

Примечания

Эта функция вычисляет не обычную корреляцию: если op2 больше op1, аргументы меняются местами, а комплексное сопряжение никогда не выполняется. Обычную корреляцию для обработки сигналов см. в PyArray_Correlate2.

Для каждой точки результата корреляция вычисляется умножением op1 на сдвинутую версию op2 с последующим суммированием произведений. Нужные при сдвиге значения за пределами op1 и op2 считаются нулевыми. Режим определяет, какие сдвиги войдут в результат: 0 — только сдвиги, не требующие дополнения нулями; 1 — результат того же размера, что и op1; 2 — все сдвиги, при которых массивы хотя бы частично перекрываются.

Примечания

Вспомогательные данные с семантикой объектов#

type NpyAuxData#

При работе с составными типами данных, например структурированным dtype, внутренним циклам обработки нужны дополнительные данные. Для этого NumPy предоставляет структуру NpyAuxData и несколько соглашений по её использованию.

Определение NpyAuxData похоже на определение класса C++, но, поскольку API написан на C, семантику объектов приходится отслеживать вручную. Ниже приведён пример функции, которая удваивает элемент, используя функцию его копирования как базовую операцию.

typedef struct {
    NpyAuxData base;
    ElementCopier_Func *func;
    NpyAuxData *funcdata;
} eldoubler_aux_data;

void free_element_doubler_aux_data(NpyAuxData *data)
{
    eldoubler_aux_data *d = (eldoubler_aux_data *)data;
    /* Free the memory owned by this auxdata */
    NPY_AUXDATA_FREE(d->funcdata);
    PyArray_free(d);
}

NpyAuxData *clone_element_doubler_aux_data(NpyAuxData *data)
{
    eldoubler_aux_data *ret = PyArray_malloc(sizeof(eldoubler_aux_data));
    if (ret == NULL) {
        return NULL;
    }

    /* Raw copy of all data */
    memcpy(ret, data, sizeof(eldoubler_aux_data));

    /* Fix up the owned auxdata so we have our own copy */
    ret->funcdata = NPY_AUXDATA_CLONE(ret->funcdata);
    if (ret->funcdata == NULL) {
        PyArray_free(ret);
        return NULL;
    }

    return (NpyAuxData *)ret;
}

NpyAuxData *create_element_doubler_aux_data(
                            ElementCopier_Func *func,
                            NpyAuxData *funcdata)
{
    eldoubler_aux_data *ret = PyArray_malloc(sizeof(eldoubler_aux_data));
    if (ret == NULL) {
        PyErr_NoMemory();
        return NULL;
    }
    memset(&ret, 0, sizeof(eldoubler_aux_data));
    ret->base->free = &free_element_doubler_aux_data;
    ret->base->clone = &clone_element_doubler_aux_data;
    ret->func = func;
    ret->funcdata = funcdata;

    return (NpyAuxData *)ret;
}

Итератор окрестности#

Итераторы окрестности являются подклассами объекта итератора и могут использоваться для перебора окрестности точки. Например, вам может потребоваться перебрать каждый воксел трехмерного изображения и для каждого такого воксела выполнить итерацию по гиперкубу. Итератор соседства автоматически обрабатывает границы, что значительно упрощает написание такого кода по сравнению с ручной обработкой границ за счет небольших накладных расходов.

PyObject *PyArray_NeighborhoodIterNew(PyArrayIterObject *iter, npy_intp bounds, int mode, PyArrayObject *fill_value)#

Создаёт новый итератор окрестности из существующего итератора. Окрестность вычисляется относительно текущей позиции iter; границы задают форму окрестности, а аргумент mode — режим обработки границ.

Аргумент bounds должен быть массивом длины (2 * iter->ao->nd), в котором диапазон bound[2*i]->bounds[2*i+1] задаёт пределы обхода по измерению i (обе границы включаются). Границы для каждого измерения должны быть упорядочены: bounds[2*i] <= bounds[2*i+1].

Режим должен быть одним из:

NPY_NEIGHBORHOOD_ITER_ZERO_PADDING#

Дополнение нулями. Значения за границами равны 0.

NPY_NEIGHBORHOOD_ITER_ONE_PADDING#

Дополнение единицами: значения за границами массива равны 1.

NPY_NEIGHBORHOOD_ITER_CONSTANT_PADDING#

Дополнение постоянным значением. За границами используются значения первого элемента fill_value.

NPY_NEIGHBORHOOD_ITER_MIRROR_PADDING#

Зеркальное дополнение. Значения за границами получаются отражением элементов массива. Например, для массива [1, 2, 3, 4], согласно исходному тексту, x[-2] равно 2, x[-2] равно 1, x[4] равно 4, x[5] равно 1 и т. д. Примечание переводчика: в примере две опечатки. Второе вхождение x[-2] должно быть x[-1], а значение x[5] должно быть 3. Это следует из зеркального отражения с повторением граничных элементов, реализованного этим режимом.

NPY_NEIGHBORHOOD_ITER_CIRCULAR_PADDING#

Циклическое дополнение. За границами массива значения определяются так, словно он повторяется. Например, для [1, 2, 3, 4] значение x[-2] равно 3, x[-2] — 4, x[4] — 1, x[5] — 2 и т. д. Примечание переводчика: во втором упоминании x[-2] в оригинале опечатка — должно быть x[-1], которому соответствует значение 4.

Если режим постоянного заполнения ( NPY_NEIGHBORHOOD_ITER_CONSTANT_PADDING ), fill_value должен указывать на объект массива, который содержит значение заполнения (первый элемент будет значением заполнения, если массив содержит более одного элемента). В других случаях fill_value может быть NULL.

  • Итератор удерживает ссылку на iter

  • При ошибке возвращает NULL (в этом случае счётчик ссылок iter не изменяется)

  • iter сам может быть итератором окрестности (Neighborhood); это полезно, например, для автоматической обработки границ.

  • объект, возвращаемый с помощью этой функции, должен быть безопасным для использования в качестве нормального итератора.

  • Если позиция iter изменилась, дальнейшие вызовы PyArrayNeighborhoodIter_Next дают неопределённое поведение; нужно вызвать PyArrayNeighborhoodIter_Reset.

  • Если iter находится не в начале данных, а его данные непрерывно расположены в памяти, итератор будет указывать на начало данных вместо позиции iter. Чтобы избежать этого, перемещайте iter в нужную позицию только после создания итератора и вызывайте PyArrayNeighborhoodIter_Reset.

PyArrayIterObject *iter;
PyArrayNeighborhoodIterObject *neigh_iter;
iter = PyArray_IterNew(x);

/*For a 3x3 kernel */
bounds = {-1, 1, -1, 1};
neigh_iter = (PyArrayNeighborhoodIterObject*)PyArray_NeighborhoodIterNew(
     iter, bounds, NPY_NEIGHBORHOOD_ITER_ZERO_PADDING, NULL);

for(i = 0; i < iter->size; ++i) {
     for (j = 0; j < neigh_iter->size; ++j) {
             /* Walk around the item currently pointed by iter->dataptr */
             PyArrayNeighborhoodIter_Next(neigh_iter);
     }

     /* Move to the next point of iter */
     PyArrayIter_Next(iter);
     PyArrayNeighborhoodIter_Reset(neigh_iter);
}

После вызова iter->dataptr указывает на следующую точку окрестности. Поведение при вызове после обхода всех точек окрестности не определено.

Скаляры массивов#

PyObject *PyArray_Return(PyArrayObject *arr)#

Эта функция забирает владение ссылкой на arr.

Проверяет, является ли arr нульмерным массивом, и, если да, возвращает соответствующий скаляр NumPy. Эту функцию следует использовать всякий раз, когда в Python может возвращаться нульмерный массив.

PyObject *PyArray_Scalar(void *data, PyArray_Descr *dtype, PyObject *base)#

Возвращает скалярный объект NumPy заданного dtype, копируя данные из памяти, на которую указывает data. Ожидается, что base — объект массива, владеющий данными. base обязателен, если dtype описывает скаляр void, либо если установлен флаг NPY_USE_GETITEM и известно, что метод getitem использует аргумент arr без проверки на NULL. В остальных случаях base может быть NULL.

Если порядок байтов данных отличается от системного (это определяется по dtype->byteorder), функция изменяет его, поскольку скаляры NumPy всегда используют системный порядок байтов.

PyObject *PyArray_ToScalar(void *data, PyArrayObject *arr)#

Возвращает скаляр NumPy с типом и размером элемента, заданными массивом arr. Данные копируются из памяти по указателю data; если в arr порядок байтов отличается от системного, он изменяется.

PyObject *PyArray_FromScalar(PyObject *scalar, PyArray_Descr *outcode)#

Возвращает нульмерный массив типа, заданного outcode, из scalar, который должен быть скаляром NumPy. Если outcode равно NULL, тип определяется по scalar.

void PyArray_ScalarAsCtype(PyObject *scalar, void *ctypeptr)#

Передаёт через ctypeptr значение скалярного объекта NumPy. Проверки ошибок нет, поэтому scalar должен быть скалярным объектом NumPy, а ctypeptr должен указывать на память достаточного размера для нужного типа. Для типов гибкого размера в память ctypeptr копируется указатель на данные; для всех остальных типов сами данные копируются по адресу ctypeptr. Примечание переводчика: первое предложение оригинала безусловно обещает указатель, но для обычных числовых типов копируется значение, как верно уточнено далее.

int PyArray_CastScalarToCtype(PyObject *scalar, void *ctypeptr, PyArray_Descr *outcode)#

Извлекает данные из скаляра NumPy, приводит их к типу, указанному outcode, и записывает из scalar в память по указателю ctypeptr. Эта область должна быть достаточно большой для получаемых данных.

Возвращает -1 в случае неудачи и 0 в случае успеха.

PyObject *PyArray_TypeObjectFromType(int type)#

Возвращает объект скалярного типа по номеру типа type. Эквивалентно PyArray_DescrFromType(type)->typeobj, кроме подсчёта ссылок и проверки ошибок. При успехе возвращает новую ссылку на объект типа, при неудаче — NULL.

NPY_SCALARKIND PyArray_ScalarKind(int typenum, PyArrayObject **arr)#

Прежний способ запроса особых правил повышения типов для скалярных значений. В самом NumPy он больше не используется и в будущем, вероятно, будет объявлен устаревшим.

Новые DType могут задавать правила повышения типов специально для скаляров Python.

int PyArray_CanCoerceScalar(char thistype, char neededtype, NPY_SCALARKIND scalar)#

Прежний способ запроса особых правил повышения типов для скалярных значений. В самом NumPy он больше не используется и в будущем, вероятно, будет объявлен устаревшим.

Используйте PyArray_ResultType для аналогичных целей.

Дескрипторы типа данных #

Предупреждение

Для объектов типов данных необходимо вести подсчёт ссылок, поэтому учитывайте, как различные вызовы C API изменяют счётчик ссылок на тип данных. По общему правилу возвращаемый объект типа данных представляет собой новую ссылку. Функции, принимающие объекты PyArray_Descr* и возвращающие массивы, забирают владение переданными ссылками на тип данных, если не указано иное. Поэтому вы должны владеть ссылкой на любой объект типа данных, передаваемый такой функции.

int PyArray_DescrCheck(PyObject *obj)#

Принимает истинное значение, если obj — объект типа данных (PyArray_Descr*).

PyArray_Descr *PyArray_DescrNew(PyArray_Descr *obj)#

Возвращает новый объект типа данных, скопированный из obj. Ссылка на fields лишь обновляется: новый объект указывает на тот же словарь полей, если он существует.

PyArray_Descr *PyArray_DescrNewFromType(int typenum)#

Создаёт новый объект типа данных на основе встроенного или зарегистрированного пользователем типа, заданного typenum. Изменять поля встроенных типов нельзя. Эта функция создаёт отдельную копию структуры PyArray_Descr, которую можно заполнить нужным образом. Она особенно важна для типов данных переменного размера: для осмысленного создания массива им требуется задать новое значение поля elsize.

PyArray_Descr *PyArray_DescrNewByteorder(PyArray_Descr *obj, char newendian)#

Создаёт новый объект типа данных с порядком байтов, заданным newendian. Все объекты типов данных, на которые он ссылается через поля subdescr и fields, также изменяются рекурсивно.

Значение newendian является одним из таких макросов:

NPY_IGNORE#
NPY_SWAP#
NPY_NATIVE#
NPY_LITTLE#
NPY_BIG#

Порядок байтов NPY_IGNORE остаётся без изменений. При newendian, равном NPY_SWAP, порядок байтов меняется на противоположный для всех типов. Другие допустимые значения newendian — NPY_NATIVE, NPY_LITTLE и NPY_BIG; возвращаемый дескриптор и все дескрипторы типов, на которые он ссылается, получают соответствующий порядок байтов.

PyArray_Descr *PyArray_DescrFromObject(PyObject *op, PyArray_Descr *mintype)#

Определяет подходящий объект типа данных по объекту op, который должен быть, возможно, вложенной последовательностью, и дескриптору минимального типа mintype, который может быть NULL. Поведение похоже на array(op).dtype. Не путайте эту функцию с PyArray_DescrConverter. Она фактически просматривает все объекты вложенной последовательности и определяет тип данных по найденным элементам.

PyArray_Descr *PyArray_DescrFromScalar(PyObject *scalar)#

Возвращает объект типа данных для объекта — скаляра массива. Проверка того, что scalar действительно является скаляром массива, не выполняется. Если подходящий тип данных определить не удаётся, по умолчанию возвращается тип NPY_OBJECT.

PyArray_Descr *PyArray_DescrFromType(int typenum)#

Возвращает объект типа данных, соответствующий typenum. Значение typenum может задавать один из типов перечисления, символьный код такого типа или пользовательский тип. Для массива с элементами переменного размера нужен flexible typenum; полю elsize результата следует присвоить нужный размер. Номер типа — одна из констант NPY_TYPES.

int PyArray_DescrConverter(PyObject *obj, PyArray_Descr **dtype)#

Преобразует любой совместимый объект Python obj в объект типа данных и сохраняет результат в dtype. В объекты типа данных можно преобразовать множество объектов Python. Полное описание см. в разделе «Объекты типов данных (dtype)». Эта версия преобразователя преобразует None в объект типа данных NPY_DEFAULT_TYPE. Функцию можно использовать с кодом формата «O&» при обработке аргументов через PyArg_ParseTuple.

int PyArray_DescrConverter2(PyObject *obj, PyArray_Descr **dtype)#

Преобразует любой совместимый объект Python obj в объект типа данных, записываемый в dtype. В этой версии преобразователя для None возвращается NULL. Функцию также можно использовать с кодом формата «O&» в PyArg_ParseTuple.

int PyArray_DescrAlignConverter(PyObject *obj, PyArray_Descr **dtype)#

Аналог PyArray_DescrConverter, но выравнивает объекты, подобные структурам C, по границам машинных слов так же, как компилятор.

int PyArray_DescrAlignConverter2(PyObject *obj, PyArray_Descr **dtype)#

Аналог PyArray_DescrConverter2, но выравнивает объекты, подобные структурам C, по границам машинных слов так же, как компилятор.

Повышение и проверка типов данных#

PyArray_DTypeMeta *PyArray_CommonDType(const PyArray_DTypeMeta *dtype1, const PyArray_DTypeMeta *dtype2)#

Эта функция задаёт операцию определения общего DType. Общий DType не будет object, если только один из исходных DType не равен object. Функция похожа на numpy.result_type, но работает с классами, а не с экземплярами.

PyArray_DTypeMeta *PyArray_PromoteDTypeSequence(npy_intp length, PyArray_DTypeMeta **dtypes_in)#

Повышает типы из списка DType до общего типа так, чтобы результат оставался стабильным даже при изменении их порядка. Эта функция учитывает больше случаев и часто даёт успешный однозначный результат там, где common_dtype(common_dtype(dt1, dt2), dt3) зависит от порядка операций или завершается ошибкой. Тем не менее реализации общего типа в DType должны стремиться к ассоциативности и коммутативности! (В основном это нарушается для знаковых и беззнаковых целых типов.)

Для гарантированно согласованных результатов DType должны реализовывать получение общего DType транзитивно. Если A повышает тип B, а B — тип C, то A в общем случае должен также повышать тип C; здесь «повышает» означает реализацию повышения типов. Для абстрактных DType есть некоторые исключения.

В общем случае этот подход работает, если наиболее общий dtype строго шире остальных или совместим со всеми ними. Например, повышение float16 с любым другим типом с плавающей запятой, знаковым или беззнаковым целочисленным типом снова даёт тип с плавающей запятой.

PyArray_Descr *PyArray_GetDefaultDescr(const PyArray_DTypeMeta *DType)#

Для заданного класса DType возвращает экземпляр по умолчанию (дескриптор). Сначала проверяется наличие singleton, а функция default_descr вызывается только при необходимости.

Пользовательские типы данных#

Добавлено в версии 2.0.

Эти функции позволяют определять пользовательские гибкие типы данных вне NumPy. Обоснование и устройство новой системы DType подробнее описаны в NEP 42. Примеры DType см. в репозитории numpy-user-dtypes. В разделе PyArray_DTypeMeta и PyArrayDTypeMeta_Spec приведена документация по PyArray_DTypeMeta и PyArrayDTypeMeta_Spec.

int PyArrayInitDTypeMeta_FromSpec(PyArray_DTypeMeta *Dtype, PyArrayDTypeMeta_Spec *spec)#

Инициализирует новый DType. Сейчас это должен быть статический тип Python, определённый на C и объявленный как PyArray_DTypeMeta, а не PyTypeObject. Он должен наследовать от np.dtype, а его тип должен быть установлен в PyArrayDTypeMeta_Type до вызова PyType_Ready. Этот метатип содержит дополнительные поля по сравнению с обычным PyTypeObject. Примеры использования с параметрическими и непараметрическими типами данных см. в репозитории numpy-user-dtypes.

Ожидается, что регистрация пользовательского DType произойдет во время импорта модуля. API регистрации изменяет глобальное состояние и не является потокобезопасным.

Флаги, которые могут быть установлены на PyArrayDTypeMeta_Spec для инициализации DType.

NPY_DT_ABSTRACT#

Указывает, что DType — абстрактный базовый тип в иерархии DType, экземпляры которого не следует создавать напрямую.

NPY_DT_PARAMETRIC#

Указывает, что DType параметрический и не имеет единственного общего экземпляра.

NPY_DT_NUMERIC#

Указывает, что DType представляет собой числовое значение.

Идентификаторы слотов и определения типов функций API#

Эти идентификаторы соответствуют слотам API DType и позволяют определить реализацию каждого слота по элементам массива slots в структуре PyArrayDTypeMeta_Spec.

NPY_DT_legacy_descriptor_proto#

Слот совместимости для перевода типов данных старого образца на новый API DType. Существующие типы старого образца, использующие PyArray_RegisterDataType, должны применять его для такого перехода. Значение слота — структура PyArray_DescrProto.

Этот слот позволяет существующему DType прежнего API использовать новый API DType без нарушения обратной совместимости или лишь с незначительными изменениями. NumPy по-прежнему считает такой DType типом прежнего API и использует старые ветви кода, где это применимо, но задействует новые возможности по мере их появления.

Если этот слот используется, он должен быть первым. Поля ArrFuncs копируются, но их также можно задать через перечисленные ниже слоты. Это позволяет переносить, например, сортировки в старые версии, хотя NumPy 2.4+ поддерживает новый способ их реализации.

Добавлено в версии 2.5: Эта возможность появилась в NumPy 2.5, но для неё подготовлена реализация, совместимая с NumPy 2.0 и новее. Для компиляции со старыми версиями NumPy можно включить в свой проект эту реализацию из npy_2_compat.h.

Примечание

Этот слот позволяет типам DType, сейчас использующим PyArray_RegisterDataType, перейти на новый API в случаях, когда иначе переход блокировался бы регрессиями. Это путь к будущему объявлению PyArray_RegisterDataType, PyArray_RegisterCastFunc, PyArray_RegisterCanCast и других слотов устаревшими.

NPY_DT_discover_descr_from_pyobject#

Используется при определении DType для поиска подходящего типа заданного PyObject. Должен возвращать экземпляр дескриптора, подходящего для хранения данных переданного объекта Python. obj — исследуемый объект Python, а cls — класс DType, для которого создаётся дескриптор.

Возвращает дескриптор DType по умолчанию. Для параметрических типов данных функция должна быть определена. Непараметрические типы по умолчанию возвращают свой единственный экземпляр.

Учитывая два входных типа DType, определяет соответствующий «общий» DType, который может хранить значения для обоих типов. Возвращает Py_NotImplemented, если такого типа не существует.

NPY_DT_common_instance#

По двум входным дескрипторам определяет подходящий общий дескриптор, способный хранить значения обоих экземпляров. При ошибке возвращает NULL.

NPY_DT_ensure_canonical#

Возвращает «каноническое» представление экземпляра дескриптора. Понятие канонического дескриптора обобщает понятие порядка байтов: канонический дескриптор всегда использует собственный порядок байтов системы. Если дескриптор уже канонический, функция возвращает новую ссылку на входной дескриптор.

NPY_DT_setitem#

Реализует присваивание скалярного значения элементу массива из заданного PyObject.

NPY_DT_getitem#
typedef PyObject *(PyArrayDTypeMeta_GetItem)(PyArray_Descr*, char*)#

Реализует скалярную операцию getitem для элемента массива. Должна возвращать скаляр Python.

NPY_DT_get_clear_loop#

Если определено, устанавливает цикл обхода, который очищает данные в массиве. Это наиболее полезно для массивов ссылок, которые должны очистить записи массива перед сборкой мусора. Реализует PyArrayMethod_GetTraverseLoop .

NPY_DT_get_fill_zero_loop#

Если задан, устанавливает цикл обхода, заполняющий массив «нулевыми» значениями со смыслом, специфичным для DType. Вызывается внутри numpy.zeros для массивов, которым нужно записать специальный маркер нуля, если обычного заполнения нулевыми байтами недостаточно. Реализует PyArrayMethod_GetTraverseLoop.

NPY_DT_finalize_descr#
typedef PyArray_Descr *(PyArrayDTypeMeta_FinalizeDescriptor)(PyArray_Descr *dtype)#

Если определено, функция, которая вызывается для «финализации» экземпляра дескриптора после создания массива. Одно из применений этой функции — заставить вновь созданные массивы иметь вновь созданный экземпляр дескриптора, независимо от того, какой входной дескриптор предоставлен пользователем.

NPY_DT_get_constant#
typedef int (PyArrayDTypeMeta_GetConstant)(PyArray_Descr *descr, int constant_id, void *out)#

Если задана, позволяет DType предоставлять константы: машинные пределы, специальные значения (бесконечность, NaN) и характеристики чисел с плавающей запятой. descr — экземпляр дескриптора, constant_id — один из макросов NPY_CONSTANT_*, а out — указатель на неинициализированную память, куда нужно записать константу. Память, на которую указывает out, не инициализирована и может быть не выровнена. Возвращает 1 при успехе, 0, если константа недоступна, или -1 с установленным исключением при ошибке.

Основание системы счисления представления с плавающей точкой. Для всех типов с плавающей точкой равно 2.

NPY_CONSTANT_finfo_eps#

Машинный эпсилон: разница между 1,0 и следующим представимым значением, превышающим 1,0. Соответствует макросам C, таким как FLT_EPSILON, DBL_EPSILON.

Примечание

Для long double в формате IBM double-double (PowerPC) это значение определено как 0x1p-105L (2^-105), исходя из примерно 106 бит точности мантиссы.

NPY_CONSTANT_finfo_epsneg#

Разность между 1.0 и ближайшим меньшим представимым значением. Для двоичных типов с плавающей точкой обычно равна eps / radix.

Наименьшее положительное нормализованное число с плавающей точкой. Соответствует C макросам FLT_MIN, DBL_MIN. Это наименьшее значение с ведущим 1 битом в мантиссе.

Наименьшее положительное субнормальное (денормализованное) число с плавающей точкой. Соответствует макросам C, таким как FLT_TRUE_MIN и DBL_TRUE_MIN. Это наименьшее представимое положительное значение; в его мантиссе есть ведущие нулевые биты.

Характеристики чисел с плавающей точкой (целочисленные значения типа npy_intp):

Эти константы возвращают целочисленные метаданные о представлении чисел с плавающей точкой. Они помечены битом 1 << 16: возвращаемое значение имеет тип npy_intp, а не собственный тип dtype.

Число битов мантиссы без неявного старшего бита. Например, формат IEEE 754 binary64 (double) имеет 52 явных бита мантиссы, поэтому возвращается 52. Соответствует MANT_DIG - 1 в стандартных макросах C.

Минимальный показатель степени. Утилиты преобразования#

Для использования с PyArg_ParseTuple#

Все эти функции можно использовать в PyArg_ParseTuple(…) со спецификатором формата «O&» для автоматического преобразования объекта Python в нужный объект C. Они возвращают NPY_SUCCEED при успехе и NPY_FAIL при неудаче. Первый аргумент — объект Python, второй — адрес переменной типа C, в которую он преобразуется.

Предупреждение

При использовании этих функций преобразования необходимо понимать, какие действия требуются для управления памятью. В зависимости от способа использования может потребоваться освобождать память и/или изменять счётчики ссылок определённых объектов.

int PyArray_Converter(PyObject *obj, PyObject **address)#

Преобразует любой объект Python в PyArrayObject. Если PyArray_Check(obj) равен TRUE, счётчик ссылок объекта увеличивается, а ссылка помещается в address. Если obj не является массивом, он преобразуется в массив с помощью PyArray_FromAny. Независимо от результата по окончании работы вы должны применить DECREF к объекту, возвращённому этой функцией через address.

int PyArray_OutputConverter(PyObject *obj, PyArrayObject **address)#

Стандартный преобразователь выходных массивов, передаваемых функциям. Если obj равен Py_None или NULL, *address будет равен NULL, но вызов завершится успешно. Если PyArray_Check(obj) равно TRUE, объект возвращается через *address без увеличения счётчика ссылок.

int PyArray_IntpConverter(PyObject *obj, PyArray_Dims *seq)#

Преобразует последовательность Python obj длиной не более NPY_MAXDIMS в массив C типа npy_intp. Объект Python может быть и отдельным числом. seq — указатель на структуру с полями ptr и len. При успехе seq->ptr указывает на память, которую нужно освободить вызовом PyDimMem_FREE, чтобы избежать утечки. Ограничение длины делает преобразователь удобным для последовательностей, задающих форму массива. Примечание переводчика: оригинал требует длину строго меньше NPY_MAXDIMS, но реализация допускает равенство.

int PyArray_BufferConverter(PyObject *obj, PyArray_Chunk *buf)#

Преобразует объект Python obj с односегментным буферным интерфейсом в структуру, описывающую используемый им участок памяти. buf — указатель на структуру с полями base, ptr, len и flags. Структура PyArray_Chunk двоично совместима с буферным объектом Python вплоть до поля len на 32-битных платформах и ptr на 64-битных. В поле base записывается obj либо его базовый объект, если obj уже является буфером другого объекта. Чтобы удерживать память, увеличьте счётчик ссылок base с помощью INCREF. Указатель на память находится в buf->ptr, длина — в buf->len. Поле flags структуры buf содержит NPY_ARRAY_ALIGNED, а также NPY_ARRAY_WRITEABLE, если obj предоставляет буфер с возможностью записи.

int PyArray_AxisConverter(PyObject *obj, int *axis)#

Преобразует объект Python obj, задающий ось, в значение для функций с целочисленным аргументом оси. В частности, если obj равен None, axis получает значение NPY_RAVEL_AXIS, корректно обрабатываемое функциями C API, принимающими оси.

int PyArray_BoolConverter(PyObject *obj, npy_bool *value)#

Преобразует произвольный объект Python obj в NPY_TRUE или NPY_FALSE и помещает результат в value.

int PyArray_ByteorderConverter(PyObject *obj, char *endian)#

Преобразует строки Python в соответствующий символ порядка байтов: «>», «<», «s», «=» или «|».

int PyArray_SortkindConverter(PyObject *obj, NPY_SORTKIND *sort)#

Преобразует строки Python в одно из значений: NPY_QUICKSORT, если строка начинается с «q» или «Q»; NPY_HEAPSORT — с «h» или «H»; NPY_MERGESORT — с «m» или «M»; NPY_STABLESORT — с «t» или «T». Значения NPY_MERGESORT и NPY_STABLESORT являются псевдонимами друг друга для обратной совместимости и в зависимости от типа данных могут обозначать один из нескольких алгоритмов устойчивой сортировки.

int PyArray_SearchsideConverter(PyObject *obj, NPY_SEARCHSIDE *side)#

Преобразует строки Python в NPY_SEARCHLEFT, если они начинаются с ‘l’ или ‘L’, либо в NPY_SEARCHRIGHT, если начинаются с ‘r’ или ‘R’.

int PyArray_OrderConverter(PyObject *obj, NPY_ORDER *order)#

Преобразуйте строки Python «C», «F», «A» и «K» в перечисление NPY_ORDER NPY_CORDER, NPY_FORTRANORDER, NPY_ANYORDER и NPY_KEEPORDER.

int PyArray_CastingConverter(PyObject *obj, NPY_CASTING *casting)#

Преобразует строки Python «no», «equiv», «safe», «same_kind» и «unsafe» в значения перечисления NPY_CASTING: NPY_NO_CASTING, NPY_EQUIV_CASTING, NPY_SAFE_CASTING, NPY_SAME_KIND_CASTING и NPY_UNSAFE_CASTING.

int PyArray_ClipmodeConverter(PyObject *object, NPY_CLIPMODE *val)#

Конвертируйте строки Python «clip», «wrap» и «raise» в перечисление NPY_CLIPMODE NPY_CLIP, NPY_WRAP и NPY_RAISE.

int PyArray_ConvertClipmodeSequence(PyObject *object, NPY_CLIPMODE *modes, int n)#

Преобразует последовательность режимов обработки выходящих за границы индексов (clipmode) либо один такой режим в массив C со значениями NPY_CLIPMODE. Число режимов n должно быть известно до вызова. Это вспомогательная функция для поддержки отдельного режима clipmode для каждого измерения.

Подключение и импорт C API#

Чтобы использовать C-API NumPy, вам обычно необходимо включить заголовок numpy/ndarrayobject.h и numpy/ufuncobject.h для некоторых функций, связанных с ufunc (arrayobject.h — это псевдоним для ndarrayobject.h).

Эти два заголовка экспортируют наиболее важные функции. В общем, любой проект, использующий NumPy API, должен импортировать NumPy с помощью одной из функций PyArray_ImportNumPyAPI() или import_array(). В некоторых местах функциональность, требующая import_array(), не нужна, поскольку вам нужны только определения типов. В этом случае достаточно включить numpy/ndarratypes.h.

В типичном проекте Python несколько файлов C или C++ компилируются в одну разделяемую библиотеку (модуль расширения Python на C); при инициализации модуля необходимо вызвать PyArray_ImportNumPyAPI().

В случае единственного файла C это будет состоять из:

#include "numpy/ndarrayobject.h"

PyMODINIT_FUNC PyInit_my_module(void)
{
    if (PyArray_ImportNumPyAPI() < 0) {
        return NULL;
    }
    /* Other initialization code. */
}

Однако большинство проектов содержит дополнительные файлы C, которые компонуются в единый модуль Python. В таких вспомогательных файлах обычно нет общепринятого места для вызова PyArray_ImportNumPyAPI, хотя частые вызовы допустимы и выполняются быстро.

Для решения этой проблемы NumPy предлагает следующий подход: в основном файле перед подключением заголовка определяется PY_ARRAY_UNIQUE_SYMBOL:

/* Main module file */
#define PY_ARRAY_UNIQUE_SYMBOL MyModule
#include "numpy/ndarrayobject.h"

PyMODINIT_FUNC PyInit_my_module(void)
{
    if (PyArray_ImportNumPyAPI() < 0) {
        return NULL;
    }
    /* Other initialization code. */
}

в то время как другие файлы используют:

/* Second file without any import */
#define NO_IMPORT_ARRAY
#define PY_ARRAY_UNIQUE_SYMBOL MyModule
#include "numpy/ndarrayobject.h"

Определения можно добавить в общий локальный заголовок. Важно лишь, чтобы основной файл _не_ определял NO_IMPORT_ARRAY.

Для numpy/ufuncobject.h действует та же логика, но уникальный символ задаётся через #define PY_UFUNC_UNIQUE_SYMBOL (оба символа могут совпадать).

Кроме того, вы, вероятно, захотите добавить #define NPY_NO_DEPRECATED_API NPY_1_7_API_VERSION, чтобы избежать предупреждений о возможном использовании старого API.

Примечание

При нарушениях доступа к памяти убедитесь, что API NumPy правильно импортирован, а PyArray_API не равен NULL. В отладчике фактическое имя этого символа строится как PY_ARRAY_UNIQUE_SYMBOL``+``PyArray_API; в приведённом выше примере это MyModulePyArray_API. Для проверки можно, например, выполнить printf("%p\n", PyArray_API); непосредственно перед местом сбоя.

Устройство механизма и динамическое связывание#

Основа механизма — таблица void **PyArray_API, которую NumPy должен определить для поиска всех функций. Способ её подключения зависит от настройки макросов: определены ли NO_IMPORT_ARRAY и PY_ARRAY_UNIQUE_SYMBOL:

  • Если ни один из них не определён, C API объявляется как static void **PyArray_API и виден только в единице компиляции или файле, использующем #include <numpy/arrayobject.h>.

  • Если определен только PY_ARRAY_UNIQUE_SYMBOL (он может быть пустым), то он объявляется нестатическим void **, что позволяет использовать его другими связанными файлами.

  • Если NO_IMPORT_ARRAY определен, таблица объявляется как extern void **, что означает, что она должна быть связана с файлом, который не использует NO_IMPORT_ARRAY.

Механизм PY_ARRAY_UNIQUE_SYMBOL дополнительно преобразует имена, чтобы избежать конфликтов.

Изменено в версии NumPy: В 2.1 заголовочные файлы изменены так, чтобы таблица не была доступна за пределами одного разделяемого объекта или DLL (в Windows так было всегда). Подробнее см. NPY_API_SYMBOL_ATTRIBUTE.

Чтобы использовать C-API из другого модуля расширения, необходимо вызвать функцию import_array. Если модуль расширения содержится в одном файле .c, то это все, что нужно сделать. Однако если модуль расширения включает в себя несколько файлов, для которых требуется C-API, необходимо предпринять некоторые дополнительные шаги.

int PyArray_ImportNumPyAPI(void)#

Гарантирует, что C API NumPy импортирован и готов к использованию. Возвращает 0 при успехе и -1 с установленной ошибкой, если импорт невозможен. Предпочтительно вызвать функцию один раз при инициализации модуля, но повторные вызовы требуют очень мало ресурсов.

Добавлено в версии 2.0: В заголовке npy_2_compat.h доступен вариант этой функции для более ранних версий.

import_array(void)#

Эту функцию необходимо вызывать при инициализации модуля, использующего C API. Она импортирует модуль с таблицей указателей на функции и устанавливает соответствующую переменную так, чтобы она указывала на таблицу. При ошибке макрос выполняет return NULL;, поэтому для собственной обработки ошибок предпочтителен PyArray_ImportNumPyAPI(). Также можно встретить _import_array() — функцию, а не макрос; при её сбое может быть полезно выдать более содержательную ошибку — и варианты import_array1(ret), позволяющие настроить возвращаемое значение.

PY_ARRAY_UNIQUE_SYMBOL#
NPY_API_SYMBOL_ATTRIBUTE#

Добавлено в версии 2.1.

Дополнительный символ, позволяющий, например, сделать API доступным за границами разделяемого объекта. По умолчанию NumPy добавляет атрибут скрытой видимости C, если он поддерживается: void __attribute__((visibility("hidden"))) **PyArray_API;. Это можно изменить, определив NPY_API_SYMBOL_ATTRIBUTE; тогда объявление примет вид void NPY_API_SYMBOL_ATTRIBUTE **PyArray_API; (с дополнительным преобразованием имени через уникальный символ).

Добавление пустого #define NPY_API_SYMBOL_ATTRIBUTE будет иметь такое же поведение, как и NumPy 1.x.

В Windows общая видимость никогда не поддерживалась по умолчанию, хотя её можно обеспечить этим макросом. Обычно мы не рекомендуем совместно использовать таблицу за пределами разделяемой библиотеки, поскольку импорт API массивов включает проверку версии NumPy.

NO_IMPORT_ARRAY#

Определение NO_IMPORT_ARRAY перед включением ndarrayobject.h означает, что импорт C API NumPy обрабатывается в другом файле и механизм включения здесь не будет добавлен. У вас должен быть один файл без определения NO_IMPORT_ARRAY.

#define PY_ARRAY_UNIQUE_SYMBOL cool_ARRAY_API
#include <numpy/arrayobject.h>

С другой стороны, coolhelper.c будет содержать в верхней части:

#define NO_IMPORT_ARRAY
#define PY_ARRAY_UNIQUE_SYMBOL cool_ARRAY_API
#include <numpy/arrayobject.h>

Общие последние две строки также можно вынести в локальный заголовочный файл расширения, если NO_IMPORT_ARRAY определён через #define до подключения этого файла через #include.

Эти определения #define работают следующим образом:

  • Если ни один из них не определён, C API объявляется как static void** и поэтому виден только внутри единицы трансляции, включающей numpy/arrayobject.h.

  • Если PY_ARRAY_UNIQUE_SYMBOL определён директивой #define, а NO_IMPORT_ARRAY не определён, C-API объявляется как void** и становится доступен другим единицам компиляции.

  • Если NO_IMPORT_ARRAY определён через #define, независимо от определения PY_ARRAY_UNIQUE_SYMBOL C API объявляется как extern void**. Предполагается, что он определён в другой единице трансляции.

  • Если PY_ARRAY_UNIQUE_SYMBOL задан с помощью #define, имя переменной, содержащей C-API (по умолчанию PyArray_API), заменяется значением, указанным в определении этого макроса.

Проверка версии API#

На большинстве платформ расширения Python используются иначе, чем обычные библиотеки, поэтому некоторые ошибки невозможно автоматически обнаружить при сборке или даже во время выполнения. Например, если собрать расширение с функцией, доступной только в NumPy >= 1.3.0, а затем импортировать его с NumPy 1.2, ошибки импорта не возникнет, но при вызове функции почти наверняка произойдёт ошибка сегментации. Поэтому предусмотрено несколько функций проверки версий NumPy. Макросы NPY_VERSION и NPY_FEATURE_VERSION соответствуют версии NumPy, использованной при сборке расширения, а значения, возвращаемые функциями PyArray_GetNDArrayCVersion и PyArray_GetNDArrayCFeatureVersion, — версии NumPy, используемой во время выполнения.

Правила совместимости ABI и API можно резюмировать следующим образом:

  • Если NPY_VERSION != PyArray_GetNDArrayCVersion(), расширение необходимо перекомпилировать из-за несовместимости ABI.

  • NPY_VERSION == PyArray_GetNDArrayCVersion() и NPY_FEATURE_VERSION <= PyArray_GetNDArrayCFeatureVersion() означает обратно совместимые изменения.

Несовместимость ABI автоматически определяется во всех версиях NumPy. Проверка совместимости API добавлена в NumPy 1.4.0. Для поддержки разных версий NumPy одним двоичным расширением собирайте его с наименьшим возможным NPY_FEATURE_VERSION.

NPY_VERSION#

Текущая версия объекта ndarray (проверьте, определена ли эта переменная, чтобы гарантировать использование заголовка numpy/arrayobject.h).

NPY_FEATURE_VERSION#

Текущая версия C-API.

unsigned int PyArray_GetNDArrayCVersion(void)#

Просто возвращает NPY_VERSION. Значение NPY_VERSION меняется при каждом изменении ABI, нарушающем обратную совместимость. Поскольку функция входит в C API, сравнение её результата со значением в текущем заголовке позволяет определить, изменился ли C API так, что использующие его модули расширения нужно перекомпилировать. Это автоматически проверяется в import_array.

unsigned int PyArray_GetNDArrayCFeatureVersion(void)#

Просто возвращает значение NPY_FEATURE_VERSION. Значение NPY_FEATURE_VERSION меняется при каждом изменении API (например, при добавлении функции). Изменение этого значения не всегда требует перекомпиляции.

Макросы для выделения, освобождения и перераспределения памяти под размеры измерений и шаги.

NPY_USE_PYMEM#
int PyArray_ResolveWritebackIfCopy(PyArrayObject *obj)#

Если в obj->flags установлен NPY_ARRAY_WRITEBACKIFCOPY, функция сбрасывает флаги, применяет DECREF к obj->base, разрешает запись в него и устанавливает obj->base в NULL. Затем она копирует obj->data в obj->base->data и возвращает состояние ошибки операции копирования. Это действие противоположно PyArray_SetWritebackIfCopyBase. Обычно функцию вызывают после завершения работы с obj, непосредственно перед Py_DECREF(obj). Её можно вызывать несколько раз или с аргументом NULL. См. также PyArray_DiscardWritebackIfCopy.

Возвращает 0, если ничего не было сделано, -1 в случае ошибки и 1, если действие было предпринято.

Поддержка потоков#

Эти макросы имеют смысл, только если NPY_ALLOW_THREADS равен True при компиляции модуля расширения. Иначе они эквивалентны пробелам. Python использует одну глобальную блокировку интерпретатора (GIL) на процесс, позволяя одновременно выполняться только одному потоку даже на многопроцессорных машинах. При вызове длительной скомпилированной функции без побочных эффектов для других потоков, например изменения глобальных переменных, GIL следует освободить, чтобы другие потоки Python могли работать. Для этого служат две группы макросов. Обычно при использовании одного макроса группы в блоке кода нужно использовать в том же блоке и остальные. NPY_ALLOW_THREADS истинен, то есть определён как 1, если параметр сборки -Ddisable-threading не равен true; при равенстве этому значению NPY_ALLOW_THREADS ложен (0).

NPY_ALLOW_THREADS#

Группа 1#

Эта группа используется для вызова кода, который может выполняться долго, но не вызывает API C Python. Поэтому на время вычисления следует освободить GIL.

NPY_BEGIN_ALLOW_THREADS#

Эквивалентно Py_BEGIN_ALLOW_THREADS, но для определения того, заменяется ли макрос пробельными символами, используется NPY_ALLOW_THREADS.

NPY_END_ALLOW_THREADS#

Эквивалентно Py_END_ALLOW_THREADS, но для определения того, заменяется ли макрос пробельными символами, используется NPY_ALLOW_THREADS.

NPY_BEGIN_THREADS_DEF#

Размещается в области объявления переменных. Этот макрос объявляет переменную, необходимую для хранения состояния Python.

NPY_BEGIN_THREADS#

Разместите непосредственно перед кодом, которому не нужен интерпретатор Python и который не вызывает API C Python. Макрос сохраняет состояние Python и освобождает GIL.

NPY_END_THREADS#

Разместите сразу после кода, которому не нужен интерпретатор Python. Этот макрос захватывает GIL и восстанавливает состояние Python из сохранённой переменной.

void NPY_BEGIN_THREADS_DESCR(PyArray_Descr *dtype)#

Полезно выпускать GIL только в том случае, если dtype не содержит произвольных объектов Python, для которых может понадобиться интерпретатор Python во время выполнения цикла.

void NPY_END_THREADS_DESCR(PyArray_Descr *dtype)#

Позволяет снова захватить GIL после освобождения с помощью варианта BEGIN этого макроса.

void NPY_BEGIN_THREADS_THRESHOLDED(int loop_size)#

Освобождает GIL, только если loop_size превышает минимальный порог, сейчас равный 500. Для повторного захвата GIL требуется парный вызов NPY_END_THREADS.

Группа 2#

Эта группа позволяет повторно захватить Python GIL после его освобождения. Например, GIL уже освобождён предыдущими вызовами, но одна из ветвей кода (возможно, в другой подпрограмме) требует Python C API. Эти макросы позволяют захватить GIL для такого участка. По существу, они выполняют действия, обратные предыдущим трём макросам: захватывают блокировку с сохранением прежнего состояния, а затем снова освобождают её, восстанавливая сохранённое состояние.

NPY_ALLOW_C_API_DEF#

Поместите в область объявления переменных, чтобы объявить необходимую переменную.

NPY_ALLOW_C_API#

Разместите перед кодом, которому нужно обращаться к C API Python, когда известно, что GIL уже освобождён.

NPY_DISABLE_C_API#

Разместите после кода, обращающегося к C API Python, чтобы снова освободить GIL.

Совет

Никогда не используйте точки с запятой после макросов поддержки потоков.

Примечание

Рекомендуется избегать использования NPY_MAXDIMS. В одной из будущих версий NumPy ограничение на число измерений может быть полностью снято, а эта константа — удалена. Ограничение введено для того, чтобы NumPy мог выделять временную рабочую память в стеке.

Прочие макросы#

int PyArray_SAMESHAPE(PyArrayObject *a1, PyArrayObject *a2)#

Принимает значение True, если массивы a1 и a2 имеют одинаковую форму.

PyArray_MAX(a, b)#

Возвращает максимум a и b. Если a или b — выражения, они вычисляются дважды.

Возвращает минимум a и b. Если a или b — выражения, они могут вычисляться дважды. Примечание переводчика: точнее, макрос повторно вычисляет только выбранный операнд, а другой вычисляется один раз; формулировка оригинала о двукратном вычислении обоих неточна.

void PyArray_DiscardWritebackIfCopy(PyArrayObject *obj)#

Если в obj->flags установлен NPY_ARRAY_WRITEBACKIFCOPY, эта функция сбрасывает флаги, выполняет DECREF для obj->base и разрешает запись в базовый массив, а затем устанавливает obj->base в NULL. В отличие от PyArray_ResolveWritebackIfCopy, она не пытается копировать данные из obj->base. Это отменяет действие PyArray_SetWritebackIfCopyBase. Обычно её вызывают после ошибки, завершив работу с obj, непосредственно перед Py_DECREF(obj). Допускаются многократные вызовы и передача NULL.
