Универсальные функции (ufunc)

Нередко требуется применять в цикле не только функции от скаляров, но и функции от векторов или массивов. В NumPy это реализовано обобщением универсальных функций (ufunc). У обычных ufunc базовая функция выполняет поэлементные операции, а обобщённые универсальные функции (gufunc) поддерживают операции над подмассивами. Аналогичная возможность есть в векторной библиотеке Perl PDL; далее используется её терминология.

С каждой обобщённой ufunc связана информация о числе основных измерений входных и выходных данных; у поэлементных ufunc основных измерений нет. Список основных измерений всех аргументов называется сигнатурой ufunc. Например, сигнатура numpy.add — (),()->(): два скалярных входа и один скалярный выход.

Другой пример — функция inner1d(a, b) с сигнатурой (i),(i)->(). Она вычисляет скалярное произведение по последней оси каждого входа, сохраняя остальные индексы. Например, если a имеет форму (3, 5, N), а b — (5, N), форма результата будет (3,5). Базовая элементарная функция вызывается 3 * 5 раз. Сигнатура задаёт одно основное измерение (i) для каждого входа и ни одного () для выхода, поскольку функция принимает два одномерных массива и возвращает скаляр. Одинаковое имя i указывает, что соответствующие измерения должны иметь одинаковый размер.

Измерения, не входящие в число основных, называются измерениями цикла («loop»). В приведённом выше примере им соответствует (3, 5).

Сигнатура определяет, как измерения каждого входного и выходного массива разделяются на базовые измерения и измерения обхода:

  1. Каждое измерение сигнатуры сопоставляется измерению переданного массива начиная с конца кортежа формы. Это основные измерения; они должны присутствовать в массивах, иначе вызывается ошибка.

  2. Основные измерения с одной и той же меткой в сигнатуре (например, i в функции inner1d с сигнатурой (i),(i)->()) должны иметь строго одинаковые размеры: трансляция массивов для них не выполняется.

  3. Основные измерения исключаются из всех входных форм, а оставшиеся измерения согласуются посредством трансляции, определяя измерения цикла.

  4. Форма каждого результата состоит из измерений цикла и основных измерений соответствующего результата

Обычно размер каждого основного измерения выходного массива определяется размером основного измерения с той же меткой во входном массиве. Однако это не обязательно: можно задать сигнатуру, в которой метка впервые появляется в выходном массиве. При вызове такой функции необходимо соблюдать определённые условия. Например, функция euclidean_pdist(a) с сигнатурой (n,d)->(p) принимает массив из n векторов размерности d и вычисляет все уникальные попарные евклидовы расстояния между ними. Поэтому размер выходного измерения p должен равняться n * (n - 1) / 2. По умолчанию вызывающий код обязан передать выходной массив нужного размера. Если размер основного измерения результата невозможно определить по переданному входному или выходному массиву, возникает ошибка. Это поведение можно изменить, определив функцию типа PyUFunc_ProcessCoreDimsFunc и присвоив её полю process_core_dims_func структуры PyUFuncObject. Подробности см. ниже.

Примечание: до NumPy 1.10.0 проверки были менее строгими. Недостающие базовые измерения создавались добавлением единиц в начало формы; базовые измерения с одинаковой меткой согласовывались трансляцией, а размеры неопределённых измерений устанавливались в 1.

Определения#

Элементарная функция

Каждая универсальная функция основана на элементарной функции, выполняющей базовую операцию над минимальной частью аргументов-массивов. Например, при сложении двух массивов такой операцией является сложение двух чисел. Универсальная функция многократно применяет элементарную функцию к разным частям массивов. Входными и выходными данными элементарных функций могут быть векторы: например, элементарная функция для inner1d принимает два вектора.

Сигнатура

Сигнатура — строка, описывающая измерения входов и выходов элементарной функции, лежащей в основе универсальной функции. Подробности приведены в следующем разделе.

Основное измерение

Размерность каждого входа и выхода элементарной функции определяется его базовыми измерениями (отсутствие базовых измерений соответствует скалярному входу или выходу). Базовые измерения сопоставляются с последними измерениями входных и выходных массивов.

Имя измерения

Имя измерения обозначает основное измерение в сигнатуре. Разные измерения могут иметь одно имя: это означает, что их размеры совпадают.

Индекс измерения

Индекс измерения — это целое число, представляющее имя измерения. Имена нумеруются в порядке их первого появления в сигнатуре.

Подробное описание сигнатуры#

Сигнатура задаёт число «основных» измерений входных и выходных переменных и тем самым определяет свёртку измерений. Сигнатура представляется строкой следующего формата:

  • Основные измерения каждого входного или выходного массива задаются списком имён в круглых скобках, (i_1,...,i_N); скалярный вход или выход обозначается (). Вместо i_1, i_2 и т. д. можно использовать любые допустимые имена переменных Python.

  • Списки измерений для различных аргументов разделены ",". Аргументы ввода/вывода разделены "->".

  • Если одно имя измерения используется в нескольких местах, соответствующие измерения обязаны иметь одинаковый размер.

Формальный синтаксис сигнатур:

<Signature>            ::= <Input arguments> "->" <Output arguments>
<Input arguments>      ::= <Argument list>
<Output arguments>     ::= <Argument list>
<Argument list>        ::= nil | <Argument> | <Argument> "," <Argument list>
<Argument>             ::= "(" <Core dimension list> ")"
<Core dimension list>  ::= nil | <Core dimension> |
                           <Core dimension> "," <Core dimension list>
<Core dimension>       ::= <Dimension name> <Dimension modifier>
<Dimension name>       ::= valid Python variable name | valid integer
<Dimension modifier>   ::= nil | "?"

Примечания:

  1. Все кавычки приведены для наглядности.

  2. Базовые измерения без модификаторов, имеющие одинаковое имя, должны иметь одинаковый размер. Каждое имя измерения обычно соответствует одному уровню цикла в реализации элементарной функции.

  3. Пробельные символы игнорируются.

  4. Целое число вместо имени измерения фиксирует его размер на этом значении.

  5. Если после имени стоит модификатор «?», измерение считается базовым только тогда, когда оно присутствует во всех входных и выходных массивах, использующих это имя. В противном случае оно игнорируется, а для элементарной функции заменяется измерением размера 1.

C-API для реализации элементарных функций #

Существующий интерфейс остаётся неизменным: PyUFunc_FromFuncAndData по-прежнему можно использовать для реализации специализированных ufunc, состоящих из скалярных элементарных функций.

С помощью PyUFunc_FromFuncAndDataAndSignature можно объявить обобщённую универсальную функцию. Список аргументов совпадает с PyUFunc_FromFuncAndData, но дополнительно передаётся сигнатура в виде строки C.

Кроме того, тип функции обратного вызова остаётся прежним: void (*foo)(char **args, intp *dimensions, intp *steps, void *func). При её вызове args — это список длины nargs с данными всех входных и выходных аргументов. Для скалярной элементарной функции steps также имеет длину nargs и содержит шаги аргументов. dimensions — указатель на одно целое число, задающее длину оси, по которой выполняется цикл.

Для нетривиальной сигнатуры dimensions также содержит длины основных измерений, начиная со второго элемента. Для каждого уникального имени измерения указывается только одна длина; порядок соответствует первому появлению имён измерений в сигнатуре.

Первые nargs элементов steps такие же, как у скалярных ufunc. Далее по порядку следуют шаги всех основных измерений для всех аргументов.

Рассмотрим универсальную функцию с сигнатурой (i,j),(i)->(). Тогда args содержит три указателя на данные входных и выходных массивов a, b и c. Массив dimensions равен [N, I, J]: он задаёт размер цикла N и размеры I и J основных измерений i и j. Наконец, steps равен [a_N, b_N, c_N, a_i, a_j, b_i] и содержит все необходимые шаги.

Настройка обработки размеров основных измерений#

Необязательная функция типа PyUFunc_ProcessCoreDimsFunc, хранящаяся в атрибуте process_core_dims_func универсальной функции, позволяет её автору вмешаться в обработку основных измерений массивов, переданных универсальной функции. Два главных применения этой возможности:

  • Проверяет ограничения на основные измерения, требуемые ufunc, и устанавливает исключение, если они нарушены.

  • Вычисляет форму выходов для основных измерений результата, не определённых входными массивами.

В качестве примера первого применения рассмотрим обобщённую универсальную функцию minmax с сигнатурой (n)->(2), одновременно вычисляющую минимум и максимум последовательности. Она должна требовать n > 0, поскольку минимум и максимум пустой последовательности не имеют смысла. Автор универсальной функции может определить её так:

int minmax_process_core_dims(PyUFuncObject *ufunc,
                             npy_intp *core_dim_sizes)
{
    npy_intp n = core_dim_sizes[0];
    if (n == 0) {
        PyErr_SetString(PyExc_ValueError,
                        "minmax requires the core dimension to "
                        "be at least 1.");
        return -1;
    }
    return 0;
}

В этом случае длина массива core_dim_sizes равна 2. Второе значение всегда равно 2, поэтому функции не нужно его проверять. Размер базового измерения n хранится в первом элементе. Если n равен 0, функция устанавливает исключение и возвращает -1.

Второе применение обработчика — вычисление размеров выходных массивов, когда вызывающий код их не передал, а одно или несколько основных измерений выхода не представлены среди основных измерений входов. Если у универсальной функции не задан обработчик process_core_dims_func, неизвестный размер основного выходного измерения вызывает исключение. Обработчик process_core_dims_func позволяет автору задать нужный размер выхода.

Базовые измерения, размеры которых не определены входными данными, обозначаются значением -1 в массиве core_dim_sizes, передаваемом функции-перехватчику. Функция может заменить -1 любым подходящим для универсальной функции значением, исходя из размеров базовых измерений входных массивов.

Предупреждение

Функция никогда не должна изменять значение в core_dim_sizes, отличное от -1 на входе. Изменение значения, отличного от -1, обычно приводит к неправильному выводу ufunc и может привести к сбою интерпретатора Python.

Например, рассмотрим обобщённую универсальную функцию conv1d, элементарная операция которой вычисляет «полную» свёртку двух одномерных массивов x и y длины m и n соответственно. Длина результата свёртки равна m + n - 1. Для реализации этой операции в виде обобщённой универсальной функции задаётся сигнатура (m),(n)->(p). В функции-хуке проверяется базовое измерение p: если оно равно -1, его заменяют на m + n - 1. Если p не равно -1, нужно проверить, что заданное значение равно m + n - 1. Иначе функция должна установить исключение и вернуть -1. Для осмысленного результата также требуется, чтобы m + n было не меньше 1: оба входа не могут одновременно иметь длину 0.

Вот как это может выглядеть в коде:

int conv1d_process_core_dims(PyUFuncObject *ufunc,
                             npy_intp *core_dim_sizes)
{
    // core_dim_sizes will hold the core dimensions [m, n, p].
    // p will be -1 if the caller did not provide the out argument.
    npy_intp m = core_dim_sizes[0];
    npy_intp n = core_dim_sizes[1];
    npy_intp p = core_dim_sizes[2];
    npy_intp required_p = m + n - 1;

    if (m == 0 && n == 0) {
        // Disallow both inputs having length 0.
        PyErr_SetString(PyExc_ValueError,
            "conv1d: both inputs have core dimension 0; the function "
            "requires that at least one input has size greater than 0.");
        return -1;
    }
    if (p == -1) {
        // Output array was not given in the call of the ufunc.
        // Set the correct output size here.
        core_dim_sizes[2] = required_p;
        return 0;
    }
    // An output array *was* given.  Validate its core dimension.
    if (p != required_p) {
        PyErr_Format(PyExc_ValueError,
                "conv1d: the core dimension p of the out parameter "
                "does not equal m + n - 1, where m and n are the "
                "core dimensions of the inputs x and y; got m=%zd "
                "and n=%zd so p must be %zd, but got p=%zd.",
                m, n, required_p, p);
        return -1;
    }
    return 0;
}
Комментарии к примеру на русском
  • core_dim_sizes будет содержать основные размеры [m, n, p].
  • Если вызывающая сторона не передала out, p будет равен -1.
  • Запрещаем случай, когда длины обоих входов равны 0.
  • Выходной массив не был передан при вызове ufunc.
  • Задаём здесь правильный размер результата.
  • Выходной массив *был* передан. Проверяем его основное измерение.
