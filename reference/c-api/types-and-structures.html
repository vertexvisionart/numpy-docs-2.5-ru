Типы Python и C-структуры #

В коде C определено несколько новых типов. Большинство доступны из Python; некоторые не предоставляются из-за узкого назначения. С каждым новым типом Python связан PyObject*, внутренняя структура которого содержит указатель на «таблицу методов», определяющую поведение объекта в Python. При получении объекта Python в C всегда передаётся указатель на структуру PyObject. Структура PyObject очень общая и определяет лишь PyObject_HEAD, поэтому сама по себе малоинформативна. Однако у конкретных объектов после PyObject_HEAD находятся дополнительные данные. Для доступа к ним нужно привести указатель к правильному типу либо воспользоваться функциями доступа или макросами.

Определены новые типы Python#

Типы Python, реализованные на C, функционально соответствуют классам Python. Создавая новый тип на C, вы предоставляете Python новый вид объектов. ndarray — пример такого типа. Определение нового типа на C состоит из двух основных шагов:

  1. создание C-структуры (обычно называемой Py{Name}Object), которая двоично совместима с самой структурой PyObject, но содержит дополнительную информацию, необходимую для этого конкретного объекта;

  2. заполнение таблицы PyTypeObject (на которую указывает член ob_type структуры PyObject) указателями на функции, реализующие желаемое поведение для типа.

Вместо специальных имен методов, определяющих поведение классов Python, существуют «таблицы функций», которые указывают на функции, реализующие желаемые результаты. Сам PyTypeObject является динамическим, что позволяет использовать типы C, которые могут быть «подтипами» других C-типов в C и подклассами в Python. Дочерние типы наследуют атрибуты и методы от своих родителей.

Есть два основных новых типа: ndarray (PyArray_Type) и ufunc (PyUFunc_Type). Вспомогательные типы — PyArrayIter_Type, PyArrayMultiIter_Type и PyArrayDescr_Type. PyArrayIter_Type — тип плоского итератора ndarray, возвращаемого атрибутом flat. PyArrayMultiIter_Type — тип результата вызова broadcast; он обеспечивает обход и трансляцию набора вложенных последовательностей. PyArrayDescr_Type — тип дескрипторов данных, а PyArray_DTypeMeta — их метакласс. Также добавлены скалярные типы Python, соответствующие каждому базовому типу элементов массивов. Другие типы служат промежуточными звеньями, позволяющими встроить скаляры NumPy в иерархию типов Python. Наконец, экземпляры PyArray_DTypeMeta для встроенных типов данных NumPy также общедоступны.

PyArray_Type и PyArrayObject #

PyTypeObject PyArray_Type#

Тип Python ndarray — PyArray_Type. В C каждый ndarray является указателем на структуру PyArrayObject. Член ob_type этой структуры содержит указатель на объект типа PyArray_Type.

type PyArrayObject#
type NPY_AO#

Структура C PyArrayObject содержит все необходимые сведения о массиве. Она есть у всех экземпляров ndarray и его подклассов. Для совместимости с будущими версиями к её членам обычно следует обращаться через предусмотренные макросы. Если нужно короткое имя, можно использовать устаревшее NPY_AO, определённое как эквивалент PyArrayObject. Прямой доступ к полям структуры объявлен устаревшим; используйте форму PyArray_*(arr). Начиная с NumPy 1.20 размер структуры не считается частью ABI NumPy; см. примечание после списка членов.

typedef struct PyArrayObject {
    PyObject_HEAD
    char *data;
    int nd;
    npy_intp *dimensions;
    npy_intp *strides;
    PyObject *base;
    PyArray_Descr *descr;
    int flags;
    PyObject *weakreflist;
    /* version dependent private members */
} PyArrayObject;
Комментарии к примеру на русском
  • Закрытые члены, зависящие от версии
PyObject_HEAD

Это необходимо всем объектам Python. Структура содержит как минимум поле счётчика ссылок (ob_refcnt) и указатель на объект типа (ob_type). Если Python скомпилирован со специальными параметрами, могут присутствовать и другие элементы; подробнее см. Include/object.h в дереве исходного кода Python. Поле ob_type указывает на объект типа Python.

char *data#

Это поле доступно через PyArray_DATA и содержит указатель на первый элемент массива. Его можно и обычно следует привести к указателю на тип данных массива.

int nd#

Целое число измерений массива. При nd=0 массив иногда называют массивом ранга 0. Для него нет элементов dimensions и strides, к которым можно обращаться. Макрос PyArray_NDIM из ndarraytypes.h предоставляет доступ к этому полю. Константа времени компиляции NPY_MAXDIMS ограничивает число измерений: начиная с NumPy 2 предел равен 64, раньше — 32. В будущем ограничение может быть снято, поэтому коду, полагающемуся на верхний предел, лучше явно проверять число измерений. Примечание переводчика: оригинал неточно говорит, что нульмерные массивы «недоступны». Их значение доступно, например через a[()]; недопустим доступ к несуществующим элементам массивов размеров и шагов.

npy_intp *dimensions#

Массив целых чисел, задающий размер по каждому измерению при nd \(\geq\) 1. Целочисленный тип всегда достаточно велик для хранения указателя на данной платформе, поэтому размер измерения ограничен только объёмом памяти. Этому полю структуры соответствует макрос PyArray_DIMS.

npy_intp *strides#

Массив целых чисел, указывающий для каждого измерения количество байтов, которые необходимо пропустить, чтобы перейти к следующему элементу в этом измерении. Связан с макросом PyArray_STRIDES.

PyObject *base#

Этот элемент, на который указывает PyArray_BASE, используется для хранения указателя на другой объект Python, связанный с этим массивом. Есть два варианта использования:

  • Если массив не владеет своей памятью, base указывает на владеющий ею объект Python, возможно другой массив.

  • Если у массива установлен флаг NPY_ARRAY_WRITEBACKIFCOPY, это рабочая копия массива, не отвечающего необходимым требованиям.

При вызове PyArray_ResolveWritebackIfCopy содержимое этого массива записывается в массив, на который указывает base.

PyArray_Descr *descr#

Указатель на объект дескриптора типа данных (см. ниже). Этот объект — экземпляр нового встроенного типа, предоставляющего общее описание памяти. Для каждого поддерживаемого типа данных существует структура дескриптора. Она содержит полезные сведения о типе и указатель на таблицу указателей на функции, реализующие конкретные операции. Как следует из названия, это поле связано с макросом PyArray_DESCR.

int flags#

Поле, доступное через макрос PyArray_FLAGS, содержит флаги интерпретации памяти, на которую указывает data. Возможные флаги: NPY_ARRAY_C_CONTIGUOUS, NPY_ARRAY_F_CONTIGUOUS, NPY_ARRAY_OWNDATA, NPY_ARRAY_ALIGNED, NPY_ARRAY_WRITEABLE, NPY_ARRAY_WRITEBACKIFCOPY.

PyObject *weakreflist#

Этот член позволяет создавать слабые ссылки на объекты массивов с помощью модуля weakref.

Примечание

Остальные поля считаются закрытыми и зависят от версии. Если размер структуры важен для вашего кода, нужна особая осторожность, например при создании подкласса на C. Если код рассчитывает на постоянное значение sizeof(PyArrayObject), добавьте следующую проверку при импорте:

if (sizeof(PyArrayObject) < PyArray_Type.tp_basicsize) {
    PyErr_SetString(PyExc_ImportError,
       "Binary incompatibility with NumPy, must recompile/update X.");
    return NULL;
}

Чтобы не компилировать код для каждой конкретной версии NumPy, можно добавить постоянный запас размера, оставив место для будущих изменений NumPy. Для гарантированной совместимости с любой будущей версией NumPy смещение и размер выделяемой памяти необходимо вычислять во время выполнения.

Объект типа PyArray_Type реализует многие возможности Python objects (объектов Python), включая интерфейсы tp_as_number, tp_as_sequence, tp_as_mapping и tp_as_buffer. Также используются rich comparison (операции сравнения) и механизм поиска атрибутов нового стиля для полей (tp_members) и свойств (tp_getset). От PyArray_Type также можно наследовать подклассы.

Совет

Методы tp_as_number используют общий механизм вызова функции, зарегистрированной для соответствующей операции. При импорте модуля _multiarray_umath числовые операции всех массивов связываются с соответствующими универсальными функциями. Этот выбор можно изменить с помощью PyUFunc_ReplaceLoopBySignature.

PyGenericArrType_Type#

PyTypeObject PyGenericArrType_Type#

PyGenericArrType_Type — определение PyTypeObject, создающее тип Python numpy.generic.

PyArrayDescr_Type и PyArray_Descr#

PyTypeObject PyArrayDescr_Type#

PyArrayDescr_Type — встроенный тип объектов-дескрипторов, описывающих интерпретацию байтов массива. Для встроенных типов данных статически определён 21 объект PyArray_Descr. Они участвуют в подсчёте ссылок, но их счётчики никогда не должны достигать нуля. Также поддерживается динамическая таблица пользовательских объектов PyArray_Descr. После регистрации объект-дескриптор типа данных также никогда не должен освобождаться. Функция PyArray_DescrFromType (…) возвращает объект PyArray_Descr по номеру типа из перечисления, встроенного или пользовательского.

type PyArray_DescrProto#

Имеет ту же структуру, что и PyArray_Descr. Используется для статического определения прототипа при регистрации нового DType старого API с помощью PyArray_RegisterDataType.

См. примечание в PyArray_RegisterDataType для подробностей.

type PyArray_Descr#

Структура PyArray_Descr лежит в основе PyArrayDescr_Type. Хотя она описана здесь для полноты, она должна рассматриваться как внутренняя для NumPy и управляться с помощью функций и макросов PyArrayDescr_* или PyDataType*. Размер этой структуры может изменяться в разных версиях NumPy. Для обеспечения совместимости:

  • Никогда не объявляйте экземпляр самой структуры; используйте указатель

  • Никогда не выполняйте арифметику указателя

  • Никогда не используйте sizeof(PyArray_Descr)

Он имеет следующую структуру:

typedef struct {
    PyObject_HEAD
    PyTypeObject *typeobj;
    char kind;
    char type;
    char byteorder;
    char _former_flags;  // unused field
    int type_num;
    /*
     * Definitions after this one must be accessed through accessor
     * functions (see below) when compiling with NumPy 1.x support.
     */
    npy_uint64 flags;
    npy_intp elsize;
    npy_intp alignment;
    NpyAuxData *c_metadata;
    npy_hash_t hash;
    void *reserved_null[2];  // unused field, must be NULLed.
} PyArray_Descr;
Комментарии к примеру на русском
  • Неиспользуемое поле
  • При компиляции с поддержкой NumPy 1.x к определениям ниже нужно обращаться через функции доступа (см. ниже).
  • Неиспользуемое поле; должно быть установлено в NULL.

Некоторые dtype имеют дополнительные члены, доступные через PyDataType_NAMES, PyDataType_FIELDS, PyDataType_SUBARRAY, а в некоторых случаях (для типов времени) — PyDataType_C_METADATA.

PyTypeObject *typeobj#

Указатель на объект типа Python, соответствующий элементам этого массива. Для встроенных типов он указывает на соответствующий скалярный тип массива. Для пользовательских типов он должен указывать на пользовательский объект типа. Этот тип может наследоваться от скалярных типов массивов, но это необязательно. Если он от них не наследуется, необходимо установить флаги NPY_USE_GETITEM и NPY_USE_SETITEM в поле flags.

char kind#

Символьный код вида массива в обозначениях typestring интерфейса массива: b — логический тип, i — знаковое целое, u — беззнаковое целое, f — число с плавающей точкой, c — комплексное число с плавающей точкой, S — 8-битные байты с нулевым завершением, U — строка Unicode с 32 битами на символ, V — произвольные данные.

char type#

Традиционный символьный код, обозначающий тип данных.

char byteorder#

Символ порядка байтов: «>» — от старшего к младшему, «<» — от младшего к старшему, «=» — системный, «|» — не имеет значения, игнорируется. У всех встроенных типов данных byteorder равно «=».

npy_uint64 flags#

Битовые флаги типа данных, определяющие, ведёт ли он себя подобно массиву объектов. Каждый бит этого поля соответствует флагу со следующим именем:

  • NPY_ITEM_REFCOUNT

  • NPY_ITEM_HASOBJECT

  • NPY_LIST_PICKLE

  • NPY_ITEM_IS_POINTER

  • NPY_NEEDS_INIT

  • NPY_NEEDS_PYAPI

  • NPY_USE_GETITEM

  • NPY_USE_SETITEM

  • NPY_FROM_FIELDS

  • NPY_OBJECT_DTYPE_FLAGS

int type_num#

Номер, который однозначно идентифицирует тип данных. Для новых типов данных этот номер присваивается при регистрации типа данных.

npy_intp elsize#

Для типов данных фиксированного размера, например long, здесь хранится размер типа. Для типов переменного размера, у которых размер элемента может различаться между массивами, значение должно быть равно 0.

О способах доступа к этому полю, совместимых с NumPy 1.x, см. PyDataType_ELSIZE и PyDataType_SET_ELSIZE.

npy_intp alignment#

Число, описывающее выравнивание типа данных. Оно показывает, на каком расстоянии от начала структуры из двух элементов, первый из которых — char, компилятор размещает значение этого типа: offsetof(struct {char c; type v;}, v)

См. PyDataType_ALIGNMENT для доступа к этому полю в NumPy 1.x совместимым способом.

PyObject *metadata#

Метаданные об этом dtype.

NpyAuxData *c_metadata#

Метаданные, специфичные для реализации C конкретного dtype. Добавлено для NumPy 1.7.0.

type npy_hash_t#
npy_hash_t *hash#

Используется для кэширования хеш-значений.

NPY_ITEM_REFCOUNT#

Указывает, что элементы этого типа данных должны иметь подсчет ссылок (с использованием Py_INCREF и Py_DECREF).

NPY_ITEM_HASOBJECT#

То же, что NPY_ITEM_REFCOUNT.

NPY_LIST_PICKLE#

Указывает, что массивы этого типа данных нужно преобразовывать в список перед сериализацией pickle.

NPY_ITEM_IS_POINTER#

Указывает, что элемент является указателем на какой-либо другой тип данных.

NPY_NEEDS_INIT#

Указывает, что память этого типа данных при создании нужно инициализировать нулями.

NPY_NEEDS_PYAPI#

Указывает, что доступ к данным этого типа требует Python C API. Поэтому, если нужен доступ к массиву, освобождать GIL нельзя.

NPY_USE_GETITEM#

При доступе к массиву использовать указатель на функцию f->getitem вместо стандартного преобразования в скаляр NumPy. Обязательно, если для типа данных не определён соответствующий скалярный тип.

NPY_USE_SETITEM#

При создании нульмерного массива из скаляра массива используйте f->setitem вместо обычного копирования из скаляра. Это обязательно, если для данного типа данных не определён соответствующий скаляр массива.

NPY_FROM_FIELDS#

Биты, которые наследуются родительским типом данных, если они установлены хотя бы в одном его поле. Сейчас это (NPY_NEEDS_INIT | NPY_LIST_PICKLE | NPY_ITEM_REFCOUNT | NPY_NEEDS_PYAPI).

NPY_OBJECT_DTYPE_FLAGS#

Биты, устанавливаемые для объектного типа данных: (NPY_LIST_PICKLE | NPY_USE_GETITEM | NPY_ITEM_IS_POINTER | NPY_ITEM_REFCOUNT | NPY_NEEDS_INIT | NPY_NEEDS_PYAPI).

int PyDataType_FLAGCHK(PyArray_Descr *dtype, int flags)#

Вернуть истинно, если все заданные флаги установлены для объекта типа данных.

int PyDataType_REFCHK(PyArray_Descr *dtype)#

Эквивалент PyDataType_FLAGCHK ( dtype , NPY_ITEM_REFCOUNT).

PyArray_ArrFuncs#

PyArray_ArrFuncs *PyDataType_GetArrFuncs(PyArray_Descr *dtype)#

Возвращает устаревшую структуру PyArray_ArrFuncs типа данных; вызов не может завершиться ошибкой.

Добавлено в NumPy: 2.0. Эта функция добавлена в NumPy 2.0 с сохранением обратной совместимости и возможностью переноса в старые версии (см. npy_2_compat.h). Код, ранее обращавшийся к полю ->f структуры PyArray_Descr, теперь должен использовать эту функцию и переносить её реализацию для компиляции с NumPy 1.x. Для этого можно включить заголовок npy_2_compat.h в исходный код своего проекта.

type PyArray_ArrFuncs#

Функции, реализующие внутренние возможности. Для данного типа не обязательно определять все указатели. Обязательные члены — nonzero, copyswap, copyswapn, setitem, getitem и cast. Предполагается, что они не равны NULL; значения NULL приведут к аварийному завершению программы. Остальные функции могут быть NULL, что означает лишь ограниченные возможности этого типа данных. Кроме того, если при регистрации пользовательского типа nonzero равна NULL, она заполняется функцией по умолчанию.

typedef struct {
    PyArray_VectorUnaryFunc *cast[NPY_NTYPES_LEGACY];
    PyArray_GetItemFunc *getitem;
    PyArray_SetItemFunc *setitem;
    PyArray_CopySwapNFunc *copyswapn;
    PyArray_CopySwapFunc *copyswap;
    PyArray_CompareFunc *compare;
    PyArray_ArgFunc *argmax;
    PyArray_DotFunc *dotfunc;

    PyArray_NonzeroFunc *nonzero;
    PyArray_FillFunc *fill;
    PyArray_FillWithScalarFunc *fillwithscalar;
    PyArray_SortFunc *sort[NPY_NSORTS];
    PyArray_ArgSortFunc *argsort[NPY_NSORTS];

    PyArray_ScalarKindFunc *scalarkind;

В описании указателей на функции используется понятие корректно расположенного сегмента: он выровнен и имеет родной порядок байтов для своего типа данных. Функции nonzero, copyswap, copyswapn, getitem и setitem могут и должны работать с массивами, не удовлетворяющими этим требованиям. Остальные функции требуют корректного выравнивания и родного порядка байтов.

Примечание

Большинство этих функций относится к старому API, но некоторые ещё используются. Начиная с NumPy 2.x они доступны только через PyDataType_GetArrFuncs (подробности см. в описании функции). Прежде чем использовать функцию из структуры, проверьте, не равен ли её указатель NULL. Обычно можно рассчитывать на наличие getitem, setitem, copyswap и copyswapn, однако все эти функции предполагается заменить новым API. Например, PyArray_Pack — более мощная версия setitem, которая, в частности, корректно обрабатывает приведение типов.

void cast(void *from, void *to, npy_intp n, void *fromarr, void *toarr)#

Массив указателей на функции приведения из текущего типа ко всем остальным встроенным типам. Каждая функция преобразует непрерывно расположенный, выровненный буфер в машинном порядке байтов, на который указывает from, в такой же непрерывный, выровненный буфер в машинном порядке байтов по указателю to. Число преобразуемых элементов задаёт n. Для массивов гибкого размера аргументы fromarr и toarr интерпретируются как PyArrayObject для получения itemsize.

PyObject *getitem(void *data, void *arr)#

Указатель на функцию, которая возвращает стандартный объект Python из одного элемента массива arr, на который указывает data. Функция должна правильно обрабатывать массивы с нарушенным выравниванием и/или переставленными байтами.

int setitem(PyObject *item, void *data, void *arr)#

Указатель на функцию, записывающую объект Python item в массив arr по адресу data. Функция поддерживает массивы с неподходящим выравниванием или порядком байтов. При успехе возвращает 0, иначе — -1 и устанавливает ошибку Python.

void copyswapn(void *dest, npy_intp dstride, void *src, npy_intp sstride, npy_intp n, int swap, void *arr)#
void copyswap(void *dest, void *src, int swap, void *arr)#

Оба поля — указатели на функции копирования данных из src в dest с перестановкой байтов при заданном swap. Значение arr используется только для массивов гибких типов NPY_STRING, NPY_UNICODE и NPY_VOID и получается из arr->descr->elsize. Вторая функция копирует одно значение, первая обходит n значений с заданными шагами. Они обрабатывают и данные src, не удовлетворяющие обычным требованиям к выравниванию и порядку байтов. При src, равном NULL, копирование не выполняется. Если swap равен 0, байты не переставляются. Предполагается, что dest и src не перекрываются. Если перекрываются, сначала используйте memmove(…), затем copyswap(n) с src, равным NULL.

int compare(const void *d1, const void *d2, void *arr)#

Указатель на функцию, сравнивающую два элемента массива arr, на которые указывают d1 и d2. Функция требует массивы с выровненными данными и родным порядком байтов. Возвращается 1, если *d1 > *d2, 0, если *d1 == *d2, и -1, если *d1 < *d2. Объект массива arr используется для получения размера элемента и сведений о полях массивов с гибким типом данных.

int argmax(void *data, npy_intp n, npy_intp *max_ind, void *arr)#

Указатель на функцию, определяющую индекс наибольшего из n элементов массива arr, начиная с элемента по адресу data. Участок памяти должен быть непрерывным и удовлетворять требованиям BEHAVED: быть выровненным и доступным для записи. Функция всегда возвращает 0; индекс наибольшего элемента записывается в max_ind.

void dotfunc(void *ip1, npy_intp is1, void *ip2, npy_intp is2, void *op, npy_intp n, void *arr)#

Указатель на функцию, которая поэлементно перемножает две последовательности длины n, суммирует произведения и записывает результат по указателю op в элемент массива arr. Начала последовательностей задаются указателями ip1 и ip2. Для перехода к следующему элементу каждой последовательности нужны смещения is1 и is2 байт соответственно. Функции требуется корректно выровненная память с подходящим порядком байтов; непрерывное расположение в памяти не обязательно.

int scanfunc(FILE *fd, void *ip, void *arr)#

Указатель на функцию, считывающую один элемент соответствующего типа в стиле scanf из файлового дескриптора fd в память массива по указателю ip. Предполагается, что массив отвечает необходимым требованиям. Последний аргумент arr — массив, в который считываются данные. Возвращает число принимающих аргументов, которым успешно присвоены значения: оно может быть нулевым, если сопоставление не удалось до первого присваивания. Возвращает EOF, если ошибка ввода произошла до первого присваивания. Функцию нужно вызывать без удержания GIL Python; для сообщения об ошибке она должна его захватить.

int fromstr(char *str, void *ip, char **endptr, void *arr)#

Указатель на функцию, которая преобразует строку по адресу str в один элемент соответствующего типа и помещает его по адресу ip. После преобразования *endptr указывает на оставшуюся часть строки. Последний аргумент arr — массив, внутрь которого указывает ip; он нужен для типов данных переменного размера. Возвращает 0 при успехе и -1 при ошибке. Требует массив с выровненными данными и родным порядком байтов. Функцию следует вызывать без удержания GIL Python; для сообщения об ошибке она должна захватить GIL.

npy_bool nonzero(void *data, void *arr)#

Указатель на функцию, возвращающую TRUE, если элемент arr, на который указывает data, ненулевой. Функция умеет работать и с массивами, не удовлетворяющими стандартным требованиям к расположению данных в памяти.

void fill(void *data, npy_intp length, void *arr)#

Указатель на функцию, заполняющую данными непрерывно расположенный массив заданной длины. Первые два элемента уже должны быть заполнены. По ним вычисляется разность, затем элементы с третьего до последнего получаются последовательным прибавлением этой разности. Буфер данных должен иметь корректные выравнивание и системный порядок байтов.

void fillwithscalar(void *buffer, npy_intp length, void *value, void *arr)#

Указатель на функцию, заполняющую непрерывный буфер buffer длины length одним скалярным значением value, адрес которого передан. Последний аргумент — массив, необходимый для определения itemsize у типов с настраиваемой длиной элемента.

int sort(void *start, npy_intp length, void *arr)#

Массив указателей на функции, реализующие алгоритмы сортировки. Алгоритм выбирается по ключу (пока определены NPY_QUICKSORT, NPY_HEAPSORT и NPY_MERGESORT). Сортировка выполняется на месте; предполагается, что данные выровнены и непрерывно расположены в памяти.

int argsort(void *start, npy_intp *result, npy_intp length, void *arr)#

Массив указателей на функции сортировки для этого типа данных. Доступны те же алгоритмы, что и для sort. Индексы, задающие порядок сортировки, возвращаются в result, который должен быть предварительно заполнен индексами от 0 до length-1 включительно.

PyObject *castdict#

Либо NULL, либо словарь с низкоуровневыми функциями приведения пользовательских типов данных. Каждая функция обёрнута в PyCapsule*, а ключом служит номер типа данных.

NPY_SCALARKIND scalarkind(PyArrayObject *arr)#

Функция для определения того, как следует интерпретировать скаляры этого типа. Аргумент — NULL или 0-мерный массив, содержащий данные (если это необходимо для определения вида скаляра). Возвратное значение должно быть типа NPY_SCALARKIND.

int **cancastscalarkindto#

Либо NULL, либо массив указателей NPY_NSCALARKINDS. Каждый указатель должен быть NULL или указывать на массив целых чисел, завершающийся NPY_NOTYPE. В нём задаются типы, к которым можно безопасно, обычно без потери точности, привести скаляр данного типа и указанной категории.

int *cancastto#

Либо NULL, либо массив целых чисел, заканчивающийся NPY_NOTYPE и указывающий типы данных, к которым этот тип можно безопасно привести (обычно это означает отсутствие потери точности).

int argmin(void *data, npy_intp n, npy_intp *min_ind, void *arr)#

Указатель на функцию, находящую индекс наименьшего из n элементов arr, начиная с элемента по указателю data. Участок памяти должен быть непрерывным, правильно выровненным и иметь подходящий порядок байтов. Возвращаемое значение всегда равно 0; индекс наименьшего элемента записывается в min_ind.

Структура для регистрации ArrayMethod в NumPy. Используется механизм слотов, принятый в ограниченном API Python. Определения слотов приведены ниже.

PyArray_DTypeMeta и PyArrayDTypeMeta_Spec#

PyTypeObject PyArrayDTypeMeta_Type#

Объект типа Python, соответствующий PyArray_DTypeMeta.

type PyArray_DTypeMeta#

В значительной степени непрозрачная структура, представляющая классы DType. Каждый экземпляр определяет метакласс для одного типа данных NumPy. Типы данных могут быть как непараметрическими, так и параметрическими. Для непараметрических типов класс DType имеет одно-к-одному соответствие с экземпляром дескриптора, созданным из класса DType. Параметрические типы могут соответствовать многим различным экземплярам dtype в зависимости от выбранных параметров. Этот тип доступен в общедоступном заголовке numpy/dtype_api.h. В настоящее время использование этой структуры не поддерживается в ограниченном API CPython, поэтому, если Py_LIMITED_API установлен, этот тип представляет собой typedef для PyTypeObject.

typedef struct {
     PyHeapTypeObject super;
     PyArray_Descr *singleton;
     int type_num;
     PyTypeObject *scalar_type;
     npy_uint64 flags;
     void *dt_slots;
     void *reserved[3];

Базовый класс, обеспечивающий взаимодействие с API объектов Python. Задайте поля этой структуры, указав функции, реализующие API PyTypeObject (например, tp_new).

PyArray_Descr *singleton#

Экземпляр дескриптора, который можно использовать как единственный общий дескриптор данного типа. Это полезно для непараметрических типов, представляющих простые данные (POD), когда для всех данных типа достаточно одного логического экземпляра дескриптора. Может быть NULL, если единый экземпляр не подходит.

int type_num#

Для прежних типов данных соответствует номеру типа. У типов, определённых вне NumPy, а возможно, и у будущих встроенных типов, type_num равен -1, поэтому это поле не следует использовать для различения типов данных.

Тип скалярных экземпляров для данного типа данных.

Флаги указывают NumPy на дополнительное поведение этого типа данных. Список допустимых значений см. в разделе Флаги.

Либо NULL, либо тип скаляра Python, связанного с DType. При скалярной индексации массива возвращается элемент этого типа.

int flags#

Статические флаги класса DType, указывающие, является ли он параметрическим, абстрактным или представляет числовые данные. Последний флаг необязателен, но полезен для указания зависимому коду, представляет ли DType числа — целые, с плавающей точкой или другой числовой тип — либо что-то иное, например строку, единицу измерения или дату.

Открытые классы DType (объекты PyArray_DTypeMeta)#

Для использования в механизмах продвижения типов NumPy предоставляет ряд Dtype с именами по шаблону PyArray_<Name>DType, соответствующих типам из np.dtypes.

Кроме того, три DType — PyArray_PyLongDType, PyArray_PyFloatDType и PyArray_PyComplexDType — соответствуют скалярным значениям Python. Их можно использовать не везде, но они поддерживают, например, операцию определения общего dtype; может потребоваться реализовать повышение типов с их участием.

Кроме того, определены следующие абстрактные DType, охватывающие как встроенные типы NumPy, так и типы Python. Пользователи в принципе могут создавать их подклассы, но это не наследует функциональность, специфичную для DType: * PyArray_IntAbstractDType * PyArray_FloatAbstractDType * PyArray_ComplexAbstractDType

Предупреждение

Начиная с NumPy 2.0 единственное допустимое применение этих DType — удобная регистрация функции повышения типов, например для сопоставления «любых целых чисел», а также проверка подклассов. Поэтому они недоступны из Python.

PyUFunc_Type и PyUFuncObject#

PyTypeObject PyUFunc_Type#

Объект универсальной функции реализуется типом PyUFunc_Type. Это простой тип с базовой поддержкой получения атрибутов, вывода и вызова, позволяющей объектам вести себя как функции. Основная идея ufunc — хранить ссылки на быстрые одномерные векторные циклы для каждого типа данных, поддерживающего операцию. У всех циклов одинаковая сигнатура; они составляют основу создания новой ufunc. Общий код обхода вызывает их нужным образом для реализации N-мерной функции. Также для массивов типов floating и complexfloating определены общие одномерные циклы, позволяющие создать ufunc из одной скалярной функции, например atanh.

type PyUFuncObject#

Основу ufunc составляет PyUFuncObject, содержащий все сведения для вызова циклов C, выполняющих вычисления. Здесь структура описана для полноты, однако её следует считать внутренней частью NumPy и работать с ней через функции PyUFunc_*. Её размер может меняться между версиями NumPy. Для совместимости:

  • Никогда не объявляйте экземпляр самой структуры; используйте указатель

  • Никогда не выполняйте арифметику указателя

  • Никогда не используйте sizeof(PyUFuncObject)

Он имеет следующую структуру:

typedef struct {
    PyObject_HEAD
    int nin;
    int nout;
    int nargs;
    int identity;
    PyUFuncGenericFunction *functions;
    void **data;
    int ntypes;
    int _ufunc_flags;
    const char *name;
    char *types;
    const char *doc;
    void *ptr;
    PyObject *obj;
    PyObject *userloops;
    int core_enabled;
    int core_num_dim_ix;
    int *core_num_dims;
    int *core_dim_ixs;
    int *core_offsets;
    char *core_signature;
    PyUFunc_TypeResolutionFunc *type_resolver;
    void *reserved2;
    void *reserved3;
    npy_uint32 *op_flags;
    npy_uint32 *iter_flags;
    /* new in API version 0x0000000D */
    npy_intp *core_dim_sizes;
    npy_uint32 *core_dim_flags;
    PyObject *identity_value;
    /* Further private slots (size depends on the NumPy version) */
} PyUFuncObject;
Комментарии к примеру на русском
  • Добавлено в версии API 0x0000000D
  • Другие закрытые слоты; размер зависит от версии NumPy
int nin#

Количество входных аргументов.

int nout#

Количество выходных аргументов.

int nargs#

Общее количество аргументов ( nin + nout ). Оно должно быть меньше NPY_MAXARGS.

int identity#

Одно из значений PyUFunc_One, PyUFunc_Zero, PyUFunc_MinusOne, PyUFunc_None, PyUFunc_ReorderableNone или PyUFunc_IdentityValue, задающее нейтральный элемент операции. Используется только при вызовах типа reduce для пустого массива.

void functions(char **args, npy_intp *dims, npy_intp *steps, void *extradata)#

Массив указателей на функции — по одному для каждого типа данных, поддерживаемого универсальной функцией. Каждая такая функция представляет собой векторный цикл, вызывающий базовую функцию dims[0] раз. Первый аргумент, args, — массив из nargs указателей на память, удовлетворяющую требованиям к выравниванию и доступу. Сначала идут указатели на данные входных аргументов, затем — выходных. Соответствующий элемент массива steps задаёт, на сколько байтов нужно сместиться для перехода к следующему элементу последовательности. Последний аргумент передаёт циклу дополнительные сведения. Обычно это позволяет использовать один общий векторный цикл для нескольких функций. В таком случае конкретная скалярная функция передаётся как extradata. Размер массива указателей на функции равен ntypes.

void **data#

Дополнительные данные для одномерных векторных циклов либо NULL, если они не нужны. Этот массив C должен иметь ту же длину (то есть ntypes), что и массив functions. Если extra_data не требуется, используется NULL. Несколько функций C API для универсальных функций — это одномерные векторные циклы, получающие через эти дополнительные данные указатель на фактически вызываемую функцию.

int ntypes#

Число поддерживаемых типов данных для ufunc. Это число определяет, сколько различных 1-d циклов (встроенных типов данных) доступно.

char *name#

Строковое имя универсальной функции. Используется для динамического формирования атрибута __doc__ универсальных функций.

char *types#

Массив из \(nargs \times ntypes\) восьмибитных номеров типов type_numbers, содержащий сигнатуру типов функции для каждого поддерживаемого встроенного типа данных. Для каждой из ntypes функций соответствующий набор номеров типов задаёт интерпретацию аргумента args в одномерном векторном цикле. Номера типов могут различаться: поддерживаются универсальные функции со смешанными типами.

char *doc#

Документация универсальной функции. Она не должна содержать сигнатуру функции: та создаётся динамически при получении __doc__.

void *ptr#

Любая динамически выделенная память. Сейчас используется для динамических ufunc, созданных из функции Python: в этой памяти хранятся данные для членов types, data и name.

PyObject *obj#

Для универсальных функций, динамически созданных из функций Python, это поле хранит ссылку на исходную функцию Python.

PyObject *userloops#

Словарь пользовательских одномерных векторных циклов для пользовательских типов, хранящихся как указатели CObject. Пользователь может зарегистрировать цикл для любого пользовательского типа. Цикл извлекается по номеру типа. Номера пользовательских типов всегда больше NPY_USERDEF.

int core_enabled#

0 для скалярных универсальных функций; 1 для обобщённых универсальных функций

int core_num_dim_ix#

Число различных имён основных измерений в сигнатуре

int *core_num_dims#

Число основных измерений каждого аргумента

int *core_dim_ixs#

Индексы измерений в плоском виде; индексы аргумента k хранятся в core_dim_ixs[core_offsets[k] : core_offsets[k] + core_numdims[k]]

int *core_offsets#

Положение первого основного измерения каждого аргумента в core_dim_ixs; эквивалентно cumsum(core_num_dims)

char *core_signature#

Строка основной сигнатуры

PyUFunc_TypeResolutionFunc *type_resolver#

Функция, которая разрешает типы и заполняет массив типами для входов и выходов

type PyUFunc_TypeResolutionFunc#

Тип указателя на функцию для type_resolver

npy_uint32 op_flags#

Переопределяет флаги по умолчанию для каждого операнда ufunc.

npy_uint32 iter_flags#

Переопределяет стандартные флаги nditer для универсальной функции.

Добавлено в API версии 0x0000000D

npy_intp *core_dim_sizes#

Для каждого отдельного основного измерения — возможный фиксированный размер, если UFUNC_CORE_DIM_SIZE_INFERRED равен 0

npy_uint32 *core_dim_flags#

Для каждого отдельного основного измерения существует набор флагов ( UFUNC_CORE_DIM_CAN_IGNORE и UFUNC_CORE_DIM_SIZE_INFERRED ).

PyObject *identity_value#

Нейтральный элемент свёртки, когда PyUFuncObject.identity равен PyUFunc_IdentityValue.

UFUNC_CORE_DIM_CAN_IGNORE#

если имя измерения заканчивается на ?

UFUNC_CORE_DIM_SIZE_INFERRED#

если размер измерения определяется по операндам, а не по фиксированной сигнатуре

PyArrayIter_Type и PyArrayIterObject #

PyTypeObject PyArrayIter_Type#

Этот объект итератора упрощает обход N-мерного массива. Он возвращается атрибутом flat объекта ndarray и широко используется внутри реализации для обхода N-мерных массивов. Благодаря интерфейсу tp_as_mapping объект итератора поддерживает одномерную индексацию; несколько методов реализованы через таблицу tp_methods. Объект реализует метод next и может использоваться везде, где в Python допустим итератор.

type PyArrayIterObject#

Объекту PyArrayIter_Type соответствует структура C PyArrayIterObject. PyArrayIterObject хранит указатель на элемент N-мерного массива и связанную информацию для быстрого обхода. Указатель можно перемещать тремя основными способами: 1) на следующую позицию в порядке C; 2) к произвольной N-мерной координате; 3) к произвольному одномерному индексу массива. В этих вычислениях используются поля структуры PyArrayIterObject. Объекты итераторов хранят собственную информацию о размерах и шагах массива. Её можно менять для трансляции массивов или обхода лишь определённых измерений.

typedef struct {
    PyObject_HEAD
    int   nd_m1;
    npy_intp  index;
    npy_intp  size;
    npy_intp  coordinates[NPY_MAXDIMS_LEGACY_ITERS];
    npy_intp  dims_m1[NPY_MAXDIMS_LEGACY_ITERS];
    npy_intp  strides[NPY_MAXDIMS_LEGACY_ITERS];
    npy_intp  backstrides[NPY_MAXDIMS_LEGACY_ITERS];
    npy_intp  factors[NPY_MAXDIMS_LEGACY_ITERS];
    PyArrayObject *ao;
    char  *dataptr;
    npy_bool  contiguous;
} PyArrayIterObject;
int nd_m1#

\(N-1\), где \(N\) — количество измерений в базовом массиве.

npy_intp index#

Текущий одномерный индекс в массиве.

npy_intp size#

Общий размер базового массива.

npy_intp *coordinates#

\(N\)-мерный индекс элемента массива.

npy_intp *dims_m1#

Размер массива минус 1 в каждом измерении.

npy_intp *strides#

Шаги массива: число байтов для перехода к следующему элементу вдоль каждого измерения.

npy_intp *backstrides#

Число байтов для перехода от конца измерения обратно к его началу. Обратите внимание: backstrides[k] == strides[k] * dims_m1[k], но это значение хранится здесь для оптимизации.

npy_intp *factors#

Этот массив используется для вычисления многомерного индекса из одномерного. Он содержит необходимые произведения размеров измерений.

PyArrayObject *ao#

Указатель на исходный ndarray, для обхода которого создан этот итератор.

char *dataptr#

Этот член указывает на элемент в ndarray, указанный индексом.

npy_bool contiguous#

Этот флаг имеет значение true, если базовый массив — NPY_ARRAY_C_CONTIGUOUS. Он используется для упрощения вычислений, когда это возможно.

Использование итератора массивов на уровне C подробнее описано в следующих разделах. Обычно не нужно обращаться к внутренней структуре объекта-итератора: достаточно макросов PyArray_ITER_NEXT (it), PyArray_ITER_GOTO (it, dest) и PyArray_ITER_GOTO1D (it, index). Во всех этих макросах аргумент it должен иметь тип PyArrayIterObject*.

PyArrayMultiIter_Type и PyArrayMultiIterObject#

PyTypeObject PyArrayMultiIter_Type#

Этот тип предоставляет итератор, реализующий трансляцию массивов. Он позволяет согласовать \(N\) массивов так, чтобы цикл обходил результат последовательно в порядке C. Соответствующая структура C — PyArrayMultiIterObject; её поля должны располагаться в начале любого объекта obj, передаваемого функции PyArray_Broadcast(obj). Для трансляции итераторы настраиваются так, чтобы каждый представлял общие форму и размер результата, а его шаги обеспечивали выбор нужного элемента исходного массива на каждой итерации.

type PyArrayMultiIterObject#
typedef struct {
    PyObject_HEAD
    int numiter;
    npy_intp size;
    npy_intp index;
    int nd;
    npy_intp dimensions[NPY_MAXDIMS_LEGACY_ITERS];
    PyArrayIterObject *iters[];
} PyArrayMultiIterObject;
int numiter#

Число массивов, формы которых нужно согласовать с помощью трансляции.

npy_intp size#

Общее число элементов после трансляции массивов.

npy_intp index#

Текущий одномерный индекс в результате трансляции массивов.

int nd#

Количество измерений в транслируемом результате.

npy_intp *dimensions#

Форма результата трансляции массивов (используются только первые nd элементов).

PyArrayIterObject **iters#

Массив объектов итераторов для массивов, формы которых нужно согласовать трансляцией. При возврате итераторы уже настроены для трансляции.

ScalarArrayTypes #

Существует тип Python для каждого из различных встроенных типов данных, которые могут присутствовать в массиве. Большинство из них представляют собой простые оболочки соответствующего типа данных в C. C-имена для этих типов — Py{TYPE}ArrType_Type, где {TYPE} может быть

Bool, Byte, Short, Int, Long, LongLong, UByte, UShort, UInt, ULong, ULongLong, Half, Float, Double, LongDouble, CFloat, CDouble, CLongDouble, String, Unicode, Void, Datetime, Timedelta и Object.

Эти имена типов входят в C API, поэтому объекты этих типов можно создавать в коде расширений на C. Также существуют PyIntpArrType_Type и PyUIntpArrType_Type — псевдонимы целочисленных типов, способных вместить указатель на данной платформе. Структура этих скалярных объектов не предоставляется коду C. Функция PyArray_ScalarAsCtype(..) извлекает значение типа C из скаляра NumPy, а функция PyArray_Scalar(…) создаёт скаляр NumPy из значения C.

Другие C-структуры #

При разработке NumPy оказались полезны несколько новых структур C. Они используются хотя бы в одном вызове C API и поэтому описаны здесь. Главная цель их введения — упростить преобразование объектов Python в удобные объекты C с помощью ParseTuple из C API Python.

PyArray_Dims#

type PyArray_Dims#

Эта структура очень полезна при интерпретации сведений о форме и/или шагах. Её определение:

typedef struct {
    npy_intp *ptr;
    int len;
} PyArray_Dims;

Членами этой структуры являются

npy_intp *ptr#

Указатель на список целых чисел типа npy_intp, обычно задающих форму массива или его шаги по памяти.

int len#

Длина списка целых чисел. Предполагается, что доступ от ptr[0] до ptr[len-1] безопасен.

PyArray_Chunk#

type PyArray_Chunk#

Эта структура эквивалентна структуре буферного объекта Python до члена ptr включительно. На 32-разрядных платформах (то есть при NPY_SIZEOF_INT == NPY_SIZEOF_INTP) член len также соответствует аналогичному члену буферного объекта. Она полезна для представления произвольного односегментного участка памяти.

typedef struct {
    PyObject_HEAD
    PyObject *base;
    void *ptr;
    npy_intp len;
    int flags;
} PyArray_Chunk;

Члены

PyObject *base#

Объект Python, которому принадлежит эта область памяти. Нужен для правильного учёта памяти.

void *ptr#

Указатель на начало односегментного фрагмента памяти.

npy_intp len#

Длина сегмента в байтах.

int flags#

Флаги данных, используемые для интерпретации памяти (например, NPY_ARRAY_WRITEABLE).

Протокол интерфейса массива

type PyArrayInterface#

Структура PyArrayInterface определена для использования быстрого протокола интерфейса массивов в NumPy и других модулях расширения. Метод __array_struct__ объекта, поддерживающего этот протокол, должен возвращать PyCapsule с указателем на структуру PyArrayInterface, содержащую сведения о массиве. После создания нового массива к полученному атрибуту следует применить DECREF, что освободит структуру PyArrayInterface. Не забудьте применить INCREF к объекту, у которого был получен атрибут __array_struct__, и указать этот же объект в члене base нового PyArrayObject. Так память массива будет управляться правильно.

typedef struct {
    int two;
    int nd;
    char typekind;
    int itemsize;
    int flags;
    npy_intp *shape;
    npy_intp *strides;
    void *data;
    PyObject *descr;
} PyArrayInterface;
int two#

целое число 2 для проверки корректности.

int nd#

количество измерений в массиве.

char typekind#

Символ, указывающий тип массива согласно соглашению typestring: «t» — битовое поле, «b» — логический тип, «i» — целое со знаком, «u» — целое без знака, «f» — число с плавающей точкой, «c» — комплексное число с плавающей точкой, «O» — объект, «S» — байтовая строка, «U» — Unicode, «V» — void.

int itemsize#

Количество байтов, требуемое для каждого элемента в массиве.

int flags#

Биты NPY_ARRAY_C_CONTIGUOUS (1), NPY_ARRAY_F_CONTIGUOUS (2), NPY_ARRAY_ALIGNED (0x100), NPY_ARRAY_NOTSWAPPED (0x200) и NPY_ARRAY_WRITEABLE (0x400), указывающие свойства данных. Флаги NPY_ARRAY_ALIGNED, NPY_ARRAY_C_CONTIGUOUS и NPY_ARRAY_F_CONTIGUOUS можно определить по другим параметрам. Флаг NPY_ARR_HAS_DESCR (0x800) также можно установить, чтобы сообщить потребителям интерфейса массивов версии 3 о наличии поля descr в структуре; потребители версии 2 игнорируют его.

npy_intp *shape#

Массив, содержащий размер массива в каждом измерении.

npy_intp *strides#

Массив, содержащий количество байтов для перехода к следующему элементу в каждом измерении.

void *data#

Указатель на первый элемент массива.

PyObject *descr#

Объект Python, подробнее описывающий тип данных (аналог ключа descr в __array_interface__). Может быть NULL, если typekind и itemsize дают достаточно информации. Поле игнорируется, если флаг NPY_ARR_HAS_DESCR не установлен в flags.

Внутренние структуры #

Внутренний код использует дополнительные объекты Python, главным образом для управления памятью. Эти типы недоступны напрямую из Python и не входят в C API. Они описаны здесь только для полноты и облегчения понимания кода.

type PyUFunc_Loop1d#

Простой связный список структур C с информацией для определения одномерного цикла ufunc для каждой заданной сигнатуры пользовательского типа данных.

PyTypeObject PyArrayMapIter_Type#

Этот тип Python обслуживает расширенное индексирование. Это простая обёртка над структурой C с переменными, необходимыми для расширенного индексирования массивов.

type PyArrayMapIterObject#

Структура C, связанная с PyArrayMapIter_Type. Она полезна для понимания кода сопоставления индексов при расширенной индексации и определена в заголовочном файле multiarray/mapping.h. Этот тип недоступен из Python и мог бы быть заменён обычной структурой C. Как тип Python он использует управление памятью с подсчётом ссылок.

C API NumPy и комплексные типы C#

C API NumPy предоставляет объявления комплексных типов npy_cdouble и npy_cfloat на основе стандартных типов C из complex.h. К сожалению, complex.h содержит #define I ... (конкретное определение зависит от компилятора). Поэтому при #include <numpy/arrayobject.h> в коде зависимого проекта может оказаться определённым I, и объявление вроде double I; вызовет непонятную ошибку компилятора, например:

Этой ошибки можно избежать, добавив:

#undef I

к вашему коду.

Изменено в версии 2.0: Заголовок complex.h начал подключаться в NumPy 2, поэтому код с другим определением I мог не требовать #undef I в старых версиях. NumPy 2.0.1 некоторое время включал #under I
