numpy.lib.format#

Бинарная сериализация

Формат NPY #

Простой формат для сохранения массивов NumPy на диск со всей информацией о них.

Формат .npy — стандартный двоичный формат NumPy для сохранения на диске одного произвольного массива NumPy. Он хранит всю информацию о форме и типе данных, необходимую для правильного восстановления массива даже на компьютере с другой архитектурой. Формат задуман максимально простым в рамках своих ограниченных задач.

.npz — стандартный формат сохранения нескольких массивов NumPy на диск. Файл .npz — архив ZIP с файлами .npy, по одному для каждого массива.

Возможности#

  • Может представлять все массивы NumPy, включая вложенные массивы записей и массивы объектов.

  • Представляет данные в их исходном двоичном виде.

  • Напрямую поддерживает массивы, непрерывно расположенные в памяти в порядке Fortran.

  • Сохраняет все сведения для восстановления массива, включая форму и dtype, на машине другой архитектуры. Поддерживаются массивы с порядком байтов little-endian и big-endian. Файл с числами little-endian даёт массив с тем же порядком байтов на любой машине. Типы описываются их фактическими размерами: например, массив C long int, записанный на машине с 64-битным long int, будет прочитан как массив 64-битных целых чисел и на машине с 32-битным long int.

  • Допускает простую обратную разработку. Наборы данных часто существуют дольше создавших их программ. Квалифицированный разработчик должен суметь написать на предпочитаемом языке программу для чтения большинства полученных файлов .npy, располагая лишь минимальной документацией.

  • Позволяет отображать данные в памяти. См. open_memmap.

  • Может быть прочитан из файлового объекта потока вместо реального файла.

  • Сохраняет массивы объектов, то есть массивы произвольных объектов Python. Файлы с такими массивами нельзя отображать в память через mmap, но можно читать с диска и записывать на диск.

Ограничения #

  • Произвольные подклассы numpy.ndarray сохраняются не полностью. Их можно передать для записи, но сохранятся только данные массива. При чтении файла будет создан обычный объект numpy.ndarray.

Предупреждение

Из-за ограничений интерпретации структурированных dtype пустые имена полей заменяются на «f0», «f1» и т. д. Поэтому сохранение и последующая загрузка таких массивов не полностью воспроизводят исходную структуру. Данные остаются неизменными; отличаются только имена полей. Мы работаем над исправлением, которое не потребует изменения формата файла. Массивы с такими структурами по-прежнему можно сохранять и загружать, а правильный dtype можно восстановить методом loadedarray.view(correct_dtype).

Расширения файлов#

Мы рекомендуем использовать расширения .npy и .npz для файлов, сохраненных в этом формате. Это ни в коем случае не является требованием; приложения могут захотеть использовать эти форматы файлов, но использовать расширение, специфичное для приложения. Однако при отсутствии очевидной альтернативы мы предлагаем использовать .npy и .npz.

Нумерация версий#

Нумерация версий этих форматов не зависит от нумерации версий NumPy. Если формат будет обновлен, код в numpy.io по-прежнему сможет читать и записывать файлы версии 1.0.

Версия формата 1.0#

Первые 6 байт — сигнатура формата, в точности \x93NUMPY.

Следующий байт — беззнаковое число, задающее старший номер версии формата файла, например \x01.

Следующий байт — беззнаковое число, задающее младший номер версии формата файла, например \x00. Примечание: версия формата файла не связана с версией пакета NumPy.

Следующие 2 байта образуют беззнаковое целое типа short int с порядком байтов от младшего к старшему: это длина данных заголовка HEADER_LEN.

Следующие HEADER_LEN байт содержат заголовок, описывающий формат массива. Это строка ASCII с литералом словаря Python. Она заканчивается переводом строки (\n) и дополняется пробелами (\x20), чтобы суммарная длина len(magic string) + 2 + len(length) + HEADER_LEN была кратна 64 для выравнивания.

Словарь содержит три ключа:

«descr»dtype.descr

Объект, который можно передать в качестве аргумента конструктору numpy.dtype для создания dtype массива.

«fortran_order» bool

Расположены ли данные массива непрерывно в порядке Fortran. Это распространённый случай массивов, не непрерывных в порядке C, поэтому для эффективности разрешена их прямая запись на диск.

«shape»кортеж int

Форма массива.

Для воспроизводимости и читаемости ключи словаря сортируются по алфавиту. Это сделано только для удобства. Реализации записи РЕКОМЕНДУЕТСЯ соблюдать этот порядок, если возможно. Реализация чтения НЕ ДОЛЖНА от него зависеть.

После заголовка следуют данные массива. Если dtype содержит объекты Python (то есть dtype.hasobject is True), данные представляют собой массив, сериализованный с помощью pickle. Иначе это непрерывная последовательность байтов массива в порядке C или Fortran, в зависимости от fortran_order. Читающая сторона может определить число байтов, умножив число элементов, заданное формой массива (при этом shape=() означает один элемент), на dtype.itemsize.

Версия формата 2.0#

В формате версии 1.0 общий размер заголовка массива ограничен 65535 байтами. Заголовки структурированных массивов с большим числом столбцов могут превышать этот предел. Формат версии 2.0 увеличивает предельный размер заголовка до 4 ГиБ. numpy.save автоматически сохраняет данные в формате 2.0, если это необходимо; в остальных случаях всегда используется более совместимый формат 1.0.

Поэтому описание четвёртого элемента заголовка стало таким: «Следующие 4 байта образуют беззнаковое целое в порядке от младшего байта к старшему (little-endian): длину данных заголовка HEADER_LEN».

Формат версии 3.0 #

Эта версия заменяет строку ASCII, на практике бывшую latin1, строкой в кодировке UTF-8. Поэтому поддерживаются структурированные типы с любыми именами полей Unicode.

Примечания#

Формат .npy, причины его создания и сравнение с альтернативами описаны в NEP «npy-format». Однако со временем детали изменились, и настоящий документ содержит более актуальное описание.

Функции

descr_to_dtype(descr)

Возвращает dtype на основе данного описания.

drop_metadata(dtype, /)

Возвращает dtype без изменений, если он не содержит метаданных, либо его копию, если метаданные есть у него самого или у любого вложенного структурированного dtype.

dtype_to_descr(dtype)

Получает сериализуемый дескриптор из dtype.

header_data_from_array_1_0(array)

Возвращает словарь метаданных заголовка для numpy.ndarray.

isfileobj(f)

magic(major, minor)

Верните магическую строку для данной версии формата файла.

open_memmap(filename[, mode, dtype, shape, ...])

Открывает файл .npy как массив, отображённый в память.

read_array(fp[, allow_pickle, ...])

Читает массив из файла NPY.

read_array_header_1_0(fp[, max_header_size])

Читает заголовок массива из файлового объекта в соответствии с версией 1.0 формата файла.

read_array_header_2_0(fp[, max_header_size])

Читает заголовок массива из файлоподобного объекта в формате версии 2.0.

read_magic(fp)

Считывает сигнатуру файла, чтобы определить версию его формата.

write_array(fp, array[, version, ...])

Записывает массив в файл NPY вместе с заголовком.

write_array_header_1_0(fp, d)

Записывает заголовок массива в формате 1.0.

write_array_header_2_0(fp, d)

Запишите заголовок для массива, используя формат 2.0.
