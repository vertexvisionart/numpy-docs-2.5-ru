Параметры сборки для процессора#

Обзор #

NumPy предоставляет параметры настройки производительности с учётом возможностей процессора. Они позволяют выбрать поддерживаемые возможности CPU, соблюдая баланс между производительностью, совместимостью и размером двоичных файлов. Этот документ объясняет их эффективное использование на разных процессорных архитектурах.

Основные параметры конфигурации #

NumPy использует несколько вариантов сборки для управления оптимизацией процессора:

  • cpu-baseline: минимальный набор возможностей процессора, необходимых для запуска скомпилированного NumPy.

    • По умолчанию: min (обеспечивает совместимость на широком спектре платформ)

    • Если целевой CPU не поддерживает все указанные базовые возможности, NumPy не загрузится и выдаст ошибку времени выполнения Python

  • cpu-baseline-detect управляет определением базового набора возможностей CPU по флагам компилятора. Значение по умолчанию auto включает определение при использовании -march= или аналогичного флага. Значения enabled и disabled безусловно включают и отключают его соответственно.

  • cpu-dispatch: дополнительные функции процессора, для которых будут генерироваться оптимизированные пути кода.

    • По умолчанию: max (включает все доступные оптимизации)

    • Во время выполнения NumPy автоматически выбирает самую быструю из доступных реализаций с учётом возможностей процессора

  • disable-optimization: полностью отключает все оптимизации процессора.

    • По умолчанию: false (оптимизация включена)

    • При значении true отключает весь код, оптимизированный для процессора, включая диспетчеризацию, SIMD и развёртывание циклов

    • Полезно для отладки, тестирования или в средах, где оптимизация вызывает проблемы.

Эти параметры указываются во время сборки через аргументы meson-python:

pip install . -Csetup-args=-Dcpu-baseline="min" -Csetup-args=-Dcpu-dispatch="max"
# or through spin
spin build -- -Dcpu-baseline="min" -Dcpu-dispatch="max"
Комментарии к примеру на русском
  • Или через spin

Для cpu-baseline и cpu-dispatch можно задать конкретные группы и возможности процессора либо специальные параметры, выполняющие определённые действия. В следующих разделах эти параметры описаны подробно.

Типичные сценарии использования#

Сборка только для локального использования#

При сборке только для своего компьютера, без последующего распространения:

python -m build --wheel -Csetup-args=-Dcpu-baseline="native" -Csetup-args=-Dcpu-dispatch="none"

Автоматически определяет и использует все возможности CPU, доступные на компьютере.

Примечание

Если платформа не поддерживает native, возникает фатальная ошибка.

Исключение отдельных возможностей процессора#

Некоторые возможности процессора можно исключить из набора, используемого для диспетчеризации:

# For x86-64: exclude all AVX-512 features
python -m build --wheel -Csetup-args=-Dcpu-dispatch="max -X86_V4"

# For ARM64: exclude SVE
python -m build --wheel -Csetup-args=-Dcpu-dispatch="max -SVE"
Комментарии к примеру на русском
  • Для x86-64: исключить все возможности AVX-512
  • Для ARM64: исключить SVE

Примечание

Исключение возможности процессора также исключает все последующие возможности, подразумеваемые ею. Например, исключение X86_V4 исключает и AVX512_ICL с AVX512_SPR.

Ориентация на старые процессоры #

На x86-64 базовый набор инструкций по умолчанию задан как min, что соответствует X86_V2. Это не подходит для старых процессоров (выпущенных до 2009 года) и старых виртуальных машин. В таком случае задайте базовый набор как none:

python -m build --wheel -Csetup-args=-Dcpu-baseline="none"

Получится сборка, совместимая со всеми процессорами x86, но без ручных оптимизаций и ветвей SIMD в базовом наборе. Для оптимизации она будет использовать только ветви кода, выбираемые диспетчеризацией.

Ориентация на новые процессоры #

Повышение базового уровня улучшает производительность по двум основным причинам:

  1. Динамически выбираемые вычислительные ядра охватывают не все ветви кода

  2. Более высокий базовый уровень уменьшает размер двоичного файла: компилятор не создаёт отдельные варианты кода для исключённых из диспетчеризации возможностей процессора.

Для процессоров с 2015 года и более новых, установка базового уровня на X86_V3 может быть подходящей:

python -m build --wheel -Csetup-args=-Dcpu-baseline="min+X86_V3"

Специальные опции #

Помимо названий конкретных возможностей можно использовать специальные значения:

NONE#

Не включает никаких возможностей (эквивалентно пустой строке).

NATIVE#

Включает все возможности, поддерживаемые процессором текущего компьютера.

DETECT#

Определяет возможности, включённые компилятором. По умолчанию добавляется к cpu-baseline, если -march, -mcpu, -xhost или /QxHost заданы в переменной окружения CFLAGS, кроме случая, когда cpu-baseline-detect равно disabled.

MIN#

Включает минимальный набор возможностей процессора для каждой архитектуры:

Для Arch

IBM/POWER (порядок байтов от младшего к старшему)

MAX#

Включает все возможности, поддерживаемые компилятором и платформой.

Операторы (-/+)#

Удаление или добавление конкретных возможностей полезно с MAX, MIN и NATIVE:

  • Добавление возможности (+) включает все подразумеваемые ею возможности

  • Удаление возможности (-) исключает все последующие возможности, подразумевающие её наличие

Примеры:

python -m build --wheel -Csetup-args=-Dcpu-dispatch="max-X86_V4"
python -m build --wheel -Csetup-args=-Dcpu-baseline="min+X86_V4"

Использование и поведение#

Независимость от регистра#

Регистр символов в названиях возможностей и параметров CPU не учитывается:

python -m build --wheel -Csetup-args=-Dcpu-dispatch="X86_v4"

Сочетание возможностей разных архитектур#

Можно сочетать возможности разных архитектур:

python -m build --wheel -Csetup-args=-Dcpu-baseline="X86_V4 VSX4 SVE"

Независимость от порядка#

Порядок заданных признаков не имеет значения:

python -m build --wheel -Csetup-args=-Dcpu-dispatch="SVE X86_V4 x86_v3"

Разделители#

Можно использовать пробелы или запятые в качестве разделителей:

# All of these are equivalent
python -m build --wheel -Csetup-args=-Dcpu-dispatch="X86_V2 X86_V4"
python -m build --wheel -Csetup-args=-Dcpu-dispatch=X86_V2,X86_V4
Комментарии к примеру на русском
  • Все эти варианты эквивалентны

Сочетание возможностей#

Возможности, заданные в параметрах, автоматически объединяются со всеми возможностями, которые из них следуют:

python -m build --wheel -Csetup-args=-Dcpu-baseline=X86_V4

Эквивалент:

python -m build --wheel -Csetup-args=-Dcpu-baseline="X86_V2 X86_V3 X86_V4"

Пересечение с базовым набором возможностей#

Возможности из cpu-baseline исключаются из cpu-dispatch вместе с подразумеваемыми ими возможностями. При этом более новые возможности, которые подразумевают исключённые, не исключаются.

Например, указание cpu-baseline="X86_V4" исключает X86_V4 и подразумеваемые им возможности X86_V2 и X86_V3 из набора cpu-dispatch.

Определение возможностей на этапе компиляции#

Указание возможностей процессора в cpu-dispatch или cpu-baseline не включает их безусловно. Они проверяются во время компиляции, и из запрошенных возможностей включается максимально доступный набор, поддерживаемый инструментами сборки и платформой.

Возможности проверяются компиляцией исходных файлов, содержащих типичные встроенные функции компилятора (intrinsics) для указанных возможностей. Если возможность поддерживают и компилятор, и ассемблер, она включается.

Например, если задать cpu-dispatch="AVX512_ICL", но компилятор не поддерживает эту возможность, она будет исключена из сборки. Однако подразумеваемые ею возможности всё равно будут включены, если они поддерживаются.

Различия между платформами#

Из-за некоторых особых условий для определённых компиляторов или архитектур приходится связывать отдельные возможности между собой, так что собрать их по отдельности невозможно.

Эти условия можно разделить на две части:

Архитектурная совместимость

Необходимость согласовать возможности процессора, поддержка которых гарантируется последующими поколениями одной архитектуры. Примеры:

  • На ppc64le VSX(ISA 2.06) и VSX2(ISA 2.07) взаимно подразумевают друг друга, поскольку первое поколение с поддержкой режима little-endian — Power-8(ISA 2.07).

  • На AArch64 возможности NEON NEON_FP16 NEON_VFPV4 ASIMD подразумевают друг друга, поскольку все входят в базовый набор оборудования.

Например:

# On ARMv8/A64, specify NEON is going to enable Advanced SIMD
# and all predecessor extensions
python -m build --wheel -Csetup-args=-Dcpu-baseline=neon
# which is equivalent to
python -m build --wheel -Csetup-args=-Dcpu-baseline="neon neon_fp16 neon_vfpv4 asimd"
Комментарии к примеру на русском
  • На ARMv8/A64 указание NEON включает Advanced SIMD
  • и все предшествующие расширения
  • что эквивалентно следующему

Примечание

Внимательно изучите раздел Поддерживаемые возможности CPU по архитектурам, чтобы определить, какие возможности подразумевают другие.

Отчёт о сборке#

В большинстве случаев параметры сборки для процессора не вызывают фатальных ошибок, останавливающих сборку. Большинство ошибок в журнале сборки служат серьёзными предупреждениями о том, что компилятор не поддерживает некоторые ожидаемые возможности процессора.

Поэтому мы настоятельно рекомендуем проверить журнал окончательного отчета, чтобы знать, какие функции процессора включены, а какие нет.

Диспетчеризация во время выполнения#

При импорте NumPy проверяет, какие возможности CPU из набора, поддерживающего диспетчеризацию, доступны. Проверку можно ограничить, задав в переменной окружения NPY_DISABLE_CPU_FEATURES список отключаемых возможностей, разделённых запятыми, табуляциями или пробелами.

Например, на x86_64 это отключит X86_V4 :

NPY_DISABLE_CPU_FEATURES="X86_V4"

При ошибке разбора или если возможность не включена параметром сборки cpu-dispatch возникает ошибка. Если сборка поддерживает возможность, но текущий процессор её не предоставляет, вместо ошибки выдаётся предупреждение.

Отслеживание функций с диспетчеризацией#

Узнать, какие целевые наборы инструкций CPU включены для разных оптимизированных функций, можно с помощью функции Python numpy.lib.introspect.opt_func_info.

Эта функция предлагает два дополнительных аргумента для фильтрации результатов:

  1. func_name - для уточнения названий функций

  2. signature — для задания типов данных в сигнатурах

Например:

 >> func_info = numpy.lib.introspect.opt_func_info(func_name='add|abs', signature='float64|complex64')
 >> print(json.dumps(func_info, indent=2))

  "absolute": {
    "dd": {
      "current": "baseline(X86_V2)",
      "available": "baseline(X86_V2)"
    },
    "Ff": {
      "current": "X86_V3",
      "available": "X86_V3 baseline(X86_V2)"
    },
    "Dd": {
      "current": "X86_V3",
      "available": "X86_V3 baseline(X86_V2)"
    }
