numpy.i: файл интерфейса SWIG для NumPy #

Введение#

Simple Wrapper and Interface Generator (SWIG) — мощный инструмент генерации кода обёрток для интерфейсов к различным скриптовым языкам. SWIG умеет разбирать заголовочные файлы и создавать интерфейс целевого языка по одним прототипам функций. Но SWIG не всесилен. Например, из прототипа он не может узнать:

double rms(double* seq, int n);

что именно представляет собой seq. Это одно значение, которое нужно изменить на месте? Массив? Если массив, то какова его длина? Он предназначен только для ввода, только для вывода или для ввода и вывода? SWIG не может определить эти подробности и не пытается этого делать.

Если rms разрабатывали мы, то, вероятно, эта функция принимает массив длины n из значений double с именем seq только для чтения и возвращает среднеквадратичное значение. Однако по умолчанию SWIG создаст обёртку, которая скомпилируется, но которой почти невозможно пользоваться из скриптового языка так, как предполагалось для функции C.

В Python для работы с непрерывными (точнее, имеющими шаги) блоками однородных данных предпочтительно использовать NumPy, предоставляющий полноценный объектно-ориентированный доступ к многомерным массивам. Поэтому естественный интерфейс Python к функции rms выглядит так (включая строку документации):

def rms(seq):
    """
    rms: return the root mean square of a sequence
    rms(numpy.ndarray) -> double
    rms(list) -> double
    rms(tuple) -> double
    """

где seq — массив NumPy значений double, а его длина n извлекается из seq перед передачей в функцию C. Более того, NumPy умеет создавать массивы из произвольных последовательностей Python, поэтому seq может быть почти любой последовательностью, если каждый элемент преобразуется в double. Код обёртки сам преобразует её в массив NumPy, затем извлечёт данные и длину.

SWIG позволяет задавать такие преобразования механизмом отображений типов (typemaps). В этом документе объясняется использование numpy.i — интерфейсного файла SWIG с набором отображений типов, упрощающих описанные выше преобразования массивов. Например, предположим, что приведённый выше прототип функции rms находится в заголовочном файле rms.h. Чтобы получить описанный интерфейс Python, в интерфейсный файл SWIG нужно добавить следующее:

%{
#define SWIG_FILE_WITH_INIT
#include "rms.h"
%}

%include "numpy.i"

%init %{
import_array();
%}

%apply (double* IN_ARRAY1, int DIM1) {(double* seq, int n)};
%include "rms.h"

Сопоставления типов выбираются по списку из одного или нескольких аргументов функции: по их типам либо по типам и именам. Такие списки мы будем называть сигнатурами. Выше используется одно из многих сопоставлений, определённых в numpy.i, с сигнатурой (double* IN_ARRAY1, int DIM1). Имена аргументов подсказывают, что double* — входной одномерный массив, а int — размер этого измерения. Именно такой шаблон встречается в прототипе rms.

В реальных прототипах функций, для которых создаются обёртки, аргументы вряд ли будут называться IN_ARRAY1 и DIM1. Директива SWIG %apply применяет typemap для одномерных входных массивов типа double к реальному прототипу rms. Поэтому для эффективного использования numpy.i нужно знать доступные typemap и их действие.

Файл интерфейса SWIG с приведёнными выше директивами SWIG создаёт примерно такой код обёртки:

 1 PyObject *_wrap_rms(PyObject *args) {
 2   PyObject *resultobj = 0;
 3   double *arg1 = (double *) 0 ;
 4   int arg2 ;
 5   double result;
 6   PyArrayObject *array1 = NULL ;
 7   int is_new_object1 = 0 ;
 8   PyObject * obj0 = 0 ;
 9
10   if (!PyArg_ParseTuple(args,(char *)"O:rms",&obj0)) SWIG_fail;
11   {
12     array1 = obj_to_array_contiguous_allow_conversion(
13                  obj0, NPY_DOUBLE, &is_new_object1);
14     npy_intp size[1] = {
15       -1
16     };
17     if (!array1 || !require_dimensions(array1, 1) ||
18         !require_size(array1, size, 1)) SWIG_fail;
19     arg1 = (double*) array1->data;
20     arg2 = (int) array1->dimensions[0];
21   }
22   result = (double)rms(arg1,arg2);
23   resultobj = SWIG_From_double((double)(result));
24   {
25     if (is_new_object1 && array1) Py_DECREF(array1);
26   }
27   return resultobj;
28 fail:
29   {
30     if (is_new_object1 && array1) Py_DECREF(array1);
31   }
32   return NULL;
33 }

Правила typemap из numpy.i создают строки кода 12–20, 25 и 30. В строке 10 разбираются входные данные функции rms. Строка формата "O:rms" показывает, что ожидается единственный объект Python: это задаёт символ O перед двоеточием, а указатель сохраняется в obj0. Функции из numpy.i выполняют и проверяют возможное преобразование произвольного объекта Python в массив NumPy. Они описаны в разделе Вспомогательные функции; надеемся, их имена понятны сами по себе. В строке 12 из obj0 создаётся массив NumPy. В строке 17 проверяется, что результат не равен NULL и имеет одно измерение произвольной длины. После этого в строках 19 и 20 извлекаются буфер данных и длина для вызова базовой функции C в строке 22. Строка 25 освобождает память, если был создан новый массив, который больше не нужен.

Значительная часть кода обрабатывает ошибки. SWIG_fail — макрос для goto fail, переходящий к метке в строке 28. Неверное число аргументов обнаруживается в строке 10. Ошибка создания массива NumPy или неверное число его измерений обнаруживаются в строке 17. Наконец, даже при ошибке память корректно освобождается в строке 30.

Обратите внимание: если бы аргументы в сигнатуре функции C шли в другом порядке:

double rms(int n, double* seq);

что SWIG не сопоставит приведённую выше сигнатуру сопоставления типов со списком аргументов rms. К счастью, numpy.i содержит набор сопоставлений, где указатель на данные идёт последним:

%apply (int DIM1, double* IN_ARRAY1) {(int n, double* seq)};

В результате определения arg1 и arg2 в строках 3 и 4 сгенерированного выше кода меняются местами, как и присваивания им в строках 19 и 20.

Использование numpy.i#

Файл numpy.i сейчас расположен в подкаталоге tools/swig каталога установки numpy. Обычно его следует скопировать в каталог, где разрабатываются обёртки.

Простой модуль, использующий единственный файл интерфейса SWIG, должен содержать следующее:

%{
#define SWIG_FILE_WITH_INIT
%}
%include "numpy.i"
%init %{
import_array();
%}

В скомпилированном модуле Python функция import_array() должна вызываться только один раз. Вызов может находиться в написанном вами файле C/C++, который компонуется с модулем. Тогда ни один файл интерфейса не должен содержать #define SWIG_FILE_WITH_INIT или вызывать import_array(). Другой вариант — разместить вызов инициализации в файле обёртки, который SWIG генерирует из файла интерфейса с показанным выше блоком %init. Если при этом файлов интерфейса SWIG несколько, только один из них должен содержать #define SWIG_FILE_WITH_INIT и вызывать import_array().

Доступные карты типов #

Директивы отображения типов (typemap), предоставляемые numpy.i для массивов разных типов данных, например double и int, и для размеров, заданных разными типами, например int или long, идентичны, за исключением спецификаций типов C и NumPy. Поэтому отображения типов реализованы (обычно скрыто от пользователя) с помощью макроса:

%numpy_typemaps(DATA_TYPE, DATA_TYPECODE, DIM_TYPE)

который можно вызвать для соответствующих троек (DATA_TYPE, DATA_TYPECODE, DIM_TYPE). Например:

%numpy_typemaps(double, NPY_DOUBLE, int)
%numpy_typemaps(int,    NPY_INT   , int)

Файл интерфейса numpy.i использует макрос %numpy_typemaps для создания отображений следующих типов данных C и размеров типа int:

  • signed char

  • unsigned char

  • short

  • unsigned short

  • int

  • unsigned int

  • long

  • unsigned long

  • long long

  • unsigned long long

  • float

  • double

В следующих описаниях мы ссылаемся на общий DATA_TYPE, который может быть любым из типов данных C, перечисленных выше, и DIM_TYPE, который должен быть одним из многих типов целых чисел.

Сигнатуры сопоставлений типов различаются главным образом именем указателя на буфер. Имена с FARRAY предназначены для массивов в порядке Fortran, а с ARRAY — для массивов в порядке C или одномерных массивов.

Входные массивы#

Входные массивы — это массивы данных, передаваемые в функцию, которые не изменяются на месте и не возвращаются пользователю. Поэтому входным массивом в Python может быть почти любая последовательность Python, например список, которую можно преобразовать в массив нужного типа. Сигнатуры входных массивов:

1D:

  • (   DATA_TYPE IN_ARRAY1[ANY] )

  • (   DATA_TYPE* IN_ARRAY1, int DIM1 )

  • (   int DIM1, DATA_TYPE* IN_ARRAY1 )

2D:

  • (   DATA_TYPE IN_ARRAY2[ANY][ANY] )

  • (   DATA_TYPE* IN_ARRAY2, int DIM1, int DIM2 )

  • (   int DIM1, int DIM2, DATA_TYPE* IN_ARRAY2 )

  • (   DATA_TYPE* IN_FARRAY2, int DIM1, int DIM2 )

  • (   int DIM1, int DIM2, DATA_TYPE* IN_FARRAY2 )

3D:

  • (   DATA_TYPE IN_ARRAY3[ANY][ANY][ANY] )

  • (   DATA_TYPE* IN_ARRAY3, int DIM1, int DIM2, int DIM3 )

  • (   int DIM1, int DIM2, int DIM3, DATA_TYPE* IN_ARRAY3 )

  • (   DATA_TYPE* IN_FARRAY3, int DIM1, int DIM2, int DIM3 )

  • (   int DIM1, int DIM2, int DIM3, DATA_TYPE* IN_FARRAY3 )

4D:

  • (DATA_TYPE IN_ARRAY4[ANY][ANY][ANY][ANY])

  • (DATA_TYPE* IN_ARRAY4, DIM_TYPE DIM1, DIM_TYPE DIM2, DIM_TYPE DIM3, DIM_TYPE DIM4)

  • (DIM_TYPE DIM1, DIM_TYPE DIM2, DIM_TYPE DIM3, , DIM_TYPE DIM4, DATA_TYPE* IN_ARRAY4)

  • (DATA_TYPE* IN_FARRAY4, DIM_TYPE DIM1, DIM_TYPE DIM2, DIM_TYPE DIM3, DIM_TYPE DIM4)

  • (DIM_TYPE DIM1, DIM_TYPE DIM2, DIM_TYPE DIM3, DIM_TYPE DIM4, DATA_TYPE* IN_FARRAY4)

Первая сигнатура, ( DATA_TYPE IN_ARRAY[ANY] ), предназначена для одномерных массивов с фиксированными размерами. Аналогично ( DATA_TYPE IN_ARRAY2[ANY][ANY] ) предназначена для двумерных массивов с фиксированными размерами; для трёхмерных используется тот же подход.

Массивы, изменяемые на месте#

Массивы in-place изменяются на месте. Их входные значения могут использоваться или не использоваться, но значения на момент возврата из функции имеют значение. Поэтому переданный аргумент Python должен быть массивом NumPy требуемого типа. Сигнатуры для работы на месте:

1D:

  • (   DATA_TYPE INPLACE_ARRAY1[ANY] )

  • (   DATA_TYPE* INPLACE_ARRAY1, int DIM1 )

  • (   int DIM1, DATA_TYPE* INPLACE_ARRAY1 )

2D:

  • (   DATA_TYPE INPLACE_ARRAY2[ANY][ANY] )

  • (   DATA_TYPE* INPLACE_ARRAY2, int DIM1, int DIM2 )

  • (   int DIM1, int DIM2, DATA_TYPE* INPLACE_ARRAY2 )

  • (   DATA_TYPE* INPLACE_FARRAY2, int DIM1, int DIM2 )

  • (   int DIM1, int DIM2, DATA_TYPE* INPLACE_FARRAY2 )

3D:

  • (   DATA_TYPE INPLACE_ARRAY3[ANY][ANY][ANY] )

  • (   DATA_TYPE* INPLACE_ARRAY3, int DIM1, int DIM2, int DIM3 )

  • (   int DIM1, int DIM2, int DIM3, DATA_TYPE* INPLACE_ARRAY3 )

  • (   DATA_TYPE* INPLACE_FARRAY3, int DIM1, int DIM2, int DIM3 )

  • (   int DIM1, int DIM2, int DIM3, DATA_TYPE* INPLACE_FARRAY3 )

4D:

  • (DATA_TYPE INPLACE_ARRAY4[ANY][ANY][ANY][ANY])

  • (DATA_TYPE* INPLACE_ARRAY4, DIM_TYPE DIM1, DIM_TYPE DIM2, DIM_TYPE DIM3, DIM_TYPE DIM4)

  • (DIM_TYPE DIM1, DIM_TYPE DIM2, DIM_TYPE DIM3, , DIM_TYPE DIM4, DATA_TYPE* INPLACE_ARRAY4)

  • (DATA_TYPE* INPLACE_FARRAY4, DIM_TYPE DIM1, DIM_TYPE DIM2, DIM_TYPE DIM3, DIM_TYPE DIM4)

  • (DIM_TYPE DIM1, DIM_TYPE DIM2, DIM_TYPE DIM3, DIM_TYPE DIM4, DATA_TYPE* INPLACE_FARRAY4)

Теперь эти typemap проверяют, что аргументы INPLACE_ARRAY используют машинный порядок байтов. В противном случае вызывается исключение.

Для обработки или изменения каждого элемента независимо от числа измерений предусмотрен также «плоский» массив, изменяемый на месте. Например, функция квантования может изменять на месте каждый элемент одномерного, двумерного или любого другого массива. Эта форма проверяет непрерывность расположения в памяти, но допускает и порядок C, и порядок Fortran.

ND:

  • (DATA_TYPE* INPLACE_ARRAY_FLAT, DIM_TYPE DIM_FLAT)

Выходные массивы argout#

Массивы argout передаются как аргументы функции C, но фактически служат выходными массивами. Такой подход часто используется, когда выходных переменных несколько и одного возвращаемого значения недостаточно. В Python несколько значений обычно возвращают, упаковав их в последовательность — кортеж, список и т. п. Именно это делают сопоставления типов argout. Если функция в обёртке с такими сопоставлениями возвращает несколько значений, они упаковываются в кортеж или список в зависимости от версии Python. Пользователь Python не передаёт эти массивы: он просто получает их как результат. Если указан размер, пользователь должен передать его аргументом. Сигнатуры argout:

1D:

  • (   DATA_TYPE ARGOUT_ARRAY1[ANY] )

  • (   DATA_TYPE* ARGOUT_ARRAY1, int DIM1 )

  • (   int DIM1, DATA_TYPE* ARGOUT_ARRAY1 )

2D:

  • (   DATA_TYPE ARGOUT_ARRAY2[ANY][ANY] )

3D:

  • (   DATA_TYPE ARGOUT_ARRAY3[ANY][ANY][ANY] )

4D:

  • (   DATA_TYPE ARGOUT_ARRAY4[ANY][ANY][ANY][ANY] )

Обычно они используются там, где в C/C++ массивы выделяются в куче, а затем функция заполняет их значения. В Python массивы выделяются автоматически и возвращаются как новые объекты массивов.

Сопоставления выходных массивов argout DATA_TYPE* поддерживаются для одного измерения, но не для двух или трёх. Это неизбежное ограничение синтаксиса сопоставлений SWIG. Для таких одномерных сопоставлений функция Python принимает один аргумент, представляющий DIM1.

Выходные массивы-представления (Argout View Arrays)#

Массивы Argoutview используются, когда код C предоставляет представление своих внутренних данных и не требует выделять память на стороне пользователя. Это может быть опасно: почти невозможно гарантировать, что внутренние данные кода C будут существовать всё время жизни массива NumPy, который их представляет. Если уничтожить объект, предоставляющий данные, раньше массива NumPy, использование массива может привести к обращению к недействительной памяти или ошибке сегментации. Тем не менее при работе с большими наборами данных иногда другого выбора нет.

Код C, для которого создаются обёртки с массивами argoutview, использует указатели на размеры и двойные указатели на данные, чтобы возвращать эти значения пользователю. Поэтому сигнатуры отображений типов argoutview имеют вид

1D:

  • ( DATA_TYPE** ARGOUTVIEW_ARRAY1, DIM_TYPE* DIM1 )

  • ( DIM_TYPE* DIM1, DATA_TYPE** ARGOUTVIEW_ARRAY1 )

2D:

  • ( DATA_TYPE** ARGOUTVIEW_ARRAY2, DIM_TYPE* DIM1, DIM_TYPE* DIM2 )

  • ( DIM_TYPE* DIM1, DIM_TYPE* DIM2, DATA_TYPE** ARGOUTVIEW_ARRAY2 )

  • ( DATA_TYPE** ARGOUTVIEW_FARRAY2, DIM_TYPE* DIM1, DIM_TYPE* DIM2 )

  • ( DIM_TYPE* DIM1, DIM_TYPE* DIM2, DATA_TYPE** ARGOUTVIEW_FARRAY2 )

3D:

  • ( DATA_TYPE** ARGOUTVIEW_ARRAY3, DIM_TYPE* DIM1, DIM_TYPE* DIM2, DIM_TYPE* DIM3)

  • ( DIM_TYPE* DIM1, DIM_TYPE* DIM2, DIM_TYPE* DIM3, DATA_TYPE** ARGOUTVIEW_ARRAY3)

  • ( DATA_TYPE** ARGOUTVIEW_FARRAY3, DIM_TYPE* DIM1, DIM_TYPE* DIM2, DIM_TYPE* DIM3)

  • ( DIM_TYPE* DIM1, DIM_TYPE* DIM2, DIM_TYPE* DIM3, DATA_TYPE** ARGOUTVIEW_FARRAY3)

4D:

  • (DATA_TYPE** ARGOUTVIEW_ARRAY4, DIM_TYPE* DIM1, DIM_TYPE* DIM2, DIM_TYPE* DIM3, DIM_TYPE* DIM4)

  • (DIM_TYPE* DIM1, DIM_TYPE* DIM2, DIM_TYPE* DIM3, DIM_TYPE* DIM4, DATA_TYPE** ARGOUTVIEW_ARRAY4)

  • (DATA_TYPE** ARGOUTVIEW_FARRAY4, DIM_TYPE* DIM1, DIM_TYPE* DIM2, DIM_TYPE* DIM3, DIM_TYPE* DIM4)

  • (DIM_TYPE* DIM1, DIM_TYPE* DIM2, DIM_TYPE* DIM3, DIM_TYPE* DIM4, DATA_TYPE** ARGOUTVIEW_FARRAY4)

Массивы с размерами, жёстко заданными в коде, не поддерживаются: они не соответствуют сигнатурам с двойным указателем, используемым этими сопоставлениями типов.

Выходные массивы-представления (argout) с управлением памятью#

В numpy.i недавно добавлены карты типов, позволяющие возвращать массивы argout как представления памяти с управляемым временем жизни.

1D:

  • (DATA_TYPE** ARGOUTVIEWM_ARRAY1, DIM_TYPE* DIM1)

  • (DIM_TYPE* DIM1, DATA_TYPE** ARGOUTVIEWM_ARRAY1)

2D:

  • (DATA_TYPE** ARGOUTVIEWM_ARRAY2, DIM_TYPE* DIM1, DIM_TYPE* DIM2)

  • (DIM_TYPE* DIM1, DIM_TYPE* DIM2, DATA_TYPE** ARGOUTVIEWM_ARRAY2)

Выходные массивы#

Файл интерфейса numpy.i не поддерживает отображения типов для выходных массивов по нескольким причинам. Во-первых, функции C/C++ возвращают только одно значение, что не позволяет универсальным способом получать сведения о размерах. Во-вторых, массивы с фиксированной длиной нельзя использовать как возвращаемые значения. Иными словами:

double[3] newVector(double x, double y, double z);

не является допустимым синтаксисом C/C++. Поэтому мы не можем предоставить отображения типов вида:

%typemap(out) (TYPE[ANY]);

Если вы столкнулись с ситуацией, когда функция или метод возвращает указатель на массив, лучше всего написать собственную версию функции, которую нужно обернуть, либо с помощью %extend для методов класса, либо с помощью %ignore и %rename для функций.

Другие распространённые типы: bool#

Тип C++ bool не поддерживается в списке раздела Доступные сопоставления типов. Логический тип NumPy занимает один байт, а тип C++ bool — четыре байта, по крайней мере в системе автора. Примечание переводчика: размер bool в C++ зависит от реализации; например, в локальной проверке GCC 16.2.1 он равен 1 байту. Следовательно:

%numpy_typemaps(bool, NPY_BOOL, int)

приведёт к созданию typemap, генерирующих код с неверными длинами данных. Можно использовать следующее раскрытие макроса:

%numpy_typemaps(bool, NPY_UINT, int)

чтобы решить проблему длины данных. Для входных массивов это сработает, но массивы, изменяемые на месте, могут не пройти проверку типов.

Другие распространённые типы: complex#

Преобразования через typemap для комплексных типов с плавающей точкой также не поддерживаются автоматически. Это связано с тем, что Python и NumPy написаны на C, в котором нет встроенных комплексных типов. И Python, и NumPy определяют собственные (по сути эквивалентные) структуры struct для комплексных переменных:

/* Python */
typedef struct {double real; double imag;} Py_complex;

/* NumPy */
typedef struct {float  real, imag;} npy_cfloat;
typedef struct {double real, imag;} npy_cdouble;

Мы могли бы реализовать:

%numpy_typemaps(Py_complex , NPY_CDOUBLE, int)
%numpy_typemaps(npy_cfloat , NPY_CFLOAT , int)
%numpy_typemaps(npy_cdouble, NPY_CDOUBLE, int)

что обеспечило бы автоматическое преобразование массивов типов Py_complex, npy_cfloat и npy_cdouble. Однако маловероятно, что независимые от Python и NumPy приложения, для которых создаётся интерфейс Python с помощью SWIG, используют именно эти определения комплексных типов. Скорее они определяют собственные комплексные типы или, в C++, используют std::complex. Если их структуры данных совместимы с комплексными типами Python и NumPy, приведённые выше раскрытия %numpy_typemap должны работать после подстановки пользовательского комплексного типа в первый аргумент.

Скаляры массива NumPy и SWIG #

SWIG тщательно проверяет числовые типы. Например, если процедура C/C++ ожидает целое число, код SWIG проверяет целые Python обычного и длинного типов и вызывает ошибку переполнения, если число слишком велико для целого C. При использовании скаляров NumPy можно извлечь целое число из массива и передать функции C/C++, обёрнутой SWIG и ожидающей int. Однако проверка SWIG может не распознать скаляр NumPy как целое число. Часто это всё же работает: зависит от того, наследуется ли используемый целочисленный тип NumPy от целого типа Python на данной платформе. Поэтому код для 32-битной машины иногда не работает на 64-битной. Здесь отражена терминология исторического описания Python.

Если вы получили ошибку Python, которая выглядит следующим образом:

TypeError: in method 'MyClass_MyMethod', argument 2 of type 'int'

а передаваемый аргумент — целое число, извлечённое из массива NumPy, значит, вы столкнулись с этой проблемой. Решение — изменить систему преобразования типов SWIG, чтобы она принимала скаляры массивов NumPy наряду со стандартными целочисленными типами. Такая возможность уже подготовлена. Просто скопируйте файл:

pyfragments.swg

в рабочий каталог сборки вашего проекта, и проблема будет решена. Это рекомендуется сделать в любом случае, поскольку возможности вашего интерфейса Python только расширятся.

Почему существует второй файл? #

Система проверки и преобразования типов SWIG представляет собой сложное сочетание макросов C, макросов SWIG, отображений типов SWIG и фрагментов SWIG. Фрагменты позволяют вставлять код в файл обёртки только при необходимости. Если один и тот же фрагмент нужен нескольким отображениям типов, он вставляется в код обёртки лишь один раз.

Есть фрагмент для преобразования целого числа Python в long языка C. Другой фрагмент преобразует целое число Python в int языка C, вызывая функцию, определённую во фрагменте long. Нужные изменения можно внести, изменив определение фрагмента long. SWIG выбирает активное определение фрагмента по принципу «первое встретившееся используется». Поэтому нужно определить фрагмент преобразований long до того, как SWIG сделает это сам. SWIG позволяет поместить наши определения фрагментов в файл pyfragments.swg. Если поместить новые определения в numpy.i, они будут проигнорированы.

Вспомогательные функции#

Файл numpy.i содержит макросы и процедуры, используемые внутри него для построения отображений типов. Однако эти функции могут пригодиться и в других частях вашего интерфейсного файла. Макросы и процедуры реализованы как фрагменты, кратко описанные в предыдущем разделе. Если при использовании приведённых ниже макросов или функций компилятор сообщает, что не распознаёт символ, необходимо явно включить соответствующие фрагменты в код с помощью:

%fragment("NumPy_Fragments");

в файле интерфейса SWIG .

Макросы#

is_array(a)

Принимает истинное значение, если a не равен NULL и может быть приведён к PyArrayObject*.

array_type(a)

Возвращает целочисленный код типа данных a при условии, что a можно привести к PyArrayObject*.

array_numdims(a)

Возвращает целое число измерений a, предполагая, что a можно привести к PyArrayObject*.

array_dimensions(a)

Даёт массив типа npy_intp длины array_numdims(a), содержащий размеры всех измерений a, при условии что a можно привести к типу PyArrayObject*.

array_size(a,i)

Возвращает размер измерения i массива a, при условии что a можно привести к PyArrayObject*.

array_strides(a)

Даёт массив типа npy_intp длины array_numdims(a) с шагами по памяти для всех измерений a, предполагая возможность привести a к PyArrayObject*. Шаг — расстояние в байтах между соседними элементами вдоль одной оси.

array_stride(a,i)

Возвращает i -й шаг a, предполагая, что a можно привести к PyArrayObject*.

array_data(a)

Даёт указатель типа void* на буфер данных a, если a можно привести к PyArrayObject*.

array_descr(a)

Возвращает заимствованную ссылку на свойство dtype (PyArray_Descr*) объекта a; предполагается, что a можно привести к PyArrayObject*.

array_flags(a)

Возвращает целое число, представляющее флаги a, предполагая, что a можно привести к PyArrayObject*.

array_enableflags(a,f)

Устанавливает флаг, представленный f для a, предполагая, что a можно привести к PyArrayObject*.

array_is_contiguous(a)

Возвращает истинное значение, если данные массива a непрерывно расположены в памяти. Эквивалентно (PyArray_ISCONTIGUOUS(a)).

array_is_native(a)

Возвращает истинное значение, если буфер данных a использует машинный порядок байтов. Эквивалентно (PyArray_ISNOTSWAPPED(a)).

array_is_fortran(a)

Истинно, если a расположен в порядке Fortran.

Дополнение стандартных отображений типов#

Существует множество ситуаций с массивами C или C++/массивами NumPy, которые не описываются простой директивой %include "numpy.i" и последующими директивами %apply.

Типичный пример #

Рассмотрим подходящий прототип функции скалярного произведения:

double dot(int len, double* vec1, double* vec2);

Интерфейс Python, который мы хотим:

def dot(vec1, vec2):
    """
    dot(PyObject,PyObject) -> double
    """

Проблема в том, что один аргумент размера относится к двум массивам, а наши отображения типов рассчитаны на размер одного массива. SWIG не предоставляет механизма связи len с vec2, принимающего два входных аргумента Python. Рекомендуется следующее решение:

%apply (int DIM1, double* IN_ARRAY1) {(int len1, double* vec1),
                                      (int len2, double* vec2)}
%rename (dot) my_dot;
%exception my_dot {
    $action
    if (PyErr_Occurred()) SWIG_fail;
}
%inline %{
double my_dot(int len1, double* vec1, int len2, double* vec2) {
    if (len1 != len2) {
        PyErr_Format(PyExc_ValueError,
                     "Arrays of lengths (%d,%d) given",
                     len1, len2);
        return 0.0;
    }
    return dot(len1, vec1, vec2);
}
%}

Если заголовочный файл с прототипом double dot() содержит и другие прототипы, для которых нужны обёртки, и поэтому его необходимо подключить через %include, потребуется также директива %ignore dot; после %rename и перед %include. Если же эта функция является методом класса, следует использовать %extend вместо %inline и дополнительно указать %ignore.

Об обработке ошибок: my_dot возвращает double, но может также установить ошибку Python. При несовпадении длин векторов созданная обёртка вернёт объект float Python со значением 0.0. Поскольку это не NULL, интерпретатор не проверит наличие ошибки. Поэтому выше добавлена директива %exception для my_dot, обеспечивающая нужное поведение. $action — макрос, раскрывающийся в корректный вызов my_dot. В общем случае для этой задачи, скорее всего, стоит написать макрос SWIG.

Другие ситуации#

Есть и другие ситуации создания обёрток, в которых numpy.i может оказаться полезным.

  • В некоторых случаях макрос %numpy_typemaps позволяет реализовать отображения типов (typemap) для собственных типов данных. Примеры см. в разделах Другие распространённые типы: bool и Другие распространённые типы: complex. Другой случай — когда размеры имеют тип, отличный от int, например long:

    %numpy_typemaps(double, NPY_DOUBLE, long)

  • Код numpy.i можно использовать для написания собственных сопоставлений типов. Например, для пятимерного массива в аргументе функции можно скопировать подходящие четырёхмерные сопоставления в свой файл интерфейса. Изменения для дополнительного измерения будут простыми. Примечание переводчика: в последнем предложении оригинала ошибочно названо четвёртое измерение; для перехода от четырёхмерного массива к пятимерному нужно добавить пятое.

  • Иногда лучше использовать директиву %extend, чтобы определить новые методы классов или перегрузить существующие. Эти методы принимают PyObject*, который является PyArrayObject* или может быть в него преобразован, вместо указателя на буфер. Здесь могут быть очень полезны вспомогательные функции из numpy.i.

  • Написание отображений типов бывает не вполне интуитивным. Если у вас есть конкретные вопросы об отображениях типов SWIG для NumPy, разработчики numpy.i читают списки рассылки Numpy-discussion и Swig-user.

Заключительное замечание#

Директива %apply, обычно необходимая для использования numpy.i, действует, пока вы явно не сообщите SWIG об её отмене. Если аргументы оборачиваемых функций или методов имеют распространённые имена, например length или vector, сопоставления типов могут применяться неожиданно или нежелательно. Поэтому после завершения работы с конкретным сопоставлением рекомендуется добавлять директиву %clear:

%apply (double* IN_ARRAY1, int DIM1) {(double* vector, int length)}
%include "my_header.h"
%clear (double* vector, int length);

Обычно эти сигнатуры typemap следует применять только там, где они нужны, а затем удалять их действие.

Краткое описание#

numpy.i изначально предоставляет сопоставления типов (typemap) для преобразований между массивами NumPy и массивами C:

  • Это может быть один из 12 различных скалярных типов: signed char, unsigned char, short, unsigned short, int, unsigned int, long, unsigned long, long long, unsigned long long, float и double.

  • Они поддерживают 74 различные сигнатуры аргументов для каждого типа данных, в том числе:

    • Одномерные, двумерные, трёхмерные и четырёхмерные массивы.

    • Поведение для входных аргументов, изменения на месте, argout, argoutview и argoutview с управлением памятью.

    • Жёстко заданные размеры, запись «буфер данных, затем размеры» и запись «размеры, затем буфер данных».

    • Для двумерных, трёхмерных и четырёхмерных массивов поддерживается как порядок C (быстрее всего меняется последнее измерение), так и порядок Fortran (быстрее всего меняется первое измерение).

Файл интерфейса numpy.i также предоставляет разработчикам обёрток дополнительные инструменты, в том числе:

  • Макрос SWIG (%numpy_typemaps) с тремя аргументами для реализации 74 сигнатур аргументов при выбранных пользователем (1) типе данных C, (2) соответствующем ему типе данных NumPy и (3) типе для размеров измерений.

  • Четырнадцать макросов C и пятнадцать функций C для написания специализированных typemap, расширений или встраиваемых функций, обрабатывающих случаи, не охваченные готовыми typemap. Макросы и функции специально реализованы для работы с C API NumPy независимо от версии — как до, так и после объявления некоторых частей API устаревшими после версии 1.6.
