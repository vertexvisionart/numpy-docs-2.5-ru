Типизация (numpy.typing)#

Добавлено в версии 1.20.

Большая часть API NumPy снабжена аннотациями типов в стиле PEP 484. Кроме того, пользователям доступны псевдонимы типов; два основных приведены ниже:

  • ArrayLike: объекты, которые могут быть преобразованы в массивы

  • DTypeLike: объекты, которые можно преобразовать в типы данных

Плагин Mypy #

Добавлено в версии 1.21.

Плагин mypy для управления рядом платформозависимых аннотаций типов. Его функции делятся на три части:

  • Определение зависящей от платформы точности некоторых подклассов number, в том числе int_, intp и longlong. Полный перечень затронутых классов приведён в документации по скалярным типам. Без плагина точность всех соответствующих классов выводится как Any.

  • Исключение всех подклассов number расширенной точности, недоступных на данной платформе, в частности float128 и complex256. Без плагина mypy считает, что все типы расширенной точности доступны на всех платформах.

  • Назначение точности (зависящей от платформы) c_intp . Без плагина тип по умолчанию будет ctypes.c_int64.

    Добавлено в версии 1.22.

Объявлено устаревшим в версии 2.3: точка входа numpy.typing.mypy_plugin объявлена устаревшей в пользу платформонезависимого статического вывода типов. Удалите numpy.typing.mypy_plugin из раздела plugins конфигурации mypy. Если после этого появятся новые ошибки, создайте issue с минимальным воспроизводящим примером.

Примеры#

Чтобы включить плагин, добавьте его в файл конфигурации mypy:

[mypy]
plugins = numpy.typing.mypy_plugin

Отличия от API NumPy во время выполнения#

NumPy очень гибок. Статическое описание всех его возможностей привело бы к малополезным типам. Поэтому типизированный API NumPy часто строже API, доступного во время выполнения. В этом разделе описаны некоторые существенные различия.

ArrayLike#

Тип ArrayLike старается не допускать создания массивов объектов. Например:

>>> np.array(x**2 for x in range(10))
array(<generator object <genexpr> at ...>, dtype=object)

— допустимый код NumPy, создающий нульмерный массив объектов. Однако при использовании типов NumPy проверщики типов сообщат об ошибке в этом примере. Если именно такое поведение и требуется, можно добавить комментарий # type: ignore:

>>> np.array(x**2 for x in range(10))  # type: ignore
Комментарии к примеру на русском
  • type: ignore

или явно аннотируйте объект, подобный массиву, типом Any:

>>> from typing import Any
>>> array_like: Any = (x**2 for x in range(10))
>>> np.array(array_like)
array(<generator object <genexpr> at ...>, dtype=object)

DTypeLike#

Тип DTypeLike намеренно не предусматривает создание объектов dtype из словаря полей, например так:

>>> x = np.dtype({"field1": (float, 1), "field2": (int, 3)})

Хотя это допустимый код NumPy, средство проверки типов сообщит о проблеме, поскольку такое использование не рекомендуется. См. «Объекты типов данных»

Точность чисел#

Точность подклассов numpy.number рассматривается как инвариантный параметр обобщённого типа (см. NBitBase), что упрощает аннотирование операций с приведением типов на основе точности.

>>> from typing import TypeVar
>>> import numpy as np
>>> import numpy.typing as npt

>>> T = TypeVar("T", bound=npt.NBitBase)
>>> def func(a: np.floating[T], b: np.floating[T]) -> np.floating[T]:
...     ...

Следовательно, float16, float32, float64 и подобные типы по-прежнему являются подтипами floating, но при статической проверке типов не обязательно считаются его подклассами, в отличие от поведения во время выполнения.

Устарело с версии 2.3: Вспомогательный класс NBitBase объявлен устаревшим и будет удалён в будущем выпуске. Вместо него выражайте связи между точностями с помощью определений typing.overload или TypeVar, ограниченных конкретными скалярными классами. Например:

from typing import TypeVar
import numpy as np

S = TypeVar("S", bound=np.floating)

def func(a: S, b: S) -> S:
    ...

или в случае отображения различных типов входных данных на различные типы выходных данных:

from typing import overload
import numpy as np

@overload
def phase(x: np.complex64) -> np.float32: ...
@overload
def phase(x: np.complex128) -> np.float64: ...
@overload
def phase(x: np.clongdouble) -> np.longdouble: ...
def phase(x: np.complexfloating) -> np.floating:
    ...

Timedelta64#

При статической проверке типов класс timedelta64 не считается подклассом signedinteger: в этом контексте он наследуется только от generic.

Типы dtype массивов записей#

dtype для numpy.recarray и вообще для функций из раздела Создание массивов записей можно задать одним из двух способов:

  • Напрямую через аргумент dtype.

  • С поддержкой до пяти вспомогательных аргументов, обрабатываемых через numpy.rec.format_parser: formats, names, titles, aligned и byteorder.

В аннотациях типов эти два подхода сейчас заданы как взаимоисключающие: то есть при указании dtype нельзя задавать formats. Хотя во время выполнения это ограничение не проверяется строго, сочетание обоих спецификаторов dtype может приводить к неожиданному и даже явно ошибочному поведению.

API#

ndarray

Класс numpy.ndarray — обобщённый тип, принимающий два аргумента типа:

  1. Тип numpy.ndarray.shape: должен быть tuple из int, например tuple[int, int] для двумерной формы или tuple[()] для нульмерной. Стандартный тип формы — tuple[Any, ...]: неизвестная форма с любым числом измерений. Целые числа Literal и другие более конкретные типы пока не поддерживаются.

  2. Тип numpy.ndarray.dtype, который должен быть подтипом numpy.dtype, например numpy.dtype[numpy.float64]. Если не указан, по умолчанию используется numpy.dtype[Any].

>>> import numpy as np

>>> type ImageRGB = np.ndarray[tuple[int, int, int], np.dtype[np.uint8]]
>>> type Vector[S: np.generic] = np.ndarray[tuple[int], np.dtype[S]]
numpy.typing.ArrayLike = typing.Union[...]#

Union, представляющий объекты, которые можно преобразовать в ndarray.

В частности, сюда относятся:

  • Скаляры.

  • Последовательности, в том числе вложенные.

  • Объекты, реализующие протокол __array__.

Добавлено в версии 1.20.

См. также

array_like:

Любой скаляр или последовательность, которые можно интерпретировать как ndarray.

Примеры

>>> import numpy as np
>>> import numpy.typing as npt

>>> def as_array(a: npt.ArrayLike) -> np.ndarray:
...     return np.array(a)
numpy.typing.DTypeLike = typing.Union[...]#

Union, представляющий объекты, которые можно преобразовать в dtype.

В частности, сюда относятся:

  • Объекты type.

  • Коды символов или имена объектов type.

  • Объекты с атрибутом .dtype.

Добавлено в версии 1.20.

Определение и создание типов данных

Полный обзор объектов, которые можно преобразовать в типы данных.

Примеры

>>> import numpy as np
>>> import numpy.typing as npt

>>> def as_dtype(d: npt.DTypeLike) -> np.dtype:
...     return np.dtype(d)
numpy.typing.NDArray = NDArray#

Псевдоним типа np.ndarray[tuple[Any, ...], np.dtype[ScalarT]], обобщённый по параметру dtype.type.

Может использоваться во время выполнения для аннотации массивов с заданным dtype и неуказанной формой.

Добавлено в версии 1.21.

Примеры

>>> import numpy as np
>>> import numpy.typing as npt

>>> print(npt.NDArray)
NDArray

>>> print(npt.NDArray[np.float64])
NDArray[numpy.float64]

>>> NDArrayInt = npt.NDArray[np.int_]
>>> a: NDArrayInt = np.arange(10)

>>> def func(a: npt.ArrayLike) -> npt.NDArray[Any]:
...     return np.array(a)
class numpy.typing.NBitBase[source]#

Тип, представляющий точность numpy.number при статической проверке типов.

NBitBase используется только для статической проверки типов и служит базовым классом иерархии подклассов. Каждый следующий подкласс представляет меньшую точность, например 64Bit > 32Bit > 16Bit.

Добавлено в версии 1.20.

Устарело с версии 2.3: Вместо этого используйте @typing.overload или TypeVar с верхней границей, заданной скалярным типом.

Примеры

Типичный пример: NBitBase используется для аннотации функции, принимающей число с плавающей точкой и целое число произвольной точности, а возвращающей число с плавающей точкой с большей из двух точностей (например np.float16 + np.int64 -> np.float64).

>>> from typing import TYPE_CHECKING
>>> import numpy as np
>>> import numpy.typing as npt

>>> def add[S: npt.NBitBase, T: npt.NBitBase](
...     a: np.floating[S], b: np.integer[T]
... ) -> np.floating[S | T]:
...     return a + b

>>> a = np.float16()
>>> b = np.int64()
>>> out = add(a, b)

>>> if TYPE_CHECKING:
...     reveal_locals()
...     # note: Revealed local types are:
...     # note:     a: numpy.floating[numpy.typing._16Bit*]
...     # note:     b: numpy.signedinteger[numpy.typing._64Bit*]
...     # note:     out: numpy.floating[numpy.typing._64Bit*]
Комментарии к примеру на русском
  • Примечание: определены следующие локальные типы:
  • Примечание: a: numpy.floating[numpy.typing._16Bit*]
  • Примечание: b: numpy.signedinteger[numpy.typing._64Bit*]
  • Примечание: out: numpy.floating[numpy.typing._64Bit*]
