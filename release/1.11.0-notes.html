Историческая справка: страница описывает NumPy 1.11.0. Слова «сейчас», «раньше» и «будет» относятся ко времени этого выпуска; описанное поведение может отличаться от NumPy 2.5.

Примечания к выпуску NumPy 1.11.0#

Выпуск поддерживает Python 2.6–2.7 и 3.2–3.5 и содержит ряд новых возможностей и улучшений. Обратите внимание и на изменения системы сборки ниже: их последствия могут быть неочевидны.

Двоичные пакеты для Windows (TM) в этом выпуске не предоставляются из-за неисправности набора инструментов сборки. Лучше воспользоваться услугами одного из сторонних поставщиков пакетов Python для Windows (TM).

Основные изменения#

Подробности этих улучшений можно найти ниже.

  • Тип datetime64 теперь не учитывает часовой пояс.

  • Параметр dtype был добавлен в randint.

  • Улучшенное обнаружение двух массивов, возможно, совместно использующих память.

  • Автоматическая оценка ширины интервалов для np.histogram.

  • Ускорение A @ A.T и dot(A, A.T).

  • Новая функция np.moveaxis для переупорядочения осей массивов.

Изменения в системе сборки#

  • Для сборки NumPy теперь используется setuptools вместо обычного distutils. Это исправляет использование install_requires='numpy' в файлах setup.py проектов, зависящих от NumPy (см. gh-6551), но может повлиять на поведение сборки и установки самого NumPy. О неожиданном поведении сообщайте в системе отслеживания ошибок NumPy.

  • Поддержка сборки с помощью Bento и связанные с ней файлы удалены.

  • Поддержка сборки отдельных файлов и связанные с ними файлы были удалены.

Будущие изменения#

Следующие изменения запланированы на NumPy 1.12.0.

  • Поддержка Python 2.6, 3.2 и 3.3 будет прекращена.

  • Ослабленная проверка шагов станет поведением по умолчанию. Подробнее о последствиях этого изменения см. примечания к выпуску 1.8.0.

  • Поведение значения datetime64 «не время» (NaT) будет согласовано с поведением «не числа» (NaN) для типов с плавающей точкой: сравнения с NaT возвращают False, кроме проверки на неравенство, которая возвращает True, в том числе для NaT != NaT. Примечание переводчика: в оригинале исключение сформулировано только для NaT != NaT, однако неравенство NaT любому обычному времени также истинно.

  • Индексация числами с плавающей запятой вызывает IndexError, например a[0, 0.0].

  • Индексирование с помощью array_like с нецелочисленными значениями возбуждает IndexError, например a['1', '2']

  • Индексация с несколькими многоточиями вызывает IndexError, например a[..., ...].

  • Нецелые значения индексов вызывают TypeError, например в reshape, take и при указании оси свёртки.

В будущем выпуске будут внесены следующие изменения.

  • Функция rand, доступная в numpy.testing, будет удалена. Она сохранилась с ранних версий NumPy и была реализована с помощью модуля Python random. Вместо неё следует использовать генераторы случайных чисел из numpy.random.

  • Метод ndarray.view будет позволять создавать представления с dtype другого размера только для массивов c_contiguous, с изменением последнего измерения. Сейчас для массивов f_contiguous, не являющихся c_contiguous, допускается такое представление с изменением первого измерения.

  • Срез MaskedArray возвращает представления данных и маски. Сейчас маска копируется при записи, поэтому изменения её среза не затрагивают исходную маску. Подробности см. ниже в разделе FutureWarnings.

Примечания о совместимости#

Изменения datetime64#

В предыдущих версиях NumPy экспериментальный тип datetime64 всегда хранил время в UTC. По умолчанию при создании объекта datetime64 из строки местное время преобразовывалось в UTC, а при выводе объекта — обратно в местное время:

# old behavior
>>> np.datetime64('2000-01-01T00:00:00')
numpy.datetime64('2000-01-01T00:00:00-0800')  # note the timezone offset -08:00
Комментарии к примеру на русском
  • Прежнее поведение
  • Обратите внимание на смещение часового пояса -08:00

Пользователи datetime64 пришли к согласию, что такое поведение нежелательно и не соответствует обычному применению datetime64, например в pandas. В большинстве случаев предпочтителен тип даты и времени без часового пояса, подобный datetime.datetime из стандартной библиотеки Python. Поэтому datetime64 больше не считает, что входные данные заданы в местном времени, и не выводит местное время:

>>> np.datetime64('2000-01-01T00:00:00')
numpy.datetime64('2000-01-01T00:00:00')

Для обратной совместимости datetime64 по-прежнему разбирает смещения часовых поясов, преобразуя время в UTC. Однако полученное значение не хранит информацию о часовом поясе:

>>> np.datetime64('2000-01-01T00:00:00-08')
DeprecationWarning: parsing timezone aware datetimes is deprecated;
this will raise an error in the future
numpy.datetime64('2000-01-01T08:00:00')

Вследствие этого изменения больше не запрещены приведения между datetime с единицами даты и datetime с единицами времени. Для datetime без часового пояса правило преобразования дат во время теперь однозначно.

Изменение типа результата linalg.norm#

Теперь функция linalg.norm во всех случаях возвращает тип с плавающей точкой. Раньше некоторые виды норм возвращались как целые числа.

Изменения подбора полиномов#

Функции аппроксимации пакета polynomial в NumPy больше не принимают нецелые значения степени.

np.dot теперь вызывает TypeError вместо ValueError#

Такое поведение соответствует другим функциям, например np.inner. Если два аргумента нельзя привести к общему типу, раньше в зависимости от их порядка мог возникнуть TypeError или ValueError. Теперь np.dot в этом случае всегда вызывает TypeError.

FutureWarning об изменении поведения#

  • Раньше в np.lib.split пустой массив в результате всегда имел форму (0,) независимо от числа измерений разделяемого массива. Теперь число измерений сохраняется. Об этом изменении предупреждал FutureWarning начиная с NumPy 1.9, но из-за ошибки иногда предупреждение не выдавалось, а число измерений уже сохранялось.

Операторы % и //#

Эти операторы реализованы функциями remainder и floor_divide соответственно. Теперь обе функции основаны на fmod и вычисляются совместно, чтобы результаты согласовывались друг с другом и с реализацией Python для типов с плавающей запятой. Результаты должны стать немного точнее, а в некоторых случаях исправлены явные ошибки. Однако они могут существенно отличаться, если округление влияет на целое число, возвращаемое floor_divide. Изменились и некоторые особые случаи: например, при нулевом делителе обе функции всегда возвращают NaN; divmod(1.0, inf) возвращает (0.0, 1.0), кроме MSVC 2008; divmod(-1.0, inf) возвращает (-1.0, inf).

C API#

Удалены check_return и inner_loop_selector члены структуры PyUFuncObject (замена их слотами reserved для сохранения компоновки структуры). Они никогда не использовались ни для чего, поэтому маловероятно, что какой-либо сторонний код также использует их, но мы упоминаем об этом здесь для полноты.

Определение объектного dtype для классов старого стиля#

В Python 2 экземпляры пользовательских классов старого стиля больше не считаются автоматически данными типа «object» при определении dtype. Вместо этого, как и в Python 3, они могут считаться последовательностями, но только если определяют оба метода: __len__ и __getitem__. Это устраняет ошибку сегментации и несогласованность поведения Python 2 и 3.

Новые возможности #

  • np.histogram теперь предоставляет методы автоматической оценки оптимального числа интервалов. Если передать в «bins» одно из значений [‘auto’, ‘fd’, ‘scott’, ‘rice’, ‘sturges’], будет использован соответствующий метод оценки.

  • Добавлен набор тестов производительности на основе Airspeed Velocity, преобразованный из прежнего набора на основе vbench. Его можно запустить локально командой python runtests.py --bench. Подробнее см. benchmarks/README.rst.

  • Добавлена новая функция np.shares_memory, которая может точно проверить, имеют ли два массива перекрытие памяти. np.may_share_memory также теперь имеет возможность тратить больше усилий на уменьшение ложных срабатываний.

  • Классы исключений SkipTest и KnownFailureException доступны в пространстве имён numpy.testing. Возбудите соответствующее исключение в тестовой функции, чтобы отметить тест как пропускаемый или как тест с известной ошибкой.

  • У f2py.compile появился именованный параметр extension, задающий расширение создаваемых временных файлов Fortran. Например, можно задать *.f90. Также задействован аргумент verbose, который раньше игнорировался.

  • Параметр dtype добавлен в np.random.randint. Теперь можно генерировать случайные ndarray следующих типов:

    • np.bool_,

    • np.int8, np.uint8,

    • np.int16, np.uint16,

    • np.int32, np.uint32,

    • np.int64, np.uint64,

    • np.int_, np.intp

    Спецификация задаётся точностью, а не типом C. Поэтому на некоторых платформах np.int64 может быть long вместо long long, даже если задан dtype long long: эти типы могут иметь одинаковую точность. Результат зависит от типа C, используемого NumPy для данной точности. Указание порядка байтов также игнорируется: создаваемые массивы всегда используют собственный порядок байтов системы.

  • Новая функция np.moveaxis позволяет перемещать одну или несколько осей массива в новую позицию, явно указывая исходную и целевую оси. Эта функция должна быть проще в использовании, чем текущая функция rollaxis, а также предоставлять больше функциональных возможностей.

  • Параметр deg функций аппроксимации numpy.polynomial теперь принимает список степеней членов, включаемых в аппроксимацию; коэффициенты всех остальных членов фиксируются равными нулю. Изменение обратно совместимо: скалярный deg действует как прежде.

  • В библиотеку npy_math добавлена функция divmod для типов с плавающей точкой, созданная по образцу версии Python.

Улучшения#

np.gradient теперь поддерживает аргумент axis #

Параметр axis был добавлен в np.gradient для согласованности. Он позволяет указать, по каким осям вычисляется градиент.

np.lexsort теперь поддерживает массивы с типом данных object#

Теперь функция внутренне вызывает универсальную npy_amergesort, если тип не реализует вариант метода argsort для сортировки слиянием.

np.ma.core.MaskedArray теперь поддерживает аргумент order #

При создании нового экземпляра MaskedArray его можно настроить с помощью аргумента order, аналогичного тому, который используется при вызове np.ndarray. Добавление этого аргумента позволяет правильно обрабатывать аргумент order в нескольких служебных функциях, связанных с MaskedArray, таких как np.ma.core.array и np.ma.core.asarray.

Улучшения потребления памяти и скорости работы маскированных массивов#

Создание маскированного массива через mask=True или mask=False теперь использует для маски np.ones или np.zeros соответственно. Это быстрее и избегает большого пикового потребления памяти. Другая оптимизация устраняет пик потребления памяти и лишние вычисления при выводе маскированного массива.

ndarray.tofile теперь использует fallocate в Linux#

Теперь функция использует системный вызов fallocate для резервирования необходимого дискового пространства в поддерживающих его файловых системах.

Оптимизации операций вида A.T @ A и A @ A.T#

Раньше для всех матричных произведений использовались операции BLAS gemm. Теперь при умножении матрицы на её транспонированную версию используются операции BLAS syrk, что повышает производительность. Оптимизация распространяется на @, numpy.dot, numpy.inner и numpy.matmul.

Примечание: транспонированная и исходная матрицы должны использовать общую память данных.

np.testing.assert_warns теперь можно использовать в качестве контекстного менеджера #.

Это соответствует поведению assert_raises.

Ускорение np.random.shuffle#

np.random.shuffle теперь работает гораздо быстрее с одномерными массивами ndarray.

Изменения#

Поддержка Pyrex удалена из numpy.distutils #

Метод build_src.generate_a_pyrex_source останется доступным: пользователи подменяли его для поддержки Cython вместо Pyrex. Однако рекомендуется перейти на лучше поддерживаемый способ сборки расширений Cython.

np.broadcast теперь можно вызывать с одним аргументом#

В таком случае результирующий объект просто имитирует обход одного массива. Это изменение делает ненужными различия вида

if len(x) == 1:

shape = x[0].shape

else:

shape = np.broadcast(*x).shape

Вместо этого np.broadcast можно использовать во всех случаях.

np.trace теперь учитывает подклассы массивов#

Такое поведение соответствует другим функциям, например np.diagonal, и, в частности, гарантирует, что для маскированных массивов np.trace(ma) и ma.trace() дают одинаковый результат.

np.dot теперь вызывает TypeError вместо ValueError#

Теперь поведение согласуется с другими функциями, например np.inner. Если два аргумента нельзя было привести к общему типу, раньше могли возникать TypeError или ValueError в зависимости от порядка аргументов. Теперь np.dot всегда вызывает TypeError.

Изменение типа результата linalg.norm#

Функция linalg.norm теперь выполняет все вычисления с плавающей точкой и возвращает вещественные результаты. Это исправляет ошибки из-за целочисленного переполнения и невозможности abs обработать минимальное целое со знаком, например int8(-128). Для единообразия вещественные числа используются и там, где подошли бы целые.

Устаревающие возможности#

Представления массивов в порядке Fortran#

Флаг F_CONTIGUOUS указывал, что представление с dtype другого размера элемента изменяет первый индекс. Это всегда было проблематично для массивов с обоими флагами F_CONTIGUOUS и C_CONTIGUOUS, поскольку приоритет имел C_CONTIGUOUS. Смягчённая проверка шагов увеличивает число таких массивов с двойной непрерывностью и нарушает работу части кода. Это касается и смены dtype присваиванием атрибуту массива. Цель объявления устаревшим — в будущем разрешать такие представления лишь для массивов C_CONTIGUOUS. Обратно совместимый обходной способ — a.T.view(...).T. К методу view также могут добавить параметр, явно запрашивающий представление в порядке Fortran, но он не будет обратно совместим.

Недопустимые аргументы порядка расположения элементов массива#

Сейчас в параметр order методов, например array.flatten или array.ravel, можно передавать значения, отличные от ‘C’, ‘F’, ‘A’, ‘K’. Допустимые значения поддерживают Unicode и не зависят от регистра. В будущих выпусках передача других значений будет запрещена.

Генератор случайных чисел в пространстве имён testing#

Генератор случайных чисел стандартной библиотеки Python ранее был представлен в пространстве имен testing как testing.rand. Использование этого генератора не рекомендуется, и он будет удален в будущем выпуске. Вместо этого используйте генераторы из пространства имен numpy.random.

Генерация случайных целых чисел на отрезке#

В соответствии с C API Python, предпочитающим полуинтервалы замкнутым интервалам, np.random.random_integers объявлен устаревшим в пользу np.random.randint, дополненного параметром dtype, как описано в новых возможностях. Однако np.random.random_integers не будет удалён в ближайшее время.

Предупреждения FutureWarning#

Присваивание срезам и представлениям MaskedArray#

Сейчас срез маскированного массива содержит представление исходных данных и представление маски с копированием при записи. Поэтому изменение маски среза сначала создаёт копию исходной маски, а затем меняет эту копию. Например, при создании среза view = original[:] изменения данных одного массива отражаются в другом, но изменения маски остаются локальными, поскольку маска копируется при присваивании. Аналогично, при явном создании массива через MaskedArray(data, mask) результат содержит представление data, а его маска — представление mask с копированием при записи.

В будущем эти случаи будут приведены к единому поведению: массив данных и маска будут обрабатываться одинаково, а изменения каждого из них будут распространяться между представлениями. В версии 1.11 NumPy выдаёт предупреждение MaskedArrayFutureWarning, когда пользовательский код меняет маску представления так, что в будущем изменения могут передаваться исходному массиву. Чтобы убрать предупреждения и подготовиться к изменению поведения, есть два варианта. Для сохранения нынешнего поведения вызовите masked_view.unshare_mask() перед изменением маски. Для перехода к будущему поведению уже сейчас используйте masked_view._sharedmask = False. Однако эффект установки атрибута _sharedmask нарушается при последующих явных вызовах masked_view.unshare_mask().
