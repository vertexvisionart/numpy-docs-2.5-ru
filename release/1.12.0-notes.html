  • Примечания к выпуску NumPy 1.12.0

Историческая справка: страница описывает NumPy 1.12.0. Слова «сейчас», «раньше» и «будет» относятся ко времени этого выпуска; описанное поведение может отличаться от NumPy 2.5.

Примечания к выпуску NumPy 1.12.0#

Данный релиз поддерживает Python 2.7 и 3.4 - 3.6.

Основные изменения#

Выпуск NumPy 1.12.0 содержит множество исправлений и улучшений, но немногие из них явно выделяются среди остальных. Поэтому выбор главных изменений несколько условен. Перечисленное ниже может представлять особый интерес или указывать направления, которые окажутся важны в будущем.

  • Порядок операций в np.einsum теперь можно оптимизировать для значительного повышения скорости.

  • Новый аргумент signature функции np.vectorize для векторизации с основными измерениями.

  • Аргумент keepdims был добавлен ко многим функциям.

  • Новый менеджер контекста для тестирования предупреждений

  • Поддержка BLIS в numpy.distutils

  • Улучшенная поддержка PyPy (еще не закончена)

Прекращённая поддержка#

  • Поддержка Python 2.6, 3.2 и 3.3 прекращена.

Добавленная поддержка#

  • Добавлена поддержка PyPy 2.7 v5.6.0. Хотя она пока неполная (updateifcopy в nditer ещё не поддерживается), это важный этап развития слоя совместимости PyPy с C API.

Изменения в системе сборки#

  • Порядок библиотек сохраняется, а не меняется в соответствии с порядком каталогов.

Устаревающие возможности#

Присваивание атрибуту data объекта ndarray#

Присваивание атрибуту «data» по своей природе небезопасно, как отмечено в gh-7083. В будущем эта возможность будет удалена.

Небезопасное приведение атрибута num к int в linspace#

np.linspace теперь выдаёт DeprecationWarning, если num нельзя безопасно интерпретировать как целое число.

Недостаточная разрядность, заданная параметром binary_repr#

Раньше, если параметр ‘width’ функции binary_repr был недостаточен для представления положительного числа в двоичной форме или отрицательного числа в дополнительном коде, функция молча игнорировала его и возвращала представление с минимально необходимым числом битов. Теперь такое поведение считается небезопасным для пользователя и в будущем будет приводить к ошибке.

Будущие изменения#

  • В версии 1.13 сравнения NAT всегда возвращают False, кроме NAT != NAT, возвращающего True. То есть NAT ведёт себя как NaN.

  • В версии 1.13 np.average будет сохранять подклассы, как и большинство других функций NumPy, например np.mean. В частности, вместо скаляра вызов может возвращать нульмерный объект подкласса.

Работа с несколькими полями структурированных массивов#

В 1.13 поведение структурированных массивов, включающих несколько полей, будет меняться двумя способами:

Во-первых, выбор нескольких полей структурированного массива, например arr[['f1', 'f3']], в версии 1.13 будет возвращать представление исходного массива вместо копии. В отличие от копии в версии 1.12, представление содержит дополнительные байты заполнения на месте промежуточных полей исходного массива. Это повлияет на код наподобие arr[['f1', 'f3']].view(newdtype).

Во-вторых, в NumPy 1.6–1.12 присваивание между структурированными массивами выполняется «по имени поля»: каждому полю целевого массива присваивается одноимённое поле исходного массива либо 0, если такого поля в источнике нет:

>>> a = np.array([(1,2),(3,4)], dtype=[('x', 'i4'), ('y', 'i4')])
>>> b = np.ones(2, dtype=[('z', 'i4'), ('y', 'i4'), ('x', 'i4')])
>>> b[:] = a
>>> b
array([(0, 2, 1), (0, 4, 3)],
      dtype=[('z', '<i4'), ('y', '<i4'), ('x', '<i4')])

В версии 1.13 присваивание будет выполняться «по позиции»: в N-е поле массива назначения будет записываться N-е поле исходного массива независимо от имён полей. Прежнее поведение можно получить, изменив порядок полей с помощью индексации перед присваиванием, например b[['x', 'y']] = a[['y', 'x']].

Примечания о совместимости#

DeprecationWarning заменено ошибкой#

  • Индексация числами с плавающей точкой, например a[0, 0.0], вызывает IndexError.

  • Индексация нецелочисленным array_like вызывает IndexError, например a['1', '2']

  • Индексация с несколькими многоточиями вызывает IndexError, например a[..., ...].

  • Нецелочисленные значения индексов вызывают TypeError, например в reshape, take и при задании оси свёртки.

FutureWarning об изменении поведения#

  • Если dtype не задан, np.full теперь возвращает массив типа значения заполнения, а не float по умолчанию.

  • np.average выдаёт предупреждение, если аргумент — экземпляр подкласса ndarray, поскольку начиная с 1.13 подкласс будет сохраняться (см. раздел «Будущие изменения»).

power и ** вызывают ошибку при возведении целых чисел в отрицательные целые степени#

Прежнее поведение зависело от того, использовались ли целочисленные скаляры NumPy или целочисленные массивы NumPy.

Для массивов

  • Возведение нуля в отрицательные целые степени возвращало минимальное значение целочисленного типа.

  • Возведение как 1, так и -1 в отрицательные целые степени возвращало правильные значения.

  • Остальные целые числа при возведении в отрицательные целые степени давали ноль.

Для скаляров

  • Возведение нуля в отрицательные целые степени возвращало минимальное значение целочисленного типа.

  • Возведение как 1, так и -1 в отрицательные целые степени возвращало правильные значения.

  • Для остальных целочисленных типов результатом иногда был ноль, а иногда — правильное число с плавающей точкой, в зависимости от сочетания целочисленных типов.

Во всех этих случаях теперь возникает ValueError, кроме сочетаний целочисленных типов, общий тип которых является типом с плавающей точкой, например uint64 и int8. Простое правило было сочтено предпочтительнее отдельных исключений для целочисленных единиц. Если нужны отрицательные степени, используйте неточный числовой тип — вещественный или комплексный.

Ослабленная проверка шагов по осям используется по умолчанию#

Это повлияет на код, который считал F_CONTIGUOUS и C_CONTIGUOUS взаимоисключающими и использовал их для определения стандартного порядка массивов, у которых теперь установлены оба флага.

np.percentile: исправлен метод интерполяции «midpoint» для точных индексов#

Метод интерполяции ‘midpoint’ теперь даёт тот же результат, что ‘lower’ и ‘higher’, когда их результаты совпадают. Прежнее ошибочное поведение с результатом ‘lower’ + 0.5 исправлено.

Именованный аргумент keepdims передаётся методам пользовательского класса#

Функции NumPy, принимающие именованный аргумент keepdims, теперь передают его значение соответствующим методам подклассов ndarray. Раньше аргумент keepdims молча отбрасывался. Теперь эти функции ведут себя следующим образом:

  1. Если пользователь не предоставляет keepdims, ключевое слово не передается в основной метод.

  2. Любое предоставленное пользователем значение keepdims передается в качестве аргумента ключевого слова в метод.

Исключение возникает, если метод не поддерживает именованный аргумент keepdims, а пользователь явно передаёт keepdims.

Изменены следующие функции: sum , product , sometrue , alltrue , any , all , amax , amin , prod , mean , std , var , nanmin , nanmax , nansum , nanprod , nanmean , nanmedian , nanvar , nanstd

Изменён нейтральный элемент bitwise_and#

Ранее нейтральный элемент был равен 1, теперь он равен -1. Подробное объяснение см. в разделе улучшений.

ma.median выдаёт предупреждение и возвращает nan при обнаружении незамаскированных недопустимых значений#

Как и обычная медиана, ma.median теперь выдаёт RuntimeWarning и возвращает NaN для срезов, содержащих незамаскированный NaN.

Большая согласованность assert_almost_equal #

Проверка точности для скаляров изменена так, чтобы совпадать с проверкой для массивов. Теперь она имеет вид:

abs(actual - desired) < 1.5 * 10**(-decimal)

Это менее строгое условие, чем ранее описанное в документации, но оно соответствует прежней реализации assert_array_almost_equal. Из-за изменения реализации некоторые особенно чувствительные тесты могут начать завершаться неудачей.

Поведение предупреждений при тестировании NoseTester#

При raise_warnings="develop" все неперехваченные предупреждения теперь приводят к неудаче теста. Ранее в ошибки преобразовывались лишь некоторые из них. Предупреждения, которые не перехватываются и не преобразуются в ошибки (главным образом в режиме выпуска), показываются один раз за цикл тестирования, как при стандартных настройках Python.

assert_warns и декоратор deprecated точнее учитывают категорию предупреждения#

Функция и менеджер контекста assert_warns теперь точнее учитывают указанную категорию предупреждений. Предупреждения других категорий обрабатываются согласно внешним настройкам. Поэтому предупреждение неверной категории, игнорируемое вне контекста, может вообще не появиться. И наоборот, предупреждения, ранее ошибочно игнорировавшиеся, теперь могут отображаться или вызывать исключения. См. также новый менеджер контекста suppress_warnings. То же относится к декоратору deprecated.

C API#

Никаких изменений.

Новые возможности #

Именованный аргумент writeable для as_strided#

У np.lib.stride_tricks.as_strided появился именованный аргумент writeable. Если запись в возвращаемый массив не предполагается, задайте False, чтобы избежать случайной записи с непредсказуемыми последствиями.

Аргумент ключевого слова axes для rot90 #

Именованный аргумент axes в rot90 задаёт плоскость поворота массива. Значение по умолчанию — axes=(0,1), как и в исходной функции.

Обобщенный flip #

flipud и fliplr обращают порядок элементов массива вдоль axis=0 и axis=1 соответственно. Новая функция flip обращает порядок элементов вдоль любой заданной оси.

  • У np.count_nonzero появился параметр axis, позволяющий подсчитывать ненулевые элементы по осям, а не только во всём массиве, развёрнутом в одномерный.

Поддержка BLIS в numpy.distutils #

Добавлена поддержка сборки с реализацией BLAS из библиотеки BLIS. См. раздел [blis] в site.cfg.example в корне репозитория NumPy или исходного дистрибутива.

Хук в numpy/__init__.py для проверок, специфичных для дистрибутива#

Двоичным дистрибутивам NumPy может потребоваться при инициализации проверять возможности оборудования или загружать определённые библиотеки. Например, если NumPy поставляется с библиотекой BLAS, требующей инструкций SSE2, желательно проверить их наличие на компьютере пользователя, чтобы при отсутствии выдать понятное сообщение об ошибке.

В numpy/__init__.py добавлен механизм импорта файла numpy/_distributor_init.py. В стандартных исходниках NumPy он останется пустым, кроме строки документации, но создатели двоичных дистрибутивов смогут заменить его.

Добавлены новые функции с обработкой NaN: nancumsum и nancumprod#

Добавлены nancumsum и nancumprod для вычисления cumsum и cumprod с игнорированием NaN.

np.interp теперь может интерполировать комплексные значения. #

np.lib.interp(x, xp, fp) теперь допускает комплексные значения интерполируемого массива fp и выполняет интерполяцию с точностью complex128.

Добавлена новая функция вычисления значений полинома polyvalfromroots#

Новая функция polyvalfromroots вычисляет значения многочлена в заданных точках непосредственно по его корням. Это полезно для высоких степеней, когда переход к коэффициентам многочлена приводит к потере точности при машинных вычислениях.

Добавлена новая функция создания массивов geomspace#

Новая функция geomspace создаёт геометрическую прогрессию. Она похожа на logspace, но начальное и конечное значения задаются напрямую: geomspace(start, stop) ведёт себя как logspace(log10(start), log10(stop)).

Новый контекстный менеджер для тестирования предупреждений #

В утилиты тестирования добавлен новый менеджер контекста suppress_warnings. Он предназначен для надёжного тестирования предупреждений, в частности для их надёжной фильтрации и игнорирования. В версиях Python до 3.4.x использование фильтра «ignore» может быстро привести к тому, что тесты перестанут надёжно проверять эти или подобные предупреждения.

Этот менеджер контекста позволяет фильтровать и записывать предупреждения подобно контексту catch_warnings, но упрощает точную настройку фильтров. Вывод неотфильтрованных предупреждений и вложенные менеджеры контекста также работают ожидаемым образом. Кроме того, менеджер контекста можно использовать как декоратор — это удобно, когда в нескольких тестах нужно скрыть одно и то же предупреждение.

Добавлены новые функции массивов с маской ma.convolve и ma.correlate#

Эти функции служат обёртками для версий без маски, но передают маску в результат. Есть два режима такого распространения. По умолчанию замаскированные значения приводят к маскированию результата; в другом режиме результат маскируется только тогда, когда альтернативы нет.

Новая универсальная функция float_power#

Новая универсальная функция float_power похожа на power, но выполняет все вычисления с точностью не ниже float64. В списке рассылки NumPy долго обсуждалось возведение целых чисел в отрицательные целые степени; популярным было предложение, чтобы оператор __pow__ всегда возвращал результат с точностью не ниже float64. Функция float_power реализует этот вариант. Массивы объектов не поддерживаются.

np.loadtxt теперь поддерживает одно целое число как аргумент usecol #

Вместо использования usecol=(n,) для чтения n-го столбца файла теперь разрешено использовать usecol=n. Кроме того, сообщение об ошибке более удобно для пользователя, если в качестве индекса столбца передается нецелое число.

Улучшены автоматические методы выбора интервалов для histogram#

В histogram через аргумент bins добавлены методы оценки ‘doane’ и ‘sqrt’. Также добавлена поддержка гистограмм с ограниченным диапазоном и автоматическим определением интервалов.

np.roll теперь может выполнять циклический сдвиг по нескольким осям одновременно#

Аргументы shift и axis функции roll теперь согласуются друг с другом по правилам трансляции массивов, а сдвиг каждой указанной оси выполняется соответственно.

Метод __complex__ реализован для ndarrays #

Вызов complex() для массива из одного элемента теперь преобразует его в complex Python.

Объекты pathlib.Path теперь поддерживаются #.

Стандартные np.load, np.save, np.loadtxt, np.savez и подобные функции теперь могут принимать в качестве аргумента объекты pathlib.Path вместо имени файла или объекта открытого файла.

Новый атрибут bits для np.finfo #

Это согласует np.finfo с np.iinfo, у которого такой атрибут уже есть.

Новый аргумент signature для np.vectorize#

Этот аргумент позволяет векторизовать пользовательские функции с основными измерениями по образцу обобщённых универсальных функций NumPy. Так можно векторизовать гораздо более широкий класс функций. Например, произвольная метрика расстояния, преобразующая два вектора в скаляр, векторизуется с signature='(n),(n)->()'. Подробности см. np.vectorize.

Предупреждения py3kwarnings при делении целочисленных массивов#

Чтобы помочь людям перенести свои базы кода с Python 2 на Python 3, интерпретатор Python имеет удобную опцию -3, которая выдает предупреждения во время выполнения. Одно из его предупреждений касается целочисленного деления:

$ python -3 -c "2/3"

-c:1: DeprecationWarning: classic int division

В Python 3 новая семантика целочисленного деления распространяется и на массивы NumPy. В этой версии NumPy будет выдавать аналогичное предупреждение:

$ python -3 -c "import numpy as np; np.array(2)/np.array(3)"

-c:1: DeprecationWarning: numpy: classic int division

numpy.sctypes теперь включает bytes и в Python 3#

Раньше он включал str (байты) и unicode на Python2, но только str (unicode) на Python3.

Улучшения#

Изменён нейтральный элемент bitwise_and#

Прежний нейтральный элемент был равен 1, поэтому при использовании метода reduce все биты, кроме младшего (LSB), обнулялись. Новый нейтральный элемент — -1: на машинах с дополнительным кодом все его биты равны единице, что обеспечивает правильную работу.

Обобщённые универсальные функции теперь освобождают GIL#

Обобщённые универсальные функции, включая большую часть модуля linalg, теперь освобождают глобальную блокировку интерпретатора Python (GIL).

Кэши np.fft теперь ограничены по общему размеру и числу элементов#

Кэши в np.fft, ускоряющие повторные БПФ одной и той же длины, больше не могут расти неограниченно. Они заменены кэшами LRU: при достижении ограничения по объёму памяти или числу элементов автоматически удаляются элементы, к которым дольше всего не обращались.

Улучшена обработка строковых и Unicode dtype нулевой длины#

Исправлено несколько интерфейсов, явно запрещавших массивы со строковыми типами нулевой длины (то есть dtype('S0') или dtype('U0')), а также несколько ошибок обработки таких типов. В частности, ndarray.__new__ больше не преобразует неявно dtype('S0') в dtype('S1') при создании новых массивов (аналогичное изменение сделано для Unicode).

Целочисленные ufunc векторизованы с помощью AVX2#

Базовые целочисленные ufunc теперь используют инструкции AVX2, если их поддержка обнаружена у процессора во время выполнения. Пока это доступно только в сборках GCC.

Оптимизация порядка операций в np.einsum#

np.einsum теперь поддерживает аргумент optimize, оптимизирующий порядок тензорных свёрток. Например, np.einsum выполняет цепочку матричных произведений np.einsum(‘ij,jk,kl->il’, a, b, c) за один проход с вычислительной сложностью N^4. Но при optimize=True функция np.einsum создаёт промежуточный массив, снижая сложность до N^3, фактически как при np.dot(a, b).dot(c). Использование промежуточных тензоров для снижения сложности распространено на общую нотацию суммирования einsum. Подробнее см. np.einsum_path.

quicksort заменён на introsort#

Режим quicksort в np.sort и np.argsort теперь использует интросортировку: обычную быструю сортировку с переходом к пирамидальной, если разбиения недостаточно эффективны. Это сохраняет высокую производительность quicksort, улучшая худшее время выполнения с O(N^2) до O(N*log(N)).

ediff1d: улучшены производительность и обработка подклассов#

Для вычитания функция ediff1d использует массив вместо плоского итератора. Если to_begin или to_end не равен None, вычитание выполняется на месте, исключая копирование. Это также улучшает обработку некоторых подклассов, в частности astropy.Quantity: сначала создаётся и оборачивается весь массив, затем задаются начальные и конечные значения вместо использования concatenate.

Улучшенная точность ndarray.mean для массивов float16 #

Среднее массивов float16 теперь вычисляется в float32 для повышения точности. Это полезно, например, в пакетах вроде Theano, где точности float16 достаточно и желательно снизить потребление памяти.

Изменения#

В fromnumeric.py все методы объектов, подобных массивам, теперь вызываются с именованными аргументами#

Во внутренних вызовах многих методов объектов, подобных массивам, в fromnumeric.py использовались позиционные аргументы, хотя внешние сигнатуры предполагали передачу по имени. Это вызвало проблему совместимости с NumPy в зависимой библиотеке pandas. Теперь все такие методы в этом модуле вызываются с именованными аргументами.

Операции с объектами np.memmap в большинстве случаев возвращают массивы NumPy#

Раньше операции над объектом memmap ошибочно возвращали экземпляр memmap, даже если результат не был отображён в файл. Например, arr + 1 и arr + arr возвращали memmap, хотя память выходного массива не была связана с файлом. В версии 1.12 такие операции возвращают обычные массивы NumPy.

Кроме того, свёртка memmap (например, .sum(axis=None) теперь возвращает скаляр NumPy вместо нульмерного memmap.

Увеличен stacklevel предупреждений#

Значение stacklevel для предупреждений Python увеличено, чтобы большинство предупреждений указывало на вызвавшую их строку пользовательского кода, а не на строку выдачи предупреждения. Передача stacklevel теперь проверяется тестами, чтобы новые предупреждения получали аргумент stacklevel.

В результате предупреждения с фильтром “default” или “module” показываются по одному разу для каждой вызвавшей их строки пользовательского кода или каждого пользовательского модуля, а не только один раз в целом. В Python до 3.4 из-за этого могут появиться предупреждения, которые раньше ошибочно подавлялись; это может оказаться неожиданным, особенно при тестировании.
