Историческая справка: страница описывает NumPy 1.13.0. Слова «сейчас», «раньше» и «будет» относятся ко времени этого выпуска; описанное поведение может отличаться от NumPy 2.5.

Примечания к выпуску NumPy 1.13.0#

Данный релиз поддерживает Python 2.7 и 3.4 - 3.6.

Основные изменения#

  • Такие операции, как a + b + c, на некоторых платформах будут повторно использовать временные объекты, что приведет к меньшему использованию памяти и более быстрому выполнению.

  • Операции с изменением на месте проверяют пересечение памяти входов и выходов и при необходимости создают временные массивы.

  • Новый атрибут __array_ufunc__ предоставляет классам улучшенную возможность переопределять поведение ufunc по умолчанию.

  • Новая функция np.block для создания блочных массивов.

Новые функции #

  • Новая универсальная функция np.positive.

  • Новая универсальная функция np.divmod обеспечивает более эффективный divmod.

  • Новая универсальная функция np.isnat проверяет наличие специальных значений NaT.

  • Новый np.heaviside ufunc вычисляет функцию Хевисайда.

  • Новая функция np.isin, представляющая собой улучшенный вариант in1d.

  • Новая функция np.block для создания блочных массивов.

  • Новый PyArray_MapIterArrayCopyIfOverlap добавлен в NumPy C-API.

Подробности см. ниже.

Устаревающие возможности#

  • Вызов np.fix, np.isposinf и np.isneginf в форме f(x, y=out) объявлен устаревшим. Аргумент следует передавать как f(x, out=out), в соответствии с другими интерфейсами универсальных функций.

  • Использование номера типа C-API NPY_CHAR, устаревшего с версии 1.7, теперь будет вызывать предупреждения об устаревании во время выполнения. Расширения, созданные с использованием более старых версий f2py, необходимо перекомпилировать, чтобы удалить предупреждение.

  • При применении np.ma.argsort, np.ma.minimum.reduce и np.ma.maximum.reduce к массивам с более чем двумя измерениями следует явно указывать аргумент axis. Его значение по умолчанию (None) отличается от значений в остальной части NumPy (-1, 0 и 0 соответственно).

  • np.ma.MaskedArray.mini объявлен устаревшим, поскольку почти дублирует возможности np.MaskedArray.min. Полностью эквивалентное поведение можно получить с помощью np.ma.minimum.reduce.

  • Формы вызова np.ma.minimum и np.ma.maximum с одним аргументом объявлены устаревшими. В оригинале здесь отдельно указано: np.maximum. Вместо np.ma.minimum(x) теперь следует писать np.ma.minimum.reduce(x); это согласуется с использованием np.minimum.

  • Вызов ndarray.conjugate для нечисловых типов данных устарел (он должен соответствовать поведению np.conjugate, который выдает ошибку).

  • Вызов expand_dims с именованным аргументом axis, не удовлетворяющим -a.ndim - 1 <= axis <= a.ndim, объявлен устаревшим; a — массив, форма которого меняется.

Будущие изменения#

  • Присваивание между структурированными массивами с разными именами полей изменится в NumPy 1.14. Ранее полю dst присваивалось значение одноимённого поля src. В NumPy 1.14 присваивание будет выполняться по позиции: n-е поле dst получит значение n-го поля src. Предупреждение FutureWarning в NumPy 1.12 ошибочно сообщало, что изменение намечено на 1.13, а не на 1.14.

Изменения в системе сборки#

  • numpy.distutils теперь автоматически определяет зависимости C-файлов с помощью совместимых компиляторов GCC.

Примечания о совместимости#

Изменения типов ошибок#

  • numpy.hstack() теперь вызывает ValueError вместо IndexError при пустых входных данных.

  • Функции с аргументом axis теперь вызывают np.AxisError, если ось вне допустимого диапазона. Раньше в разных случаях вызывались IndexError или ValueError. Для обратной совместимости AxisError наследуется от обоих этих классов исключений.

Типы данных object, заданные кортежем#

Удалена поддержка некоторых редких форм dtype, которые допускались непреднамеренно: (old_dtype, new_dtype), где один из типов является object или содержит его. Исключение — форма (object, [('name', object)]): она по-прежнему поддерживается, поскольку известно о её реальном использовании.

DeprecationWarning заменено ошибкой#

Подробности смотрите в разделе «Изменения».

  • partition вызывает TypeError при нецелочисленном индексе разбиения.

  • NpyIter_AdvancedNew: ValueError при oa_ndim == 0 и значении op_axes, равном NULL

  • negative(bool_): применение унарного минуса к логическим значениям вызывает TypeError.

  • subtract(bool_, bool_), TypeError при вычитании логического значения из логического.

  • Для np.equal, np.not_equal тождество объектов не отменяет отрицательный результат сравнения.

  • np.equal, np.not_equal: идентичность объектов не отменяет сравнение, возвращающее небулев результат.

  • Устаревшее поведение булевой индексации больше не поддерживается. Подробности см. ниже в разделе изменений.

  • Удалены устаревшие np.alterdot() и np.restoredot().

FutureWarning об изменении поведения#

Подробности смотрите в разделе «Изменения».

  • numpy.average сохраняет подклассы

  • array == None и array != None выполняют поэлементное сравнение.

  • np.equal, np.not_equal, тождество объекта не переопределяет результат сравнения.

Объекты dtype теперь всегда имеют истинное логическое значение#

Раньше bool(dtype) использовало стандартную реализацию Python, проверявшую условие len(dtype) > 0. Поскольку для объектов dtype метод __len__ возвращает число полей записи, bool для скалярных dtype давал False, что было неочевидно. Теперь bool(dtype) == True для всех dtype.

__getslice__ и __setslice__ больше не нужны в подклассах ndarray#

При подклассировании np.ndarray в Python 2.7 больше не требуется реализация __*slice__ на производном классе, так как __*item__ будет правильно перехватывать эти вызовы.

Код, реализующий эти методы, продолжит работать как прежде. Код, вызывающий ndarray.__getslice__ (например, через super(...).__getslice__), теперь выдаёт DeprecationWarning; вместо этого следует использовать .__getitem__(slice(start, end)).

Индексирование MaskedArrays/Constants с помощью ... (многоточия) теперь возвращает MaskedArray#

Поведение соответствует np.ndarray и учитывает вложенные массивы в MaskedArray с dtype object, а также многоточие в сочетании с другими видами индексации.

Изменения C API#

GUfuncs на пустых массивах и удаление оси NpyIter #

Теперь разрешено удалять ось нулевого размера из NpyIter. Это может означать, что код, удаляющий оси из NpyIter, должен добавить дополнительную проверку при последующем доступе к удаленным измерениям.

Главное следующее изменение: gufunc теперь допускают внутренние измерения нулевого размера. Поэтому реализации gufunc должны учитывать пустое внутреннее измерение; раньше такой случай был невозможен и вызывал ошибку.

Для большинства обобщённых универсальных функций изменений не требуется. Однако функции с сигнатурами вроде (..., N, M) -> (..., M) теперь могут возвращать корректный результат при N=0 без дополнительного кода-обёртки.

PyArray_MapIterArrayCopyIfOverlap добавлен в NumPy C-API #

Аналогична PyArray_MapIterArray, но принимает дополнительный аргумент copy_if_overlap. Если copy_if_overlap != 0, проверяет, перекрывается ли память входного массива с памятью других массивов, и при необходимости создаёт копии, чтобы избежать проблем при изменении входных данных во время итерации. Дополнительные сведения см. в документации.

Новые возможности #

Добавлен __array_ufunc__#

Это переименованный и переработанный __numpy_ufunc__. Любой класс, независимо от наследования от ndarray, может определить этот метод или задать ему значение None для переопределения поведения универсальных функций NumPy. Механизм похож на __mul__ Python и другие методы бинарных операций. Подробности реализации и поведения см. в документации. API предварительный: обратная совместимость пока не гарантируется, поскольку отзывы могут привести к изменениям. Подробнее см. NEP 13 и документацию.

Новая универсальная функция positive#

Этот ufunc соответствует унарному +, но в отличие от + на ndarray он вызовет ошибку, если значения массива не поддерживают числовые операции.

Новая универсальная функция divmod#

Эта ufunc соответствует встроенной функции Python divmod и реализует divmod для массивов NumPy. Вызов np.divmod(x, y) эквивалентен (np.floor_divide(x, y), np.remainder(x, y)), но примерно вдвое быстрее раздельного вызова функций.

Универсальная функция np.isnat проверяет наличие специального значения NaT в данных datetime и timedelta#

Новая универсальная функция np.isnat находит специальные значения NaT в массивах datetime и timedelta аналогично np.isnan.

Универсальная функция np.heaviside вычисляет функцию Хевисайда#

Новая функция np.heaviside(x, h0) (ufunc) вычисляет функцию Хевисайда:

                   { 0   if x < 0,
heaviside(x, h0) = { h0  if x == 0,
                   { 1   if x > 0.

Функция np.block для создания блочных массивов#

Добавлена новая функция block в дополнение к функциям объединения vstack, hstack и stack. Она позволяет объединять массивы одновременно по нескольким осям. Синтаксис похож на создание массива, но элементы сами могут быть массивами. Например:

>>> A = np.eye(2) * 2
>>> B = np.eye(3) * 3
>>> np.block([
...     [A,               np.zeros((2, 3))],
...     [np.ones((3, 2)), B               ]
... ])
array([[ 2.,  0.,  0.,  0.,  0.],
       [ 0.,  2.,  0.,  0.,  0.],
       [ 1.,  1.,  3.,  0.,  0.],
       [ 1.,  1.,  0.,  3.,  0.],
       [ 1.,  1.,  0.,  0.,  3.]])

Хотя это в первую очередь полезно для блочных матриц, подход работает с массивами любой размерности.

Это похоже на квадратные скобки Matlab для создания матриц блоков.

Функция isin, улучшающая возможности in1d#

Новая функция isin проверяет, присутствует ли каждый элемент N-мерного массива где-либо во втором массиве. Это усовершенствование in1d, сохраняющее форму первого массива.

Устранение временных массивов#

На платформах с функцией backtrace NumPy старается не создавать временные массивы в выражениях с базовыми числовыми типами. Например, d = a + b + c преобразуется в d = a + b; d += c. Это может ускорить работу с большими массивами, поскольку уменьшается объём передачи данных через память.

Аргумент axes для unique#

Теперь для N-мерного массива с помощью numpy.unique можно выбрать ось поиска повторяющихся (N−1)-мерных элементов. Прежнее поведение сохраняется при axis=None (по умолчанию).

np.gradient теперь поддерживает данные с неравномерным шагом#

Теперь пользователи могут задавать неравномерный шаг данных. В частности, np.gradient теперь принимает:

  1. Один скаляр, задающий расстояние между точками для всех измерений.

  2. N скаляров, задающих постоянное расстояние между точками по каждому измерению, то есть dx, dy, dz, …

  3. N массивов для указания координат значений по каждому измерению F. Длина массива должна соответствовать размеру соответствующего измерения.

  4. Любое сочетание N скаляров и массивов со смыслом, описанным в пунктах 2 и 3.

Это означает, например, что теперь можно сделать следующее:

>>> f = np.array([[1, 2, 6], [3, 4, 5]], dtype=np.float_)
>>> dx = 2.
>>> y = [1., 1.5, 3.5]
>>> np.gradient(f, dx, y)
[array([[ 1. ,  1. , -0.5], [ 1. ,  1. , -0.5]]),
 array([[ 2. ,  2. ,  2. ], [ 2. ,  1.7,  0.5]])]

Поддержка возврата массивов с произвольным числом измерений в apply_along_axis#

Раньше функция, переданная apply_along_axis, могла возвращать только скаляр или одномерный массив. Теперь она может возвращать массив с любым числом измерений, включая 0. Форма этого массива заменяет ось массива, вдоль которой выполняется обход.

Свойство .ndim добавлено в dtype, чтобы дополнить .shape #

Для согласования с ndarray и broadcast, d.ndim является сокращением для len(d.shape).

Поддержка tracemalloc в Python 3.6 #

NumPy теперь поддерживает отслеживание памяти через модуль tracemalloc Python 3.6 и новее. Выделения памяти NumPy относятся к домену numpy.lib.tracemalloc_domain. В более ранних версиях Python они не отображаются в tracemalloc.

NumPy можно собрать с отладкой ослабленной проверки шагов массива#

Если включена ослабленная проверка шагов по памяти, установка переменной окружения NPY_RELAXED_STRIDES_DEBUG=1 приводит к сборке NumPy со значениями затронутых шагов, равными максимуму npy_intp. Это помогает обнаруживать некорректное использование шагов в зависимых проектах. Обычно такие случаи приводят к ошибке, но её тип зависит от кода; на практике встречались TypeError и OverflowError.

Раньше этот параметр был отключён в выпусках и включён в ветке master, а для переключения требовалось редактировать код. Теперь он отключён по умолчанию, но его можно включить для тестовых сборок.

Улучшения#

Поведение Ufunc для перекрывающихся входов #

В прежних версиях NumPy операции ufunc с перекрывающейся памятью входных и выходных операндов давали неопределённые результаты из-за зависимостей данных. В NumPy 1.13.0 их результат теперь определяется как результат эквивалентной операции без перекрытия памяти.

В затронутых операциях теперь при необходимости создаются временные копии, устраняющие зависимость от данных. Поскольку выявление таких случаев вычислительно затратно, применяется эвристика, которая изредка может создавать ненужные временные копии. Если зависимость достаточно проста для анализа и эвристика устанавливает, что копирование не требуется, временные копии не создаются даже при перекрытии массивов. Например, ``np.add(a, b, out=a)`` выполняется без копирования.

Чтобы проиллюстрировать ранее неопределенную операцию:

>>> x = np.arange(16).astype(float)
>>> np.add(x[1:], x[:-1], out=x[1:])

В NumPy 1.13.0 последняя строка гарантированно будет эквивалентна:

>>> np.add(x[1:].copy(), x[:-1].copy(), out=x[1:])

Аналогичная операция с простой непроблемной зависимостью данных:

>>> x = np.arange(16).astype(float)
>>> np.add(x[1:], x[:-1], out=x[:-1])

Он будет продолжать производить те же результаты, что и в предыдущих версиях NumPy, и не будет включать ненужные временные копии.

Изменение также относится к бинарным операциям на месте, например:

>>> x = np.random.rand(500, 500)
>>> x += x.T

Теперь эта операция гарантированно эквивалентна x[...] = x + x.T, тогда как в прежних версиях NumPy результат был неопределён.

Частичная поддержка 64-разрядных расширений f2py с MinGW#

Расширения, включающие библиотеки Fortran, теперь можно собирать бесплатным набором инструментов MinGW также и для Python 3.5. Это лучше всего работает для расширений, которые преимущественно выполняют вычисления и лишь ограниченно используют библиотеку времени выполнения — например, для чтения и записи файлов. Потребность в Mingwpy при этом сохраняется: при активном использовании библиотеки времени выполнения вы, скорее всего, столкнётесь с проблемами. Это временное решение до появления полностью работоспособного Mingwpy.

Расширения можно также компилировать средствами MinGW с библиотекой времени выполнения из переносимого дистрибутива WinPython 3.4. Это бывает полезно для программ с интерфейсом PySide1/Qt4.

Повышение производительности packbits и unpackbits#

Функции numpy.packbits с логическим входом и numpy.unpackbits оптимизированы и теперь значительно быстрее обрабатывают непрерывно расположенные в памяти данные.

Исправление сведений о числах long double на PPC#

В предыдущих версиях NumPy функция finfo возвращала неверные сведения о формате double double типа longdouble на Power PC (PPC). Алгоритм NumPy не справлялся с переменным числом значащих цифр, характерным для PPC long doubles. В этом выпуске вместо сбойного алгоритма применяется эвристическое обнаружение формата double double на PPC. Дополнительный эффект: finfo работает быстрее, чем в предыдущих выпусках.

Улучшенное представление repr по умолчанию для подклассов ndarray#

Для подклассов ndarray без собственной реализации repr теперь правильно расставляются отступы в строках данных и типа.

Более надёжное сравнение маскированных массивов#

Сравнения массивов с маской некорректно работали с замаскированными скалярами и завершались ошибкой для структурированных массивов с числом измерений больше одного. Обе проблемы решены. При сравнении структурированных массивов замаскированные поля теперь правильно игнорируются: результат означает равенство, если равны все поля, незамаскированные в обоих массивах. Это соответствует сравнению неструктурированных массивов с маской с последующим вызовом .all() вдоль некоторой оси.

np.matrix с булевыми элементами теперь можно создавать с помощью синтаксиса строк #

np.matrix завершалась ошибкой при использовании с логическими значениями, например np.matrix('True'). Теперь это работает как ожидается.

Больше операций linalg теперь поддерживают пустые векторы и матрицы#

Все следующие функции из np.linalg теперь работают с входными массивами, у которых размер в последних двух измерениях равен 0: det, slogdet, pinv, eigvals, eigvalsh, eig, eigh.

Версия LAPACK в комплекте теперь 3.2.2 #.

Для систем без установленной библиотеки LAPACK в NumPy включена её минимальная реализация под именем lapack_lite. Она обновлена с LAPACK 3.0.0 (30 июня 1999 года) до LAPACK 3.2.2 (30 июня 2010 года). Подробности всех связанных с этим изменений см. в журналах изменений LAPACK.

Новые возможности через numpy не предоставляются, но исправлены ошибки размеров рабочей области и в некоторых случаях используются более быстрые алгоритмы.

reduce для np.hypot.reduce и np.logical_xor допускается в большем числе случаев#

Теперь это работает и с пустыми массивами, возвращая 0, и позволяет выполнять свёртку по нескольким осям. Раньше в этих случаях возникало исключение ValueError.

Лучше repr объектных массивов #

Объектные массивы, которые содержат себя, больше не вызывают рекурсионную ошибку.

Массивы объектов с элементами типа list теперь выводятся так, что различие между двумерным массивом объектов и одномерным массивом списков очевидно.

Изменения#

argsort для массивов с маской использует те же значения аргументов по умолчанию, что и sort#

По умолчанию argsort теперь помещает замаскированные значения в конец отсортированного массива, как это уже делала sort. Кроме того, аргумент end_with добавлен в argsort для согласования с sort. Он добавлен не в конец списка аргументов, поэтому нарушается работа кода, передававшего fill_value позиционно.

average сохраняет подклассы #

Для подклассов ndarray функция numpy.average теперь возвращает экземпляр подкласса, как и большинство других функций NumPy, например mean. Поэтому вызовы, ранее возвращавшие скаляр, теперь также могут возвращать скалярный массив соответствующего подкласса.

array == None и array != None выполняют поэлементное сравнение#

Ранее эти операции возвращали скаляры False и True соответственно.

np.equal, np.not_equal для объектных массивов игнорируют идентичность объектов#

Раньше эти функции всегда считали равными ссылки на один и тот же объект. Это обходило ошибки сравнения, случаи, когда сравнение не возвращает логическое значение (например, для массивов NumPy), и случаи, когда равенство не совпадает с идентичностью объектов, например для NaN.

Изменения логической индексации#

  • Логические объекты, подобные массивам, например списки значений bool Python, всегда рассматриваются как логические индексы.

  • Логические скаляры, включая True в Python, допустимы как логические индексы и никогда не трактуются как целые числа.

  • Размеры логических индексных массивов должны совпадать с размерами индексируемых осей.

  • При присваивании логическая маска в левой части должна соответствовать индексируемым измерениям массива, а правая часть — допускать присваивание выбранным элементам. Примечание переводчика: в оригинале ошибочно требуется совпадение размеров логических индексов с правой частью. Маска сопоставляется с исходным массивом; справа допустимы, например, скаляр или массив длины, равной числу выбранных элементов.

  • Логическая индексация нульмерного массива возвращает новый одномерный массив. Поэтому array(1)[array(True)] даёт array([1]), а не исходный массив.

Поведение np.random.multivariate_normal при некорректной ковариационной матрице#

Теперь можно настроить поведение функции при работе с ковариационной матрицей, используя два новых ключевых аргумента:

  • tol задаёт допуск при проверке положительной полуопределённости ковариационной матрицы.

  • check_valid можно использовать для настройки того, что будет делать функция при наличии матрицы, которая не является положительно полуопределенной. Допустимые параметры: ignore, warn и raise. Значение по умолчанию warn сохраняет поведение, использовавшееся в предыдущих выпусках.

assert_array_less теперь сравнивает np.inf и -np.inf#

Ранее np.testing.assert_array_less игнорировал все бесконечные значения, что противоречило документации и интуитивным ожиданиям. Теперь -inf < x < inf считается True для любого вещественного x, а все остальные случаи не проходят проверку.

assert_array_ и assert_equal для массивов с маской подавляют меньше предупреждений#

Некоторые предупреждения, ранее подавлявшиеся функциями assert_array_, больше не подавляются. В большинстве случаев они обоснованны и при появлении потребуют изменений в тестах, использующих эти функции. Версия assert_equal для массивов с маской может выдавать предупреждения при сравнении NaT. Сейчас она не обрабатывает NaT или NaN особым образом, поэтому при появлении предупреждения из-за этого изменения, возможно, лучше временно отказаться от её использования.

Значение атрибута offset в объектах memmap#

Атрибут offset объекта memmap теперь содержит смещение в файле. Поведение изменилось только для смещений, превышающих mmap.ALLOCATIONGRANULARITY.

np.real и np.imag возвращают скаляры для скалярных входных данных#

Ранее np.real и np.imag возвращали объекты массивов при скалярных входных данных, что не соответствовало поведению других функций, таких как np.angle и np.conj.

Классы для удобной работы с многочленами нельзя передавать универсальным функциям#

Класс ABCPolyBase, от которого наследуются вспомогательные классы, задаёт __array_ufun__ = None, чтобы отказаться от поддержки универсальных функций. Передача экземпляра вспомогательного класса полиномов в универсальную функцию теперь вызывает TypeError.

Аргументы вывода ufunc могут быть кортежами и при вызове методов ufunc#

При вызове универсальных функций с несколькими результатами уже можно было и рекомендовалось передавать в аргумент out кортеж. Теперь это разрешено и для выходных аргументов методов reduce, accumulate и reduceat. Это главным образом нужно для совместимости с __array_ufunc; универсальных функций с несколькими результатами, поддерживающих эти методы, пока нет. Примечание переводчика: без уточнения про методы последнее утверждение оригинала неверно — например, modf уже тогда имела два результата. Имя протокола в оригинале также сокращено; правильно __array_ufunc__.
