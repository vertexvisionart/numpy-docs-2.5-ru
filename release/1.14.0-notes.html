Примечания к выпуску NumPy 1.14.0#

NumPy 1.14.0 — результат семи месяцев работы: он содержит множество исправлений и новых возможностей, а также изменения с возможным нарушением совместимости. Самое заметное — новый стиль вывода массивов и скаляров, влияющий на doctest. Ниже описано, как при необходимости сохранить прежний стиль.

Важное для дальнейшего развития решение касается графика прекращения поддержки Python 2.7 к 2020 году. Все выпуски 2018 года будут поддерживать Python 2.7, а последний станет выпуском с длительной поддержкой и исправлениями до конца 2019 года. Новые выпуски 2019 года больше не будут поддерживать 2.7. Подробнее см. NEP 14. Примечание переводчика: в оригинале ошибочно указано NEP 12; ссылка ведёт на NEP 14 о прекращении поддержки Python 2.7.

Данный релиз поддерживает Python 2.7 и 3.4 - 3.6.

Основные изменения#

  • Функция np.einsum использует BLAS, когда это возможно.

  • genfromtxt, loadtxt, fromregex и savetxt теперь обрабатывают файлы в любой кодировке, поддерживаемой Python.

  • Значительные улучшения вывода массивов и скаляров NumPy.

Новые функции #

  • parametrize: декоратор добавлен в numpy.testing

  • chebinterpolate: интерполяция функции в узлах Чебышёва.

  • format_float_positional и format_float_scientific: однозначное форматирование скаляров с плавающей точкой с управлением округлением и заполнением.

  • PyArray_ResolveWritebackIfCopy и PyArray_SetWritebackIfCopyBase — новые функции C-API, полезные для достижения совместимости с PyPy.

Устаревающие возможности#

  • Использование объектов np.bool_ вместо целых чисел устарело. Раньше operator.index(np.bool_) был законным и допускал такие конструкции, как [1, 2, 3][np.True_]. Это вводило в заблуждение, поскольку его поведение отличалось от np.array([1, 2, 3])[np.True_].

  • Проверка логического значения пустого массива объявлена устаревшей. Чтобы проверить, что массив непустой, используйте array.size > 0.

  • Вызов np.bincount с minlength=None объявлен устаревшим. Вместо него используйте minlength=0.

  • Вызов np.fromstring со стандартным значением аргумента sep объявлен устаревшим. Если аргумент не задан, используется некорректный вариант np.frombuffer: он без предупреждения принимает строки Unicode, кодирует их в UTF-8 в Python 3 или в кодировку по умолчанию в Python 2 и рассматривает результат как двоичные данные. Для чтения двоичных данных следует напрямую использовать np.frombuffer.

  • Параметр style функции array2string объявлен устаревшим для нового режима вывода.

  • PyArray_SetUpdateIfCopyBase объявлена устаревшей. В NumPy >= 1.14 используйте PyArray_SetWritebackIfCopyBase; подробности см. ниже в разделе C API changes.

  • Использование массивов UPDATEIFCOPY является устаревшим, см. C API changes ниже для деталей. Мы не будем отказываться от поддержки этих массивов, но они не совместимы с PyPy.

Будущие изменения#

  • np.issubdtype перестанет понижать тип аргументов, задающих dtype. Можно ожидать, что issubdtype(np.float32, 'float64') и issubdtype(np.float32, np.float64) означают одно и то же. Однако существовало недокументированное исключение: первый вызов преобразовывался в issubdtype(np.float32, np.floating), что неожиданно давало True.

    Теперь такое преобразование сопровождается предупреждением, объясняющим его суть. В будущем преобразование отключат, и первый пример станет эквивалентен второму.

  • Значение по умолчанию np.linalg.lstsq для rcond изменится. Новое стандартное значение параметра rcond функции np.linalg.lstsq будет равно машинной точности, умноженной на максимальный размер входного массива по осям. Если rcond не передан явно, выдаётся FutureWarning.

  • a.flat.__array__() будет возвращать доступную для записи копию a, если a не расположен непрерывно в памяти. Ранее возвращался массив UPDATEIFCOPY, если a был доступен для записи. В настоящее время возвращается копия, недоступная для записи. Обсуждение проблемы см. в gh-7054.

  • Метод .item неструктурированного массива void будет возвращать bytes. В будущем вызов .item() для массивов или скаляров типа np.void вернёт bytes вместо буфера или массива int, как и bytes(void_scalar). Это может затронуть код, считавший результат изменяемым: теперь он таким не будет. Сейчас в таком случае выдаётся FutureWarning.

Примечания о совместимости#

Маска представления массива с маской теперь тоже является представлением, а не копией#

В NumPy 1.11.x об этом изменении выдавалось FutureWarning. Теперь изменение маски представления массива с маской распространяется на исходный массив; раньше этого не происходило. В частности, это касается срезов. Однако если маска исходного массива равна nomask, изменение маски представления пока не работает корректно. Подробное обсуждение см. в gh-5580. Прежнее поведение с отдельной копией маски можно получить, вызвав метод unshare_mask у представления.

np.ma.masked больше недоступен для записи#

Попытки изменить константу masked теперь приводят к ошибке, поскольку базовые массивы помечены как доступные только для чтения. Раньше можно было обойтись:

# emulating a function that sometimes returns np.ma.masked
val = random.choice([np.ma.masked, 10])
var_arr = np.asarray(val)
val_arr += 1  # now errors, previously changed np.ma.masked.data
Комментарии к примеру на русском
  • Имитируем функцию, иногда возвращающую np.ma.masked
  • Теперь вызывает ошибку; раньше менял np.ma.masked.data

Изменились функции np.ma, формирующие fill_value#

Ранее np.ma.default_fill_value возвращал нульмерный массив, а np.ma.minimum_fill_value и np.ma.maximum_fill_value — кортеж значений полей. Теперь все три метода возвращают структурированный объект np.void, такой же, как в атрибуте .fill_value.

Кроме того, определение dtype теперь совпадает с np.array: для скаляра Python x результаты maximum_fill_value(x) и maximum_fill_value(np.array(x)) всегда одинаковы. Раньше x = long(1) в Python 2 нарушал это правило.

a.flat.__array__() возвращает массивы только для чтения, если данные a расположены не непрерывно#

В будущем массив UPDATEIFCOPY, ранее возвращавшийся, когда a не был непрерывно расположен в памяти, планируется заменить копией с возможностью записи. Эта временная мера призвана предупредить пользователей, ожидающих изменения исходного массива в такой ситуации, что этого больше не будет. Скорее всего, это будет заметно при использовании выражений вида np.asarray(a.flat) или при передаче a.flat в качестве параметра out универсальной функции.

np.tensordot теперь возвращает массив нулей при свёртке по измерению нулевой длины#

Раньше np.tensordot вызывал ValueError при свёртке по измерению длины 0. Теперь он возвращает массив нулей, что соответствует поведению np.dot и np.einsum.

Реорганизация numpy.testing#

Это, как ожидается, не вызовет проблем, но, возможно, что-то было упущено. Если вы испытываете неожиданные проблемы с импортом с помощью numpy.testing дайте нам знать.

np.asfarray больше не принимает через аргумент dtype значения, не являющиеся типами данных#

Раньше допускалось dtype=some_array, что подразумевало dtype=some_array.dtype. Это поведение не было документировано, не встречалось в других функциях NumPy и при использовании, скорее всего, указывало на опечатку.

Для одномерных данных np.linalg.norm сохраняет входные типы с плавающей точкой даже при произвольных порядках нормы#

Раньше при передаче произвольных порядков тип повышался до float64, хотя в простых случаях этого не происходило:

>>> f32 = np.float32([[1, 2]])
>>> np.linalg.norm(f32, 2.0, axis=-1).dtype
dtype('float32')
>>> np.linalg.norm(f32, 2.0001, axis=-1).dtype
dtype('float64')  # numpy 1.13
dtype('float32')  # numpy 1.14
Комментарии к примеру на русском
  • NumPy 1.13
  • NumPy 1.14

Это изменение касается только массивов float32 и float16.

count_nonzero(arr, axis=()) теперь выполняет подсчёт без свёртки по осям, а не по всем осям#

В остальных случаях axis==() всегда означает «ни одной оси», но count_nonzero особым образом трактовал это как «все оси». Это было несогласованно и неожиданно. Правильный способ подсчёта по всем осям всегда состоял в передаче axis == None.

Файлы __init__.py добавлены в тестовые каталоги #

Это обеспечивает совместимость с pytest, когда в разных каталогах есть тестовые файлы с одинаковыми именами. В результате run_module_suite больше не работает: python <path-to-test-file> вызывает ошибку.

.astype(bool) для неструктурированных массивов типа void теперь вызывает bool для каждого элемента#

В Python 2 void_array.astype(bool) всегда возвращал массив True, если dtype не был V0. В Python 3 эта операция обычно приводила к аварийному завершению. Теперь поведение astype соответствует bool(np.void): буфер из одних нулей считается ложным, любой другой — истинным. Проверку V0 по-прежнему можно выполнить с помощью arr.dtype.itemsize == 0.

MaskedArray.squeeze больше не возвращает np.ma.masked#

Согласно документации, np.squeeze возвращает представление, но версия для массивов с маской иногда возвращала masked, который представлением не является. Теперь результат всегда является представлением исходного массива с маской. Это нарушает работу кода с проверкой masked_arr.squeeze() is np.ma.masked, но исправляет код, записывающий данные в результат squeeze().

Переименован первый параметр can_cast от from до from_ #

Предыдущее имя параметра from является зарезервированным ключевым словом в Python, что затрудняло передачу аргумента по имени. Это было исправлено путем переименования параметра в from_.

isnat вызывает TypeError при передаче неверного типа#

Раньше ufunc isnat вызывал ValueError, если передавались переменные, не имеющие типа datetime или timedelta. Теперь вызывается TypeError.

dtype.__getitem__ вызывает TypeError при передаче неверного типа#

Раньше при индексировании числом с плавающей точкой объект dtype возбуждал исключение ValueError.

Пользовательские типы теперь должны реализовать __str__ и __repr__ #

Раньше пользовательские типы могли использовать стандартные реализации __str__ и __repr__ из NumPy, если собственные отсутствовали. Эта возможность удалена: теперь используются стандартные реализации Python object.__str__ и object.__repr__.

Многочисленные изменения вывода массивов; прежнее поведение можно вернуть новым режимом “legacy”#

Представления str и repr массивов ndarray и скаляров NumPy изменены различными способами. Эти изменения, вероятно, нарушат doctest-тесты в проектах пользователей.

Новое поведение можно отключить и в основном воспроизвести поведение NumPy 1.13, включив новый режим вывода «legacy» для версии 1.13. Для этого вызовите np.set_printoptions(legacy="1.13") или используйте новый аргумент legacy функции np.array2string: np.array2string(arr, legacy='1.13').

Таким образом, основные изменения заключаются в следующем:

  • Для типов с плавающей точкой:

    • В repr массивов с плавающей точкой теперь часто опускается пробел, раньше выводившийся на месте знака. См. новый параметр sign функции np.set_printoptions.

    • Для десятичного представления массивов и скаляров с плавающей точкой используется новый алгоритм, дающий кратчайшее однозначное представление. Обычно он сокращает дробный вывод float16, а иногда также float32 и float128. Вывод float64 не должен измениться. См. новый параметр floatmode функции np.set_printoptions.

    • При выводе массивов с плавающей запятой в экспоненциальной записи больше не используется фиксированная точность: теперь выбирается кратчайшее представление, однозначно определяющее значение.

    • Строковое представление str скаляров с плавающей точкой больше не обрезается в Python 2.

  • Для других типов данных:

    • Неконечные комплексные скаляры выводятся как nanj вместо nan*j.

    • Значения NaT в массивах даты и времени теперь выравниваются правильно.

    • Массивы и скаляры типа данных np.void теперь печатаются с использованием шестнадцатеричной нотации.

  • Для переноса строк:

    • Часть dtype в представлении ndarray теперь переносится на следующую строку, если не помещается в последней строке вывода массива.

    • Параметр форматирования linewidth теперь всегда учитывается. Ширина строк repr или str массива не превышает его значение, если только отдельный элемент сам не слишком широк.

    • Последняя строка строкового представления массива никогда не содержит больше элементов, чем предыдущие строки.

    • Если элементы слишком широки, в первую строку больше не вставляется лишний пробел.

  • Для сокращённого вывода длинных массивов с помощью ...:

    • Завершающая запятая больше не вставляется для str . Раньше str(np.arange(1001)) давал '[   0    1    2 ...,  998  999 1000]' , в котором была дополнительная запятая.

    • Для массивов с двумя и более измерениями при выводе ... отдельной строкой для сокращённого отображения любой оси, кроме последней, после этой строки теперь добавляется столько же переводов строки, сколько стоит перед ней, а завершающий пробел удаляется.

  • При выводе массивов MaskedArray элементы теперь разделяются запятыми, всегда указывается dtype, а элементы длинных массивов корректно переносятся на несколько строк. Если у массива больше одного измерения, его атрибуты выводятся в новом стиле с выравниванием по левому краю.

  • При выводе массивов recarray больше нет лишнего пробела перед dtype, а перенос строк учитывает правильное число столбцов.

  • Нульмерные массивы больше не имеют собственных особых реализаций str и repr. Аргумент style функции np.array2string объявлен устаревшим.

  • Для массивов типа bool тип данных не указывается в repr.

  • Пользовательские dtypes (подклассы np.generic) теперь должны реализовать __str__ и __repr__.

Некоторые изменения подробнее описаны ниже. Чтобы сохранить прежнее поведение для doctest-тестов или по другим причинам, можно сделать следующее:

# FIXME: We need the str/repr formatting used in Numpy < 1.14.
try:
    np.set_printoptions(legacy='1.13')
except TypeError:
    pass
Комментарии к примеру на русском
  • FIXME: нужно форматирование str/repr из NumPy < 1.14.

Изменения C API#

Совместимая с PyPy альтернатива массивам UPDATEIFCOPY #

Массивы UPDATEIFCOPY — непрерывные копии существующих массивов, возможно другой формы. Их содержимое копируется обратно в оригинал, когда счётчик ссылок становится нулевым и копии освобождаются. Поскольку PyPy не использует подсчёт ссылок, этот механизм с ним работает некорректно. NumPy постепенно устраняет его внутреннее использование; две новые функции C API,

  • PyArray_SetWritebackIfCopyBase

  • PyArray_ResolveWritebackIfCopy,

добавлены вместе с дополнительным флагом NPY_ARRAY_WRITEBACKIFCOPY. Для использования новой возможности при создании массивов также нужно заменить некоторые флаги: NPY_ARRAY_INOUT_ARRAY на NPY_ARRAY_INOUT_ARRAY2 и NPY_ARRAY_INOUT_FARRAY на NPY_ARRAY_INOUT_FARRAY2. У массивов, созданных с новыми флагами, будет семантика WRITEBACKIFCOPY.

Если совместимость с PyPy не требуется, новые функции можно не использовать, хотя будет выдаваться DeprecationWarning. Если вы хотите обеспечить совместимость с PyPy, подробнее об этих функциях и их применении см. документацию C API и пример в разделе о создании расширений.

Новые возможности #

Аргумент кодировки для функций текстового ввода-вывода#

genfromtxt, loadtxt, fromregex и savetxt теперь могут обрабатывать файлы в любой кодировке, поддерживаемой Python, с помощью аргумента encoding. Для обратной совместимости по умолчанию используется специальное значение bytes: текст по-прежнему обрабатывается как необработанные байты, а пользовательским преобразователям передаются байты в кодировке latin1. Любое другое значение (включая None для системной кодировки по умолчанию) включает настоящий текстовый ввод-вывод: результирующие массивы содержат строки Unicode вместо байтов.

Внешние плагины nose используются numpy.testing.Tester #

numpy.testing.Tester теперь распознаёт плагины nose, не входящие в стандартную поставку nose. Например, nose-timer можно использовать так: np.test(extra_argv=['--with-timer', '--timer-top-n', '20']) — чтобы узнать время выполнения 20 самых медленных тестов. Также добавлен именованный аргумент timer в Tester.test, поэтому np.test(timer=20) тоже выводит 20 самых медленных тестов.

Декоратор parametrize добавлен в numpy.testing #

Базовый декоратор parametrize теперь доступен в numpy.testing. Он предназначен для переписывания тестов на основе yield, объявленных устаревшими в pytest, чтобы облегчить будущий переход на pytest. Тестовая система nose не поддерживается уже несколько лет и выглядит заброшенной.

Новый декоратор parametrize не обладает всеми возможностями аналога из pytest. Он не работает с классами, не поддерживает вложенность и не подставляет имена переменных. Тем не менее его должно быть достаточно для переписывания тестов NumPy.

Функция chebinterpolate добавлена в numpy.polynomial.chebyshev #

Новая функция chebinterpolate интерполирует заданную функцию в узлах Чебышёва первого рода. Новый метод класса Chebyshev.interpolate поддерживает интерполяцию на произвольных интервалах с помощью масштабированных и сдвинутых узлов Чебышёва первого рода.

Поддержка чтения текстовых файлов, сжатых lzma, в Python 3#

С версиями Python, содержащими модуль lzma, функции ввода текста теперь могут прозрачно считывать из файлов с расширением xz или lzma.

Опция sign добавлена в np.setprintoptions и np.array2string #

Параметр управляет выводом знака чисел с плавающей запятой и принимает символы «-», «+» или « » (пробел). При «+» NumPy всегда выводит знак положительных значений; при « » — пробел на месте их знака; при «-» — опускает знак положительных значений. Новое значение по умолчанию — «-».

Новое значение по умолчанию меняет вывод чисел с плавающей точкой по сравнению с NumPy 1.13. Прежнее поведение можно получить в режиме вывода «legacy» для 1.13; см. примечания о совместимости выше.

Опция hermitian добавлена в np.linalg.matrix_rank #

Новая опция hermitian позволяет выбирать между стандартным расчетом ранга матрицы на основе SVD и более эффективным методом, основанным на собственных значениях, для симметричных/эрмитовых матриц.

Опции threshold и edgeitems добавлены в np.array2string #

Раньше эти параметры задавались через np.set_printoptions; теперь их можно менять для каждого отдельного вызова с помощью аргументов np.array2string.

concatenate и stack получили аргумент out #

Предварительно выделенный буфер желаемого dtype теперь можно использовать для вывода этих функций.

Поддержка компилятора PGI flang в Windows#

Компилятор PGI flang — это интерфейсная часть Fortran для LLVM, выпущенная NVIDIA по лицензии Apache 2. Его можно вызвать с помощью

python setup.py config --compiler=clang --fcompiler=flang install

Опыт работы с этим новым компилятором невелик, поэтому любые отзывы людей, использующих его, будут оценены по достоинству.

Улучшения#

Число степеней свободы числителя в random.noncentral_f должно быть лишь положительным.#

До версии NumPy 1.14.0 степени свободы числителя должны были быть > 1, но распределение справедливо для значений > 0, что является новым требованием.

GIL освобождается во всех вариантах np.einsum#

До NumPy 1.14.0 некоторые структуры циклов, имеющие ускоренную реализацию, не освобождали GIL. Это упущение исправлено.

Функция np.einsum по возможности использует BLAS и выполняет оптимизацию по умолчанию#

Функция np.einsum теперь в подходящих случаях вызывает np.tensordot. Поскольку np.tensordot по возможности использует BLAS, это ускоряет вычисления. По умолчанию np.einsum также пытается оптимизировать вычисления: накладные расходы малы по сравнению с возможным ускорением.

f2py теперь обрабатывает массивы размерности 0 #

f2py теперь допускает выделение памяти для нульмерных массивов. Это позволяет зависимым проектам более единообразно обрабатывать особые случаи.

numpy.distutils поддерживает совместное использование MSVC и mingw64-gfortran#

NumPy distutils теперь поддерживает совместное использование Mingw64 gfortran и MSVC. Это позволяет создавать в Windows модули расширения Python с кодом Fortran, совместимые с двоичными сборками Python.org. Поддерживаются не все сценарии, но наиболее распространённые способы создания обёрток Fortran для Python работают.

Компиляция в этом режиме обычно включается автоматически; её можно выбрать с помощью параметров --fcompiler и --compiler команды setup.py. Также поддерживается компоновка кода Fortran со статической библиотекой OpenBLAS; по умолчанию ищется совместимый с gfortran статический архив openblas.a.

np.linalg.pinv теперь работает со стопками матриц#

Раньше он был ограничен одним 2D-массивом.

numpy.save выравнивает данные по границе 64 байт вместо 16#

При сохранении массивов NumPy в формате npy с помощью numpy.save перед данными массива добавляется заполнение для выравнивания по границе 64 байтов. Ранее выравнивание составляло лишь 16 байтов, иногда меньше из-за ошибки в коде для версии 2. Теперь оно равно 64 байтам, что соответствует самому широкому распространённому набору инструкций SIMD и наиболее частому размеру строки кэша. Это упрощает использование файлов npy в программах, открывающих их через mmap, особенно в Linux, где смещение mmap должно быть кратно размеру страницы.

Файлы NPZ теперь можно писать без использования временных файлов #

В Python 3.6+ numpy.savez и numpy.savez_compressed теперь пишут непосредственно в ZIP-файл, не создавая промежуточных временных файлов.

Улучшенная поддержка пустых структурированных и строковых типов #

Структурированные типы могут содержать ноль полей, а строковые типы могут содержать ноль символов. Строки нулевой длины по-прежнему не могут быть созданы напрямую и должны создаваться с помощью структурированных типов данных:

str0 = np.empty(10, np.dtype([('v', str, N)]))['v']
void0 = np.empty(10, np.void)

С ними можно было работать и раньше, но теперь для этих массивов поддерживаются следующие операции:

  • arr.sort()

  • arr.view(bytes)

  • arr.resize(…)

  • pickle.dumps(arr)

Поддержка decimal.Decimal в np.lib.financial#

Если не оговорено иное, все функции пакета financial теперь поддерживают встроенный тип decimal.Decimal.

Вывод чисел с плавающей точкой теперь использует алгоритм dragon4 для получения кратчайшего десятичного представления#

str и repr чисел с плавающей запятой разрядностью 16, 32, 64 и 128 бит теперь используют кратчайшее десятичное представление, однозначно отличающее значение от других значений того же типа. Ранее это относилось только к float64. Представления остальных типов с плавающей запятой теперь часто короче, чем в NumPy 1.13. При выводе массивов в экспоненциальной записи также используется кратчайшее представление вместо прежней фиксированной точности.

Кроме того, str скаляров с плавающей точкой больше не усекается в Python 2, в отличие от объектов float в Python 2. Теперь значения np.double имеют такие же представления str и repr, как float в Python 3.

Для генерации этих десятичных представлений предоставляются новые функции np.format_float_scientific и np.format_float_positional.

Новый параметр floatmode, добавленный в np.set_printoptions и np.array2string, управляет однозначностью представления и округлением выводимых элементов массива. Новое значение по умолчанию — floatmode='maxprec' с precision=8: выводится не более восьми знаков после десятичной точки или меньше, если для однозначного представления элемента достаточно меньшего числа знаков. Новый полезный режим floatmode="unique" выводит столько цифр, сколько необходимо для однозначного представления элементов массива.

Комплексные скаляры NumPy со значениями вроде inf*j или nan*j теперь выводятся как infj и nanj, как у встроенного типа Python complex.

Классы FloatFormat и LongFloatFormat устарели, и их следует заменить на FloatingFormat. Аналогично ComplexFormat и LongComplexFormat следует заменить на ComplexFloatingFormat.

Элементы типа данных void теперь печатаются в шестнадцатеричной нотации #

Шестнадцатеричное представление, совместимое с типом Python bytes, теперь выводится для неструктурированных элементов np.void, например с типом данных V4. Ранее в Python 2 необработанные данные элемента void напрямую записывались в stdout, а в Python 3 выводились целочисленные значения байтов.

Стиль вывода данных типа void теперь можно настраивать независимо#

Стиль печати массивов np.void теперь можно настраивать независимо с помощью аргумента formatter для np.set_printoptions и ключа 'void' вместо универсального ключа numpystr, как раньше.

Снижено потребление памяти np.loadtxt#

np.loadtxt теперь читает файлы частями, а не целиком, что значительно уменьшает расход памяти для больших файлов.

Изменения#

Индексация и присваивание по нескольким полям структурированных массивов#

Индексация и присваивание структурированных массивов с несколькими полями изменились в нескольких отношениях, о чём предупреждалось в предыдущих выпусках.

Во-первых, выбор нескольких полей структурированного массива, например arr[['f1', 'f3']], возвращает представление исходного массива вместо копии. В отличие от копии в версии 1.13, это представление содержит дополнительные байты заполнения на месте промежуточных полей исходного массива. Это повлияет на код вида arr[['f1', 'f3']].view(newdtype).

Во-вторых, присваивание между структурированными массивами теперь выполняется по позиции, а не по имени поля. N-е поле назначения получает N-е поле источника независимо от имени. В NumPy 1.6–1.13 использовалось одноимённое поле источника, а при его отсутствии — 0.

Соответственно, порядок полей структурированного dtype теперь влияет на проверку равенства типов данных. Например, для типов

x = dtype({'names': ['A', 'B'], 'formats': ['i4', 'f4'], 'offsets': [0, 4]})
y = dtype({'names': ['B', 'A'], 'formats': ['f4', 'i4'], 'offsets': [4, 0]})

теперь выражение x == y возвращает False, в отличие от прежнего поведения. Поэтому в Python < 3.6 опасно задавать dtype через словарь, например dtype({'a': ('i4', 0), 'b': ('f4', 4)}): в этих версиях порядок ключей словаря не сохраняется.

Присваивание из структурированного массива в логический теперь вызывает ValueError; в версии 1.13 оно всегда устанавливало элементы назначения в True.

Присваивание из структурированного массива с несколькими полями в неструктурированный массив теперь вызывает ValueError. В версии 1.13 при этом копировалось лишь первое поле исходного массива.

Использовать дополнительные названия полей (titles) при индексировании по нескольким полям теперь запрещено, как и повторять имя поля в одном таком индексе.

Документация по структурированным массивам в руководстве пользователя была значительно обновлена с учетом этих изменений.

Целочисленные скаляры и скаляры void больше не зависят от np.set_string_function#

Раньше, в отличие от большинства других скаляров NumPy, представления str и repr целочисленных скаляров и скаляров void можно было задавать через np.set_string_function. Теперь это невозможно.

Изменён вывод нульмерных массивов; аргумент style функции array2string объявлен устаревшим#

Ранее str и repr нульмерных массивов имели особую реализацию: возвращали str(a.item()) и 'array(' + repr(a.item()) + ')' соответственно для нульмерного массива a, в отличие от скаляров NumPy и многомерных ndarray.

Теперь str нульмерного массива ведёт себя как для скаляра NumPy, используя str(a[()]), а repr — как для массивов с большим числом измерений, используя formatter(a[()]). При этом formatter можно задать через np.set_printoptions. Аргумент style функции np.array2string объявлен устаревшим.

Новое поведение отключено в прежнем режиме вывода 1.13; см. примечания о совместимости выше.

Для инициализации RandomState массивом seed требуется одномерный массив#

Раньше RandomState принимал пустые массивы и массивы с двумя и более измерениями. Это приводило к отсутствию инициализации для пустых массивов либо к игнорированию части переданных значений при задании начального состояния.

Объекты MaskedArray показывают более полезный repr #

Представление repr объекта MaskedArray теперь ближе к коду Python, который его создаёт: массивы отображаются с запятыми и типами данных. Как и другие изменения форматирования, это можно отключить режимом вывода, совместимым с 1.13, чтобы облегчить адаптацию doctest-тестов.

repr классов np.polynomial является более явным #.

Теперь параметры domain и window показываются как именованные аргументы, чтобы сделать их назначение понятнее:

>>> np.polynomial.Polynomial(range(4))
Polynomial([0.,  1.,  2.,  3.], domain=[-1,  1], window=[-1,  1])
