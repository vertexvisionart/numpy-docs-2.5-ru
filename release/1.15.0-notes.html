Историческая справка: страница описывает NumPy 1.15.0. Слова «сейчас», «раньше» и «будет» относятся ко времени этого выпуска; описанное поведение может отличаться от NumPy 2.5.

Примечания к выпуску NumPy 1.15.0#

В NumPy 1.15.0 необычно много изменений по очистке кода; многие старые функции объявлены устаревшими, а многие существующие улучшены. Прочитайте подробные описания ниже, чтобы понять, затрагивают ли изменения ваш код.

Для тестирования мы перешли на pytest вместо больше не поддерживаемого фреймворка nose. Старый интерфейс на основе nose сохранён для проектов, которые ещё могут им пользоваться.

Этот выпуск поддерживает Python 2.7 и 3.4–3.7. Пакеты wheel скомпонованы с OpenBLAS v0.3.0, что должно устранить часть проблем linalg, обнаруженных в NumPy 1.14.

Основные изменения#

  • NumPy перешел на pytest для тестирования

  • Новый контекстный менеджер numpy.printoptions.

  • Множество улучшений в функциях гистограммы.

  • Поддержка имён полей Unicode в Python 2.7.

  • Улучшенная поддержка PyPy.

  • Исправления и улучшения numpy.einsum.

Новые функции #

  • numpy.gcd и numpy.lcm для вычисления наибольшего общего делителя и наименьшего общего кратного.

  • numpy.ma.stack, функция соединения массивов numpy.stack, обобщенная на маскированные массивы.

  • Функция numpy.quantile, интерфейс к percentile без коэффициентов 100

  • Функция numpy.nanquantile, интерфейс к nanpercentile без коэффициентов 100

  • numpy.printoptions, контекстный менеджер, который временно устанавливает параметры печати для области действия блока with:

    >>> with np.printoptions(precision=2):
...     print(np.array([2.0]) / 3)
[0.67]

  • numpy.histogram_bin_edges — функция, позволяющая получить границы интервалов гистограммы без вычисления самой гистограммы.

  • Добавлены функции C npy_get_floatstatus_barrier и npy_clear_floatstatus_barrier для обработки случаев, когда оптимизация компилятора меняет порядок операций. Подробности см. ниже.

Устаревающие возможности#

  • Псевдонимы встроенных функций pickle устарели в пользу их имен без псевдонимов pickle.<func>:

    • numpy.loads

    • numpy.core.numeric.load

    • numpy.core.numeric.loads

    • numpy.ma.loads, numpy.ma.dumps

    • numpy.ma.load, numpy.ma.dump — эти функции и раньше завершались ошибкой в Python 3 при вызове со строкой.

  • Многомерное индексирование объектами, отличными от кортежа, объявлено устаревшим. Список индексов в ind = [slice(None), 0]; arr[ind] нужно заменить кортежем, например ind = [slice(None), 0]; arr[tuple(ind)] или arr[(slice(None), 0)]. Это устраняет неоднозначность выражений вроде arr[[[0, 1], [0, 1]]]: сейчас оно интерпретируется как arr[array([0, 1]), array([0, 1])], а в будущем будет означать arr[array([[0, 1], [0, 1]])].

  • Импорт из следующих подмодулей объявлен устаревшим; в будущем эти возможности будут удалены.

    • numpy.testing.utils

    • numpy.testing.decorators

    • numpy.testing.nosetester

    • numpy.testing.noseclasses

    • numpy.core.umath_tests

  • Передача генератора в numpy.sum объявлена устаревшей. Это недокументированное поведение раньше работало и вычисляло сумму генераторного выражения, но в будущем результат может измениться. Вместо него используйте np.sum(np.from_iter(generator)) или встроенную функцию Python sum. Примечание переводчика: в примере оригинала есть опечатка from_iter. В NumPy 2.5.4 используется np.fromiter с обязательным аргументом dtype, например np.sum(np.fromiter(generator, dtype=np.float64)); выбирайте dtype по типу данных генератора.

  • Пользователи C API должны вызвать PyArrayResolveWriteBackIfCopy или PyArray_DiscardWritebackIfCopy для любого массива с установленным флагом WRITEBACKIFCOPY перед освобождением памяти этого массива. Если необходимые вызовы пропущены, будет выдано предупреждение об устаревшем использовании.

  • При наличии хотя бы одного операнда с возможностью записи используйте nditer как менеджер контекста, чтобы NumPy мог выполнить запись временных данных обратно, либо вызовите it.close(). Иначе в таких случаях может выдаваться RuntimeWarning.

  • Использование аргумента normed функции np.histogram, объявленного устаревшим ещё в версии 1.6.0, теперь вызывает предупреждение DeprecationWarning.

Будущие изменения#

  • В NumPy 1.16 будет прекращена поддержка Python 3.4.

  • NumPy 1.17 откажется от поддержки Python 2.7

Примечания о совместимости#

Скомпилированные тестовые модули переименованы и сделаны внутренними#

Следующие скомпилированные модули переименованы и сделаны внутренними:

  • umath_tests -> _umath_tests

  • test_rational -> _rational_tests

  • multiarray_tests -> _multiarray_tests

  • struct_ufunc_test -> _struct_ufunc_tests

  • operand_flag_tests -> _operand_flag_tests

Модуль umath_tests по-прежнему доступен для обратной совместимости, но будет удален в будущем.

Объект NpzFile (в оригинале ошибочно сказано, что его возвращает np.savez) теперь реализует collections.abc.Mapping#. Примечание переводчика: NpzFile возвращает np.load при чтении .npz; np.savez сохраняет архив и возвращает None.

Это означает, что он ведет себя как словарь только для чтения и имеет новый метод .values() и реализацию len().

В Python 3 методы .iteritems() и .iterkeys() объявлены устаревшими, а .keys() и .items() теперь возвращают представления вместо списков. Это соответствует изменению встроенного типа dict при переходе с Python 2 на Python 3.

В некоторых случаях nditer необходимо использовать как менеджер контекста#

При использовании numpy.nditer с флагом "writeonly" или "readwrite" в некоторых случаях nditer возвращает копию, а не представление массива, доступного для записи. Если изменить копию, nditer позже запишет изменения обратно в исходный массив. Сейчас это происходит при удалении объектов массива сборщиком мусора, что делает API ненадёжным в CPython и полностью неработоспособным в PyPy. Поэтому при работе с массивами, доступными для записи, nditer теперь следует использовать как менеджер контекста, например with np.nditer(...) as it: .... Если менеджер контекста неприменим, например в генераторных выражениях, можно явно вызвать it.close().

Для тестирования NumPy теперь использует pytest вместо nose#

Последний выпуск nose, 1.3.7, вышел в июне 2015 года, после чего развитие инструмента прекратилось. Поэтому NumPy перешёл на pytest. Старые декораторы и инструменты nose, использовавшиеся некоторыми зависимыми проектами, остаются доступны, но больше не поддерживаются. Обычные средства тестирования, например assert_almost_equal, не затронуты, кроме специфичных для nose функций import_nose и raises. NumPy их не использует, но они сохранены для совместимости зависимых проектов.

В ctypes больше не добавляется __array_interface__ динамической подменой NumPy#

Ранее numpy добавлял атрибуты __array_interface__ ко всем целочисленным типам из ctypes.

np.ma.notmasked_contiguous и np.ma.flatnotmasked_contiguous всегда возвращают списки #

Именно такое поведение описано в документации, однако раньше результатом мог быть объект slice, None или список.

По-видимому, все проекты, использующие эту функцию, проверяют результат None из flatnotmasked_contiguous и заменяют его на []. Такой вызывающий код продолжит работать как раньше.

np.squeeze восстанавливает прежнее поведение объектов, не принимающих аргумент axis#

До версии 1.7.0 у numpy.squeeze не было аргумента axis, и все оси размера один удалялись по умолчанию. Добавление аргумента axis позволило выборочно удалять одну или несколько таких осей. Однако ожидания старого API не соблюдались: операция могла без ошибки выборочно удалить оси у объекта, который ожидал удаления всех осей размера один. Такое неявное выборочное удаление для объектов, рассчитанных на прежнее поведение, исправлено; прежнее поведение восстановлено.

Метод .item неструктурированного массива void теперь возвращает объект bytes#

.item теперь возвращает объект bytes вместо буфера или массива байтов. Это может повлиять на код, предполагающий, что возвращаемый объект изменяемый: теперь он неизменяем.

copy.copy и copy.deepcopy больше не превращают masked в массив #

Поскольку np.ma.masked — скаляр, доступный только для чтения, копирование не должно ничего менять. Теперь эти функции ведут себя согласованно с np.copy().

Индексация структурированных массивов по нескольким полям по-прежнему возвращает копию#

Изменение, при котором выбор нескольких полей структурированного массива возвращает представление вместо копии, перенесено на версию 1.16. Для смягчения последствий добавлен метод numpy.lib.recfunctions.repack_fields: он позволяет написать код, совместимый и с NumPy 1.15, и с 1.16. О подготовке к этому изменению см. раздел «Доступ к нескольким полям» руководства пользователя.

Изменения C API#

Новые функции npy_get_floatstatus_barrier и npy_clear_floatstatus_barrier #

Добавлены функции npy_get_floatstatus_barrier и npy_clear_floatstatus_barrier, которые следует использовать вместо npy_get_floatstatus и npy_clear_status. При использовании прежних функций в SIMD-реализациях универсальных функций оптимизирующие компиляторы, например GCC 8.1 и Clang, меняли порядок операций. В результате флаги floatstatus проверялись до выполнения операции, состояние которой требовалось проверить. См. #10339.

Изменения в PyArray_GetDTypeTransferFunction#

PyArray_GetDTypeTransferFunction теперь по умолчанию использует пользовательские copyswapn / copyswap для пользовательских типов данных. Если это приводит к значительному снижению производительности, рассмотрите реализацию copyswapn по образцу PyArray_GetStridedCopyFn. См. #10898.

Новые возможности #

Добавлены функции np.gcd и np.lcm для целочисленных и объектных типов #.

Они вычисляют наибольший общий делитель и наименьшее общее кратное соответственно. Они работают со всеми целыми типами numpy, а также со встроенными типами произвольной точности Decimal и long.

Поддержка кроссплатформенных сборок для iOS #

Система сборки была изменена, чтобы добавить поддержку переменной среды _PYTHON_HOST_PLATFORM, используемой distutils при компиляции на одной платформе для другой платформы. Это позволяет скомпилировать NumPy для iOS.

Этот подход позволяет компилировать NumPy только для одной конкретной платформы за раз. Для создания полноценного пакета NumPy с поддержкой iOS нужно выполнить сборку для пяти архитектур iOS — i386, x86_64, armv7, armv7s и arm64 — и объединить результаты в один универсальный двоичный файл («fat binary»).

Именованный аргумент return_indices добавлен в np.intersect1d#

Новый именованный параметр return_indices позволяет получить индексы общих элементов в обоих входных массивах.

np.quantile и np.nanquantile #

Аналогично np.percentile и np.nanpercentile, но принимает квантили в диапазоне [0, 1] вместо процентилей в [0, 100]. Теперь np.percentile — тонкая обёртка над np.quantile, выполняющая дополнительное деление на 100.

Система сборки#

Добавлена ​​экспериментальная поддержка 64-битной архитектуры RISC-V.

Улучшения#

Изменения np.einsum#

Согласованы методы оптимизации порядка вычислений einsum между numpy и opt_einsum. В частности, алгоритм greedy получил множество улучшений от @jcmgray. Полный список исправленных проблем:

  • В путь обработки greedy теперь можно передать произвольную область памяти. Исправляет gh-11210.

  • В жадный алгоритм поиска пути добавлены элементы динамического программирования, позволяющие избежать большого числа повторных и затратных вызовов для определения фактически выполняемой попарной свёртки. Теперь обработка нескольких сотен входных тензоров занимает несколько секунд. Это полезно для методов матричных произведений состояний.

  • Обнаружение ошибок трансляции массивов при dot, обсуждавшееся в gh-11218 и gh-10352, перенесено на более ранний этап.

  • Улучшает функциональность can_dot, в которой раньше не учитывался один граничный случай (часть gh-11308).

np.ufunc.reduce и связанные с ним функции теперь принимают начальное значение #

np.ufunc.reduce, np.sum, np.prod, np.min и np.max теперь принимают именованный аргумент initial, задающий начальное значение свёртки.

np.flip может работать по нескольким осям #

np.flip теперь принимает None или кортежи целых чисел в аргументе axis. При axis=None порядок элементов обращается вдоль всех осей.

Функции histogram и histogramdd перешли на np.lib.histograms #

Ранее они находились в np.lib.function_base. Они по-прежнему доступны непосредственно по именам np.histogram(dd); для совместимости также сохранены псевдонимы np.lib.function_base.histogram(dd).

В коде с from np.lib.function_base import * нужно указать новое расположение. Также стоит отказаться от import * в дальнейшем.

histogram принимает NaN при явно заданных границах интервалов#

Раньше происходил сбой при попытке вычислить конечный диапазон данных. Поскольку при явном задании границ интервалов диапазон всё равно игнорируется, такая ошибка была излишней.

Вызов histogram для значений NaN по-прежнему выдаёт обычные для работы с nan предупреждения RuntimeWarning. Их, как и раньше, можно подавить с помощью errstate.

histogram работает с типами datetime при явном задании границ интервалов#

Теперь можно строить гистограммы для дат, времени и временных интервалов. Границы интервалов нужно передавать явно: автоматически они пока не вычисляются.

histogramОценка «auto» лучше обрабатывает данные с малой дисперсией#

Нулевой межквартильный размах (IQR) больше не приводит к n_bins=1; в этом случае число интервалов выбирается с учётом объёма данных.

Границы интервалов, возвращаемые histogram и histogramdd, теперь имеют тот же тип с плавающей точкой, что и данные#

При передаче данных np.float16, np.float32 или np.longdouble возвращаемые границы интервалов теперь имеют тот же dtype. Ранее histogram возвращала тот же тип только при явно заданных интервалах, а histogram создавала границы типа float64 независимо от входных данных.

histogramdd позволяет задавать явные диапазоны в подмножестве осей #

Аргумент range функции numpy.histogramdd теперь может содержать None: это означает, что диапазон соответствующей оси вычисляется по данным. Ранее задать такое поведение отдельно для каждой оси было нельзя.

Аргументы normed функций histogramdd и histogram2d переименованы#

Эти аргументы теперь называются density, что согласуется с histogram. Старый аргумент продолжает работать, но новое название должно быть предпочтительным.

np.r_ работает с 0d-массивами, а np.ma.mr_ работает с np.ma.masked #

Нульмерные массивы, переданные средствам конкатенации r_ и mr_, теперь обрабатываются как массивы длины 1. Раньше их передача вызывала ошибку. Благодаря этому numpy.ma.mr_ теперь корректно работает с константой masked.

np.ptp принимает аргумент keepdims; расширены возможности задания осей кортежем#

np.ptp (размах) теперь работает по нескольким осям, как np.max и np.min.

MaskedArray.astype теперь идентичен ndarray.astype #

Это означает, что принимаются все те же аргументы, поэтому больше кода, написанного для ndarray, работает и с массивами с маской.

Включить AVX2/AVX512 во время компиляции #

Изменения в simd.inc.src позволяют использовать AVX2 или AVX512 при компиляции. Ранее при сборке для AVX2 (или AVX512) с -march=native функции SIMD всё равно использовали код SSE, даже если остальной код использовал AVX2.

nan_to_num всегда возвращает скаляры при приеме скалярных или 0d входов #

Раньше для целочисленного скалярного входа возвращался массив, что не соответствовало поведению для вещественных входов и ufunc в целом. Теперь для любого скалярного или нульмерного входа возвращается скаляр.

np.flatnonzero работает с типами, преобразуемыми в массив NumPy#

np.flatnonzero теперь использует np.ravel(a) вместо a.ravel(), поэтому он работает для списков, кортежей и т. Д.

np.interp возвращает скаляры NumPy вместо встроенных скаляров#

Ранее np.interp(0.5, [0, 1], [10, 20]) возвращал float, но теперь он возвращает объект np.float64, который более точно соответствует поведению других функций.

Кроме того, особый случай np.interp(object_array_0d, ...) больше не поддерживается, поскольку np.interp(object_array_nd) и так никогда не поддерживался.

В результате этого изменения аргумент period теперь может использоваться на 0d-массивах.

Разрешены имена полей dtype в Unicode в Python 2#

Ранее np.dtype([(u'name', float)]) вызывал TypeError в Python 2, поскольку в именах полей допускались только байтовые строки. Теперь имена полей в виде строк Unicode кодируются кодеком ascii; при неудаче возникает UnicodeEncodeError.

Это изменение упрощает написание кода, совместимого с Python 2 и 3, с использованием from __future__ import unicode_literals. Ранее при этом имена полей, заданные строковыми литералами, вызывали TypeError в Python 2.

Универсальные функции сравнения принимают dtype=object вместо используемого по умолчанию bool#

Это позволяет объектным массивам символьных типов, которые переопределяют == и другие операторы для возврата выражений, сравниваться по элементам с np.equal(a, b, dtype=object).

Функции sort принимают kind='stable'#

До сих пор для устойчивой сортировки данных требовалось:

>>> np.sort([5, 2, 6, 2, 1], kind='mergesort')
[1, 2, 2, 5, 6]

поскольку сортировка слиянием — единственный доступный в NumPy алгоритм устойчивой сортировки. Однако запись kind=’mergesort’ не выражает явно намерение пользователя выполнить устойчивую сортировку, что ухудшает читаемость.

Это изменение позволяет пользователю указать kind=’stable’, тем самым проясняя намерение.

Отказ от временных копий при накоплении на месте#

При выполнении накопления универсальные функции больше не создают временные копии из-за перекрытия входных и выходных данных. Следующий элемент добавляется к накопленному значению до записи результата на его место, поэтому перекрытие безопасно. Отказ от копирования ускоряет выполнение.

linalg.matrix_power теперь может обрабатывать стеки матриц #.

Как и другие функции linalg, matrix_power теперь поддерживает массивы с более чем двумя измерениями, рассматривая их как наборы матриц. Для согласованности первый аргумент переименован в a (ранее M), а для неквадратных матриц теперь вызывается LinAlgError вместо ValueError.

Повышение производительности в random.permutation для многомерных массивов #

permutation использует быстрый путь в random.shuffle для всех размеров входных массивов. Раньше быстрый путь использовался только для 1-d массивов.

Обобщённые универсальные функции теперь принимают аргументы axes, axis и keepdims#

Оси работы обобщённой универсальной функции можно задать аргументом axes — списком кортежей индексов осей. Например, при сигнатуре (i,j),(j,k)->(i,k) для матричного умножения базовые элементы — двумерные матрицы, по умолчанию расположенные в двух последних осях каждого аргумента. Соответствующее значение axes — [(-2, -1), (-2, -1), (-2, -1)]. Чтобы использовать первые измерения, передайте [(0, 1), (0, 1), (0, 1)].

Для удобства в обобщённых универсальных функциях, работающих с одномерными массивами (векторами), вместо кортежа из одного элемента можно передать целое число. Если все выходы скалярные, пустые кортежи для них можно опустить. Например, для сигнатуры скалярного произведения (i),(i)->() можно передать axes=[0, 0], указав, что векторы расположены вдоль первых осей двух входных аргументов.

Для обобщённых ufunc, похожих на свёртки, то есть работающих с одним общим основным измерением, как в примере скалярного произведения выше, можно использовать сокращённую запись с аргументом axis. Она эквивалентна передаче axes с одинаковыми записями для всех аргументов с этим основным измерением (например, axes=[(axis,), (axis,)] для примера выше).

Кроме того, как и при свёртках, для обобщённых универсальных функций, у которых все входы имеют одинаковое число базовых измерений, а выходы не имеют базовых измерений, можно передать keepdims. Тогда в выходе сохраняется измерение длины 1, что позволяет правильно согласовать его с исходными входами по правилам трансляции массивов. Положение этого измерения можно задать через axes. Например, для скалярного произведения keepdims=True, axes=[-2, -2, -2] выполняет операцию над предпоследним измерением входных аргументов; keepdims=True, axis=-2 также выполняет её над предпоследним измерением и сохраняет на его месте в выходе измерение длины 1. Примечание переводчика: в английском оригинале в описании первого вызова повторена фраза о примере скалярного произведения; оба приведённых вызова эквивалентны.

Значения float128 теперь корректно выводятся в системах ppc#

Раньше вывод float128 на ppc был ошибочным: не учитывался особый формат double-double на этих системах. Теперь значения float128 выводятся с правильным округлением и однозначным представлением.

Предупреждение пользователям ppc: обновите glibc версии <=2.23, особенно если используете float128. В этих версиях malloc glibc на ppc часто неверно выравнивает выделенную память, что может вызвать аварийное завершение NumPy при работе с float128.

Новые функции np.take_along_axis и np.put_along_axis#

При использовании на многомерных массивах, argsort, argmin, argmax и argpartition возвращают массивы, которые трудно использовать в качестве индексов. take_along_axis обеспечивает простой способ использования этих индексов для поиска значений в массиве, так что:

np.take_along_axis(a, np.argsort(a, axis=axis), axis=axis)

Это то же самое, что:

np.sort(a, axis=axis)

np.put_along_axis выполняет парную операцию: запись по этим индексам внутри массива.
