Историческая справка: страница описывает NumPy 1.16.0. Слова «сейчас», «раньше» и «будет» относятся ко времени этого выпуска; описанное поведение может отличаться от NumPy 2.5.

Примечания к выпуску NumPy 1.16.0#

Это последний выпуск NumPy с поддержкой Python 2.7; он будет получать исправления ошибок в режиме долгосрочного сопровождения до 2020 года. Поддержка Python 3.4 прекращена; поддерживаются Python 2.7 и 3.5–3.7. Пакеты wheel на PyPI скомпонованы с OpenBLAS v0.3.4+, что должно устранить известные проблемы многопоточности прежних версий OpenBLAS.

Разработчикам зависимых проектов, собирающим этот выпуск, следует использовать Cython >= 0.29, а при использовании OpenBLAS — OpenBLAS > v0.3.4.

В этом выпуске выполнен значительный рефакторинг, исправлено много ошибок, улучшены организация кода и совместимость между платформами. Не все улучшения заметны пользователям, но они должны упростить дальнейшее сопровождение.

Основные изменения#

  • Экспериментальная поддержка переопределения функций NumPy, включаемая только явно; см. __array_function__ ниже.

  • Функция matmul теперь является ufunc. Это повышает производительность и позволяет переопределять её поведение через __array_ufunc__.

  • Улучшена поддержка архитектур ARM и POWER.

  • Улучшенная поддержка AIX и PyPy.

  • Улучшено взаимодействие с ctypes.

  • Улучшенная поддержка PEP 3118.

Новые функции #

  • В модуль numpy.lib.recfuntions добавлены функции, облегчающие переход к изменениям присваивания структурированных данных:

    • assign_fields_by_name

    • structured_to_unstructured

    • unstructured_to_structured

    • apply_along_fields

    • require_fields

    Подробнее см. руководство пользователя: <https://docs.scipy.org/doc/numpy/user/basics.rec.html>.

Новые устаревшие возможности#

  • Словари типов numpy.core.typeNA и numpy.core.sctypeNA объявлены устаревшими. Они содержали ошибки, не были документированы и будут удалены в выпуске 1.18. Используйте вместо них numpy.sctypeDict.

  • Функция numpy.asscalar объявлена устаревшей. Это псевдоним более функционального метода numpy.ndarray.item; функция не покрыта тестами и не работает со скалярами.

  • Функции numpy.set_array_ops и numpy.get_array_ops объявлены устаревшими в рамках NEP 15 вместе с функциями C API PyArray_SetNumericOps и PyArray_GetNumericOps. Для переопределения внутренних циклов встроенных универсальных функций используйте PyUFunc_ReplaceLoopBySignature.

  • Именованный аргумент numpy.unravel_index dims объявлен устаревшим; используйте shape.

  • В функции numpy.histogram аргумент normed объявлен устаревшим. Это было сделано ранее, но предупреждение не выдавалось.

  • Применение оператора positive (+) к нечисловым массивам объявлено устаревшим. Подробности см. ниже.

  • Передача итератора функциям объединения массивов объявлена устаревшей

Окончательно удалённые устаревшие возможности#

  • Сравнения с NaT теперь возвращают False без предупреждения, завершая переходный период, начатый в NumPy 1.11. Примечание переводчика: это не относится к проверке неравенства !=, которая возвращает True.

  • np.lib.function_base.unique удалена: завершён процесс отказа от неё, начатый в NumPy 1.4. Используйте numpy.unique.

  • Индексация нескольких полей теперь возвращает представления вместо копий, завершая период устаревания, начатый в NumPy 1.7. Изменение уже пробовали в NumPy 1.14, но тогда откатили.

  • np.PackageLoader и np.pkgload были удалены. Они устарели в версии 1.10, не имели тестов и, похоже, больше не работают в версии 1.15.

Будущие изменения#

  • NumPy 1.17 откажется от поддержки Python 2.7

Примечания о совместимости#

Скрипт f2py в Windows#

В Windows установленный скрипт для запуска f2py теперь является файлом .exe, а не файлом *.py и должен запускаться из командной строки как f2py всякий раз, когда каталог Scripts находится в пути. Запуск f2py в качестве модуля python -m numpy.f2py [...] будет работать без изменения пути в любой версии NumPy .

Сравнения с NaT#

Аналогично поведению NaN, все сравнения со значениями NaT («не время») типов datetime64 или timedelta64, кроме проверки на неравенство, теперь всегда возвращают False, а проверка на неравенство с NaT всегда возвращает True. Это относится и к сравнению значений NaT между собой. Для совместимости с прежним поведением используйте np.isnat для явной проверки на NaT либо перед сравнением преобразуйте массивы datetime64/timedelta64 с помощью .astype(np.int64).

Изменилось выравнивание complex64/128#

Выравнивание комплексных типов теперь совпадает с выравниванием структуры C из двух чисел с плавающей запятой; раньше оно равнялось размеру типа. Для многих систем, например x64/unix/gcc, complex64 теперь требует выравнивания на 4, а не на 8 байтов. Поэтому размер выровненных структурированных типов может измениться. Например, np.dtype('c8,u1', align=True) раньше имел itemsize 16 на x64/gcc, а теперь — 12.

Точнее, выравнивание complex64 теперь совпадает с выравниванием структуры C struct {float r, i;}, определяемым компилятором, которым собран NumPy. То же относится к complex128 и complex256.

Удаление __len__ у nd_grid#

len(np.mgrid) и len(np.ogrid) теперь считаются некорректными и вызывают TypeError.

np.unravel_index теперь принимает именованный аргумент shape#

Ранее форму массива, используемую для преобразования плоских индексов в координаты, можно было задать только именованным аргументом dims. Аргумент dims по-прежнему поддерживается, но объявлен устаревшим.

Выбор нескольких полей возвращает представление вместо копии#

Индексация структурированного массива по нескольким полям, например arr[['f1', 'f3']], теперь возвращает представление исходного массива вместо копии. В отличие от прежнего результата, представление часто содержит дополнительные байты заполнения, соответствующие промежуточным полям исходного массива. Это влияет на код вида arr[['f1', 'f3']].view('float64'). Изменение планировалось с NumPy 1.7; соответствующие операции с тех пор выдавали FutureWarnings. В версии 1.12 добавлены дополнительные FutureWarnings об этом изменении.

Чтобы помочь пользователям адаптировать код к этим изменениям, в модуль numpy.lib.recfunctions добавлены функции для безопасного выполнения таких операций. Например, приведённый выше код можно заменить на structured_to_unstructured(arr[['f1', 'f3']], dtype='float64'). См. раздел «Доступ к нескольким полям» руководства пользователя.

Изменения C API#

Значение NPY_FEATURE_VERSION увеличено до 0x0000D из-за добавления:

  • PyUFuncObject.core_dim_flags

  • PyUFuncObject.core_dim_sizes

  • PyUFuncObject.identity_value

  • PyUFunc_FromFuncAndDataAndSignatureAndIdentity

Новые возможности #

В histogram добавлен метод оценки по интегральной квадратичной ошибке (ISE)#

Этот метод (bins='stone') оптимизации числа интервалов обобщает правило Скотта. Правило Скотта предполагает приблизительно нормальное распределение, а ISE — непараметрический метод на основе перекрёстной проверки.

Именованный аргумент max_rows добавлен в np.loadtxt#

Новый именованный аргумент max_rows функции numpy.loadtxt ограничивает число строк, читаемых после skiprows, как в numpy.genfromtxt.

Добавлена поддержка оператора остатка от деления для операндов np.timedelta64#

Теперь оператор остатка от деления поддерживается для двух операндов типа np.timedelta64. Их единицы измерения могут различаться; возвращаемое значение имеет тот же тип, что и операнды.

Улучшения#

Сериализация массивов NumPy с помощью pickle без копирования#

До протокола 4 включительно сериализация массивов NumPy через pickle создавала две лишние копии данных. Протокол pickle 5 и API PickleBuffer позволяют сериализовать многие массивы NumPy без копирования при вынесении буферов за пределы потока pickle и с одной копией меньше при включении буферов в поток. Для больших массивов снижение пикового потребления памяти достигает 66%.

Независимость сборки от командной оболочки#

NumPy сборки больше не должны взаимодействовать с оболочкой хост-машины напрямую. exec_command был заменен на subprocess.check_output, где это уместно.

Классы np.polynomial.Polynomial отображаются в LaTeX в ноутбуках Jupyter #

При использовании в интерфейсе, который поддерживает его, экземпляры Polynomial теперь визуализируются через LaTeX. Текущий формат является экспериментальным и может быть изменен.

randint и choice теперь работают с пустыми распределениями#

Раньше np.random.randint и np.random.choice вызывали ошибку, если аргументы задавали пустое распределение, даже когда не требовалось генерировать ни одного элемента. Это исправлено; например, теперь np.random.choice([], 0) == np.array([], dtype=float64).

linalg.lstsq, linalg.qr и linalg.svd теперь работают с пустыми массивами#

Раньше при передаче пустой матрицы или пустых матриц с нулевым числом строк и/или столбцов вызывалось LinAlgError. Теперь возвращаются результаты подходящей формы.

Цепочки исключений для более понятных сообщений о недопустимых строках формата PEP3118#

Это должно помочь отследить проблемы.

Обновления путей оптимизации einsum и повышение эффективности#

Реализация einsum синхронизирована с актуальными изменениями исходного проекта.

numpy.angle и numpy.expand_dims теперь работают с подклассами ndarray#

В частности, теперь они работают с замаскированными массивами.

Подавление предупреждений компилятора с помощью NPY_NO_DEPRECATED_API#

Установка NPY_NO_DEPRECATED_API значения 0 приведет к подавлению текущих предупреждений компилятора при использовании устаревшего API numpy.

В np.diff добавлены именованные аргументы prepend и append#

Новые именованные аргументы prepend и append позволяют добавлять значения в начало и конец при вычислении разностей, аналогично параметрам ediff1d. Теперь операцию, обратную cumsum, легко получить с помощью prepend=0.

Обновлена поддержка ARM#

Поддержка процессоров ARM обновлена: теперь охватываются 32- и 64-битные целевые платформы и оба порядка байтов. Исправлены проблемы выравнивания памяти AARCH32. В тестирование CI добавлены целевые платформы AARCH64 с использованием сервисов shippable.com.

Дополнение флагов сборки#

Раньше при компиляции расширений Fortran numpy.distutils заменял значения LDFLAGS и подобных переменных окружения, а не дополнял их. Теперь при переменной NPY_DISTUTILS_APPEND_FLAGS, равной 1, значения дополняются. Это касается LDFLAGS, F77FLAGS, F90FLAGS, FREEFLAGS, FOPT, FDEBUG и FFLAGS. Подробнее см. gh-11525.

Сигнатуры обобщённых ufunc теперь допускают измерения фиксированного размера#

Число в сигнатуре обобщённой универсальной функции означает, что функция требует от входа или выхода измерения заданного размера. Например, сигнатура преобразования полярного угла в двумерный декартов единичный вектор — ()->(2); преобразования двух сферических углов в трёхмерный единичный вектор — (),()->(3); векторного произведения двух трёхмерных векторов — (3),(3)->(3).

Для элементарной функции эти измерения ничем не отличаются от переменных измерений, обозначенных именем, начинающимся с буквы. Циклу по-прежнему передаётся соответствующий размер, но теперь можно полагаться на его равенство фиксированному размеру из сигнатуры.

Сигнатуры обобщённых универсальных функций теперь допускают гибкие измерения#

Некоторые функции, в частности реализация оператора @ в NumPy — matmul, похожи на обобщённые универсальные функции: они работают по основным измерениям. Ранее представить их так было нельзя, поскольку они допускают отсутствие некоторых измерений входов. Теперь после имени измерения можно поставить вопросительный знак, обозначив его необязательность.

С этим дополнением сигнатуру matmul можно записать как (m?,n),(n,p?)->(m?,p?). Если, например, второй операнд одномерен, элементарная функция будет обрабатывать его как вход с основной формой (n, 1), а выход — как имеющий основную форму (m, 1). Однако из фактически возвращаемого массива необязательное измерение удаляется: его форма будет (..., m). Аналогично, если оба аргумента одномерны, элементарная функция получает входы форм (1, n) и (n, 1) и выход формы (1, 1), но фактически возвращаемый массив имеет форму (). Таким образом, одна элементарная функция может обслуживать четыре связанные, но различные сигнатуры: (m,n),(n,p)->(m,p), (n),(n,p)->(p), (m,n),(n)->(m) и (n),(n)->().

np.clip и метод clip проверяют перекрытие памяти#

Аргумент out для этих функций теперь всегда проверяется на перекрытие памяти, чтобы избежать поврежденных результатов при перекрытии памяти.

Новое значение unscaled для опции cov в np.polyfit #

К параметру cov функции np.polyfit добавлено ещё одно допустимое значение. При cov='unscaled' масштабирование ковариационной матрицы полностью отключается, аналогично установке absolute_sigma=True в scipy.optimize.curve_fit. Это полезно, когда веса заданы как 1/sigma, где sigma — известные стандартные ошибки точек данных с гауссовским распределением: в таком случае немасштабированная матрица уже корректно оценивает ковариационную матрицу.

Подробные докстринги для скалярных числовых типов #

Функция help, применяемая к числовым типам, таким как numpy.intc, numpy.int_ и numpy.longlong, теперь перечисляет все псевдонимы для этого типа, различая зависимые от платформы и независимые псевдонимы.

Атрибут __module__ теперь указывает на общедоступные модули #

Атрибут __module__ большинства функций NumPy теперь указывает на предпочтительный публичный модуль, через который следует обращаться к функции, а не на модуль её реализации. Благодаря этому представление функций в инструментах вроде IPython стало информативнее: вместо <function 'numpy.core.fromnumeric.sum'> теперь отображается <function 'numpy.sum'>.

Крупные блоки выделенной памяти помечаются как подходящие для прозрачных больших страниц (transparent huge pages)#

В системах, поддерживающих прозрачные большие страницы памяти через системный вызов madvise, NumPy теперь помечает крупные выделения памяти как пригодные для размещения на больших страницах. Это снижает накладные расходы на обработку страничных исключений и в некоторых случаях, когда таких исключений много, значительно повышает производительность. В Linux параметр использования больших страниц /sys/kernel/mm/transparent_hugepage/enabled должен иметь значение как минимум madvise. Системы, где уже задано always, почти не заметят разницы: ядро и так автоматически использует большие страницы там, где это уместно.

Пользователям очень старых ядер Linux (примерно 3.x и более ранних) следует убедиться, что для /sys/kernel/mm/transparent_hugepage/defrag не задано значение always. Это позволит избежать снижения производительности из-за проблем с параллельным выполнением при дефрагментации памяти.

Поддержка Alpine Linux и других дистрибутивов с библиотекой C musl#

Теперь по умолчанию для получения сведений об ошибках операций с плавающей запятой используется fenv.h. Прежняя реализация по умолчанию работала некорректно и иногда не сообщала об антипереполнении, переполнении и недопустимых операциях с плавающей запятой. Теперь поддерживаются дистрибутивы без glibc, например Alpine Linux, если в них есть fenv.h.

Ускорение np.block для больших массивов #

Для больших массивов (более 512 * 512 элементов) теперь используется алгоритм сборки блоков, копирующий данные непосредственно в соответствующий срез результирующего массива. Это значительно ускоряет работу с большими массивами, особенно при сборке блоков более чем по двум измерениям.

arr.ctypes.data_as(...) содержит ссылку на arr #

Ранее вызывающая сторона должна была обеспечивать существование массива в течение всего срока действия указателя.

Ускорение np.take для массивов только для чтения #

Реализация np.take больше не создает ненужную копию исходного массива, когда его флаг writeable установлен в False.

Поддержка объектов пути в большем числе функций#

Функция np.core.records.fromfile теперь принимает не только файловый объект, но и pathlib.Path и другие объекты, представляющие путь. Кроме того, np.load теперь поддерживает такие объекты и при отображении файла в память (именованный аргумент mmap_mode).

Улучшена обработка нейтральных элементов универсальных функций при свёртках#

У универсальных функций есть атрибут .identity — нейтральный элемент, используемый при вызове .reduce для пустой оси.

Начиная с этого выпуска, бинарные логические универсальные функции logical_and, logical_or и logical_xor имеют значения identity типа bool вместо прежнего int. Благодаря этому свёртка пустых массивов объектов такими функциями снова возвращает bool, как в версии 1.14. При этом сохраняется поведение версии 1.15: возвращается int при свёртке пустых массивов объектов арифметическими универсальными функциями, например add и multiply.

Также у logaddexp теперь есть нейтральный элемент -inf, что позволяет вызывать функцию на пустых последовательностях; раньше это было невозможно.

Это стало возможным благодаря новой PyUFunc_FromFuncAndDataAndSignatureAndIdentity, позволяющей задавать произвольные нейтральные элементы операции.

Улучшено преобразование объектов ctypes#

NumPy всегда позволял взять значение или тип из ctypes и преобразовать его в массив или dtype, но корректно обрабатывались лишь более простые типы. В этом выпуске ограничение снято — теперь:

  • Учитывается атрибут _pack_ класса ctypes.Structure, используемый для эмуляции __attribute__((packed)) языка C.

  • Порядок байтов всех объектов ctypes сохраняется

  • ctypes.Union поддерживается

  • Конструкции, которые невозможно представить, вызывают исключения вместо опасно неверных результатов:

    • Битовые поля больше не интерпретируются как подмассивы

    • Указатели больше не заменяются типом, на который они указывают

Новый атрибут ndpointer.contents#

Это соответствует атрибуту .contents обычных массивов ctypes и позволяет создавать np.array для содержимого указателя. Так заменяется np.array(some_nd_pointer), переставшее работать в версии 1.15. Заодно ndpointer теперь поддерживает dtype с перекрывающимися полями и байтами заполнения.

matmul теперь является ufunc#

numpy.matmul теперь является ufunc, поэтому и функцию, и оператор __matmul__ можно переопределять через __array_ufunc__. Реализация тоже изменилась: используются те же функции BLAS, что и в numpy.dot, обеспечивая похожую производительность на больших матрицах.

Массивы начальных и конечных значений для linspace, logspace и geomspace#

Раньше эти функции принимали только скалярные значения stop и start. Теперь можно передавать массивы: их формы согласуются по правилам трансляции, а в начало формы результата добавляется одна ось. Это позволяет, например, получать линейно интерполированные точки между наборами точек.

CI расширяется за счет дополнительных сервисов #

Теперь мы используем дополнительные бесплатные сервисы CI благодаря компаниям, которые их предоставляют:

  • Проверка покрытия кода тестами через codecov.io

  • Тестирование на Arm через shippable.com

  • Дополнительные запуски тестов в Azure Pipelines

Это дополняет продолжающееся использование travis, appveyor (для пакетов wheel) и LGTM.

Изменения#

Универсальные функции сравнения теперь вызывают ошибку вместо возврата NotImplemented#

Ранее универсальные функции сравнения, например np.equal, возвращали NotImplemented для аргументов со структурированными dtype, помогая операторам сравнения, например __eq__, обрабатывать их. Теперь эта логика перенесена в сами операторы сравнения, которые по-прежнему возвращают NotImplemented при необходимости. Поэтому, как и другие универсальные функции, функции сравнения теперь вызывают ошибку для структурированных dtype.

Унарный плюс теперь выдаёт предупреждение об устаревании для нечисловых массивов#

Раньше +array всегда возвращало копию. Теперь выдаётся предупреждение DeprecationWarning, если массив нечисловой (то есть если np.positive(array) вызывает TypeError). Для подклассов ndarray, переопределяющих стандартную реализацию __array_ufunc__, исключение TypeError передаётся вызывающему коду.

NDArrayOperatorsMixin теперь реализует матричное умножение#

Ранее np.lib.mixins.NDArrayOperatorsMixin не реализовывал специальные методы оператора матричного умножения Python (@). Теперь это изменено, поскольку matmul стал универсальной функцией и может быть переопределён через __array_ufunc__.

Изменено масштабирование ковариационной матрицы в np.polyfit#

Ранее np.polyfit использовала нестандартный множитель для масштабирования ковариационной матрицы: вместо стандартного chisq/(M-N) применялся chisq/(M-N-2), где M — число точек данных, а N — число параметров. Это не согласуется с другими средствами аппроксимации, например scipy.optimize.curve_fit, поэтому множитель заменён на chisq/(M-N).

maximum и minimum больше не выдают предупреждения #

В коде, добавленном в 1.10, для типов float32 и float64 при встрече NaN в numpy.maximum и numpy.minimum с семантикой SSE2 устанавливался флаг invalid вычислений с плавающей точкой. Это иногда приводило к RuntimeWarning. В 1.15 мы исправили несогласованности, после чего предупреждения стали заметнее. Теперь они выдаваться не будут.

Модули расширения на C umath и multiarray объединены в один модуль#

Два модуля объединены согласно NEP 15. Ранее np.core.umath и np.core.multiarray были отдельными модулями расширения на C. Теперь это обёртки Python над единым модулем расширения C np.core/_multiarray_math.

Расширены проверки корректности в getfield#

numpy.ndarray.getfield теперь проверяет аргументы dtype и offset, предотвращая доступ к недопустимым адресам памяти.

Функции NumPy теперь поддерживают переопределение с __array_function__ #

В NumPy появился экспериментальный механизм переопределения реализации почти всех функций NumPy для сторонних массивов: нужно определить метод __array_function__, как описано в NEP 18.

Эта возможность пока не включена по умолчанию; она опубликована, чтобы заинтересованные пользователи могли поэкспериментировать. Подробности настройки соответствующей переменной окружения см. в NEP. Ожидается, что в NumPy 1.17 переопределения будут включены по умолчанию и станут быстрее благодаря новой реализации на C.

Для массивов на основе буферов, доступных только для чтения, нельзя установить флаг writeable#

Теперь запрещено устанавливать флаг writeable в True для массивов, созданных из fromstring(readonly-buffer).
