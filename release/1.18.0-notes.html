Историческая справка: страница описывает NumPy 1.18.0. Слова «сейчас», «раньше» и «будет» относятся ко времени этого выпуска; описанное поведение может отличаться от NumPy 2.5.

Примечания к выпуску NumPy 1.18.0#

Помимо обычных исправлений ошибок, в этом выпуске NumPy упорядочен и документирован новый C API генерации случайных чисел, удалено множество давно устаревших возможностей и улучшен внешний вид документации. Поддерживаются Python 3.5–3.8. Это последняя серия выпусков NumPy с поддержкой Python 3.5.

Разработчикам пакетов, зависящих от NumPy, следует использовать Cython >= 0.29.14 для поддержки Python 3.8 и OpenBLAS >= 0.3.7 во избежание проблем на архитектуре Skylake. Примечание переводчика: в оригинале номер версии OpenBLAS ошибочно указан как 3.7; имеется в виду 0.3.7.

Основные изменения#

  • C-API для numpy.random был определен и документирован.

  • Базовая инфраструктура для связи с 64-битными библиотеками BLAS и LAPACK.

  • Много улучшений документации.

Новые функции #

В numpy.random добавлено многомерное гипергеометрическое распределение#

Метод multivariate_hypergeometric добавлен в класс numpy.random.Generator. Он генерирует случайные значения из многомерного гипергеометрического распределения. (gh-13794)

Устаревающие возможности#

np.fromfile и np.fromstring будут вызывать исключение при некорректных данных#

В будущих выпусках NumPy функции np.fromfile и np.fromstring будут выдавать ошибку при разборе некорректных данных. Теперь в случаях, когда раньше молча возвращались частичные или даже неверные данные, выдаётся DeprecationWarning. Это объявление об устаревании также относится к функциям C PyArray_FromString и PyArray_FromFile (gh-13605)

Нескалярные массивы в качестве значений заполнения ma.fill_value объявлены устаревшими#

Присваивание нескалярного массива атрибуту MaskedArray.fill_value объявлено устаревшим: логика трансляции значения заполнения на массив ненадёжна, особенно при получении срезов. (gh-13698)

PyArray_As1D и PyArray_As2D объявлены устаревшими#

PyArray_As1D и PyArray_As2D объявлены устаревшими; используйте PyArray_AsCArray (gh-14036)

Объявление np.alen устаревшей#

np.alen объявлена устаревшей. Вместо неё используйте len. (gh-14181)

Финансовые функции объявлены устаревшими#

В соответствии с NEP-32 финансовые функции fv ipmt, irr, mirr, nper, npv, pmt, ppmt, pv и rate объявлены устаревшими и будут удалены из NumPy 1.20. Вместо них используется пакет Python numpy-financial. (gh-14720)

Аргумент axis функций numpy.ma.mask_cols и numpy.ma.mask_row объявлен устаревшим#

Этот аргумент всегда игнорировался ( gh-14996 ).

Окончательно удалённые устаревшие возможности#

  • PyArray_As1D и PyArray_As2D были удалены в пользу PyArray_AsCArray ( gh-14036 )

  • np.rank удалена. Она была объявлена устаревшей в NumPy 1.10 и заменена на np.ndim. (gh-14039)

  • Завершён переходный период, начатый в версии 1.13.0: индексы осей вне допустимого диапазона больше не поддерживаются в expand_dims. (gh-14051)

  • PyArray_FromDimsAndDataAndDescr и PyArray_FromDims были удалены (они всегда будут вызывать ошибку). Используйте вместо этого PyArray_NewFromDescr и PyArray_SimpleNew. ( gh-14100 )

  • numeric.loads, numeric.load, np.ma.dump, np.ma.dumps, np.ma.load, np.ma.loads удалены; используйте функции pickle (gh-14256)

  • arrayprint.FloatFormat и arrayprint.LongFloatFormat удалены; вместо них используйте FloatingFormat

  • arrayprint.ComplexFormat и arrayprint.LongComplexFormat удалены; вместо них используйте ComplexFloatingFormat

  • arrayprint.StructureFormat был удален, вместо этого используйте StructureVoidFormat ( gh-14259 )

  • np.testing.rand удалена. Она объявлена устаревшей в NumPy 1.11 и заменена на np.random.rand. (gh-14325)

  • Класс SafeEval из numpy/lib/utils.py удалён; он был объявлен устаревшим в NumPy 1.10. Вместо него используйте np.safe_eval. (gh-14335)

  • Удалена устаревшая поддержка логических значений и пустых списков условий в np.select (gh-14583)

  • Для порядка массива допустимы только ‘C’, ‘F’, ‘A’ и ‘K’. Остальные варианты объявлены устаревшими в NumPy 1.11. (gh-14596)

  • Параметр num функции np.linspace должен быть целым числом. Нецелые значения объявлены устаревшими в NumPy 1.12. (gh-14620)

  • Для ufunc с несколькими выходами именованный аргумент out должен быть кортежем. Это завершает отказ от устаревшего поведения, начатый в NumPy 1.10. (gh-14682)

Удалены файлы numpy/testing/decorators.py, numpy/testing/noseclasses.py и numpy/testing/nosetester.py. Они не предназначались для публичного использования: все соответствующие объекты доступны в пространстве имён numpy.testing. Их импорт выдавал предупреждение об устаревании начиная с NumPy 1.15.0 (gh-14567).

Примечания о совместимости#

numpy.lib.recfunctions.drop_fields больше не может возвращать None#

Если drop_fields используется для удаления всех полей, раньше массив отбрасывался целиком и возвращалось None. Теперь возвращается массив той же формы, что и входной, но без полей. Прежнее поведение можно сохранить следующим образом:

dropped_arr = drop_fields(arr, ['a', 'b'])
if dropped_arr.dtype.names == ():
    dropped_arr = None

преобразование пустого recarray в None (gh-14510)

numpy.argmin/argmax/min/max возвращает NaT, если он есть в массиве#

numpy.argmin, numpy.argmax, numpy.min и numpy.max теперь учитывают наличие NaT в массиве. Примечание переводчика: оригинал утверждает, что все четыре функции возвращают NaT. Точнее, min и max возвращают NaT, а argmin и argmax — его индекс. (gh-14717)

np.can_cast(np.uint64, np.timedelta64, casting='safe') теперь возвращает False#

Ранее это было True, однако такое поведение противоречило невозможности безопасного приведения uint64 к int64 и приводило к странным результатам разрешения типов.

Если это затрагивает ваш код, сначала приведите uint64 к int64. (gh-14718)

Изменение потока случайных значений, выдаваемого numpy.random.Generator.integers#

В numpy.random.Generator.integers была ошибка, приводившая к статистически смещённой генерации 8- и 16-битных целых чисел. Её исправление изменило поток результатов по сравнению с предыдущими выпусками. (gh-14777)

Добавлены дополнительные внутренние циклы универсальных функций для datetime64 и timedelta64#

Поведение np.datetime('NaT') должно быть ближе к поведению float('Nan'). Добавлена необходимая инфраструктура для работы np.isinf(a) и np.isnan(a) с типами данных datetime64 и timedelta64. Также добавлены специальные циклы для numpy.fmin и numpy.fmax, маскирующие NaT. Это может потребовать изменений в пользовательском коде. В частности, потребуется адаптировать код, который запрещал вызовы numpy.isinf или numpy.isnan либо проверял, что они вызывают исключение. Также потребуется исправить код, ошибочно вызывавший numpy.fmax и numpy.fmin вместо numpy.maximum и numpy.minimum соответственно. Это также затрагивает numpy.nanmax и numpy.nanmin. (gh-14841)

Перемещённые модули в numpy.random#

В рамках очистки API подмодули numpy.random bit_generator, philox, pcg64, sfc64, common, generator и bounded_integers были перемещены в _bit_generator, _philox, _pcg64, _sfc64, _common, _generator и _bounded_integers соответственно, чтобы указать, что они не являются частью общедоступного интерфейса. ( gh-14608 )

Изменения C API#

PyDataType_ISUNSIZED(descr) теперь возвращает False для структурированных типов данных #

Раньше для любого типа данных с itemsize 0 возвращалось True. Теперь для негибкого типа с itemsize 0, np.dtype([]), возвращается False. (gh-14393)

Новые возможности #

Добавим собственный файл импорта Cython *.pxd#

Добавлен файл numpy/__init__.pxd для использования при cimport numpy (gh-12284)

В expand_dims теперь можно передавать кортеж осей#

Для функции numpy.expand_dims именованный аргумент axis теперь может принимать кортеж осей. Раньше axis должен был быть целым числом. (gh-14051)

Поддержка 64-разрядного OpenBLAS #

Добавлена поддержка 64-битного (ILP64) OpenBLAS. Подробности см. в site.cfg.example. ( gh-15012 )

Добавление параметра --f2cmap в F2PY#

Разрешено указывать файл с пользовательскими настройками соответствия типов Fortran и C. (gh-15113)

Улучшения#

Разные числовые типы C одинакового размера имеют уникальные имена#

На каждой платформе два из типов np.intc, np.int_ и np.longlong ранее выглядели неразличимыми по repr, хотя соответствующие dtype имели разные свойства. Похожая проблема была у беззнаковых аналогов этих типов, а на некоторых платформах — у np.double и np.longdouble.

Эти типы теперь всегда выводятся с уникальным __name__. (gh-10151)

argwhere теперь даёт согласованный результат для нульмерных массивов#

Для N-мерных массивов numpy.argwhere теперь всегда возвращает массив формы (n_non_zero, arr.ndim), даже при arr.ndim == 0. Раньше в этом случае длина последней оси равнялась 1. (gh-13610)

Добавлен аргумент axis для random.permutation и random.shuffle#

Раньше функции random.permutation и random.shuffle могли перемешивать элементы массива только по первой оси. Теперь у них есть новый аргумент axis, позволяющий перемешивать элементы по указанной оси. (gh-13829)

Аргумент ключевого слова method для np.random.multivariate_normal #

Аргумент ключевого слова method теперь доступен для np.random.multivariate_normal с возможными значениями {'svd', 'eigh', 'cholesky'} . Чтобы использовать его, напишите np.random.multivariate_normal(..., method=<method>) . ( gh-14197 ).

Добавлена поддержка комплексных чисел в numpy.fromstring#

Теперь numpy.fromstring умеет считывать комплексные числа. (gh-14227)

В numpy.unique порядок осей согласован при axis, отличном от None#

Используется moveaxis вместо swapaxes в numpy.unique, чтобы не нарушать порядок осей, кроме указанной в аргументах. (gh-14255)

numpy.matmul с логическим выходным типом теперь преобразует значения в логические#

Раньше вызов numpy.matmul с выходным массивом логического типа заполнял его эквивалентами результата в uint8 вместо 0/1. Теперь результат принудительно приводится к 0 или 1 (NPY_TRUE или NPY_FALSE). (gh-14464)

numpy.random.randint возвращала неверное значение при диапазоне 2**32#

В реализации, появившейся в версии 1.17.0, выбор между 32-битным и полным 64-битным путями выполнялся с ошибочной проверкой. Из-за неё генерация случайных целых чисел с диапазоном high - low, равным 2**32, ошибочно направлялась к 64-битному генератору. (gh-14501)

Добавлена поддержка комплексных чисел в numpy.fromfile#

numpy.fromfile теперь читает комплексные числа. (gh-14730)

std=c99 добавляется, если компилятор называется gcc #

Для GCC до версии 5 нужен аргумент командной строки -std=c99. Новые компиляторы автоматически включают режим C99. Код настройки компилятора автоматически добавляет этот флаг, если имя компилятора содержит gcc. (gh-14771)

Изменения#

NaT теперь помещается в конец массива при сортировке#

При сортировке NaT теперь фактически считается наибольшим целым числом и помещается в конец массива. Это согласует его поведение с сортировкой NaN. (gh-12658) (gh-15068)

Некорректный threshold в np.set_printoptions вызывает TypeError или ValueError#

Ранее неверное значение threshold вызывало ValueError; теперь возникает TypeError для нечисловых типов и ValueError для значений nan. (gh-13899)

Предупреждение при сохранении dtype с метаданными #

Предупреждение UserWarning выдаётся при сохранении массива через numpy.save, если у массива есть metadata. При этом метаданные могут не сохраниться, а если они сохранятся, загрузка приведёт к ValueError. Этот недостаток сохранения и загрузки будет устранён в будущем выпуске. (gh-14142)

В numpy.distutils изменено поведение добавления значений к LDFLAGS и аналогичным переменным#

Ранее numpy.distutils при компиляции расширений на Fortran заменял значения LDFLAGS и подобных переменных окружения, а не дополнял их. Теперь по умолчанию значения дополняются, как и ожидается в большинстве случаев. Чтобы сохранить прежнее поведение с перезаписью, задайте переменную окружения NPY_DISTUTILS_APPEND_FLAGS равной 0. Это относится к LDFLAGS, F77FLAGS, F90FLAGS, FREEFLAGS, FOPT, FDEBUG и FFLAGS. NumPy 1.16 и 1.17 выдавали предупреждения сборки, если это изменение могло повлиять на используемые флаги компиляции. (gh-14248)

Удаление numpy.random.entropy без предварительного объявления устаревшей#

numpy.random.entropy был добавлен в пространство имён numpy.random в версии 1.17.0. Он задумывался как внутренний модуль расширения на C, но стал общедоступным. Его заменил numpy.random.SeedSequence, поэтому модуль полностью удалён. (gh-14498)

Добавлены параметры для подавления вывода конфигурации сборки и сборки с -Werror#

Добавлены два новых параметра конфигурации. Во время выполнения подкоманды build_src в рамках настройки NumPy файлы _numpyconfig.h и config.h создаются путем проверки поддержки различных функций и подпрограмм времени выполнения. Раньше очень подробный вывод компилятора на этом этапе затуманивал более важную информацию. По умолчанию вывод отключен. Запуск runtests.py --debug-info добавит --verbose-cfg к подкоманде build_src, что восстановит предыдущее поведение.

Задание CFLAGS=-Werror для преобразования предупреждений в ошибки приводило к сбоям конфигурации. Теперь runtests.py --warn-error передаёт --warn-error подкоманде build, откуда параметр поступает в build_ext и build_lib. Флаг компилятора применяется на этих этапах при сборке самого NumPy, превращая предупреждения в ошибки, но не затрагивает вызовы компилятора из build_src.

( gh-14527 ) ( gh-14518 )

    • numpy.argmin/argmax/min/max возвращает NaT, если он есть в массиве
    • np.can_cast(np.uint64, np.timedelta64, casting='safe') теперь возвращает False
    • Изменение потока случайных значений, выдаваемого numpy.random.Generator.integers
    • Добавлены дополнительные внутренние циклы универсальных функций для datetime64 и timedelta64
    • Перемещённые модули в numpy.random

    • Разные числовые типы C одинакового размера имеют уникальные имена

    • Добавлен аргумент axis для random.permutation и random.shuffle
    • Аргумент ключевого слова method для np.random.multivariate_normal
    • Добавлена поддержка комплексных чисел в numpy.fromstring
    • В numpy.unique порядок осей согласован при axis, отличном от None

    • numpy.random.randint возвращала неверное значение при диапазоне 2**32

    • Удаление numpy.random.entropy без предварительного объявления устаревшей
