Историческая справка: страница описывает NumPy 1.19.0. Слова «сейчас», «раньше» и «будет» относятся ко времени этого выпуска; описанное поведение может отличаться от NumPy 2.5.

Примечания к выпуску NumPy 1.19.0#

В этом выпуске NumPy устранён значительный объём технического долга: удалена поддержка Python 2, прекращена поддержка многих ранее объявленных устаревшими возможностей, улучшена документация. Продолжается доработка модуля random: исправляются ошибки и улучшается удобство использования из Cython.

Этот выпуск поддерживает Python 3.6–3.8. Разработчикам проектов, использующих NumPy, следует применять Cython >= 0.29.16 для поддержки Python 3.8 и OpenBLAS >= 3.7 во избежание проблем на архитектуре Skylake.

Основные изменения#

  • Из кода Python и C удалена совместимость с версиями Python < 3.6, включая Python 2. Адаптеры совместимости в numpy.compat останутся для поддержки сторонних пакетов, но в будущем могут быть объявлены устаревшими. Обратите внимание: версия 1.19.x не компилируется с более ранними версиями Python из-за использования f-строк.

    (gh-15233)

Окончательно удалённые устаревшие возможности#

В numpy.insert и numpy.delete больше нельзя указывать ось для нульмерных массивов#

Завершается процесс отказа от поведения, объявленного устаревшим в версии 1.9: при передаче аргумента axis в вызовах ~numpy.insert и ~numpy.delete для нульмерного массива аргумент axis и индексы obj полностью игнорировались. В этих случаях insert(arr, "nonsense", 42, axis=0) фактически перезаписывал весь массив, а delete(arr, "nonsense", axis=0) был эквивалентен arr.copy()

Теперь передача axis для нульмерного массива вызывает ~numpy.AxisError.

(gh-15802)

numpy.delete больше не игнорирует индексы за пределами массива#

Это завершает отказ от поведения, объявленного устаревшим в версиях 1.8 и 1.9: np.delete игнорировала отрицательные и выходящие за границы элементы последовательности индексов. Такое поведение не соответствовало обработке одиночного индекса.

Теперь индексы за границами вызывают IndexError, а отрицательные индексы отсчитываются с конца.

(gh-15804)

numpy.insert и numpy.delete больше не принимают нецелочисленные индексы#

Это завершает отказ от поведения, объявленного устаревшим в версии 1.9: последовательности нецелочисленных индексов допускались и преобразовывались в целочисленные. Теперь передача такой последовательности вызывает IndexError, как и передача одного нецелочисленного скаляра.

( gh-15805 )

numpy.delete больше не преобразует логические индексы в целые числа. #

Это завершает отказ от поведения, объявленного устаревшим в версии 1.8: np.delete преобразовывал булевы массивы и скаляры, переданные как аргумент индекса, в целочисленные индексы. Теперь булевы массивы трактуются как маски, а булевы скаляры вызывают ошибку.

(gh-15815)

Примечания о совместимости#

Изменение потока случайных значений, выдаваемого numpy.random.Generator.dirichlet#

Исправлена ошибка генерации выборок из распределения Дирихле при малых значениях alpha: при max(alpha) < 0.1 используется другой алгоритм. Вследствие этого последовательность значений, генерируемая dirichlet в данном случае, отличается от предыдущих выпусков.

(gh-14924)

Повышение типов скаляров в PyArray_ConvertToCommonType#

Правила выбора общего типа для сочетаний скаляров и массивов в PyArray_ConvertToCommonType приведены в соответствие с np.result_type. Теперь для входных данных вида (1000, np.array([1], dtype=np.uint8))) возвращается тип uint16. В большинстве случаев поведение не меняется. Использовать эту функцию C API в целом не рекомендуется. Также исправлена np.choose: теперь в этом отношении она ведёт себя так же, как остальные функции NumPy.

(gh-14933)

Слоты fasttake и fastputmask объявлены устаревшими и установлены в NULL#

Поля fasttake и fastputmask больше не используются и всегда должны быть равны NULL. Поведение при этом не меняется. Однако если пользовательский dtype задаёт одно из этих полей, выдаётся DeprecationWarning.

(gh-14942)

Поведение приведения типов в np.ediff1d с to_end и to_begin#

np.ediff1d теперь использует правило приведения типов "same_kind" для дополнительных аргументов to_end и to_begin. Это обеспечивает безопасность типов, кроме случаев, когда целочисленный тип входного массива имеет меньшую разрядность, чем тип to_begin или to_end. В редких случаях ограничения будут строже, чем в версиях 1.16 и 1.17. Это необходимо для устранения проблем со значениями NaN с плавающей точкой.

(gh-14981)

Преобразование пустых объектов, подобных массивам, в массивы NumPy#

Объекты с len(obj) == 0, реализующие интерфейс массива (obj.__array__(), obj.__array_interface__, obj.__array_struct__ или буферный интерфейс Python) и одновременно являющиеся последовательностями, например объекты Pandas, теперь всегда сохраняют правильную форму при преобразовании в массив. Ранее объект формы (0, 1) мог преобразоваться в массив формы (0,), теряя все измерения после первого измерения нулевой длины.

(gh-14995)

Удалён multiarray.int_asbuffer#

В рамках дальнейшего удаления совместимости с Python 2 удалён multiarray.int_asbuffer. В Python 3 он вызывал NotImplementedError и не использовался внутри NumPy. Предполагается, что зависимые пакеты также не используют этот метод с Python 3.

(gh-15229)

numpy.distutils.compat удалён#

Этот модуль содержал только функцию get_exception(), которая использовалась как:

try:
    ...
except Exception:
    e = get_exception()

Его целью было обработать изменение синтаксиса, введенное в Python 2.6, от except Exception, e: до except Exception as e:, то есть это было необходимо только для кодовых баз, поддерживающих Python 2.5 и старше.

(gh-15255)

issubdtype больше не интерпретирует float как np.floating #.

Переходный период для numpy.issubdtype, сопровождавшийся FutureWarning с NumPy 1.14, завершён. Теперь, если второй аргумент не был объектом типа данных или скалярным типом NumPy (например, это строка или тип Python int либо float), результат совпадает с передачей np.dtype(arg2).type. Это соответствует ожидаемому поведению и в некоторых случаях даёт false вместо прежнего true.

(gh-15773)

Результат round для скаляров приведён в соответствие с Python#

При вызове без аргументов специальный метод __round__ и, соответственно, встроенная функция Python round теперь возвращают Python int, как и при вызове для объектов Python float. Ранее возвращался скаляр того типа np.dtype, который был передан.

(gh-15840)

Конструктор numpy.ndarray больше не трактует strides=() как strides=None#

Поведение первого варианта изменено: теперь он ожидаемым образом устанавливает numpy.ndarray.strides в (), тогда как второй по-прежнему приводит к автоматическому выбору шагов.

(gh-15882)

Изменены преобразования строк в datetime на уровне C#

Приведения из строк на уровне C упрощены. Это также исправляет преобразование строк в datetime и timedelta: теперь оно работает как в Python с string_arr.astype("M8"), а раньше вело себя как string_arr.astype(np.int_).astype("M8"). Изменение затрагивает только код, вручную приводящий отдельные скалярные значения через низкоуровневый C API, а не целые массивы, или использующий, например, PyArray_GetCastFunc. Поэтому подавляющее большинство пользователей его не заметит.

(gh-16068)

Малые значения seed в SeedSequence больше не конфликтуют с созданием дочерних последовательностей#

Ранее небольшие начальные значения (меньше 2**96) неявно дополнялись нулями до 128 бит — размера внутреннего пула энтропии. При порождении потомков ключ порождения присоединялся до дополнения нулями. Поскольку первый ключ порождения равен (0,), небольшое исходное значение и первый порождённый SeedSequence давали одинаковые состояния. Теперь начальное значение явно дополняется нулями до размера внутреннего пула перед добавлением ключа порождения. Порождённые SeedSequences будут давать другие результаты, чем в предыдущем выпуске. Непорождённые SeedSequences сохраняют прежние результаты.

(gh-16551)

Устаревающие возможности#

Автоматический dtype=object для входных данных с неодинаковой длиной вложенных последовательностей объявлен устаревшим#

Вызов np.array([[1, [1, 2, 3]]) выдаёт DeprecationWarning согласно NEP 34. Чтобы избежать предупреждения, нужно явно указать dtype=object. Примечание переводчика: в исходном примере не согласованы скобки; для иллюстрации имеется в виду np.array([1, [1, 2, 3]]).

(gh-15119)

Передача shape=0 фабричным функциям в numpy.rec объявлена устаревшей#

Значение 0 обрабатывается как особый случай и эквивалентно None в функциях:

  • numpy.core.records.fromarrays

  • numpy.core.records.fromrecords

  • numpy.core.records.fromstring

  • numpy.core.records.fromfile

В будущем 0 не будет обрабатываться особо: как и любое другое целое число, это значение будет трактоваться как длина массива.

(gh-15217)

Возможно неиспользуемые функции C API объявлены устаревшими#

Следующие функции C-API, вероятно, не используются и объявлены устаревшими:

  • PyArray_GetArrayParamsFromObject

  • PyUFunc_GenericFunction

  • PyUFunc_SetUsesArraysAsData

В большинстве случаев PyArray_GetArrayParamsFromObject следует заменить путем преобразования в массив, а PyUFunc_GenericFunction можно заменить на PyObject_Call (подробности см. в документации).

(gh-15427)

Преобразование некоторых типов в dtype объявлено устаревшим#

Суперклассы скалярных типов, например np.integer, np.generic и np.inexact, теперь вызывают предупреждение об устаревании при преобразовании в dtype или использовании в именованном аргументе dtype. Причина в том, что np.integer преобразуется в np.int_, хотя ожидается обозначение любого целочисленного типа, включая int8, int16 и т. д. Например, dtype=np.floating сейчас идентично dtype=np.float64, хотя np.float32 тоже является подклассом np.floating.

( gh-15534 )

round объявлен устаревшим для скаляров np.complexfloating#

Для комплексных скаляров использование специального метода __round__ и, следовательно, встроенной функции Python round объявлено устаревшим. Это не затрагивает np.round.

(gh-15840)

numpy.ndarray.tostring() объявлен устаревшим в пользу tobytes()#

~numpy.ndarray.tobytes существует с версии 1.9, но до этого выпуска ~numpy.ndarray.tostring не выдавала предупреждения. Добавление предупреждения приводит NumPy в соответствие с одноимёнными методами встроенного типа array.array.

( gh-15867 )

Изменения C API#

Улучшена поддержка размеров с квалификатором const в функциях API#

Следующие функции теперь принимают доступный только для чтения массив элементов типа npy_intp:

  • PyArray_BroadcastToShape

  • PyArray_IntTupleFromIntp

  • PyArray_OverflowMultiplyList

Раньше вызывающему коду приходилось снимать квалификатор const приведением типа, чтобы вызвать эти функции.

( gh-15251 )

Добавление квалификатора const во внутренние циклы ufunc#

UFuncGenericFunction теперь принимает указатели на константные dimension и strides. Поэтому внутренним циклам нельзя изменять dimension и strides. Из-за этого возникает предупреждение incompatible-pointer-types: пользователям нужно либо игнорировать его, либо добавить const в сигнатуры собственных циклов.

(gh-15355)

Новые возможности #

numpy.frompyfunc теперь принимает аргумент identity (нейтральный элемент)#

Это позволяет задать атрибут numpy.ufunc.identity создаваемой универсальной функции и использовать её для пустых массивов и многомерных свёрток через numpy.ufunc.reduce.

( gh-8255 )

Скалары np.str_ теперь поддерживают буферный протокол #

Массивы np.str_ всегда хранятся в формате UCS4. Теперь соответствующие скаляры предоставляют это представление через буферный интерфейс, поэтому memoryview(np.str_('test')) работает.

(gh-15385)

Параметр subok для numpy.copy#

Новый именованный параметр subok добавлен в numpy.copy для управления поведением numpy.copy относительно подклассов массивов. По умолчанию он равен False, что соответствует поведению numpy.copy в предыдущих версиях NumPy. Чтобы создать копию с сохранением подкласса через numpy.copy, вызовите np.copy(arr, subok=True). Это дополнение яснее показывает различие между поведением numpy.copy по умолчанию и методом numpy.ndarray.copy, который по умолчанию сохраняет подклассы.

(gh-15685)

numpy.linalg.multi_dot теперь принимает аргумент out #

out позволяет избежать ненужного копирования итогового произведения, вычисленного numpy.linalg.multidot. Примечание переводчика: в имени функции опечатка; правильно numpy.linalg.multi_dot.

( gh-15715 )

Параметр keepdims для numpy.count_nonzero#

Параметр keepdims добавлен в numpy.count_nonzero. Он имеет то же значение, что и в функциях свёртки, например numpy.sum или numpy.mean.

(gh-15870)

Параметр equal_nan для numpy.array_equal#

Именованный аргумент equal_nan добавлен в numpy.array_equal. Булев параметр equal_nan определяет, считаются ли значения nan равными при сравнении (по умолчанию False). Это соответствует API связанных функций, например numpy.isclose и numpy.allclose.

(gh-16128)

Улучшения#

Улучшенное определение возможностей процессора#

Специфичный для gcc механизм проверки поддержки AVX npy_cpu_supports заменён более общими функциями npy_cpu_init и npy_cpu_have. Результаты доступны через макрос C NPY_CPU_HAVE и словарь Python __cpu_features__.

( gh-13421 )

Использование 64-битных целых чисел на 64-битных платформах в резервной реализации lapack_lite#

В резервной библиотеке LAPACK, используемой при отсутствии системной LAPACK, на 64-битных платформах теперь применяются 64-битные целые числа. Это позволяет выполнять операции линейной алгебры с большими массивами.

( gh-15218 )

Инструкции AVX512 используются для реализации np.exp при входных данных типа np.float64#

Для np.exp с входными данными np.float64 использованы встроенные функции AVX512, что ускоряет np.exp для np.float64 в 5–7 раз. Размер модуля _multiarray_umath.so в linux64 увеличился примерно на 63 КБ.

(gh-15648)

Возможность отключить большие страницы памяти через madvise#

В Linux NumPy ранее была добавлена поддержка огромных страниц madavise, которая может повысить производительность для очень больших массивов. К сожалению, в более старых версиях ядра это приводило к снижению производительности, поэтому по умолчанию поддержка была отключена в ядрах до версии 4.6. Чтобы переопределить значение по умолчанию, вы можете использовать переменную среды:

NUMPY_MADVISE_HUGEPAGE=0

либо установите значение 1, чтобы принудительно включить поддержку. Это имеет значение лишь при настройке ОС на использование прозрачных больших страниц через madvise.

(gh-15769)

numpy.einsum принимает тип NumPy int64 в списке индексов#

Передача в numpy.einsum массива NumPy int64 в качестве списка индексов больше не вызывает ошибку типа.

( gh-16080 )

np.logaddexp2.identity сменился на -inf #

Универсальная функция ~numpy.logaddexp2 теперь имеет нейтральный элемент -inf, что позволяет вызывать её для пустых последовательностей. Это совпадает с нейтральным элементом ~numpy.logaddexp.

(gh-16102)

Изменения#

Удалить обработку дополнительного аргумента в __array__ #

Начиная с NumPy 0.4 код содержал ветвь и тест для варианта __array__(dtype=None, context=None) с двумя аргументами. Она использовалась при вызове ufunc(op) или ufunc.reduce(op), если существовал op.__array__. Этот вариант не был документирован, и его назначение неясно. Теперь он удалён.

(gh-15118)

numpy.random._bit_generator перешел в numpy.random.bit_generator #

Чтобы предоставить Cython доступ к numpy.random.BitGenerator и numpy.random.SeedSequence, модуль _bitgenerator теперь открыт как numpy.random.bit_generator.

Доступ из Cython к случайным распределениям предоставляется через файл pxd#

c_distributions.pxd предоставляет из Cython доступ к функциям C, реализующим многие распределения случайных величин, что упрощает их использование и расширение.

( gh-15463 )

Исправлены методы eigh и cholesky в numpy.random.multivariate_normal#

Раньше при передаче method='eigh' или method='cholesky' функция numpy.random.multivariate_normal генерировала выборки из неверного распределения. Теперь это исправлено.

(gh-15872)

Исправлена реализация переходов в MT19937.jumped#

Это исправление меняет поток чисел генераторов MT19937 после скачка состояния. Оно не влияет на поток RandomState или MT19937, инициализированных напрямую.

При переносе кода перехода вперёд для MT19937 порядок циклов оказался обратным. Теперь MT19937.jumped соответствует исходной реализации Макото Мацумото методов перехода Хорнера и скользящего окна.

( gh-16153 )
