Историческая справка: страница описывает NumPy 1.22.0. Слова «сейчас», «раньше» и «будет» относятся ко времени этого выпуска; описанное поведение может отличаться от NumPy 2.5.

Примечания к выпуску NumPy 1.22.0#

NumPy 1.22.0 — крупный выпуск, над которым работали 153 участника, создавшие 609 запросов на слияние. Основные из многочисленных улучшений:

  • Аннотации типов основного пространства имён практически завершены. Основной код продолжает меняться, поэтому дальнейшие улучшения вероятны, но главная работа уже сделана. Возможно, это самое заметное для пользователей улучшение выпуска.

  • Предложена предварительная версия предлагаемого Array-API. Это шаг в создании стандартного набора функций, которые могут использоваться в таких приложениях, как CuPy и JAX.

  • В NumPy появился бэкенд DLPack. DLPack предоставляет общий формат обмена данными массивов (тензоров).

  • Новые методы для quantile, percentile и связанных с ними функций.Новые методы обеспечивают полный набор методов, обычно встречающихся в литературе.

  • Реализация универсальных функций переработана в соответствии с большей частью NEP 43. Это также позволяет экспериментировать с будущим API DType.

  • Новый настраиваемый распределитель памяти для проектов, зависящих от NumPy.

Всё это дополняет продолжающуюся работу над поддержкой SIMD в часто используемых функциях, улучшениями F2PY и документации.

В этом выпуске поддерживаются версии Python 3.8–3.10; поддержка Python 3.7 прекращена. Пакеты wheel для Mac теперь рассчитаны на OS X 10.14 вместо 10.9, использовавшейся в предыдущих циклах выпуска NumPy. На момент выпуска 10.14 — самая старая версия, поддерживаемая Apple. 32-битные wheel предоставляются только для Python 3.8 и 3.9 в Windows; все остальные wheel — 64-битные, поскольку Ubuntu, Fedora и другие дистрибутивы Linux прекратили поддержку 32-битных систем. Все 64-битные wheel также скомпонованы с OpenBLAS с 64-битными целочисленными аргументами. Это должно устранить редкие проблемы при работе с действительно огромными массивами.

Использование строк "Bytes0", "Datetime64", "Str0", "Uint32" и "Uint64" в качестве dtype теперь вызывает TypeError.

numpy.loads объявлена устаревшей в v1.15; вместо неё рекомендуется pickle.loads. ndfromtxt и mafromtxt объявлены устаревшими в v1.17; используйте numpy.genfromtxt с подходящим значением параметра usemask.

Имя аргумента delimitor функции numpy.ma.mrecords.fromtextfile(), содержащее опечатку, заменено на delimiter. Использование прежнего имени вызывает предупреждение об устаревании.

Раньше numpy.partition и numpy.argpartition принимали логические значения параметра kth, которые затем преобразовывались в целые числа. Теперь это поведение объявлено устаревшим.

( gh-20000 )

Класс numpy.MachAr и атрибут finfo.machar <numpy.finfo> объявлены устаревшими. Рекомендуется получать нужное свойство непосредственно через соответствующий атрибут numpy.finfo.

(gh-20201)

Примечания о совместимости#

Distutils принудительно использует строгую модель с плавающей запятой в clang #

NumPy теперь устанавливает опцию -ftrapping-math на clang, чтобы обеспечить правильную обработку ошибок с плавающей запятой для универсальных функций. По умолчанию Clang не соответствует IEEE и C99. Это изменение (с использованием эквивалентного, но более нового -ffp-exception-behavior=strict) было предпринято в NumPy 1.21, но фактически никогда не использовалось.

(gh-19479)

Удалена поддержка целочисленного деления для комплексных типов#

Деление с округлением вниз для комплексных типов теперь вызывает TypeError

>>> a = np.arange(10) + 1j* np.arange(10)
>>> a // 1
TypeError: ufunc 'floor_divide' not supported for the input types...

(gh-19135)

Функции numpy.vectorize теперь возвращают результат того же класса, что и исходная функция#

Если функция, поддерживающая подклассы numpy.ndarray, векторизуется через numpy.vectorize, векторизованная функция теперь сохраняет поддержку подклассов и при заданной сигнатуре, то есть при создании gufunc: класс результата совпадает с классом, возвращённым первым вызовом исходной функции.

( gh-19356 )

Python 3.7 больше не поддерживается#

Поддержка Python прекращена. Это довольно строго, есть изменения, требующие Python >= 3.8.

( gh-19665 )

str/repr комплексных dtype теперь содержат пробелы после знаков пунктуации#

Теперь repr объекта np.dtype({"names": ["a"], "formats": [int], "offsets": [2]}) имеет вид dtype({'names': ['a'], 'formats': ['<i8'], 'offsets': [2], 'itemsize': 10}), тогда как ранее пробелы после двоеточий и между полями опускались.

Старое поведение может быть восстановлено с помощью np.set_printoptions(legacy="1.21").

(gh-19687)

Исправлен advance в PCG64DSXM и PCG64 #

Исправлена ошибка метода advance генераторов PCG64DSXM и PCG64. Она влияла на результат только при шаге больше \(2^{64}\) на платформах без 128-битных целых чисел, например Windows и 32-разрядном Linux.

(gh-20049)

Изменение генерации 32-битных случайных значений с плавающей точкой#

При генерации 32-битных чисел с плавающей запятой из равномерного распределения существовала ошибка: младший бит полученного случайного числа всегда был равен 0. Ошибка исправлена.

Изменение влияет на случайные значения, генерируемые методами random.Generator random, standard_normal, standard_exponential и standard_gamma, но только при dtype равном numpy.float32.

( gh-20314 )

Изменения C API#

Внутренние циклы с маской больше нельзя настраивать#

Механизм выбора внутреннего цикла с маской больше не используется. В маловероятном случае, если он был переопределён, выдаётся предупреждение.

Мы не ожидаем, что какой-либо код использует это. Если вы используете его, вы должны отключить селектор на более новой версии NumPy. Пожалуйста, также свяжитесь с разработчиками NumPy, мы ожидаем предоставления нового, более конкретного, механизма.

Эта настройка была частью так и не реализованной возможности ускорения операций с масками.

(gh-19259)

Экспериментальный доступ к будущему API DType и UFunc#

Новый заголовок experimental_public_dtype_api.h позволяет экспериментировать с будущим API для улучшенной поддержки универсальных функций и, особенно, пользовательских DType. На данном этапе рекомендуется использовать разрабатываемую версию NumPy: ожидаются изменения и добавление новых возможностей.

(gh-19919)

Новые возможности #

NEP 49: настраиваемые аллокаторы#

Как описано в NEP 49, функцию выделения сегмента данных ndarray можно менять. Политику можно задать глобально или в контексте. Подробнее см. NEP и справочный раздел Управление памятью в NumPy. Также добавлено переопределение NUMPY_WARN_IF_NO_MEM_POLICY для предупреждения об опасной передаче владения через установку NPY_ARRAY_OWNDATA.

(gh-17582)

Реализация NEP 47 (принятие стандарта Array API)#

Добавлена начальная реализация NEP 47 — внедрения стандарта Array API — в виде numpy.array_api. Она экспериментальная и при импорте выдаёт UserWarning, поскольку стандарт Array API ещё является черновиком. numpy.array_api соответствует стандарту и минимальна: реализует только обязательные функции и поведение (подробнее см. NEP). Библиотекам, использующим Array API, рекомендуется проверять с помощью numpy.array_api, что они зависят только от возможностей, гарантированных стандартом.

(gh-18585)

Теперь можно создавать справочную документацию C/C++ API из блоков комментариев#

Эта функция зависит от Doxygen в процессе генерации и от Breathe для интеграции с Sphinx.

( gh-18884 )

Определение платформенной точности c_intp с помощью плагина mypy#

Возможности плагина mypy, добавленного в numpy/numpy#17843, снова расширены. Теперь он задаёт зависящую от платформы точность numpy.ctypeslib.c_intp — типа данных, используемого для различных атрибутов numpy.ndarray.ctypes.

Без плагина для упомянутого типа по умолчанию используется ctypes.c_int64.

Чтобы включить плагин, добавьте его в файл конфигурации mypy:

[mypy]
plugins = numpy.typing.mypy_plugin

(gh-19062)

Добавлена поддержка dlpack, совместимая с NEP 47#

Добавлен метод ndarray.__dlpack__(), возвращающий структуру C dlpack, обёрнутую в PyCapsule. Также добавлена функция np._from_dlpack(obj), где obj поддерживает __dlpack__(); она возвращает ndarray.

(gh-19083)

Необязательный аргумент keepdims добавлен в numpy.argmin и numpy.argmax#

Аргумент keepdims добавлен в numpy.argmin и numpy.argmax. При значении True оси, по которым выполняется свёртка, сохраняются в результате как измерения размера 1. Полученный массив имеет столько же измерений, сколько входной, и совместим с ним по правилам трансляции массивов.

(gh-19211)

bit_count для подсчёта единичных битов в целом числе#

Подсчитывает единичные биты в абсолютном значении входа. Работает со всеми целочисленными типами NumPy. Аналогично встроенной функции int.bit_count или popcount в C++.

>>> np.uint32(1023).bit_count()
10
>>> np.int32(-127).bit_count()
7

Clang-format — средство форматирования кода C/C++. Вместе с добавленным файлом .clang-format оно формирует код, достаточно близкий к NumPy C_STYLE_GUIDE для повседневного использования. (gh-19754)

is_integer теперь доступен для numpy.floating и numpy.integer#

По аналогии с типами Python float и int целочисленные типы NumPy и типы с плавающей запятой теперь поддерживают float.is_integer. Метод возвращает True, если число конечно и имеет целое значение, и False в противном случае.

>>> np.float32(-2.0).is_integer()
True
>>> np.float64(3.2).is_integer()
False
>>> np.int32(-2).is_integer()
True

(gh-19803)

( gh-19805 )

ndarray, dtype и number теперь поддерживают параметризацию через квадратные скобки во время выполнения#

По аналогии с PEP 585 классы numpy.ndarray, numpy.dtype и numpy.number теперь поддерживают параметризацию в квадратных скобках в Python 3.9 и новее. Поэтому выражения, которые раньше допускались только в файлах заглушек .pyi или с помощью from __future__ import annotations, теперь допустимы и во время выполнения.

>>> import numpy as np
>>> from typing import Any

>>> np.ndarray[Any, np.dtype[np.float64]]
numpy.ndarray[typing.Any, numpy.dtype[numpy.float64]]

Атрибуты smallest_normal и smallest_subnormal доступны в качестве расширения класса finfo для любого типа данных с плавающей запятой. Для использования этих новых атрибутов напишите np.finfo(np.float64).smallest_normal или np.finfo(np.float64).smallest_subnormal.

numpy.linalg.qr теперь обрабатывает пакеты входных матриц. Кроме того, реализация QR-разложения перенесена с Python на C.

(gh-19151)

numpy.fromregex теперь принимает объекты, реализующие протокол __fspath__<os.PathLike>, например pathlib.Path.

( gh-19680 )

Добавлены новые методы вычисления quantile и percentile#

У quantile и percentile появился именованный аргумент method= с поддержкой 13 различных методов. Он заменяет именованный аргумент interpolation=.

Теперь методы соответствуют девяти методам, известным из научной литературы и языка R. Остальные методы — прежние разрывные варианты метода “linear”, используемого по умолчанию.

Пожалуйста, ознакомьтесь с документацией numpy.percentile для получения дополнительной информации.

( gh-19857 )

В функции nan<x> добавлены недостающие параметры #

В некоторых функциях nan<x> раньше отсутствовали параметры их обычных аналогов <x>: например, параметр where был у numpy.mean, но не у numpy.nanmean.

В функции nan<x> добавлены следующие параметры:

  • nanmin: initial и where

  • nanmax: initial и where

  • nanargmin: keepdims и out

  • nanargmax: keepdims и out

  • nansum: initial и where

  • nanprod: initial и where

  • nanmean: where

  • nanvar: where

  • nanstd: where

Аннотации типов в основном пространстве имён NumPy#

Начиная с версии 1.20, аннотации типов PEP 484 включены для частей библиотеки NumPy; аннотирование остальных функций находится в стадии разработки. С выпуском версии 1.22 этот процесс был завершен для основного пространства имен NumPy, которое теперь полностью аннотировано.

Помимо основного пространства имен, ограниченное количество подпакетов также содержит аннотации. Это включает, среди прочего, numpy.testing, numpy.linalg и numpy.random (доступен с 1.21).

(gh-20217)

Векторизация модуля umath с помощью AVX-512#

Благодаря Intel Short Vector Math Library (SVML) 18 функций umath (exp2, log2, log10, expm1, log1p, cbrt, sin, cos, tan, arcsin, arccos, arctan, sinh, cosh, tanh, arcsinh, arccosh, arctanh) векторизованы с помощью инструкций AVX-512 для одинарной и двойной точности. Сейчас это изменение действует только в Linux на процессорах с AVX-512. Среднее ускорение составляет 32 и 14 раз для функций одинарной и двойной точности соответственно.
