Историческая справка: страница описывает NumPy 1.23.0. Слова «сейчас», «раньше» и «будет» относятся ко времени этого выпуска; описанное поведение может отличаться от NumPy 2.5.

Примечания к выпуску NumPy 1.23.0#

В NumPy 1.23.0 продолжается улучшение обработки и повышения типов данных, ускорение выполнения, уточнение документации и окончательное удаление давно устаревших возможностей. Основные изменения:

  • Реализация loadtxt на C, значительно повышающая производительность.

  • Предоставление DLPack на уровне Python для удобного обмена данными.

  • Изменения повышения типов и сравнения структурированных dtype.

  • Улучшения для f2py.

Подробности см. ниже,

Новые функции #

  • Специализация маскированного массива ndenumerate теперь доступна как numpy.ma.ndenumerate. Он обеспечивает альтернативу numpy.ndenumerate и пропускает маскированные значения по умолчанию.

    ( gh-20020 )

  • Добавлена numpy.from_dlpack для удобного обмена данными по протоколу DLPack. Она принимает объекты Python с методами __dlpack__ и __dlpack_device__ и возвращает ndarray, который обычно является представлением данных входного объекта.

    (gh-21145)

Устаревающие возможности#

  • Присваивание __array_finalize__ значения None объявлено устаревшим. Теперь этот атрибут должен быть методом; в нём можно вызвать super().__array_finalize__(obj), предварительно проверив, не равен ли метод родителя None, либо убедившись, что версия NumPy достаточно новая.

    (gh-20766)

  • Значение axis=32 (axis=np.MAXDIMS) во многих случаях имело тот же смысл, что и axis=None. Такое использование объявлено устаревшим; вместо него нужно указывать axis=None.

    (gh-20920)

  • Функция-хук PyDataMem_SetEventHook объявлена устаревшей, а пример её использования в tool/allocation_tracking удалён. Теперь отслеживание выделения памяти встроено в Python через tracemalloc.

    ( gh-20394 )

  • numpy.distutils объявлен устаревшим вследствие объявления устаревшим самого distutils. Он не будет присутствовать в NumPy для Python >= 3.12 и будет полностью удалён через два года после выпуска Python 3.12. Подробнее см. Состояние numpy.distutils и рекомендации по переходу.

    (gh-20875)

  • Теперь numpy.loadtxt выдаёт DeprecationWarning, если запрошен целочисленный dtype, а значение записано как число с плавающей точкой.

    (gh-21663)

Окончательно удалённые устаревшие возможности#

  • Методы NpzFile.iteritems() и NpzFile.iterkeys() удалены в рамках дальнейшего отказа от совместимости с Python 2. Этим завершён процесс, начатый объявлением их устаревшими в версии 1.15.

    (gh-16830)

  • Функции alen и asscalar были удалены.

    (gh-20414)

  • Флаг массива UPDATEIFCOPY удалён вместе с элементом перечисления NPY_ARRAY_UPDATEIFCOPY. Также удалён связанный устаревший PyArray_XDECREF_ERR. Всё это объявлено устаревшим в 1.14. Замена — NPY_ARRAY_WRITEBACKIFCOPY, требующий вызова PyArray_ResolveWritebackIfCopy перед освобождением массива.

    (gh-20589)

  • При создании массива из объектов, подобных массиву, теперь передаются возникшие исключения. Ранее исключение, возникавшее при доступе к специальным атрибутам __array__ или __array_interface__ объекта, обычно игнорировалось. Такое поведение объявлено устаревшим в 1.21; теперь исключение передаётся вызывающему коду.

    (gh-20835)

  • Многомерная индексация значениями, не являющимися кортежами, больше не допускается. Раньше arr[ind] при ind = [[0, 1], [0, 1]] выдавало FutureWarning и интерпретировалось как многомерный индекс, то есть arr[tuple(ind)]. Теперь такой пример рассматривается как индексация массивом по одному измерению (arr[array(ind)]). Многомерная индексация чем-либо, кроме кортежа, объявлена устаревшей в NumPy 1.15.

    (gh-21029)

  • Для массивов, непрерывно расположенных в памяти в порядке Fortran, изменение dtype на тип с другим размером элемента больше не допускается. Эта возможность объявлена устаревшей в NumPy 1.11.0. Подробное объяснение последствий изменения приведено ниже.

    ( gh-20722 )

Новые возможности #

crackfortran поддерживает перегрузку операторов и оператора присваивания#

Парсер crackfortran теперь распознаёт определения операторов и присваивания в модуле. Они добавляются в список body модуля с новым ключом implementedby, перечисляющим имена реализующих их подпрограмм или функций.

(gh-15006)

f2py поддерживает чтение атрибутов доступа из объявлений производных типов#

В результате не нужно использовать public или private для указания свойств доступа производного типа.

(gh-15844)

Новый параметр ndmin добавлен в genfromtxt #

Этот параметр ведет себя так же, как ndmin из numpy.loadtxt.

(gh-20500)

np.loadtxt теперь поддерживает символ кавычек и единую функцию преобразования#

numpy.loadtxt теперь поддерживает дополнительный именованный аргумент quotechar, по умолчанию не заданный. Значение quotechar='"' позволяет читать поля в кавычках, используемые в варианте CSV для Excel.

Кроме того, в аргумент converters теперь можно передать один вызываемый объект вместо словаря.

(gh-20580)

Для смены dtype на тип другого размера теперь требуется непрерывное расположение только по последней оси#

Раньше для представления массива с dtype другого размера элемента требовалось, чтобы весь массив непрерывно располагался в памяти в порядке C. Это вынуждало создавать непрерывные копии других массивов перед изменением dtype, хотя такая необходимость была излишней.

Это изменение затрагивает не только ndarray.view, но и другие способы создания, включая не рекомендуемое прямое присваивание атрибуту ndarray.dtype.

Это изменение завершает отказ от ранее объявленного устаревшим создания представлений массивов с непрерывным расположением в порядке Fortran, описанного в другом месте примечаний к выпуску.

( gh-20722 )

Детерминированные выходные файлы для F2PY #

Для исходного кода F77 f2py всегда создаёт modname-f2pywrappers.f, хотя файл может быть пустым. Для кода в свободном формате всегда создаются modname-f2pywrappers.f и modname-f2pywrappers2.f90; они также могут быть пустыми. Это позволяет писать общие правила для выходных файлов в cmake, meson и других системах сборки. Прежнее поведение можно восстановить, передав параметр --skip-empty-wrappers в f2py. Подробнее см. в разделе Использование через meson.

(gh-21187)

Параметр keepdims для average#

Параметр keepdims добавлен в numpy.average и numpy.ma.average с тем же смыслом, что и в функциях свёртки, например numpy.sum и numpy.mean.

(gh-21485)

Новый параметр equal_nan добавлен в np.unique #

В версии 1.21 np.unique изменён: все значения NaN считаются равными и возвращается единственный NaN. Настройка equal_nan=False восстанавливает поведение до 1.21, при котором значения NaNs считаются различными. По умолчанию True.

(gh-21623)

Примечания о совместимости#

Для одномерных массивов np.linalg.norm сохраняет входной тип с плавающей запятой даже при скалярном результате#

Ранее тип повышался до float64, если аргумент ord не входил в явно перечисленные значения, например ord=3:

>>> f32 = np.float32([1, 2])
>>> np.linalg.norm(f32, 2).dtype
dtype('float32')
>>> np.linalg.norm(f32, 3)
dtype('float64')  # numpy 1.22
dtype('float32')  # numpy 1.23
Комментарии к примеру на русском
  • NumPy 1.22
  • NumPy 1.23

Это изменение затрагивает только векторы float32 и float16 с ord, отличными от -Inf, 0, 1, 2 и Inf.

( gh-17709 )

Изменения повышения типов и сравнения структурированных dtype (void)#

Теперь NumPy обеспечивает корректное, хотя и несколько ограниченное повышение структурированных типов данных: вместо исключения выполняется повышение типов каждого поля:

>>> np.result_type(np.dtype("i,i"), np.dtype("i,d"))
dtype([('f0', '<i4'), ('f1', '<f8')])

Для повышения типов имена полей, их порядок и заголовки должны совпадать; байты заполнения при этом игнорируются. Повышение с участием структурированных dtype теперь всегда обеспечивает системный порядок байтов во всех полях, что может изменить результат np.concatenate. Результат также всегда «упакован»: поля располагаются подряд, а байты заполнения удаляются. Подробнее см. «Сравнение структур и повышение типов».

repr выровненных структур теперь использует длинную форму с offsets и itemsize только если структура содержит заполнение, не гарантируемое align=True.

В соответствии с изменениями продвижения типов обновлены правила безопасности приведения:

  • Правило "equiv" требует совпадения имён и дополнительных названий полей (titles). Размер элемента может различаться из-за байтов заполнения.

  • "safe" допускает несовпадающие имена полей и их дополнительные названия (titles)

  • Безопасность приведения типов ограничивается безопасностью приведения каждого входящего поля.

  • Безопасность приведения каждого поля определяется порядком полей. Ранее использовались имена полей; если они не совпадали, допускалось только небезопасное приведение.

Основное изменение: несовпадения имён теперь считаются «безопасными» приведениями типов.

(gh-19226)

NPY_RELAXED_STRIDES_CHECKING удалён#

NumPy больше нельзя компилировать с NPY_RELAXED_STRIDES_CHECKING=0. Ослабленные требования к шагам по памяти уже много лет используются по умолчанию; этот параметр изначально ввели для более плавного перехода.

(gh-20220)

np.loadtxt получил несколько изменений #

Исправлен подсчёт строк в numpy.loadtxt. Функция loadtxt пропускает полностью пустые строки файла, но раньше учитывала их при подсчёте max_rows. Теперь при использовании max_rows пустые строки файла не учитываются. Ранее результат мог содержать меньше max_rows строк, хотя в файле оставались данные для чтения. Если требуется прежнее поведение, можно использовать itertools.islice:

import itertools
lines = itertools.islice(open("file"), 0, max_rows)
result = np.loadtxt(lines, ...)

Хотя numpy.loadtxt в целом стала значительно быстрее и получила ряд улучшений, некоторые строки, ранее успешно считывавшиеся, теперь могут не преобразовываться в числа. Важнейшие случаи:

  • Преобразование при чтении значений с плавающей точкой, например 1.0, в целые числа теперь объявлено устаревшим.

  • Разбор шестнадцатеричных чисел с плавающей запятой, например 0x3p3, завершится ошибкой

  • Раньше _ допускался как разделитель разрядов, например 100_000. Теперь это вызывает ошибку.

Эти ограничения можно обойти, передав подходящие преобразователи через converters=. Для удобства NumPy теперь поддерживает передачу одного преобразователя для всех столбцов. Например, converters=float.fromhex позволяет читать шестнадцатеричные числа с плавающей точкой, а converters=int — значения вида 100_000.

Кроме того, сообщения об ошибках в целом улучшены. Однако типы ошибок при этом могут отличаться. В частности, теперь при неудачном разборе отдельной записи всегда возбуждается ValueError.

(gh-20580)

Улучшения#

ndarray.__array_finalize__ теперь можно вызывать#

Теперь подклассы могут использовать super().__array_finalize__(obj), не заботясь о том, является ли ndarray их родительским классом. Сам вызов по-прежнему ничего не делает.

(gh-20766)

Добавлена поддержка VSX4/Power10#

Поддержка VSX4/Power10 позволяет использовать новые инструкции Power ISA 3.1 для ускорения операций NumPy, например floor_divide, вычисления остатка и других.

(gh-20821)

np.fromiter теперь принимает объекты и подмассивы#

numpy.fromiter теперь поддерживает объектные типы данных и типы подмассивов. Примеры см. в документации функции.

(gh-20993)

При обнаружении возможностей математической библиотеки C теперь используются правильные сигнатуры#

Компиляции предшествует проверка поддержки некоторых математических операций системной libc. Ранее этот код использовал неверные сигнатуры. Исправление позволяет собирать с помощью wasm-ld (для WebAssembly) и уменьшает число предупреждений.

( gh-21154 )

np.kron теперь сохраняет информацию о подклассе#

np.kron теперь сохраняет информацию о подклассах, в том числе о маскированных массивах, при вычислении произведения Кронекера входных массивов

>>> x = ma.array([[1, 2], [3, 4]], mask=[[0, 1], [1, 0]])
>>> np.kron(x,x)
masked_array(
  data=[[1, --, --, --],
        [--, 4, --, --],
        [--, --, 4, --],
        [--, --, --, 16]],
  mask=[[False,  True,  True,  True],
        [ True, False,  True,  True],
        [ True,  True, False,  True],
        [ True,  True,  True, False]],
  fill_value=999999)

Предупреждение

При определении класса результата np.kron теперь использует тот же порядок, что и ufunc (multiply)

>>> class myarr(np.ndarray):
>>>    __array_priority__ = -1
>>> a = np.ones([2, 2])
>>> ma = myarray(a.shape, a.dtype, a.data)
>>> type(np.kron(a, ma)) == np.ndarray
False # Before it was True
>>> type(np.kron(a, ma)) == myarr
True
Комментарии к примеру на русском
  • Раньше было True

(gh-21262)

Улучшения производительности и изменения #

Ускорение np.loadtxt#

numpy.loadtxt теперь, как правило, намного быстрее, чем раньше, поскольку большая часть его теперь реализована в C.

(gh-20580)

Ускоренные операции свёртки#

Операции свёртки, такие как numpy.sum, numpy.prod, numpy.add.reduce и numpy.logical_and.reduce, теперь выполняются значительно быстрее для непрерывно расположенных в памяти целочисленных массивов.

Ускорение np.where#

numpy.where теперь намного быстрее, чем раньше, на непредсказуемых/случайных входных данных.

(gh-21130)

Ускорение операций со скалярами NumPy#

Многие операции со скалярами NumPy стали значительно быстрее, хотя редкие операции, например с нульмерными массивами вместо скаляров, в отдельных случаях могут замедлиться. Даже с этими улучшениями для максимальной скорости может быть полезно преобразовать известный скаляр NumPy в скаляр Python через scalar.item().

( gh-21188 )

Ускорение np.kron#

numpy.kron работает примерно на 80% быстрее, поскольку произведение теперь вычисляется с помощью трансляции массивов.
