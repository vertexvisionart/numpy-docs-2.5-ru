Примечания к выпуску NumPy 1.3.0#

Этот минорный выпуск содержит многочисленные исправления ошибок, официальную поддержку Python 2.6 и несколько новых возможностей, в том числе обобщённые универсальные функции.

Основные изменения#

Поддержка Python 2.6#

Python 2.6 теперь поддерживается на всех ранее поддерживаемых платформах, включая Windows.

https://www.python.org/dev/peps/pep-0361/

Обобщённые универсальные функции#

Нужен общий механизм циклического применения не только функций над скалярами, но и функций над векторами или массивами, как объясняется на http://scipy.org/scipy/numpy/wiki/GeneralLoopingFunctions. Мы предлагаем реализовать эту идею обобщением универсальных функций ufunc и предоставить реализацию на C, добавляющую около 500 строк в код NumPy. В существующих специализированных ufunc элементарная функция ограничена поэлементными операциями, тогда как обобщённый вариант поддерживает операции над целыми подмассивами. Векторная библиотека PDL для Perl предоставляет похожие возможности; далее используется её терминология.

С каждой обобщённой универсальной функцией связаны сведения о числе базовых измерений входов и соответствующем числе базовых измерений выходов. У поэлементных ufunc базовых измерений нет. Список базовых измерений всех аргументов называется сигнатурой универсальной функции. Например, numpy.add имеет сигнатуру «(),()->()», задающую два скалярных входа и один скалярный выход.

Ещё один пример (см. страницу GeneralLoopingFunctions) — функция inner1d(a,b) с сигнатурой «(i),(i)->()». Она вычисляет скалярное произведение вдоль последней оси каждого входного массива, сохраняя остальные индексы. Например, если a имеет форму (3,5,N), а b — форму (5,N), результат будет иметь форму (3,5). Базовая элементарная функция вызывается 3*5 раз. В сигнатуре для каждого входа задано одно основное измерение «(i)», а для выхода — ни одного «()», поскольку функция принимает два одномерных массива и возвращает скаляр. Одинаковое имя «i» указывает, что два соответствующих измерения должны иметь одинаковый размер (либо одно из них имеет размер 1 и расширяется посредством трансляции массивов).

Измерения, не входящие в основные, называются измерениями цикла (“loop”). В примере выше им соответствует (3,5).

Применяются обычные правила трансляции массивов NumPy. Сигнатура определяет, как измерения каждого входного и выходного объекта делятся на основные измерения и измерения внешнего цикла:

Если число измерений входного массива меньше требуемого числа основных измерений, в начало его формы добавляются единицы до достижения нужного числа измерений. Основные измерения всех входных массивов исключаются из рассмотрения, а оставшиеся измерения согласуются по правилам трансляции массивов, образуя измерения цикла. Форма результата состоит из измерений цикла и основных измерений выходного массива.

Новые возможности#

Проблемы форматирования#

Форматирование чисел с плавающей точкой теперь выполняет NumPy, а не библиотека времени выполнения C. Это обеспечивает независимость от локали и повышает надёжность fromstring и связанных методов. Представления специальных значений inf и nan стали единообразнее на разных платформах (nan вместо IND/NaN и т. п.) и лучше согласованы с изменениями форматирования в Python 2.6 и новее.

Обработка Nan в max/min #

Универсальные функции maximum/minimum теперь надёжно распространяют NaN: если один из аргументов равен NaN, возвращается NaN. Это влияет на np.min/np.max, amin/amax и методы массива max/min. Добавлены универсальные функции fmax и fmin, которые не распространяют NaN.

Обработка NaN в sign#

Универсальная функция sign теперь возвращает nan для знака nan.

Новые универсальные функции#

  1. fmax — аналог maximum для целочисленных типов и чисел с плавающей запятой, не равных nan. Если только один аргумент равен nan, возвращается другой; если оба равны nan, возвращается nan.

  2. fmin — аналог minimum для целочисленных типов и чисел с плавающей запятой, не равных nan. Если только один аргумент равен nan, возвращается другой; если оба равны nan, возвращается nan.

  3. deg2rad — переводит градусы в радианы, как и универсальная функция radians.

  4. rad2deg — преобразует радианы в градусы, как универсальная функция degrees.

  5. log2 - логарифм по основанию 2.

  6. exp2 — показательная функция с основанием 2.

  7. trunc — усечение числа с плавающей запятой до ближайшего целого числа в сторону нуля.

  8. logaddexp — складывает числа, заданные своими логарифмами, и возвращает логарифм суммы.

  9. logaddexp2 — складывает числа, хранящиеся в виде двоичных логарифмов, и возвращает двоичный логарифм результата.

Маскированные массивы #

Несколько новых функций и исправлений ошибок, в том числе:

  • Структурированные массивы теперь должны полностью поддерживаться MaskedArray (r6463, r6324, r6305, r6300, r6294…)

  • Незначительные исправления ошибок (r6356, r6352, r6335, r6299, r6298)

  • Улучшенная поддержка __iter__ (r6326).

  • Атрибуты baseclass, sharedmask и hardmask стали доступны пользователю только для чтения

  • обновление документации

Поддержка gfortran в Windows #

Gfortran теперь можно использовать как компилятор Fortran для NumPy в Windows, даже если компилятором C служит Visual Studio: поддерживаются VS 2005 и новее, но не VS 2003. Сочетание gfortran и Visual Studio не работает в 64-битной Windows, хотя gcc с gfortran работает. Пока неясно, получится ли вообще использовать gfortran с Visual Studio на x64.

Параметр архитектуры для двоичной сборки Windows#

Автоматическое определение архитектуры в установщике superpack теперь можно обойти параметром командной строки:

numpy-1.3.0-superpack-win32.exe /arch=nosse

установит NumPy, работающий на любом x86, даже если компьютер сборки поддерживает инструкции SSE.

Устаревшие возможности#

Гистограмма #

Поведение histogram изменено для устранения давних проблем с обработкой выбросов. Основные изменения касаются

  1. определение границ интервалов, теперь включая крайнюю правую границу, и

  2. обработки выбросов выше верхней границы: теперь они игнорируются, а не учитываются в крайнем правом интервале.

Предыдущее поведение по-прежнему доступно с помощью new=False, но оно устарело и будет полностью удалено в версии 1.4.0.

Изменения в документации #

Добавлено много документации. И руководство пользователя, и справочник можно собрать с помощью Sphinx.

Новый API C#

API multiarray#

В C API multiarray добавлены следующие функции:

  • PyArray_GetEndianness: чтобы получить порядок байтов во время выполнения

API универсальных функций#

В API универсальных функций добавлены следующие функции:

  • PyUFunc_FromFuncAndDataAndSignature: объявление более общего вида универсальной функции (обобщённой универсальной функции).

Новые определения #

Новые общедоступные определения C для кода, зависящего от архитектуры, доступны через numpy/npy_cpu.h:

  • NPY_CPU_X86: архитектура x86 (32 бита)

  • NPY_CPU_AMD64: архитектура amd64 (x86_64, НЕ Itanium)

  • NPY_CPU_PPC: 32-битный ppc

  • NPY_CPU_PPC64: 64-разрядная ppc

  • NPY_CPU_SPARC: 32-битный sparc

  • NPY_CPU_SPARC64: 64-битная архитектура SPARC

  • NPY_CPU_S390: S390

  • NPY_CPU_IA64: ia64

  • NPY_CPU_PARISC: PARISC

Также были добавлены новые макросы для порядка байтов ЦП (подробности см. во внутренних изменениях ниже):

  • NPY_BYTE_ORDER: целое число

  • Определения NPY_LITTLE_ENDIAN/NPY_BIG_ENDIAN

Они предоставляют портативные альтернативы макросам glibc endian.h для платформ без него.

Переносимые NAN, INFINITY и другие константы#

npy_math.h теперь предоставляет несколько переносимых макросов для получения NAN и INFINITY:

  • NPY_NAN: эквивалент NAN, который является расширением GNU.

  • NPY_INFINITY: эквивалент C99 INFINITY.

  • NPY_PZERO, NPY_NZERO: положительный и отрицательный ноль соответственно

Также доступны соответствующие макросы одинарной и расширенной точности. Для единообразия удалены все прямые обращения к NAN и самостоятельные вычисления NAN на лету.

Внутренние изменения #

Обновление математической конфигурации numpy.core #

Это должно сделать портирование на новые платформы проще и надежнее. В частности, этап конфигурации не требует выполнения какого-либо кода на целевой платформе, что является первым шагом к кросс-компиляции.

https://www.numpy.org/neps/nep-0003-math_config_clean.html

Рефакторинг umath#

Масштабная очистка кода umath/ufunc (charris).

Улучшены предупреждения при сборке#

NumPy теперь собирается с -W -Wall без предупреждений

https://www.numpy.org/neps/nep-0002-warnfix.html

Отдельная базовая математическая библиотека#

Основные математические функции (sin, cos и т. п. для базовых типов C) вынесены в отдельную библиотеку. Она служит слоем совместимости, поддерживающим большинство математических функций C99 (пока только для вещественных чисел). Библиотека включает платформозависимые исправления, поэтому её функции должны работать надёжнее прямых вызовов системных функций. API существующих функций полностью совпадает с API математических функций C99, кроме префикса npy: например, npy_cos вместо cos.

Базовая библиотека будет доступна для любого расширения в 1.4.0.

Определение архитектуры процессора#

В npy_cpu.h определены специфичные для NumPy макросы процессоров, например NPY_CPU_X86. Они переносимы между ОС и наборами инструментов и задаются при обработке заголовка, поэтому их можно безопасно использовать при кросс-компиляции (значения не фиксируются во время сборки NumPy) и для двоичных файлов, поддерживающих несколько архитектур (например, универсальных двоичных файлов в Mac OS X).

npy_endian.h определяет макросы порядка байтов NumPy по образцу glibc endian.h. NPY_BYTE_ORDER эквивалентен BYTE_ORDER; определяется один из NPY_LITTLE_ENDIAN и NPY_BIG_ENDIAN. Как и макросы архитектуры CPU, они задаются при обработке заголовка компилятором, поэтому подходят для кросс-компиляции и двоичных файлов для нескольких архитектур.
