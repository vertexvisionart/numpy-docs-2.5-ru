Историческая справка: страница описывает NumPy 1.7.0. Слова «сейчас», «раньше» и «будет» относятся ко времени этого выпуска; описанное поведение может отличаться от NumPy 2.5.

Примечания к выпуску NumPy 1.7.0#

Этот выпуск содержит несколько новых возможностей, многочисленные исправления ошибок и изменения внутренней структуры кода. Он поддерживает Python 2.4–2.7 и 3.1–3.3 и является последним с поддержкой Python 2.4–2.5.

Основные изменения#

  • Параметр where= универсальных функций позволяет булевым массивом выбирать элементы, для которых выполняется вычисление

  • Улучшения vectorize: добавлены именованные аргументы excluded и cache, выполнена общая очистка кода и исправлены ошибки

  • numpy.random.choice (функция генерации случайной выборки)

Примечания о совместимости#

В будущей версии NumPy функции np.diag, np.diagonal и метод diagonal массивов ndarray будут возвращать представление исходного массива вместо создаваемой сейчас копии. Это важно при записи в массив, возвращённый любой из этих функций. Чтобы облегчить переход, NumPy 1.7 выдаёт FutureWarning, если обнаруживает возможную попытку записи в такой массив. Подробнее см. документацию np.diagonal.

Подобно описанной выше np.diagonal, в будущей версии NumPy индексация массива записей списком имён полей будет возвращать представление исходного массива вместо нынешней копии. Как и в случае np.diagonal, NumPy 1.7 выдаёт FutureWarning, если обнаруживает возможную попытку записи в такой массив. Подробности см. в документации по индексации массивов.

В будущей версии NumPy правило приведения типов по умолчанию для параметров out= универсальных функций изменится с «unsafe» на «same_kind». Это касается и операций на месте: например, a += b эквивалентно np.add(a, b, out=a). Большинство случаев нарушения правила «same_kind», вероятно, являются ошибками, поэтому изменение может выявить ранее незамеченные ошибки в проектах, зависящих от NumPy. В этой версии NumPy такие операции ещё выполняются, но выдают DeprecationWarning.

Индексация логической маской, охватывающей весь массив, теперь использует отдельный оптимизированный путь выполнения. Результаты должны остаться прежними; будем признательны за сообщения об изменениях поведения вашего кода.

Раньше попытка записи в массив только для чтения (у которого arr.flags.writeable установлен в False) могла вызывать RuntimeError, ValueError или TypeError в зависимости от пути выполнения кода. Теперь во всех случаях вызывается ValueError.

Функции <ufunc>.reduce выполняют некоторые свёртки в ином порядке, чем в предыдущих версиях NumPy, что обычно повышает производительность. Из-за особенностей арифметики с плавающей запятой некоторые результаты могут слегка измениться, как и при связывании NumPy с другой реализацией BLAS, например MKL.

При обновлении с версии 1.5 учитывайте, что в 1.6 и 1.7 добавлено много кода и изменены некоторые пути выполнения, особенно определение типов и буферизованный обход в универсальных функциях. Это может повлиять на ваш код, особенно если он полагался на случайное поведение.

Новые возможности#

Обобщён параметр axis= для методов свёртки универсальных функций#

Вызовы ufunc.reduce и другие свёртки, такие как sum, prod, any, all, max и min, позволяют выбирать подмножество осей. Раньше axis=None означало все оси, а axis=# — одну ось. Теперь axis=(#,#) позволяет задать несколько осей для свёртки.

Новый параметр keepdims= для свёрток универсальными функциями#

Добавлен параметр keepdims=: при True оси свёртки сохраняются с длиной 1. Это позволяет корректно транслировать результат свёртки к исходному операнду.

Поддержка даты и времени#

Примечание

В версии 1.7.0 API datetime является экспериментальным и может измениться в будущих версиях NumPy.

В datetime64 было внесено множество исправлений и улучшений по сравнению с NumPy 1.6:

  • парсер строго принимает только даты ISO 8601, с несколькими расширениями для удобства

  • корректно преобразует между единицами измерения

  • арифметика datetime работает корректно

  • средства работы с рабочими днями: позволяют использовать datetime в случаях, когда допустимы лишь определённые дни недели

Подробнее см. doc/source/reference/arrays.datetime.rst; этот материал также доступен в онлайн-документации arrays.datetime.html.

Пользовательский формататор для печати массивов #

См. новый параметр formatter функции numpy.set_printoptions.

Новая функция numpy.random.choice#

Добавлена универсальная функция выборки элементов из заданного объекта, подобного массиву. Выборка может выполняться с возвращением или без него, с равными либо заданными неравными вероятностями.

Новая функция isclose#

Возвращает логический массив поэлементного совпадения двух массивов в пределах допуска. Можно задать относительный и абсолютный допуски.

Предварительная поддержка многомерных данных в пакете многочленов#

В функции интегрирования и дифференцирования добавлен именованный аргумент axis, а в функции вычисления значений — именованный аргумент tensor. Эти дополнения позволяют использовать в них многомерные массивы коэффициентов. Добавлены новые функции для вычисления значений по двумерным и трёхмерным массивам коэффициентов на сетках или наборах точек, а также двумерные и трёхмерные псевдоматрицы Вандермонда, пригодные для аппроксимации.

Возможность дополнения n-мерных массивов#

Добавлен модуль pad с функциями для дополнения n-мерных массивов. Различные внутренние функции дополнения доступны через параметры общедоступной функции «pad». Пример:

pad(a, 5, mode='mean')

Текущими режимами являются constant, edge, linear_ramp, maximum, mean, median, minimum, reflect, symmetric, wrap и <function>.

Новый аргумент searchsorted#

Функция searchsorted теперь принимает аргумент ‘sorter’ — массив перестановки, сортирующей массив, в котором выполняется поиск.

Система сборки#

Добавлена экспериментальная поддержка архитектуры AArch64.

C API#

Новая функция PyArray_FailUnlessWriteable обеспечивает согласованный интерфейс для проверки записываемости массива - любой код C, который работает с массивами, чей WRITEABLE флаг не известен как True a priori, должен обязательно вызвать эту функцию перед записью.

Добавлено руководство по стилю кода NumPy на C (doc/C_STYLE_GUIDE.rst).

Изменения#

Общие сведения#

Функция np.concatenate пытается сохранить расположение данных входных массивов в памяти. Ранее выбор расположения не подчинялся определённым правилам и нежелательным образом зависел от оси объединения. Также исправлена ошибка, из-за которой недопустимые значения оси принимались без предупреждения.

Универсальные функции logical_or, logical_and и logical_not теперь следуют поведению Python для массивов объектного типа, вместо того чтобы пытаться вызывать методы объектов. Например, выражение (3 and ‘test’) даёт строку ‘test’; теперь np.logical_and(np.array(3, ‘O’), np.array(‘test’, ‘O’)) также даёт ‘test’.

Атрибут .base массивов ndarray удерживает массив, владеющий памятью, от преждевременного освобождения. Теперь для представления другого представления промежуточные ссылки в этой цепочке устраняются. Например:

a = np.arange(10)
b = a[1:]
c = b[1:]

В numpy 1.6 c.base - это b, а c.base.base - это a. В numpy 1.7 c.base - это a.

Чтобы повысить обратную совместимость программного обеспечения, которое использует старое поведение .base, мы «пропускаем» только те объекты, которые имеют точно такой же тип, что и вновь созданное представление. Это имеет значение, если вы используете подклассы ndarray. Например, если у нас есть смесь объектов ndarray и matrix, которые представляют собой представления одного и того же исходного ndarray:

a = np.arange(10)
b = np.asmatrix(a)
c = b[0, 1:]
d = c[0, 1:]

тогда d.base будет равен b. Это объясняется тем, что d — объект matrix: процесс сворачивания цепочки продолжается лишь до тех пор, пока встречаются другие объекты matrix. Последовательно рассматриваются c, b и a; b — последний элемент этого списка, являющийся объектом matrix.

Правила приведения типов#

В связи с работой над поддержкой NA правила приведения типов изменились в некоторых особых случаях. В частности, для сочетаний скаляр + скаляр:

  • тип longlong (q) теперь сохраняется как longlong при операциях с числами других типов (? b h i l q p B H I); раньше он приводился к int_ (l). Тип ulonglong (Q) теперь сохраняется как ulonglong вместо преобразования в uint (L).

  • Тип timedelta64 (m) теперь можно смешивать с любым целочисленным типом (b h i l q p B H I L Q P); раньше это вызывало TypeError.

Для массива + скаляр правила выше применяются с трансляцией, кроме сочетаний знаковых и беззнаковых целых: тогда результат приводится к типу массива, возможно увеличенной разрядности, как показано в примерах:

>>> (np.zeros((2,), dtype=np.uint8) + np.int16(257)).dtype
dtype('uint16')
>>> (np.zeros((2,), dtype=np.int8) + np.uint16(257)).dtype
dtype('int16')
>>> (np.zeros((2,), dtype=np.int16) + np.uint32(2**17)).dtype
dtype('int32')

Увеличивается ли размер, зависит от размера скаляра, например:

>>> (np.zeros((2,), dtype=np.uint8) + np.int16(255)).dtype
dtype('uint8')
>>> (np.zeros((2,), dtype=np.uint8) + np.int16(256)).dtype
dtype('uint16')

Кроме того, сумма скаляра complex128 и массива float32 приводится к complex64.

В NumPy 1.7 тип datetime64 ( M ) должен быть создан путем явного указания типа в качестве второго аргумента ( e.g . np.datetime64(2000, 'Y') ).

Устаревающие возможности#

Общие сведения#

Задание пользовательского форматирования строк через атрибут массива _format устарело. Вместо него можно использовать новый именованный аргумент formatter в numpy.set_printoptions или numpy.array2string.

Устаревшие импорты в пакете polynomial удалены.

concatenate теперь выдаёт предупреждение об устаревании для одномерных массивов при axis != 0. В NumPy < 1.7.0 значение axis для них игнорировалось. Пока это допускается, но в дальнейшем будет выдаваться ошибка.

C API#

Прямой доступ к полям PyArrayObject* объявлен устаревшим. Его не рекомендовалось использовать уже на протяжении многих выпусков. В рамках подготовки к NumPy 2.0 ожидается аналогичное объявление прямого доступа устаревшим для PyArray_Descr* и других основных объектов.

Макросы из old_defines.h объявлены устаревшими и будут удалены в следующем мажорном выпуске (>= 2.0). Сценарий sed tools/replace_old_macros.sed позволяет заменить их новыми версиями.

Чтобы проверить код на использование устаревшего C API, добавьте перед подключением любых заголовочных файлов NumPy строку из #define NPY_NO_DEPRECATED_API и номера целевой версии, например NPY_1_7_API_VERSION.

Значение NPY_CHAR перечисления NPY_TYPES объявлено устаревшим и будет удалено в NumPy 1.8. Подробнее см. обсуждение gh-2801.
