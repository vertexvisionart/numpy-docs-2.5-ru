  • Примечания к выпуску NumPy 1.8.0

Историческая справка: страница описывает NumPy 1.8.0. Слова «сейчас», «раньше» и «будет» относятся ко времени этого выпуска; описанное поведение может отличаться от NumPy 2.5.

Примечания к выпуску NumPy 1.8.0#

Данный релиз поддерживает Python 2.6 -2.7 и 3.2 - 3.3.

Основные изменения#

  • Новое: Python 2 и Python 3 поддерживаются общей кодовой базой без 2to3.

  • Новые обобщённые универсальные функции (gufuncs) для линейной алгебры, позволяющие выполнять операции над наборами матриц в массивах.

  • Новая расширенная индексация на месте для универсальных функций с методом .at.

  • Новая функция partition выполняет частичное упорядочение алгоритмом выбора для быстрого вычисления медианы.

  • Новые функции nanmean, nanvar и nanstd пропускают NaN.

  • Новые функции full и full_like для создания массивов, заполненных заданным значением.

  • Новая функция PyUFunc_RegisterLoopForDescr улучшает поддержку пользовательских dtype в универсальных функциях.

  • Многочисленные улучшения производительности во многих областях.

Прекращённая поддержка#

Поддержка Python версий 2.4 и 2.5 была прекращена.

Поддержка SCons удалена.

Будущие изменения#

Тип Datetime64 остается экспериментальным в этом выпуске. В 1.9, вероятно, будут некоторые изменения, чтобы сделать его более пригодным для использования.

Сейчас метод diagonal возвращает новый массив и выдаёт FutureWarning. В версии 1.9 он будет возвращать представление только для чтения.

Выбор нескольких полей из массива структурированного типа сейчас возвращает новый массив и выдаёт FutureWarning. В версии 1.9 он будет возвращать представление только для чтения.

Модули совместимости numpy/oldnumeric и numpy/numarray будут удалены в 1.9.

Примечания о совместимости#

Содержимое doc/sphinxext перенесено в отдельный репозиторий GitHub и подключено к NumPy как подмодуль. Инструкции по получению этих файлов приведены в doc/HOWTO_BUILD_DOCS.rst.

Изменена хеш-функция скаляров numpy.void. Ранее указатель на данные хешировался как целое число. Теперь для объединения хешей элементов скаляра используется алгоритм хеширования кортежей, но лишь если скаляр доступен только для чтения.

NumPy перешёл на раздельную компиляцию по умолчанию. В предыдущих выпусках она поддерживалась, но не была стандартным режимом. Результаты должны совпадать с прежней системой, однако при сложных сценариях, например статической компоновке NumPy или использовании необычного компилятора, возможны проблемы. Сообщите о них в трекере ошибок. Временное обходное решение — включить прежнюю систему сборки, экспортировав переменную оболочки NPY_SEPARATE_COMPILATION=0.

Для итератора AdvancedNew параметр oa_ndim теперь должен быть равен -1, чтобы указать, что op_axes и itershape не переданы. Случай oa_ndim == 0 теперь обозначает нульмерный обход с op_axes, равным NULL; прежний способ использования объявлен устаревшим. Это не затрагивает функции NpyIter_New и NpyIter_MultiNew.

Функции nanargmin и nanargmax теперь возвращают np.iinfo[‘intp’].min в качестве индекса для срезов, состоящих только из NaN. Раньше в случае массива они вызывали ValueError, а в скалярном случае возвращали NaN.

NPY_RELAXED_STRIDES_CHECKING#

Добавлена переменная окружения времени компиляции NPY_RELAXED_STRIDES_CHECKING. При значении 1 NumPy считает больше массивов непрерывно расположенными в порядке C или Fortran. Например, вектор-столбец может удовлетворять обоим условиям одновременно. Новое определение точнее, позволяет выполнять код быстрее с меньшим числом лишних копий и упрощает внутреннюю реализацию NumPy. Однако оно может нарушить работу сторонних библиотек, делающих слишком строгие предположения о шагах таких массивов. (Известно также, что пока это нарушает работу кода Cython с memoryview; исправление будет сделано в Cython.) В БУДУЩЕМ ВЫПУСКЕ ЭТО СТАНЕТ ПОВЕДЕНИЕМ ПО УМОЛЧАНИЮ, ПОЭТОМУ ПРОВЕРЬТЕ СВОЙ КОД УЖЕ СЕЙЧАС С NUMPY, СОБРАННЫМ С:

NPY_RELAXED_STRIDES_CHECKING=1 python setup.py install

Вы можете проверить, действует ли NPY_RELAXED_STRIDES_CHECKING, выполнив:

np.ones((10, 1), order="C").flags.f_contiguous

Значение равно True, если включена ослабленная проверка шагов, и False в противном случае. Типичная выявленная проблема — код C, работающий с непрерывно расположенными в порядке C массивами и считающий, что itemsize равен последнему элементу PyArray_STRIDES(arr). При ослабленной проверке шагов это неверно; в некоторых особых случаях это было неверно всегда. Вместо этого используйте PyArray_ITEMSIZE(arr).

Подробнее см. раздел «Внутреннее расположение ndarray в памяти» в документации.

Бинарные операции со вторым аргументом, не являющимся массивом#

Бинарные операции вида <array-or-subclass> * <non-array-subclass>, где <non-array-subclass> задаёт __array_priority__ выше, чем у <array-or-subclass>, теперь безусловно возвращают NotImplemented, позволяя <non-array-subclass> обработать операцию. Ранее NotImplemented возвращался, только если <non-array-subclass> действительно реализовывал обратную операцию, причём сначала предпринималась потенциально затратная попытка преобразовать <non-array-subclass> в массив. (ошибка, pull request)

Функция median с параметром overwrite_input сортирует массив лишь частично#

Если median используется с опцией overwrite_input, массив ввода теперь будет сортироваться только частично, а не полностью.

Исправление financial.npv#

В функции npv была ошибка: вопреки документации она суммировала значения по индексам от 1 до M вместо диапазона от 0 до M - 1. Исправление меняет возвращаемое значение. Функция mirr вызывала npv, но обходила эту проблему; её код также исправлен, при этом возвращаемое значение mirr не изменилось.

Предупреждения во время выполнения при сравнении значений NaN#

Сравнение чисел с плавающей точкой NaN теперь выдаёт предупреждение времени выполнения invalid. Если значение NaN ожидаемо, предупреждение можно игнорировать с помощью np.errstate. Например:

with np.errstate(invalid='ignore'):
    operation()

Новые возможности #

Поддержка линейной алгебры для пакетов массивов#

Для np.linalg теперь используется механизм обобщённых универсальных функций, позволяющий выполнять операции над наборами матриц и векторов. Например:

>>> a
array([[[ 1.,  1.],
        [ 0.,  1.]],

       [[ 1.,  1.],
        [ 0.,  1.]]])

>>> np.linalg.inv(a)
array([[[ 1., -1.],
        [ 0.,  1.]],

       [[ 1., -1.],
        [ 0.,  1.]]])

Расширенная индексация с изменением на месте для универсальных функций#

В объекты универсальных функций добавлен метод at, позволяющий выполнять операции на месте без буферизации при расширенной индексации. Например, следующий вызов увеличит первый и второй элементы массива по одному разу, а третий — дважды: numpy.add.at(arr, [0, 1, 2, 2], 1)

Многие ошибочно полагали, что именно так действует arr[[0, 1, 2, 2]] += 1. Однако это не работает: увеличенное значение arr[2] просто дважды копируется в третью позицию arr, а не увеличивается дважды.

Новые функции partition и argpartition #

Новые функции для частичной сортировки массивов с помощью алгоритма выбора.

Операция partition с индексом k, по формулировке оригинала, перемещает элемент порядка k «в начало массива». Примечание переводчика: элемент помещается на свою позицию k в отсортированном порядке, а не обязательно в начало; индексы считаются с нуля. Все элементы до k не больше значения на позиции k, а после k — не меньше значения на позиции k. Порядок внутри этих частей не определён. Можно передать последовательность индексов и итеративным разбиением сразу поместить все соответствующие элементы на отсортированные позиции. Это эффективно для порядковых статистик, например медианы и процентилей. Временная сложность partition линейна — O(n), тогда как полная сортировка требует O(n log(n)).

Новые функции nanmean, nanvar и nanstd#

Добавлены новые статистические функции, игнорирующие nan. Их результаты совпадают с теми, которые получились бы при исключении значений nan из всех вычислений.

Новые функции full и full_like #

Новые удобные функции создания массивов, заполненных заданным значением; дополняют существующие функции zeros и zeros_like.

Совместимость ввода-вывода с большими файлами#

Большие файлы NPZ размером более 2 ГБ можно загружать на 64-разрядных системах.

Сборка с OpenBLAS#

Теперь NumPy можно собрать с OpenBLAS, изменив site.cfg.

Новая константа #

Постоянная Эйлера теперь доступна в NumPy как euler_gamma.

Новые режимы для qr #

В QR-разложение добавлены режимы «complete», «reduced» и «raw»; прежние режимы «full» и «economic» объявлены устаревшими. Режим «reduced» заменяет прежний «full» и, как и он, используется по умолчанию. Поэтому для сохранения обратной совместимости достаточно не указывать режим.

Режим «complete» возвращает полноразмерное разложение, полезное для получения базиса ортогонального дополнения пространства образа. Режим «raw» возвращает массивы с отражениями Хаусхолдера и масштабными множителями, которые в будущем можно использовать для применения q без преобразования в матрицу. Режим «economic» просто объявлен устаревшим: он редко полезен и не эффективнее режима «raw».

Новый аргумент invert для in1d#

Функция in1d теперь принимает аргумент invert; при значении True возвращаемый массив инвертируется.

Расширенная индексация с np.newaxis#

Теперь np.newaxis/None можно использовать вместе с индексными массивами, а не только в простых индексах. Например, array[np.newaxis, [0, 1]] теперь работает как ожидается: выбирает первые две строки и добавляет новую ось в начало массива.

C API#

Теперь можно регистрировать новые универсальные функции со встроенными входными типами и пользовательским выходным типом. Раньше NumPy не находил нужный вычислительный цикл при вызове такой функции из Python, поскольку сопоставление сигнатур не учитывало тип выходного операнда. Теперь цикл выбирается правильно, если пользователь передаёт выходной аргумент нужного типа.

runtests.py#

Был добавлен простой скрипт запуска тестов runtests.py. Он также собирает Numpy через setup.py build и может использоваться для легкого запуска тестов во время разработки.

Улучшения#

Улучшения производительности ввода-вывода#

Чтение больших файлов ускорено благодаря обработке частями (см. также совместимость ввода-вывода).

Улучшение производительности pad #

Функция pad получила новую реализацию, существенно ускоряющую обработку всех входов, кроме mode= с функцией в качестве значения (этот вариант сохранён для обратной совместимости). Масштабирование по числу измерений значительно улучшено при ранге >= 4.

Улучшения производительности isnan, isinf, isfinite и byteswap #

isnan, isinf, isfinite и byteswap улучшены: теперь они используют встроенные средства компилятора вместо затратных вызовов libc. В системах с GNU libc это ускоряет операции примерно вдвое.

Повышение производительности благодаря векторизации SSE2#

Несколько функций были оптимизированы для использования инструкций SIMD процессора SSE2.

  • Float32 и float64:

    • базовые арифметические операции (add, subtract, divide, multiply)

    • sqrt

    • minimum/maximum

    • absolute

  • Bool:

    • logical_or

    • logical_and

    • logical_not

Это ускоряет операции до 4 раз для float32, до 2 раз для float64 и до 10 раз для bool в зависимости от расположения данных в кэшах CPU. Наибольший выигрыш дают операции на месте.

Для использования улучшенных функций при компиляции нужно включить набор инструкций SSE2. На системах x86_64 он включён по умолчанию. На x86_32 с поддерживающим его процессором нужно добавить соответствующий флаг в переменную сборки CFLAGS: для gcc это -msse2.

Улучшение производительности median #

median теперь реализован через partition вместо sort, что снижает временную сложность с O(n log(n)) до O(n). При использовании параметра overwrite_input массив теперь сортируется лишь частично, а не полностью.

Переопределяемые флаги операндов в C API ufunc#

При создании ufunc по умолчанию флаги операндов ufunc могут быть переопределены с помощью нового атрибута op_flags объекта ufunc. Например, для установки флага операнда для первого ввода для чтения/записи:

PyObject *ufunc = PyUFunc_FromFuncAndData(…); ufunc->op_flags[0] = NPY_ITER_READWRITE;

Это позволяет ufunc выполнять операции на месте. Также глобальные флаги nditer можно переопределять новым атрибутом iter_flags объекта ufunc. Например, флаг reduce задаётся так:

ufunc->iter_flags = NPY_ITER_REDUCE_OK;

Изменения#

Общие сведения#

Функция np.take теперь допускает нульмерные массивы в качестве индексов.

Отдельный режим компиляции теперь включен по умолчанию.

Несколько изменений в np.insert и np.delete:

  • Раньше отрицательные индексы и индексы за концом массива просто игнорировались. Теперь они вызывают FutureWarning или DeprecationWarning. В будущем они будут обрабатываться как при обычной индексации: отрицательные индексы отсчитываются от конца, а выход за границы вызывает ошибку.

  • Ранее логические индексы трактовались как целые числа, то есть всегда указывали на элемент с индексом 0 или 1. В будущем они будут трактоваться как маски. В этом выпуске при их использовании выдаётся FutureWarning о предстоящем изменении.

  • В Numpy 1.7. np.insert уже позволил синтаксису np.insert(arr, 3, [1,2,3]) вставлять несколько элементов в одну позицию. В Numpy 1.8. это также возможно для np.insert(arr, [3], [1, 2, 3]) .

Дополненные области из np.pad теперь правильно округляются, а не обрезаются.

Дополнения к C API массивов#

В C API массивов добавлены четыре функции.

  • PyArray_Partition

  • PyArray_ArgPartition

  • PyArray_SelectkindConverter

  • PyDataMem_NEW_ZEROED

Дополнения C API универсальных функций#

В C-API универсальных функций добавлена новая функция для регистрации внутреннего цикла пользовательских типов с помощью descr.

  • PyUFunc_RegisterLoopForDescr

Улучшения C API для разработчиков#

Функция создания экземпляра PyArray_Type, tp_new, теперь использует tp_basicsize, чтобы определить объём выделяемой памяти. В предыдущих выпусках выделялось лишь sizeof(PyArrayObject) байт, из-за чего подтипам C API часто приходилось переопределять tp_new.

Устаревающие возможности#

Режимы «full» и «economic» QR-разложения объявлены устаревшими.

Общие сведения#

Использование нецелых значений как индексов и большинства целочисленных аргументов объявлено устаревшим. Раньше вещественные индексы и аргументы, например оси или формы, усекались до целых без предупреждения. Например, arr.reshape(3., -1) и arr[0.] вызовут предупреждение об устаревании в NumPy 1.8, а в будущей версии будут вызывать ошибку.
