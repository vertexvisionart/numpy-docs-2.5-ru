  • Примечания к выпуску NumPy 1.9.0

Историческая справка: страница описывает NumPy 1.9.0. Слова «сейчас», «раньше» и «будет» относятся ко времени этого выпуска; описанное поведение может отличаться от NumPy 2.5.

Примечания к выпуску NumPy 1.9.0#

Данный релиз поддерживает Python 2.6 - 2.7 и 3.2 - 3.4.

Основные изменения#

  • Производительность улучшена во многих областях. Особенно заметно ускорились индексация и операции с небольшими массивами. Кроме того, операции индексации теперь освобождают GIL.

  • Добавление nanmedian и nanpercentile дополняет набор функций, работающих с NaN.

Прекращённая поддержка#

  • Модули oldnumeric и numarray удалены.

  • Каталоги doc/pyrex и doc/cython были удалены.

  • Каталог doc/numpybook был удален.

  • Файл numpy/testing/numpytest.py был удален вместе с содержащейся в нем функцией importall.

Будущие изменения#

  • Файл numpy/polynomial/polytemplate.py будет удален в NumPy 1.10.0.

  • Приведение по умолчанию для операций на месте изменится на «same_kind» в Numpy 1.10.0. Это наверняка нарушит некоторый код, который в настоящее время игнорирует предупреждение.

  • В версии 1.10.0 ослабленная проверка шагов будет использоваться по умолчанию

  • Сравнение версий как строк приводит к ошибкам: например, ‘1.9’ > ‘1.10’ равно True. Для таких сравнений добавлен класс NumpyVersion.

  • Функции diagonal и diag в версии 1.10.0 будут возвращать представления, доступные для записи

  • Типы данных S и/или a могут быть изменены для представления строк Python вместо байтов. В Python 3 эти два типа сильно различаются.

Примечания о совместимости#

Функции diagonal и diag возвращают представления, доступные только для чтения.#

В NumPy 1.8 функции diagonal и diag возвращали копии только для чтения, в NumPy 1.9 они возвращают представления только для чтения, а в 1.10 будут возвращать представления с возможностью записи.

Специальные скалярные значения float больше не вызывают повышения типа до double#

В прежних версиях NumPy операции со скалярами с плавающей точкой, содержащими специальные значения NaN, Inf и -Inf, давали тип результата не ниже float64. Поскольку эти значения представимы и в самом узком доступном типе с плавающей точкой, такое повышение типа больше не выполняется.

Например, dtype из:

np.array([1.], dtype=np.float32) * float('nan')

теперь остается float32 вместо преобразования в float64. Операции, включающие неспециальные значения, не были изменены.

Изменения результата percentile#

Если задано несколько процентилей, numpy.percentile возвращает массив вместо списка. Для одного процентиля по-прежнему возвращается скаляр. Полученный массив эквивалентен преобразованию списка из прежних версий с помощью np.array.

Если используется опция overwrite_input, входные данные сортируются только частично, а не полностью.

Тип исключения ndarray.tofile#

Все исключения tofile теперь являются IOError, некоторые из них ранее были ValueError.

Исключения при недопустимых значениях заполнения#

Два изменения в numpy.ma.core._check_fill_value:

  • Если значение заполнения — строка, а тип массива не относится к «OSUV», возникает TypeError вместо использования стандартного значения заполнения.

  • Если значение заполнения выходит за пределы типа массива, вызывается TypeError вместо OverflowError.

Классы многочленов больше не наследуются от PolyBase#

Это может затронуть код, рассчитывавший на наследование классов многочленов от PolyBase. Теперь все они наследуются от абстрактного базового класса ABCPolyBase. Строго говоря, следовало бы предусмотреть период предупреждений об устаревании, но внешнего кода, использующего прежний базовый класс, найти не удалось.

Использование numpy.random.binomial может менять состояние RNG по сравнению с NumPy < 1.9#

Исправлена ошибка в одном из алгоритмов генерации биномиальной случайной величины. Это изменение, вероятно, изменит число извлечённых случайных значений, а значит, после вызова distribution.c::rk_binomial_btpe позиция в последовательности будет иной. Поэтому тесты, полагающиеся на известное состояние генератора случайных чисел, следует проверить и при необходимости обновить.

Начальное значение seed должно быть 32-битным беззнаковым целым числом#

np.random.seed и np.random.RandomState теперь вызывают ValueError, если seed нельзя безопасно преобразовать в 32-битные беззнаковые целые числа. Исправить затронутый код можно обнулением старших битов: seed = seed & 0xFFFFFFFF. Старые версии делали это незаметно, поэтому поток случайных чисел останется прежним.

Аргумент out у argmin и argmax#

Аргумент out функций np.argmin, np.argmax и их аналогов в C API теперь проверяется на точное соответствие требуемой форме результата. Если проверка не пройдена, вызывается ValueError вместо TypeError.

Einsum#

Сняты ненужные ограничения записи трансляции массивов. np.einsum('ijk,j->ijk', A, B) теперь можно записывать и как np.einsum('ij...,j->ij...', A, B): многоточие для ‘j’ больше не требуется.

Индексация #

В этой версии механизм индексации NumPy полностью переписан. Благодаря этому большинство операций расширенной целочисленной индексации выполняется гораздо быстрее; других последствий не предполагается. Однако в операции расширенной индексации внесены некоторые небольшие изменения, а часть поведения объявлена устаревшей:

  • Логическое индексирование нульмерных массивов всегда возвращает новый одномерный массив. Например, array(1)[array(True)] даёт array([1]), а не исходный массив.

  • Раньше расширенное индексирование одномерных массивов имело недокументированную особенность: при присваивании значения повторялись, если массив значений был слишком мал или его форма не подходила. Теперь такой код вызывает ошибку. Для совместимости можно использовать arr.flat[index] = values, задействующий прежнюю ветку кода. Например: a = np.ones(10); a[np.arange(10)] = [1, 2, 3].

  • Ранее обход расширенных индексов всегда выполнялся в порядке C. В NumPy 1.9 порядок обхода подстраивается под входные данные и не гарантируется, кроме случая единственного расширенного индекса, который ради совместимости никогда не обходится в обратном порядке. Поэтому результат не определён, если одному элементу присваивается несколько значений. Например, arr[[0, 0], [1, 1]] = [1, 2] может присвоить arr[0, 1] как 1, так и 2.

  • Как и порядок обхода, расположение в памяти результата расширенной индексации выбирается для ускорения индексации и не может быть заранее предсказано.

  • Все операции индексирования возвращают представление или копию. Никакая операция индексирования не вернет исходный объект массива. (Например arr[...])

  • В будущем логические объекты, подобные массивам, например списки bool Python, всегда будут трактоваться как логические индексы. Логические скаляры, включая True Python, станут допустимыми логическими индексами. Для нульмерных массивов это уже работает, чтобы общий код positive = a[a > 0] был применим и к нульмерному a.

  • В NumPy 1.8 можно было использовать array(True) и array(False), эквивалентные 1 и 0, если результат операции был скалярным. Это вызовет ошибку в NumPy 1.9 и, как отмечалось выше, в дальнейшем будет трактоваться как булевой индекс.

  • Использование любых нецелочисленных объектов, подобных массивам, объявлено устаревшим; для объектных массивов с пользовательскими объектами, подобными целым числам, может потребоваться явное приведение типа.

  • Сообщения об ошибках расширенной индексации стали информативнее, однако в некоторых случаях тип исключения изменился. Ошибки трансляции индексных массивов теперь вызывают IndexError.

  • Индексация с несколькими многоточиями (...) объявлена устаревшей.

Нецелочисленные индексы осей свёртки объявлены устаревшими#

Нецелочисленные индексы осей для свёрток универсальными функциями, например add.reduce или sum, объявлены устаревшими.

promote_types и строковый тип данных#

promote_types теперь возвращает тип с достаточной длиной строки, если один аргумент — целочисленный тип или тип с плавающей точкой, а другой — строковый тип. Раньше всегда возвращался исходный строковый тип, даже если его длины не хватало для строкового представления максимального целого или вещественного значения.

can_cast и строковый тип данных#

Функция can_cast в режиме приведения “safe” теперь возвращает False для целочисленного типа или типа с плавающей точкой и строкового типа, если длины строкового типа недостаточно для хранения строкового представления максимального числового значения. Ранее can_cast в режиме “safe” возвращала True для таких числовых типов и строкового типа любой длины.

astype и строковый dtype#

Метод astype теперь выдаёт ошибку в режиме приведения “safe”, если длины целевого строкового dtype недостаточно для представления максимального значения преобразуемого целочисленного или вещественного массива. Раньше преобразование допускалось даже с усечением результата.

Изменение именованных аргументов npyio.recfromcsv#

npyio.recfromcsv больше не принимает недокументированный именованный аргумент update, ранее переопределявший dtype.

Каталог doc/swig перемещён#

Каталог doc/swig был перемещен в tools/swig.

Изменения заголовочного файла npy_3kcompat.h#

Неиспользуемая функция simple_capsule_dtor была удалена из npy_3kcompat.h. Обратите внимание, что этот заголовок не предназначен для использования вне numpy; другие проекты должны использовать свою собственную копию этого файла, когда это необходимо.

Отрицательные индексы в методах последовательностей C-Api sq_item и sq_ass_item #

При прямом обращении к слотам sq_item или sq_ass_item объекта PyObject для доступа к элементам отрицательные индексы больше не поддерживаются. Однако PySequence_GetItem и PySequence_SetItem преобразуют отрицательные индексы, поэтому при использовании этих функций они допустимы.

NDIter#

Теперь при вызове NpyIter_RemoveAxis диапазон итератора сбрасывается.

Если отслеживается многомерный индекс, а итератор не использует буферизацию, можно вызвать NpyIter_RemoveAxis. При этом размер итератора может уменьшиться. Поскольку общий размер итератора ограничен, до этих вызовов он может быть слишком большим. В таком случае его размер устанавливается в -1, а ошибка возникает не при создании, а при отключении отслеживания многомерного индекса, задании диапазона итератора или получении функции перехода к следующему элементу.

Это не влияет на текущий рабочий код, но подчеркивает необходимость проверки возврата ошибки, если такие условия могут возникнуть. В большинстве случаев итерируемые массивы имеют такой же размер, как и итератор, поэтому такая проблема не может возникнуть.

Это изменение уже было применено к выпуску 1.8.1.

zeros_like для типов строк теперь возвращает пустые строки #

Чтобы соответствовать функции zeros, zeros_like теперь возвращает массив, инициализированный пустыми строками, вместо массива, заполненного ‘0’.

Новые возможности #

Процентиль поддерживает больше вариантов интерполяции #

В np.percentile добавлен именованный аргумент interpolation, задающий способ интерполяции, если процентиль находится между двумя значениями. Доступные варианты см. в документации.

Обобщённая поддержка осей для median и percentile#

np.median и np.percentile теперь поддерживают обобщённое задание осей, как операции свёртки универсальных функций начиная с версии 1.7. Теперь можно указать axis=(index, index), чтобы выбрать несколько осей для свёртки. Также добавлен именованный аргумент keepdims, упрощающий трансляцию результата с массивами исходной формы.

Параметр dtype добавлен в np.linspace и np.logspace#

Тип данных, возвращаемый функциями linspace и logspace, теперь можно указать с помощью параметра dtype.

Более общая трансляция массивов в np.triu и np.tril#

Для массивов с ndim > 2 эти функции теперь применяются к двум последним осям вместо возбуждения исключения.

tobytes — псевдоним метода tostring#

ndarray.tobytes и MaskedArray.tobytes были добавлены в качестве псевдонимов для tostring, который экспортирует массивы как bytes. Это более последовательно в Python 3, где str и bytes не совпадают.

Система сборки#

Добавлена экспериментальная поддержка архитектуры ppc64le и OpenRISC.

Совместимость с модулем Python numbers#

Все числовые типы NumPy теперь зарегистрированы в иерархии типов модуля Python numbers.

Параметр increasing добавлен в np.vander #

Упорядочение столбцов матрицы Вандермонда может быть определено этим новым булевым аргументом.

Параметр unique_counts добавлен в np.unique #

Число вхождений каждого уникального элемента во входные данные теперь можно получить как необязательный результат.

Поддержка медианы и процентилей в nanfunctions#

Функции np.nanmedian и np.nanpercentile работают как функции вычисления медианы и процентилей, но игнорируют NaN.

Класс NumpyVersion добавлен #

Этот класс можно импортировать из numpy.lib и использовать для сравнения версий, когда версия NumPy достигнет 1.10.devel. Например:

>>> from numpy.lib import NumpyVersion
>>> if NumpyVersion(np.__version__) < '1.10.0'):
...     print('Wow, that is an old NumPy version!')

Сохранение массивов с большим числом именованных столбцов#

Формат хранения NumPy 1.0 ограничивал общий размер заголовка массива 65535 байтами. Структурированные массивы с большим числом столбцов могут превысить этот предел. Добавлен формат 2.0, увеличивающий допустимый размер заголовка до 4 ГиБ. np.save автоматически сохраняет в формате 2.0, если этого требуют данные; иначе всегда используется более совместимый формат 1.0.

Полная поддержка трансляции массивов для np.cross#

np.cross теперь правильно выполняет трансляцию двух входных массивов, даже если у них разное число измерений. Ранее это приводило к ошибке или неверным результатам.

Улучшения#

Улучшена численная устойчивость sum в некоторых случаях#

В методе sum теперь используется попарное суммирование, но только вдоль быстрой оси и для групп длиной не более 8192 значений. Это также должно повысить точность var и std в некоторых распространённых случаях.

Вычисление процентилей реализовано через np.partition#

np.percentile был реализован на основе np.partition, который лишь частично сортирует данные с помощью алгоритма выбора. Это улучшает временную сложность с O(nlog(n)) до O(n).

Улучшение производительности np.array #

Улучшена производительность преобразования списков, содержащих массивы, в массивы с использованием np.array. Теперь она эквивалентна по скорости np.vstack(list).

Улучшение производительности np.searchsorted #

Для встроенных числовых типов np.searchsorted больше не использует функцию compare типа данных для поиска: теперь поиск реализуют функции, специализированные для каждого типа. В зависимости от размера входных данных ускорение может превышать два раза.

Возможность уменьшить подробность вывода np.distutils#

Задайте numpy.distutils.system_info.system_info.verbosity = 0, и вызовы numpy.distutils.system_info.get_info('blas_opt') не будут ничего выводить. Это в основном предназначено для других пакетов, использующих numpy.distutils.

Проверка ковариации в np.random.multivariate_normal#

Предупреждение RuntimeWarning выдается, когда ковариационная матрица не является положительно-полуопределенной.

Полиномиальные классы больше не основаны на шаблонах #

Классы полиномов переработаны: для реализации общего интерфейса вместо шаблона используется абстрактный базовый класс. Это ускоряет импорт пакета полиномов, поскольку классы больше не требуется компилировать при импорте.

Освобождение GIL в большем числе операций#

Ещё несколько функций теперь освобождают глобальную блокировку интерпретатора (GIL), что позволяет эффективнее распараллеливать вычисления с помощью модуля threading. В частности, GIL освобождается при расширенной индексации и вызовах np.where, а модуль random теперь использует отдельную блокировку для каждого состояния вместо GIL.

Поддержка MaskedArray для более сложных базовых классов #

Встроенные предположения о том, что базовый класс вел себя как простой массив, снимаются. В частности, repr и str теперь должны работать надежнее.

C API#

Устаревающие возможности#

Нецелые скаляры для повторения последовательности #

Использование нецелочисленных скаляров NumPy для повторения последовательностей Python объявлено устаревшим. Например, np.float_(2) * [1] в будущем будет вызывать ошибку.

Устаревшие варианты входных данных select#

Целочисленные и пустые входные данные select объявлены устаревшими. В будущем допустимыми условиями будут только логические массивы, а пустой condlist будет считаться ошибкой входных данных вместо возврата значения по умолчанию.

Функция rank#

Функция rank объявлена устаревшей во избежание путаницы с numpy.linalg.matrix_rank.

Сравнение массивов объектов на равенство#

В будущем сравнения объектных массивов через == и np.equal больше не будут проверять идентичность объектов. Например:

>>> a = np.array([np.array([1, 2, 3]), 1])
>>> b = np.array([np.array([1, 2, 3]), 1])
>>> a == b

теперь всегда возвращает False (а в будущем будет вызывать исключение), даже если массивы a и b — один и тот же объект.

Оператор равенства == в будущем будет вызывать ошибки, такие как np.equal, если трансляция массивов или сравнение элементов и т. д. не увенчаются успехом.

В дальнейшем arr == None будет выполнять поэлементное сравнение, а не просто возвращать False. Используйте arr is None.

Сейчас все эти изменения сопровождаются DeprecationWarning или FutureWarning.

C API#

Вспомогательные функции npy_PyFile_Dup и npy_PyFile_DupClose работают некорректно из-за внутренней буферизации файловых объектов в Python 3. Для исправления в npy_3kcompat.h объявлены две новые функции, npy_PyFile_Dup2 и npy_PyFile_DupClose2, а прежние объявлены устаревшими. Из-за ненадёжности этих функций рекомендуется по возможности использовать вместо них API Python.

Это изменение уже было применено к выпуску 1.8.1.
