  • Примечания к выпуску NumPy 2.2.0

Историческая справка: страница описывает NumPy 2.2.0. Слова «сейчас», «раньше» и «будет» относятся ко времени этого выпуска; описанное поведение может отличаться от NumPy 2.5.

Примечания к выпуску NumPy 2.2.0#

NumPy 2.2.0 выпущен вскоре после предыдущего, чтобы вернуться к обычному графику из двух выпусков в год. Внесён ряд небольших улучшений кода, продолжена работа над завершением нового StringDType и улучшена поддержка Python со свободными потоками. Основные изменения:

  • Новые функции matvec и vecmat, см. ниже.

  • Множество улучшений аннотаций.

  • Улучшенная поддержка нового StringDType.

  • Улучшена поддержка свободнопоточного Python

  • Исправления для f2py

Этот выпуск поддерживает версии Python 3.10–3.13.

Устаревающие возможности#

  • _add_newdoc_ufunc объявлена устаревшей. Используйте ufunc.__doc__ = newdoc.

    (gh-27735)

Окончательно удалённые устаревшие возможности#

  • bool(np.array([])) и аналогичные преобразования других пустых массивов в bool теперь вызывают ошибку. Для проверки наличия элементов используйте arr.size > 0. Примечание переводчика: в оригинале ошибочно сказано «проверить отсутствие элементов»; выражение arr.size > 0 истинно, когда массив не пуст.

    (gh-27160)

Примечания о совместимости#

  • numpy.cov теперь правильно транспонирует матрицы плана с одной строкой (двумерные массивы) при rowvar=False. Ранее в этом случае возвращался скаляр, что неверно. Поэтому поведение изменено: теперь возвращается массив подходящей формы.

    ( gh-27661 )

Новые возможности #

  • Новые функции умножения матрицы на вектор и вектора на матрицу

    Добавлены две новые обобщённые универсальные функции:

    • numpy.matvec — произведение матрицы на вектор; аргументы рассматриваются как пакеты матриц и векторов-столбцов соответственно.

    • numpy.vecmat — произведение вектора на матрицу; аргументы рассматриваются соответственно как наборы векторов-столбцов и матриц. Для комплексных векторов применяется комплексное сопряжение.

    Они дополняют существующую функцию numpy.matmul, а также numpy.vecdot, добавленную в NumPy 2.0.

    numpy.matmul никогда не выполняет комплексное сопряжение, даже если левый аргумент — вектор. В то же время numpy.vecdot и numpy.vecmat выполняют сопряжение комплексных векторов слева: согласно принятому в физике соглашению, именно эти векторы считаются транспонированными.

    (gh-25675)

  • np.complexfloating[T, T] теперь может быть записан как np.complexfloating[T]

    (gh-27420)

  • UFuncs теперь поддерживают атрибут __dict__ и позволяют переопределять __doc__ (либо напрямую, либо через ufunc.__dict__["__doc__"]). __dict__ может использоваться для переопределения других свойств, таких как __module__ или __qualname__.

    (gh-27735)

  • Параметр типа nbit у np.number и его подтипов теперь по умолчанию равен typing.Any. Поэтому средства проверки типов интерпретируют аннотации вроде x: np.floating как x: np.floating[Any] даже в строгом режиме.

    (gh-27736)

Улучшения#

  • Хеши datetime64 и timedelta64 теперь корректно соответствуют встроенным в Python datetime и timedelta. Хэши теперь оцениваются равными даже для равных значений с разными единицами времени.

    (gh-14622)

  • Исправлен ряд проблем повышения типов строковых ufunc с аргументами StringDType. Смешивание StringDType и строковых типов фиксированной длины теперь должно давать более единообразные результаты.

    ( gh-27636 )

  • Улучшена поддержка пустого memmap. Ранее пустой memmap завершался ошибкой, если не был установлен ненулевой offset. Теперь memmap нулевого размера поддерживается, даже если offset=0 . Для этого, если memmap отображается в пустой файл, этот файл дополняется одним байтом.

    ( gh-27723 )

f2py обрабатывает несколько модулей и снова предоставляет доступ к переменным#

Исправлена регрессия: пользователи F2PY снова могут предоставлять Python доступ к переменным в модулях, содержащих только присваивания. Также исправлены случаи, когда в одном исходном файле находится несколько модулей.

(gh-27695)

Улучшения производительности и изменения #

  • Улучшено масштабирование многопоточной работы в сборке со свободными потоками, когда много потоков одновременно вызывают одни и те же операции ufunc.

    (gh-27896)

  • NumPy теперь использует поиск атрибутов протоколов, который быстро обрабатывает их отсутствие. Это значительно снижает накладные расходы вызовов функций и создания массивов, особенно с пользовательскими объектами Python. Наибольший эффект достигается в Python 3.12 и новее.

    ( gh-27119 )

  • OpenBLAS для x86_64 и i686 собирается с меньшим числом вычислительных ядер. Тестирование выявило пять групп производительности вокруг ядер PRESCOTT NEHALEM SANDYBRIDGE HASWELL SKYLAKEX.

  • OpenBLAS для Windows компонуется без quadmath, что упрощает лицензирование

  • Из-за регресса в OpenBLAS в Windows улучшения производительности при использовании нескольких потоков для OpenBLAS 0.3.26 были отменены.

    (gh-27147)

  • Теперь NumPy также запрашивает использование огромных страниц памяти (hugepages) при выделении больших массивов с помощью np.zeros в Linux. Обычно это должно повышать производительность.

    (gh-27808)

Изменения#

  • numpy.fix больше не приводит целочисленные и логические входные массивы к типу с плавающей точкой.

    (gh-26766)

  • Аннотации типов numpy.float64 и numpy.complex128 теперь отражают, что они также являются подтипами встроенных float и complex соответственно. Благодаря этому средства статической проверки типов больше не сообщают об ошибках в случаях вроде следующего:

    x: float = numpy.float64(6.28)  # valid
z: complex = numpy.complex128(-1j)  # valid
    Комментарии к примеру на русском
    • Допустимо

    ( gh-27334 )

  • repr массивов, достаточно больших для сокращённого вывода, то есть с заменой элементов на ..., теперь содержит shape массива. Ранее это уже выполнялось для пустых массивов с неочевидной формой. Теперь форма всегда указывается, когда её нельзя определить по значениям. Хотя она записана как shape=..., такой аргумент на самом деле нельзя передать конструктору np.array. При проблемах, например сбоях doctest, прежнее поведение можно вернуть параметром вывода legacy=2.1.

    ( gh-27482 )

  • Прямой вызов __array_wrap__ для массивов или скаляров NumPy теперь корректно обрабатывает переданный аргумент return_scalar, добавленный в NumPy 2. Кроме того, теперь безопасно вызывать скалярный метод __array_wrap__ для нескалярного результата.

    (gh-27807)

Образ CI и wheel-пакеты musllinux обновлены с 1_1 до 1_2, поскольку поддержка 1_1 завершена.

( gh-27088 )

Удалён параметр состояния повышения типов NEP 50#

Настройки состояния повышения типов NEP 50 удалены. Они всегда были временными средствами тестирования. Значение переменной среды, отличное от NPY_PROMOTION_STATE=weak, вызывает предупреждение, а _set_promotion_state и _get_promotion_state удалены. Если код использовал _no_nep50_warning, при его отсутствии можно подставить contextlib.nullcontext.

(gh-27156)
