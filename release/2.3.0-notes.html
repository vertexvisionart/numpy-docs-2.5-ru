Примечания к выпуску NumPy 2.3.0#

В NumPy 2.3.0 продолжается улучшение поддержки Python без GIL и аннотаций типов наряду с обычными исправлениями ошибок. Этот выпуск отличается большим числом окончательно удалённых устаревших возможностей, обновлений кода и исправлений стиля. Последние могут быть незаметны пользователям, но важны для долгосрочного сопровождения кода. Кроме того, мы перешли с manylinux2014 на manylinux_2_28.

Пользователи, работающие на Mac с процессором M4, могут видеть различные предупреждения о недопустимых значениях и тому подобном. Эти предупреждения — известная проблема Accelerate. Они раздражают, но в остальном безобидны. Apple обещает их исправить.

Этот релиз поддерживает версии Python 3.11-3.13, Python 3.14 будет поддерживаться при его выпуске.

Добавлена функция numpy.strings.slice, обеспечивающая быстрое получение срезов строковых массивов средствами NumPy. Поддерживается весь API срезов, включая отрицательные границы и шаги.

Устаревающие возможности#

  • numpy.typing.mypy_plugin объявлен устаревшим в пользу статического вывода типов, независимого от платформы. Удалите numpy.typing.mypy_plugin из раздела plugins конфигурации mypy. Если после этого появятся новые ошибки, создайте задачу в репозитории.

    (gh-28129)

  • Тип numpy.typing.NBitBase объявлен устаревшим и будет удалён в одной из будущих версий.

    Ранее этот тип предполагалось использовать в качестве общей верхней границы для типовых параметров, например:

    import numpy as np
import numpy.typing as npt

def f[NT: npt.NBitBase](x: np.complexfloating[NT]) -> np.floating[NT]: ...

    Но в NumPy 2.2.0 float64 и complex128 были изменены на конкретные подтипы, в результате чего статические средства проверки типов отклоняли x: np.float64 = f(np.complex128(42j)) .

    Поэтому лучше использовать typing.overload:

    import numpy as np
from typing import overload

@overload
def f(x: np.complex64) -> np.float32: ...
@overload
def f(x: np.complex128) -> np.float64: ...
@overload
def f(x: np.clongdouble) -> np.longdouble: ...

    ( gh-28884 )

Например, такие ошибки возможны при приведении float64(1e300) к float32 (переполнение до бесконечности) или NaN к целому числу (недопустимое значение).

Новая функция NpyIter_GetTransferFlags и изменение NpyIter_IterationNeedsAPI#

В NumPy добавлена функция NpyIter_GetTransferFlags, позволяющая точнее проверить требования итерации и буферизации: нужен ли Python API/GIL и могут ли возникнуть ошибки вычислений с плавающей точкой. Она также быстрее, если требования для случая без буферизации уже известны.

Функция NpyIter_IterationNeedsAPI теперь выполняет все проверки, которые раньше выполнялись на этапе настройки. Многократный вызов и прежде не был необходим, а теперь он станет более затратным.

( gh-27998 )

Новые возможности #

  • Параметр типа np.dtype теперь по умолчанию равен typing.Any. Поэтому средства статической проверки типов интерпретируют dtype: np.dtype как dtype: np.dtype[Any], не сообщая об ошибке.

    (gh-28669)

  • Средства статической проверки типов теперь интерпретируют:

    • _: np.ndarray как _: npt.NDArray[typing.Any].

    • _: np.flatiter как _: np.flatiter[np.ndarray].

    Это связано с тем, что их параметры типов теперь имеют значения по умолчанию.

    (gh-28940)

NumPy теперь регистрирует свои пути pkg-config в пакете PyPI pkgconf#

Пакет pkgconf из PyPI предоставляет интерфейс, позволяющий таким проектам, как NumPy, регистрировать собственные каталоги для добавления в путь поиска pkg-config. Поэтому при использовании pkgconf из PyPI NumPy обнаруживается без дополнительной настройки окружения.

Внимание

Внимание

Это относится только к пакету pkgconf из PyPI, то есть только к установке pkgconf через менеджер пакетов Python.

Если pkg-config или pkgconf установлены системой либо из другого источника, не использующего проект pkgconf-pypi, каталог pkg-config NumPy не добавляется в путь поиска автоматически. В таком случае можно использовать numpy-config.

(gh-28214)

Поддержка out=... в ufunc для гарантированного возврата массива#

Иногда неудобная особенность NumPy состоит в том, что он обычно возвращает скаляры вместо нульмерных массивов, даже если входные данные были нульмерными массивами. Это особенно проблематично для нечисловых типов данных, например object.

Для ufunc (то есть большинства простых математических функций) теперь можно использовать out=... (буквально `…`, например out=Ellipsis). Это соответствует вызову без out, но гарантирует нескалярный результат. Такая запись заимствована из arr1d[0, ...], где ... также гарантирует нескалярный результат.

Со временем поддержку должны получить и другие функции с именованным аргументом out=. Зависимым библиотекам, взаимодействующим через __array_ufunc__ или __array_function__, может потребоваться адаптация.

(gh-28576)

Сборка NumPy с распараллеливанием OpenMP#

Теперь NumPy поддерживает параллельную обработку с OpenMP при сборке с параметром Meson -Denable_openmp=true. По умолчанию эта возможность отключена. При её включении функции np.sort и np.argsort могут использовать OpenMP для параллельного выполнения в нескольких потоках, что повышает производительность этих операций.

(gh-28619)

Интерактивные примеры в документации NumPy #

Документация NumPy включает ряд примеров, которые теперь можно запускать в интерактивном режиме в браузере с помощью WebAssembly и Pyodide.

Обратите внимание, что примеры в настоящее время носят экспериментальный характер и могут работать не так, как ожидалось, для всех методов в общедоступном API.

(gh-26745)

Улучшения#

  • Скалярные сравнения несопоставимых dtype, например np.array(1) == np.array('s'), теперь возвращают bool NumPy вместо bool Python.

    (gh-27288)

  • np.nditer теперь не ограничивает число поддерживаемых операндов (кроме диапазона целого числа C).

    (gh-28080)

  • Сериализация pickle без копирования теперь поддерживается для любого массива, который можно транспонировать в массив, непрерывно расположенный в памяти в порядке C.

    (gh-28105)

  • __repr__ для пользовательских типов dtype теперь предпочитает __name__ пользовательского dtype более общему имени, составленному из его kind и itemsize.

    (gh-28250)

  • np.dot теперь сообщает об исключениях вычислений с плавающей точкой.

    ( gh-28442 )

  • np.dtypes.StringDType теперь является обобщённым типом, принимающим аргумент типа для na_object со значением по умолчанию typing.Never. Например, StringDType(na_object=None) возвращает StringDType[None], а StringDType() — StringDType[typing.Never].

    ( gh-28856 )

Добавлены предупреждения для np.isclose #

Добавлены предупреждения для случаев, когда хотя бы один из atol или rtol равен np.nan или np.inf в np.isclose.

  • Предупреждения учитывают настройки np.seterr, заданные пользователем

(gh-28205)

Улучшения производительности и изменения #

Улучшение производительности np.unique #

np.unique теперь пытается находить уникальные значения с помощью хеш-таблицы вместо предварительной сортировки. Пока это поддерживается лишь для некоторых типов данных; для них функция стала быстрее. Также добавлен параметр sorted, позволяющий возвращать уникальные значения в порядке обнаружения, без последующей сортировки.

( gh-26018 )

Улучшение производительности np.sort и np.argsort #

Функции np.sort и np.argsort теперь могут использовать OpenMP для параллельной работы потоков, ускоряясь до 3,5 раза на x86 с AVX2 или AVX-512. Возможность включается явно: NumPy нужно собрать с флагом Meson -Denable_openmp. Число потоков задаётся переменной окружения OMP_NUM_THREADS.

(gh-28619)

Повышение производительности приведения типов np.float16#

Ранее преобразования чисел с плавающей точкой в типы np.float16 и обратно программно эмулировались на всех платформах.

Теперь на устройствах ARM с поддержкой инструкций Neon для float16 (например, современных Apple Silicon) используется аппаратная обработка float16 для наилучшей производительности.

(gh-28769)

Повышена производительность np.matmul#

Использование BLAS для matmul разрешено и для операндов, не расположенных непрерывно в памяти: при необходимости они копируются.

( gh-23752 )

Изменения#

  • Векторная норма ord=inf и матричные нормы ord={1, 2, inf, 'nuc'} теперь всегда возвращают ноль для пустых массивов. Пустые массивы имеют по крайней мере одну ось размера ноль. Это влияет на np.linalg.norm, np.linalg.vector_norm и np.linalg.matrix_norm. Раньше NumPy вызывал ошибки или возвращал ноль в зависимости от формы массива.

    (gh-28343)

  • Была исправлена орфографическая ошибка в сообщении об ошибке, возвращенном при преобразовании строки в float с помощью метода np.format_float_positional.

    ( gh-28569 )

  • В NumPy __array_api_version__ обновлён с 2023.12 до 2024.12.

  • numpy.count_nonzero для axis=None (по умолчанию) теперь возвращает скаляр NumPy вместо целого числа Python.

  • Параметр axis в функции numpy.take_along_axis теперь имеет значение по умолчанию -1.

    (gh-28615)

  • Улучшен вывод скаляров и массивов np.float16 и np.float32: переход к экспоненциальной записи теперь учитывает точность типа с плавающей точкой. Для обратной совместимости добавлен режим прежнего поведения np.printoptions со значением '2.2'.

    ( gh-28703 )

  • Умножение строки на целое число теперь вызывает OverflowError вместо MemoryError, если длина получаемой строки превышает представимый предел. Это соответствует поведению Python.

    (gh-29060)

unique_values может возвращать несортированные данные #

Относительно новая функция unique_values, добавленная в NumPy 2.0, теперь может возвращать неотсортированные результаты. Как и unique_counts и unique_all, она никогда не гарантировала сортировку, хотя до сих пор результат был отсортирован. В случаях, где эти функции ещё возвращают отсортированные данные, поведение может измениться в будущих выпусках ради производительности.

( gh-26018 )

Изменения в основном итераторе и возможные численные изменения #

Главный итератор, используемый в математических функциях и через np.nditer из Python и NpyIter в C, теперь ведет себя по-другому для некоторых буферизованных итераций. Это означает, что:

  • Используемый размер буфера часто будет меньше максимального размера буфера, разрешенного параметром buffersize.

  • Флаг growinner теперь учитывается при буферизованных свёртках, когда ни одному операнду буферизация не нужна.

Для np.sum() такие изменения размера буфера могут немного изменить численные результаты операций с плавающей точкой. Пользователи, применяющие «growinner» в собственных свёртках, могут заметить изменения точности. Например, в NumPy мы убрали этот флаг из einsum, чтобы избежать большинства таких изменений и повысить точность для некоторых 64-битных входных данных с плавающей точкой.

(gh-27883)

Минимальная поддерживаемая версия GCC теперь 9.3.0#

Минимальная поддерживаемая версия повышена с 8.4.0 до 9.3.0, прежде всего для снижения риска проблем из-за платформозависимых ошибок старых версий GCC.

(gh-28102)

Изменения автоматического выбора интервалов в numpy.histogram#

Алгоритм автоматического выбора интервалов в numpy.histogram изменён, чтобы избежать нехватки памяти для выборок с малой изменчивостью. Для полного контроля над интервалами можно задать параметры bin или range функции numpy.histogram. Примечание переводчика: в оригинале опечатка — параметр называется bins, а не bin.

(gh-28426)

Сборка wheel-пакетов manylinux_2_28#

Пакеты wheel для Linux будут использовать тег manylinux_2_28 вместо manylinux2014. Это означает прекращение поддержки redhat7/centos7, amazonlinux2, debian9, ubuntu18.04 и других версий операционных систем с версией glibc ниже 2.28 согласно таблице поддержки PEP 600.

(gh-28436)

Прекращено использование -Wl,-ld_classic в macOS#

Удалено использование -Wl,-ld_classic в macOS. Этот обходной приём больше не нужен Spack и приводит к созданию библиотек, которые нельзя скомпоновать с другими библиотеками, собранными новым ld.

(gh-28713)

Повторное включение переопределения функций в numpy.strings#

Восстановлена возможность переопределять функции модуля numpy.strings.

(gh-28741)
