Взаимодействие с NumPy #

Объекты ndarray в NumPy предоставляют высокоуровневый API для операций с массивами и его конкретную реализацию, основанную на хранении в оперативной памяти с шагами по осям. API достаточно универсален, но у реализации есть ограничения. По мере роста наборов данных и использования NumPy в новых средах и архитектурах такое хранение подходит не всегда. Поэтому другие библиотеки реализуют этот API для своих задач: массивы на GPU — CuPy; разреженные массивы — scipy.sparse и PyData/Sparse; параллельные вычисления — массивы Dask. Подобные NumPy реализации есть и в системах глубокого обучения, например TensorFlow и PyTorch. Другие проекты расширяют API NumPy дополнительными возможностями: метками и индексами — XArray; автоматическим дифференцированием — JAX; масками — numpy.ma; физическими единицами — astropy.units, pint, unyt. Это лишь некоторые примеры.

Тем не менее, пользователи по-прежнему хотят работать с этими массивами, используя знакомый API NumPy, и повторно использовать существующий код с минимальными (в идеале нулевыми) затратами на портирование. С этой целью определены различные протоколы для реализации многомерных массивов с API-интерфейсами высокого уровня, соответствующими NumPy.

Средства взаимодействия с NumPy можно разделить на три группы:

  1. Методы преобразования стороннего объекта в ndarray;

  2. передача выполнения из функции NumPy другой библиотеке массивов;

  3. использование функций NumPy с возвращением объекта стороннего типа.

Ниже рассмотрены эти возможности.

1. Использование произвольных объектов в NumPy#

Первая группа средств API NumPy позволяет по возможности обращаться со сторонними объектами как с массивами NumPy. Встретив такой объект, функции NumPy по очереди пробуют следующие способы:

  1. Буферный протокол, описанный в документации C API Python.

  2. Протокол __array_interface__, описанный на этой странице. Это предшественник буферного протокола Python, определяющий доступ к содержимому массива NumPy из других расширений C.

  3. Метод __array__(), предлагающий объекту самостоятельно преобразовать себя в массив.

В буферном протоколе и протоколе __array_interface__ объект описывает расположение данных в памяти, а NumPy выполняет остальную работу, по возможности без копирования. Если это невозможно, сам объект должен вернуть ndarray из метода __array__().

DLPack — ещё один протокол преобразования сторонних объектов в массивы NumPy, независимый от языка и устройства. NumPy не использует DLPack для неявного преобразования в ndarray. Для этого есть функция numpy.from_dlpack: она принимает совместимый объект с методом __dlpack__ и возвращает ndarray, обычно представляющий буфер входных данных без копирования. Подробное описание протокола приведено в спецификации Python для DLPack; см. __dlpack__.

dtype: совместимость#

Подобно __array__() для массивов, определение __numpy_dtype__ позволяет собственному объекту типа данных взаимодействовать с NumPy. __numpy_dtype__ должен возвращать экземпляр dtype NumPy. Учтите различие: np.float64 — не экземпляр dtype, а np.dtype(np.float64) — экземпляр.

Добавлено в версии 2.4: До NumPy 2.4 аналогичным образом обрабатывался атрибут .dtype. Начиная с NumPy 2.4 допускаются оба варианта; при наличии реализации __numpy_dtype__ атрибут .dtype не проверяется.

Протокол интерфейса массива #

Протокол интерфейса массива позволяет объектам, подобным массивам, использовать буферы данных друг друга. Он опирается на следующие атрибуты и методы:

  • __array_interface__ — словарь Python с формой массива, типом элемента и, при необходимости, адресом буфера данных и шагами по осям;

  • __array__() — метод, возвращающий ndarray: копию данных или представление объекта, подобного массиву;

Атрибут __array_interface__ можно проверить напрямую:

>>> import numpy as np
>>> x = np.array([1, 2, 5.0, 8])
>>> x.__array_interface__
{'data': (94708397920832, False), 'strides': None, 'descr': [('', '<f8')], 'typestr': '<f8', 'shape': (4,), 'version': 3}

Атрибут __array_interface__ также позволяет изменять данные объекта на месте:

>>> class wrapper():
...     pass
...
>>> arr = np.array([1, 2, 3, 4])
>>> buf = arr.__array_interface__
>>> buf
{'data': (140497590272032, False), 'strides': None, 'descr': [('', '<i8')], 'typestr': '<i8', 'shape': (4,), 'version': 3}
>>> buf['shape'] = (2, 2)
>>> w = wrapper()
>>> w.__array_interface__ = buf
>>> new_arr = np.array(w, copy=False)
>>> new_arr
array([[1, 2],
       [3, 4]])

Проверим, что arr и new_arr используют один буфер данных:

>>> new_arr[0, 0] = 1000
>>> new_arr
array([[1000,    2],
       [   3,    4]])
>>> arr
array([1000, 2, 3, 4])

Метод __array__()#

Метод __array__() позволяет использовать реализующий его NumPy-подобный объект как массив NumPy. Среди подобных объектов — массивы, объекты с интерфейсом массива, объекты с методом __array__(), возвращающим массив, и вложенные последовательности. По возможности используется __array__() для создания представления ndarray без копирования. В противном случае данные копируются в новый ndarray. Такое преобразование не всегда оптимально: оно может снижать производительность, требовать копирования и приводить к потере метаданных, атрибутов и поведения исходного объекта.

Метод должен иметь сигнатуру __array__(self, dtype=None, copy=None). Если переданный dtype не равен None и отличается от типа данных объекта, данные нужно привести к указанному типу. Если copy равен None, копия создаётся лишь тогда, когда этого требует dtype. При copy=True копия создаётся всегда; при copy=False нужно вызвать исключение, если без копирования обойтись нельзя.

Если класс реализует старую сигнатуру __array__(self), при np.array(a) выдаётся предупреждение об отсутствии аргументов dtype и copy.

Протокол DLPack#

Протокол DLPack задаёт расположение в памяти n-мерных массивов с шагами по осям. Для обмена данными используются следующие средства:

  1. Функция numpy.from_dlpack принимает объекты массивов с методом __dlpack__ и с его помощью создаёт новый массив с данными из x.

  2. Методы __dlpack__(self, stream=None) и __dlpack_device__ объекта массива, вызываемые внутри from_dlpack, позволяют определить устройство, на котором находятся данные, и получить к ним доступ. Устройство нужно знать, в частности, для передачи правильного потока выполнения при работе с несколькими GPU.

В отличие от буферного протокола, DLPack позволяет обмениваться массивами, данные которых находятся на других устройствах, кроме центрального процессора, например GPU или устройствах, доступных через Vulkan. NumPy поддерживает только CPU, поэтому может преобразовывать лишь объекты с данными в памяти CPU. Однако другие библиотеки, такие как PyTorch и CuPy, могут использовать этот протокол для обмена данными на GPU.

2. Операции над сторонними объектами без преобразования#

Второй набор методов API NumPy позволяет передать выполнение функции NumPy другой библиотеке массивов.

Рассмотрим следующую функцию.

>>> import numpy as np
>>> def f(x):
...     return np.mean(np.exp(x))

np.exp — универсальная функция, или ufunc: она обрабатывает ndarray поэлементно. А np.mean выполняет операцию вдоль одной из осей массива.

Мы можем применить f к объекту NumPy ndarray напрямую:

>>> x = np.array([1, 2, 3, 4])
>>> f(x)
21.1977562209304

Нам нужно, чтобы эта функция одинаково хорошо работала с любым NumPy-подобным массивом.

NumPy позволяет классу задать собственный способ выполнения вычислений через следующие интерфейсы:

  • __array_ufunc__: позволяет сторонним объектам поддерживать и переопределять универсальные функции (ufunc).

  • __array_function__: общий механизм для возможностей NumPy, не охваченных протоколом __array_ufunc__ для универсальных функций.

Если сторонние объекты реализуют протокол __array_ufunc__ или __array_function__, с ними можно работать без явного преобразования.

Протокол __array_ufunc__ #

Универсальная функция, сокращённо ufunc, — векторизованная обёртка над функцией с фиксированным числом входов и выходов определённых типов. Результат ufunc и её методов не обязательно является ndarray, если некоторые входные объекты имеют другой тип. Если входной объект определяет метод __array_ufunc__, управление может быть передано этому методу: поведение ufunc переопределяется. Метод __array_ufunc__ стороннего объекта получает доступ к ufunc NumPy. Благодаря чётко определённой структуре ufunc сторонний метод __array_ufunc__ может использовать её атрибуты, например .at(), .reduce() и другие.

Подкласс может изменить обработку универсальных функций NumPy, переопределив метод ndarray.__array_ufunc__. Он вызывается вместо стандартного выполнения ufunc и должен вернуть результат операции либо NotImplemented, если запрошенная операция не реализована.

Протокол __array_function__ #

Чтобы охватить достаточно API NumPy для проектов, использующих библиотеку, одного __array_ufunc__ недостаточно. Нужен протокол, позволяющий аргументам функции NumPy перехватывать управление и перенаправлять выполнение другой функции — например, реализации для GPU или параллельных вычислений. Это должно работать безопасно и согласованно между проектами.

Семантика __array_function__ очень похожа на __array_ufunc__, но операция задаётся произвольным вызываемым объектом, а не экземпляром ufunc и его методом. Подробнее см. NEP 18 — Механизм диспетчеризации высокоуровневых функций NumPy для массивов.

3. Возврат объектов сторонних типов#

Третий механизм позволяет использовать реализацию функции NumPy, а затем преобразовать результат обратно в объект стороннего типа. Методы __array_finalize__ и __array_wrap__ обеспечивают это автоматически, позволяя при необходимости задать тип результата функции NumPy.

Метод __array_finalize__ позволяет подклассу обрабатывать разные способы создания новых экземпляров. Он вызывается, когда NumPy внутренним механизмом создаёт новый массив на основе объекта подкласса ndarray. Метод можно использовать для изменения атрибутов после создания или переноса метаданных от родительского объекта.

Метод __array_wrap__ «завершает действие»: он позволяет объекту (например, пользовательской функции) задавать тип возвращаемого значения и обновлять атрибуты и метаданные. В этом смысле он противоположен методу __array__. При завершении операции с объектами, реализующими __array_wrap__, этот метод вызывается у входного объекта с наивысшим приоритетом массива либо у выходного объекта, если он задан. Атрибут __array_priority__ определяет тип возвращаемого объекта в ситуациях, когда возможны несколько типов Python. Например, подкласс может использовать этот метод, чтобы преобразовать выходной массив в экземпляр подкласса и обновить метаданные перед возвратом массива пользователю.

Подробнее об этих методах см. в разделах Создание подклассов ndarray и Особенности создания подтипов ndarray.

Примеры взаимодействия #

Пример: объекты Pandas Series#

Рассмотрим пример:

>>> import pandas as pd
>>> ser = pd.Series([1, 2, 3, 4])
>>> type(ser)
pandas.core.series.Series

Объект ser не является ndarray, но реализует протокол __array_ufunc__. Поэтому к нему можно применять ufunc как к массиву ndarray:

>>> np.exp(ser)
   0     2.718282
   1     7.389056
   2    20.085537
   3    54.598150
   dtype: float64
>>> np.sin(ser)
   0    0.841471
   1    0.909297
   2    0.141120
   3   -0.756802
   dtype: float64

Можно даже выполнять совместные операции с другими массивами ndarray:

>>> np.add(ser, np.array([5, 6, 7, 8]))
   0     6
   1     8
   2    10
   3    12
   dtype: int64
>>> f(ser)
21.1977562209304
>>> result = ser.__array__()
>>> type(result)
numpy.ndarray

Пример: тензоры PyTorch#

PyTorch — оптимизированная тензорная библиотека для глубокого обучения на GPU и CPU. Массивы PyTorch обычно называют тензорами. Они похожи на ndarray NumPy, но могут обрабатываться на GPU и других аппаратных ускорителях. Тензоры и массивы NumPy часто могут использовать общую область памяти, что позволяет избежать копирования данных.

>>> import torch
>>> data = [[1, 2],[3, 4]]
>>> x_np = np.array(data)
>>> x_tensor = torch.tensor(data)

Обратите внимание, что x_np и x_tensor являются различными типами объектов:

>>> x_np
array([[1, 2],
       [3, 4]])
>>> x_tensor
tensor([[1, 2],
        [3, 4]])

При этом тензоры PyTorch можно использовать как массивы NumPy без явного преобразования:

>>> np.exp(x_tensor)
tensor([[ 2.7183,  7.3891],
        [20.0855, 54.5982]], dtype=torch.float64)

Тип результата этой функции совместим с исходным типом данных.

Предупреждение

Хотя такое смешивание ndarray и тензоров может быть удобным, оно не рекомендуется. Оно не работает с тензорами вне CPU и может давать неожиданные результаты в особых случаях. Лучше явно преобразовывать ndarray в тензор.

Примечание

PyTorch не реализует __array_function__ и __array_ufunc__. Внутри метод Tensor.__array__() возвращает ndarray NumPy как представление буфера данных тензора. Подробности см. в этом issue и в реализации __torch_function__.

Здесь также видно действие __array_wrap__, хотя torch.Tensor не является подклассом ndarray:

>>> import torch
>>> t = torch.arange(4)
>>> np.abs(t)
tensor([0, 1, 2, 3])

PyTorch реализует __array_wrap__, чтобы иметь возможность получать тензоры обратно из функций NumPy, и мы можем напрямую изменять его, чтобы контролировать, какой тип объектов возвращается из этих функций.

Пример: массивы CuPy#

CuPy — совместимая с NumPy и SciPy библиотека массивов для вычислений на GPU в Python. Она реализует часть интерфейса NumPy через cupy.ndarray — аналог ndarray NumPy.

>>> import cupy as cp
>>> x_gpu = cp.array([1, 2, 3, 4])

Объект cupy.ndarray реализует интерфейс __array_ufunc__. Поэтому к массивам CuPy можно применять ufunc NumPy: выполнение передаётся соответствующей реализации CuPy для CUDA или ROCm.

>>> np.mean(np.exp(x_gpu))
array(21.19775622)

Обратите внимание, что тип возвращаемого значения этих операций по-прежнему соответствует исходному типу:

>>> arr = cp.random.randn(1, 2, 3, 4).astype(cp.float32)
>>> result = np.sum(arr)
>>> print(type(result))
<class 'cupy._core.core.ndarray'>

Подробности см. на этой странице документации CuPy.

cupy.ndarray также реализует интерфейс __array_function__, что означает, что можно выполнять такие операции, как

>>> a = np.random.randn(100, 100)
>>> a_gpu = cp.asarray(a)
>>> qr_gpu = np.linalg.qr(a_gpu)

CuPy реализует многие, но не все функции NumPy для объектов cupy.ndarray. Подробности см. в документации CuPy.

Пример: массивы Dask#

Dask — гибкая библиотека параллельных вычислений на Python. Dask Array реализует часть интерфейса ndarray NumPy через блочные алгоритмы, разбивая большой массив на множество небольших. Это позволяет на нескольких ядрах обрабатывать массивы, не помещающиеся в оперативную память.

Dask поддерживает __array__() и __array_ufunc__.

>>> import dask.array as da
>>> x = da.random.normal(1, 0.1, size=(20, 20), chunks=(10, 10))
>>> np.mean(np.exp(x))
dask.array<mean_agg-aggregate, shape=(), dtype=float64, chunksize=(), chunktype=numpy.ndarray>
>>> np.mean(np.exp(x)).compute()
5.090097550553843

Примечание

Dask использует отложенные вычисления: результат не вычисляется, пока вы явно не запросите его вызовом compute().

Подробности см. в документации по массивам Dask и в описании возможностей взаимодействия массивов Dask с массивами NumPy.

Пример: DLPack #

Некоторые библиотеки Python для анализа данных реализуют протокол __dlpack__, например PyTorch и CuPy. Полный список приведён на этой странице документации DLPack.

Преобразование тензора PyTorch на CPU в массив NumPy:

>>> import torch
>>> x_torch = torch.arange(5)
>>> x_torch
tensor([0, 1, 2, 3, 4])
>>> x_np = np.from_dlpack(x_torch)
>>> x_np
array([0, 1, 2, 3, 4])
>>> # note that x_np is a view of x_torch
>>> x_torch[1] = 100
>>> x_torch
tensor([  0, 100,   2,   3,   4])
>>> x_np
array([  0, 100,   2,   3,   4])
Комментарии к примеру на русском
  • x_np — представление x_torch

В приведённом в оригинале примере импортированные массивы доступны только для чтения, поэтому запись и изменение на месте вызывают ошибку. Примечание переводчика: в NumPy 2.5.4 это зависит от версии протокола и библиотеки-источника. Например, np.from_dlpack, получив обычный записываемый массив NumPy, может вернуть записываемое представление. Проверяйте атрибут flags.writeable; показанная ниже ошибка возникает лишь для представления, доступного только для чтения:

>>> x_np.flags.writeable
False
>>> x_np[1] = 1
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ValueError: assignment destination is read-only

Если импортированный массив доступен только для чтения, для изменения на месте потребуется копия. Это удваивает память, занятую данными; не делайте так без необходимости для очень больших массивов:

>>> x_np_copy = x_np.copy()
>>> x_np_copy.sort()  # works
Комментарии к примеру на русском
  • Работает

Примечание

Тензоры на GPU нельзя напрямую преобразовать в массивы NumPy без копирования, поскольку NumPy не поддерживает устройства GPU. Однако начиная с DLPack v1 поддерживается копирование между устройствами через параметр device:

>>> x_torch = torch.arange(5, device='cuda')
>>> np.from_dlpack(x_torch)  # fails: implicit device=None means same device
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
RuntimeError: Unsupported device in DLTensor.
>>> np.from_dlpack(x_torch, device='cpu')  # works: explicit copy to CPU
array([0, 1, 2, 3, 4])
Комментарии к примеру на русском
  • Не работает: неявное device=None означает то же устройство
  • Работает: явное копирование на CPU

Если обе библиотеки поддерживают устройство, на котором расположен буфер данных, можно использовать протокол __dlpack__ (например, между PyTorch и CuPy):

>>> x_torch = torch.arange(5, device='cuda')
>>> x_cupy = cupy.from_dlpack(x_torch)

Аналогично, массив NumPy может быть преобразован в тензор PyTorch:

>>> x_np = np.arange(5)
>>> x_torch = torch.from_dlpack(x_np)

Экспорт массива, доступного только для чтения, в старом формате DLPack невозможен. Примечание переводчика: утверждение оригинала «массивы только для чтения нельзя экспортировать» относится к старому формату капсулы. NumPy 2.5.4 поддерживает экспорт с сохранением этого ограничения через версионный формат DLPack, например при max_version=(1, 0):

>>> x_np = np.arange(5)
>>> x_np.flags.writeable = False
>>> torch.from_dlpack(x_np)  
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
  File ".../site-packages/torch/utils/dlpack.py", line 63, in from_dlpack
    dlpack = ext_tensor.__dlpack__()
TypeError: NumPy currently only supports dlpack for writeable arrays
