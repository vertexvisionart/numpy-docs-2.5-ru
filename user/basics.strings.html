Работа с массивами строк и байтов #

Хотя NumPy в первую очередь является числовой библиотекой, часто бывает удобно работать с массивами строк или байтов NumPy. Два наиболее распространенных случая использования:

  • Работа с данными, загруженными из файла или отображёнными из файла в память, когда одно или несколько полей содержат строки или байтовые строки с заранее известной максимальной длиной. Это часто используется для полей имён или меток.

  • Использование индексации и трансляции NumPy с массивами строк Python заранее неизвестной длины, в которых также могут встречаться пропущенные значения.

Для первого случая NumPy предоставляет типы фиксированной ширины numpy.void, numpy.str_ и numpy.bytes_. Для второго — numpy.dtypes.StringDType. Ниже описана работа с массивами строк фиксированной и переменной длины, преобразование между этими представлениями и способы эффективно обрабатывать строковые данные в NumPy.

Типы фиксированной ширины#

До NumPy 2.0 типы фиксированной ширины numpy.str_, numpy.bytes_ и numpy.void были единственными типами для работы со строками и байтовыми строками. Поэтому они по-прежнему выбираются по умолчанию для соответствующих данных:

>>> np.array(["hello", "world"])
array(['hello', 'world'], dtype='<U5')

Определён тип данных '<U5': строки Unicode с порядком байтов от младшего к старшему и максимальной длиной 5 кодовых точек Unicode.

Аналогично для байтовых строк:

>>> np.array([b"hello", b"world"])
array([b'hello', b'world'], dtype='|S5')

Поскольку элементы кодировки занимают по одному байту, порядок байтов указан как ‘|’ — «неприменимо». Автоматически выбран тип байтовой строки длиной не более 5 байтов.

Вы также можете использовать numpy.void для представления байтовых строк:

>>> np.array([b"hello", b"world"]).astype(np.void)
array([b'\x68\x65\x6C\x6C\x6F', b'\x77\x6F\x72\x6C\x64'], dtype='|V5')

Это особенно удобно для потоков байтов, которые лучше рассматривать как наборы 8-битных целых чисел, а не как байтовые строки.

Строки переменной ширины #

Добавлено в версии 2.0.

Примечание

numpy.dtypes.StringDType — новое дополнение NumPy, реализованное с помощью нового механизма гибких пользовательских типов данных. Оно ещё не прошло столь же широкую проверку в реальных рабочих процессах, как прежние типы данных NumPy.

В реальных данных длина строк часто заранее неизвестна. Тип фиксированной ширины в таком случае неудобен: чтобы сохранить все строки без обрезки, ещё до создания массива нужно знать длину самой длинной строки.

Для подобных случаев NumPy предоставляет numpy.dtypes.StringDType, хранящий строки переменной длины в кодировке UTF-8 в массиве NumPy:

>>> from numpy.dtypes import StringDType
>>> data = ["this is a longer string", "short string"]
>>> arr = np.array(data, dtype=StringDType())
>>> arr
array(['this is a longer string', 'short string'], dtype=StringDType())

В отличие от типов фиксированной ширины, StringDType не требует задавать максимальную длину элемента. Один массив может содержать и длинные, и короткие строки без резервирования места для дополняющих байтов у коротких строк.

Также обратите внимание, что в отличие от строк фиксированной ширины и большинства других типов данных NumPy, StringDType не сохраняет строковые данные в «основном» буфере данных ndarray. Вместо этого буфер массива используется для хранения метаданных о том, где в памяти хранятся строковые данные. Эта разница означает, что код, ожидающий, что буфер массива будет содержать строковые данные, не будет работать правильно, и его необходимо будет обновить для поддержки StringDType.

Поддержка пропущенных данных#

Часто наборы строковых данных не являются полными, и требуется специальная метка, указывающая на отсутствие значения. По умолчанию StringDType не имеет какой-либо специальной поддержки пропущенных значений, кроме того факта, что для заполнения пустых массивов используются пустые строки:

>>> np.empty(3, dtype=StringDType())
array(['', '', ''], dtype=StringDType())

При необходимости можно создать экземпляр StringDType с поддержкой пропущенных значений, передав конструктору именованный аргумент na_object:

>>> dt = StringDType(na_object=None)
>>> arr = np.array(["this array has", None, "as an entry"], dtype=dt)
>>> arr
array(['this array has', None, 'as an entry'],
      dtype=StringDType(na_object=None))
>>> arr[1] is None
True

В качестве na_object можно использовать любой объект Python. Часто выбирают numpy.nan, float('nan'), None, специальный маркер пропущенных данных, например pandas.NA, или строку, которая предположительно не встретится среди обычных значений, например "__placeholder__".

NumPy отдельно обрабатывает маркеры, подобные NaN, и строковые маркеры.

Маркеры пропущенных данных, подобные NaN#

Маркер, подобный NaN, распространяется через арифметические операции: результатом снова становится такое отсутствующее значение. К этой категории относятся вещественное значение nan Python и маркер пропущенных данных pandas pd.NA. В строковых операциях это поведение сохраняется: например, сложение маркера с любой другой строкой даёт маркер:

>>> dt = StringDType(na_object=np.nan)
>>> arr = np.array(["hello", np.nan, "world"], dtype=dt)
>>> arr + arr
array(['hellohello', nan, 'worldworld'], dtype=StringDType(na_object=nan))

Как nan в вещественных массивах, маркеры, подобные NaN, при сортировке перемещаются в конец массива:

>>> np.sort(arr)
array(['hello', 'world', nan], dtype=StringDType(na_object=nan))

Маркеры отсутствующих данных в строках#

Строковый маркер пропущенных данных — экземпляр str или подкласса str. Если такой массив передать строковой операции или приведению типов, пропущенные элементы обрабатываются как значения, равные строковому маркеру. Операции сравнения также непосредственно используют этот маркер вместо пропущенных значений.

Другие маркеры пропущенных значений#

Другие объекты, например None, также можно использовать как маркеры пропущенных данных. Если массив содержит пропуски, обозначенные таким маркером, строковые операции вызывают ошибку:

>>> dt = StringDType(na_object=None)
>>> arr = np.array(["this array has", None, "as an entry"])
>>> np.sort(arr)
Traceback (most recent call last):
...
TypeError: '<' not supported between instances of 'NoneType' and 'str'

Преобразование нестроковых объектов#

По умолчанию нестроковые данные преобразуются в строки:

>>> np.array([1, object(), 3.4], dtype=StringDType())
array(['1', '<object object at 0x7faa2497dde0>', '3.4'], dtype=StringDType())

Если такое поведение нежелательно, можно создать экземпляр DType, отключив преобразование в строки с помощью coerce=False в инициализаторе:

>>> np.array([1, object(), 3.4], dtype=StringDType(coerce=False))
Traceback (most recent call last):
...
ValueError: StringDType only allows string data when string coercion is disabled.

Это позволяет строго проверять данные за тот же проход, в котором NumPy создаёт массив. coerce=True возвращает поведение по умолчанию с разрешённым приведением к строкам.

Приведение к строкам фиксированной длины и обратно#

StringDType поддерживает преобразования в numpy.str_, numpy.bytes_ и numpy.void и обратно. Приведение к строкам фиксированной длины особенно полезно для отображения строк в память через ndarray или для чтения и записи в столбцовый формат с известной максимальной длиной строки.

При любом преобразовании в строковый тип фиксированной ширины нужно указать максимальную допустимую длину строки:

>>> arr = np.array(["hello", "world"], dtype=StringDType())
>>> arr.astype(np.str_)  
Traceback (most recent call last):
...
TypeError: Casting from StringDType to a fixed-width dtype with an
unspecified size is not currently supported, specify an explicit
size for the output dtype instead.

The above exception was the direct cause of the following
exception:

TypeError: cannot cast dtype StringDType() to <class 'numpy.dtypes.StrDType'>.
>>> arr.astype("U5")
array(['hello', 'world'], dtype='<U5')

Приведение numpy.bytes_ наиболее полезно для строковых данных, которые, как известно, содержат только символы ASCII, поскольку символы вне этого диапазона не могут быть представлены в одном байте в кодировке UTF-8 и отклоняются.

Любую корректную строку Unicode можно преобразовать в numpy.str_. Однако numpy.str_ хранит каждый символ в 32-битной кодировке UCS4. Поэтому для обычного текста этот тип нередко расходует больше памяти, чем более компактная кодировка.

Кроме того, любая допустимая строка Unicode может быть преобразована в numpy.void , сохраняя байты UTF-8 непосредственно в выходном массиве:

>>> arr = np.array(["hello", "world"], dtype=StringDType())
>>> arr.astype("V5")
array([b'\x68\x65\x6C\x6C\x6F', b'\x77\x6F\x72\x6C\x64'], dtype='|V5')

Убедитесь, что в выходном массиве достаточно места для всех байтов строки в UTF-8: число байтов в UTF-8 не обязательно совпадает с числом символов строки.
