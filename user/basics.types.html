Типы массивов и преобразования между типами #

NumPy поддерживает гораздо больше числовых типов, чем Python. В этом разделе перечислены доступные типы и показано, как изменить тип данных массива.

Числовые типы NumPy описываются объектами numpy.dtype, каждый из которых имеет собственные характеристики. После импорта NumPy командой import numpy as np можно создавать массивы заданного типа, указывая скалярные типы из API верхнего уровня, например numpy.bool, numpy.float32 и другие.

Эти скалярные типы можно передавать аргументу dtype, который принимают многие функции и методы NumPy. Например:

>>> z = np.arange(3, dtype=np.uint8)
>>> z
array([0, 1, 2], dtype=uint8)

Типы массивов также можно задавать символьными кодами, например:

>>> np.array([1, 2, 3], dtype='f')
array([1.,  2.,  3.], dtype=float32)
>>> np.array([1, 2, 3], dtype='d')
array([1.,  2.,  3.], dtype=float64)

Подробнее о задании и создании объектов типов данных, включая параметры вроде порядка байтов, см. Задание и создание типов данных.

Чтобы узнать тип данных массива, посмотрите его атрибут dtype:

>>> z.dtype
dtype('uint8')

Объект dtype также содержит характеристики типа: число битов, порядок байтов и другие сведения. Через него можно проверять свойства типа, например является ли он целочисленным:

>>> d = np.dtype(np.int64)
>>> d
dtype('int64')

>>> np.issubdtype(d, np.integer)
True

>>> np.issubdtype(d, np.floating)
False

Для преобразования типа данных массива используйте метод .astype(). Например:

>>> z.astype(np.float64)                 
array([0.,  1.,  2.])

В предыдущем примере встроенный тип float языка Python можно было указать как dtype вместо numpy.float64. NumPy интерпретирует int как numpy.int_, bool — как numpy.bool, float — как numpy.float64, а complex — как numpy.complex128. У остальных типов данных прямых аналогов среди встроенных типов Python нет.

Иногда преобразование вызывает переполнение: например, при преобразовании значения 300 типа numpy.int64 в numpy.int8. NumPy следует правилам приведения типов C, поэтому переполнение даёт 44 (300 - 256). Чтобы вместо переполнения получить ошибку, задайте same_value для аргумента casting (см. также «Ошибки переполнения»):

>>> z.astype(np.float64, casting="same_value")   
array([0.,  1.,  2.])

Числовые типы данных#

Существует пять основных категорий числовых типов: логические значения (bool), целые числа (int), беззнаковые целые числа (uint), числа с плавающей точкой (float) и комплексные числа (complex). Название категории в сочетании с разрядностью определяет конкретный тип. Разрядность — число бит, необходимых для хранения одного значения в памяти. Например, numpy.float64 — 64-битный тип с плавающей точкой. Разрядность некоторых типов, таких как numpy.int_ и numpy.intp, зависит от платформы (например, от того, является ли архитектура процессора 32- или 64-битной). Это следует учитывать при взаимодействии с низкоуровневым кодом, например на C или Fortran, который обращается непосредственно к памяти.

Типы данных для строк и байтов#

Помимо чисел, NumPy поддерживает строки Unicode с типом numpy.str_ и символьным кодом U, байтовые строки с типом numpy.bytes_ и кодом S, а также произвольные последовательности байтов с типом numpy.void и кодом V. Примечание переводчика: оригинал называет байтовые строки «завершаемыми нулём». На практике данные фиксированной ширины дополняются нулевыми байтами, только если есть свободное место; для элемента, занимающего всю ширину, отдельный завершающий нуль не требуется.

Все перечисленные выше типы имеют фиксированную ширину. Она задаёт максимальный размер одного элемента в байтах или кодовых точках Unicode. Поэтому для хранения строк или байтовых последовательностей нужно заранее знать или вычислить длину самого длинного элемента.

Например, мы можем создать массив, хранящий слова "hello" и "world!" :

>>> np.array(["hello", "world!"])
array(['hello', 'world!'], dtype='<U6')

Здесь автоматически выбран тип строки Unicode длиной не более 6 кодовых точек: этого достаточно для обоих элементов без обрезки. Если явно задать меньшую или большую ширину типа, строка соответственно обрезается либо дополняется нулями в буфере до заданной ширины:

>>> np.array(["hello", "world!"], dtype="U5")
array(['hello', 'world'], dtype='<U5')
>>> np.array(["hello", "world!"], dtype="U7")
array(['hello', 'world!'], dtype='<U7')

Дополнение нулевыми байтами видно яснее, если использовать байтовый тип и вывести сами байты буфера массива:

>>> np.array(["hello", "world"], dtype="S7").tobytes()
b'hello\x00\x00world\x00\x00'

Каждый элемент дополняется двумя нулевыми байтами. Однако NumPy не может отличить намеренно сохранённые конечные нулевые байты от нулевых байтов заполнения:

>>> x = [b"hello\0\0", b"world"]
>>> a = np.array(x, dtype="S7")
>>> print(a[0])
b"hello"
>>> a[0] == x[0]
False

Если нужно сохранять и точно восстанавливать завершающие нулевые байты, используйте неструктурированный тип данных void:

>>> a = np.array(x, dtype="V7")
>>> a
array([b'\x68\x65\x6C\x6C\x6F\x00\x00', b'\x77\x6F\x72\x6C\x64\x00\x00'],
      dtype='|V7')
>>> a[0] == np.void(x[0])
True

Более сложные типы, не перечисленные выше, рассматриваются в разделе Структурированные массивы.

Соответствие типов NumPy и типов C#

NumPy предоставляет имена типов как с явной разрядностью, так и на основе имён типов C. Поскольку определения типов C зависят от платформы, для предотвращения платформенных различий в программах NumPy следует предпочитать типы с явно заданной разрядностью.

Для удобства взаимодействия с C, где естественно использовать зависящие от платформы типы, NumPy предоставляет соответствующие псевдонимы типов. В конце некоторых имён стоит подчёркивание, например numpy.bool_, чтобы отличать их от встроенных типов Python.

Скаляры массивов#

NumPy обычно возвращает элементы массивов как скаляры массива — скалярные значения с соответствующим dtype. Они отличаются от скаляров Python, но в большинстве случаев взаимозаменяемы с ними. Основное исключение относится к версиям Python до 2.x: в них целочисленные скаляры массива нельзя использовать как индексы списков и кортежей. Возможны и другие исключения: например, когда код использует особые атрибуты скаляра или явно проверяет, является ли значение скаляром Python. Обычно такие проблемы легко устранить явным преобразованием скаляра массива в скаляр Python с помощью соответствующего конструктора типа Python (например, int, float, complex, str).

Главное преимущество скаляров NumPy — сохранение типа данных массива. В Python может не быть соответствующего встроенного скалярного типа, например int16. Поэтому тип значения сохраняет свои характеристики независимо от того, находится значение внутри массива или извлечено из него. У скаляров NumPy также есть многие методы массивов.

Ошибки переполнения#

Из-за фиксированного размера числовых типов NumPy возможно переполнение: значение может не помещаться в диапазон выбранного типа. Например, numpy.power правильно вычисляет 100 ** 9 для 64-битных целых чисел, но при 32-битном типе даёт неверное значение -1486618624.

>>> np.power(100, 9, dtype=np.int64)
1000000000000000000
>>> np.power(100, 9, dtype=np.int32)
np.int32(-1486618624)

При переполнении целочисленные типы NumPy и Python ведут себя по-разному. Это может удивить тех, кто ожидает от целых NumPy поведения встроенного int Python. Размер int в Python не фиксирован: при необходимости он увеличивается, чтобы вместить целое число, поэтому обычного переполнения фиксированной разрядности не возникает.

NumPy предоставляет numpy.iinfo и numpy.finfo для проверки минимальных или максимальных значений целых чисел NumPy и значений с плавающей запятой соответственно.

>>> np.iinfo(int) # Bounds of the default integer on this system.
iinfo(min=-9223372036854775808, max=9223372036854775807, dtype=int64)
>>> np.iinfo(np.int32) # Bounds of a 32-bit integer
iinfo(min=-2147483648, max=2147483647, dtype=int32)
>>> np.iinfo(np.int64) # Bounds of a 64-bit integer
iinfo(min=-9223372036854775808, max=9223372036854775807, dtype=int64)
Комментарии к примеру на русском
  • Границы целочисленного типа по умолчанию в этой системе.
  • Границы 32-битного целого числа
  • Границы 64-битного целого числа

Если диапазона 64-битных целых чисел недостаточно, можно вычислять результат в типе с плавающей точкой. Такие типы имеют более широкий диапазон значений, но не обеспечивают точное представление всех целых чисел.

>>> np.power(100, 100, dtype=np.int64) # Incorrect even with 64-bit int
0
>>> np.power(100, 100, dtype=np.float64)
1e+200
Комментарии к примеру на русском
  • Неверно даже для 64-битного int

Точность чисел с плавающей запятой#

Многие функции NumPy, особенно в numpy.linalg, используют арифметику с плавающей точкой. Из-за способа представления десятичных чисел в компьютере при вычислениях возможны небольшие погрешности. Например, при выполнении обычных арифметических операций:

>>> 0.3 - 0.2 - 0.1  # This does not equal 0 due to floating-point precision
-2.7755575615628914e-17
Комментарии к примеру на русском
  • Не равно 0 из-за ограниченной точности вычислений с плавающей точкой

В таких случаях рекомендуется сравнивать значения с помощью функций вроде np.isclose вместо проверки на точное равенство:

>>> np.isclose(0.3 - 0.2 - 0.1, 0, rtol=1e-05)  # Check for closeness to 0
True
Комментарии к примеру на русском
  • Проверяем близость к 0

В этом примере np.isclose учитывает небольшие погрешности вычислений с плавающей точкой, применяя допуск при сравнении. Значения, различающиеся в пределах этого допуска, считаются близкими. Примечание переводчика: упомянутый в оригинале относительный допуск — лишь часть проверки numpy.isclose; по умолчанию также используется абсолютный допуск.

О точности вычислений см. «Арифметика с плавающей точкой».

Расширенная точность#

Тип float Python обычно использует 64-битные числа с плавающей точкой, почти эквивалентные numpy.float64. Иногда нужна большая точность. Доступность такой арифметики в NumPy зависит от оборудования и среды сборки. Например, процессоры x86 поддерживают 80-битный расширенный формат. Многие компиляторы C предоставляют его как long double, но MSVC, обычно используемый для сборок Windows, делает long double идентичным double — 64-битному типу. NumPy предоставляет тип компилятора long double под именем numpy.longdouble и его комплексный аналог np.clongdouble. Характеристики типа в вашей сборке можно узнать через np.finfo(np.longdouble).

Среди встроенных вещественных типов NumPy нет типа с большей точностью, чем C long double. В оригинале далее утверждается, что 128-битный формат IEEE четверной точности, соответствующий REAL*16 в Fortran, недоступен. Примечание переводчика: это утверждение зависит от платформы и в общем виде устарело. На некоторых платформах longdouble использует IEEE binary128; на типичной x86-сборке — 80-битный расширенный формат, а в сборке MSVC — 64-битный. Наличие имени float128 само по себе не гарантирует четверную точность; проверяйте numpy.finfo(numpy.longdouble).

Для эффективного выравнивания в памяти numpy.longdouble обычно дополняется нулевыми битами до 96 или 128 бит. Оптимальный вариант зависит от оборудования и среды разработки: в 32-битных системах обычно используется 96 бит, а в 64-битных — 128 бит. Для np.longdouble выбирается системный вариант по умолчанию; np.float96 и np.float128 позволяют явно выбрать размер с дополнением. Несмотря на названия, np.float96 и np.float128 обеспечивают лишь ту же точность, что и np.longdouble: 80-битное представление на большинстве машин x86 и 64-битное в стандартных сборках Windows.

Даже если numpy.longdouble имеет большую точность, чем встроенный float Python, дополнительную точность легко потерять: многие операции Python преобразуют значение через float. Например, оператор форматирования % требует преобразования аргументов во встроенные типы Python. Поэтому расширенная точность теряется, даже если запросить много знаков после запятой. Для проверки кода полезно использовать значение 1 + np.finfo(np.longdouble).eps.
