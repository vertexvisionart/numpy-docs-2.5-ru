Изменение порядка байтов#

Введение в порядок байтов и ndarrays #

Объект ndarray предоставляет интерфейс массива Python для данных в памяти.

Часто данные в памяти, которые вы хотите представить массивом, имеют порядок байтов, отличный от порядка компьютера, на котором работает Python.

Например, я работаю на компьютере с процессором little-endian, таким как Intel Pentium, но загружаю данные из файла, записанного компьютером с порядком байтов big-endian. Допустим, я загрузил 4 байта из файла, записанного компьютером Sun (big-endian). Я знаю, что они представляют два 16-битных целых числа. На машине big-endian в двухбайтовом целом числе сначала хранится старший байт (MSB), затем младший (LSB). Поэтому в памяти байты располагаются так:

  1. Первое целое число со старшим байтом первым (MSB).

  2. LSB целое число 1

  3. Второе целое число со старшим байтом первым (MSB).

  4. LSB целое число 2

Допустим, на самом деле эти два целых числа были 1 и 770. Поскольку 770 = 256 * 3 + 2, 4 байта в памяти будут содержать соответственно: 0, 1, 3, 2. Байты, которые я загрузил из файла, будут иметь следующее содержимое:

>>> big_end_buffer = bytearray([0,1,3,2])
>>> big_end_buffer
bytearray(b'\x00\x01\x03\x02')

Для доступа к этим целым числам можно использовать ndarray. Создадим массив-обёртку для этой памяти и укажем NumPy, что она содержит два 16-битных целых числа с порядком байтов big-endian:

>>> import numpy as np
>>> big_end_arr = np.ndarray(shape=(2,),dtype='>i2', buffer=big_end_buffer)
>>> big_end_arr[0]
np.int16(1)
>>> big_end_arr[1]
np.int16(770)

Обратите внимание на указанный выше dtype массива: >i2. Символ > означает big-endian, то есть старший байт первым (< — little-endian, младший байт первым), а i2 — знаковое целое размером 2 байта. Например, для одного беззнакового 4-байтового целого в порядке little-endian строка dtype была бы <u4.

На самом деле, почему бы нам не попробовать это?

>>> little_end_u4 = np.ndarray(shape=(1,),dtype='<u4', buffer=big_end_buffer)
>>> little_end_u4[0] == 1 * 256**1 + 3 * 256**2 + 2 * 256**3
True

Вернёмся к big_end_arr: исходные данные имеют порядок байтов big-endian, и dtype задан соответственно — тоже big-endian. Однако иногда нужно изменить этот порядок.

Предупреждение

Скаляры не хранят информацию о порядке байтов, поэтому целочисленный скаляр, извлечённый из массива, имеет системный порядок байтов. Следовательно:

>>> big_end_arr[0].dtype.byteorder == little_end_u4[0].dtype.byteorder
True

NumPy намеренно не стремится всегда сохранять порядок байтов: например, numpy.concatenate преобразует данные в машинный порядок байтов.

Изменение порядка байтов#

Как следует из введения, есть два способа изменить соотношение между порядком байтов, заданным в массиве, и фактическими данными в памяти:

  • Изменить сведения о порядке байтов в dtype массива, чтобы лежащие в его основе данные интерпретировались с другим порядком байтов. Для этого служит arr.view(arr.dtype.newbyteorder())

  • Изменить порядок байтов самих данных, сохранив прежнюю интерпретацию dtype. Именно это делает arr.byteswap().

Общие ситуации, в которых вам нужно изменить порядок байтов:

  1. Порядок байтов данных и dtype не совпадает, и вы хотите изменить dtype в соответствии с данными.

  2. Порядок байтов данных не совпадает с указанным в dtype, и вы хотите переставить байты данных, чтобы привести их в соответствие с dtype

  3. Порядок байтов данных и dtype совпадает, но нужно поменять порядок байтов данных и соответственно изменить dtype

Порядок байтов данных и dtype не совпадает: изменить dtype в соответствии с данными#

Создадим пример, в котором они не совпадают:

>>> wrong_end_dtype_arr = np.ndarray(shape=(2,),dtype='<i2', buffer=big_end_buffer)
>>> wrong_end_dtype_arr[0]
np.int16(256)

Очевидным решением этой ситуации является изменение dtype, чтобы он давал правильный порядок байтов:

>>> fixed_end_dtype_arr = wrong_end_dtype_arr.view(np.dtype('<i2').newbyteorder())
>>> fixed_end_dtype_arr[0]
np.int16(1)

Обратите внимание, что массив не изменился в памяти:

>>> fixed_end_dtype_arr.tobytes() == big_end_buffer
True

Порядок байтов данных не совпадает с типом: изменение данных в соответствии с dtype#

Это может понадобиться, если данные в памяти должны иметь определённый порядок байтов. Например, при записи памяти в файл с заданным порядком байтов.

>>> fixed_end_mem_arr = wrong_end_dtype_arr.byteswap()
>>> fixed_end_mem_arr[0]
np.int16(1)

Теперь массив действительно изменился в памяти:

>>> fixed_end_mem_arr.tobytes() == big_end_buffer
False

Порядок байтов данных и dtype совпадает: меняем его и в данных, и в dtype#

Тип dtype массива может быть указан правильно, но вам нужно изменить порядок байтов данных в памяти на противоположный и соответственно изменить dtype, чтобы значения массива интерпретировались верно. В этом случае выполните обе предыдущие операции:

>>> swapped_end_arr = big_end_arr.byteswap()
>>> swapped_end_arr = swapped_end_arr.view(swapped_end_arr.dtype.newbyteorder())
>>> swapped_end_arr[0]
np.int16(1)
>>> swapped_end_arr.tobytes() == big_end_buffer
False

Более простой способ привести данные к определённому dtype и порядку байтов — использовать метод astype объекта ndarray:

>>> swapped_end_arr = big_end_arr.astype('<i2')
>>> swapped_end_arr[0]
np.int16(1)
>>> swapped_end_arr.tobytes() == big_end_buffer
False
