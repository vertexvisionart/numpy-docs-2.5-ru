Обход элементов массива#

Базовая итерация #

Часто алгоритму необходимо обойти все элементы многомерного массива. Объект итератора массива позволяет легко сделать это универсальным способом, подходящим для любого числа измерений. Конечно, если число измерений известно заранее, можно написать вложенные циклы for. Но для кода, работающего с любым числом измерений, пригодится итератор массива. Он возвращается при обращении к атрибуту .flat массива.

Обычный способ использования — вызвать PyArray_IterNew(array), передав ndarray или экземпляр его подкласса. Возвращается итератор массива — такой же объект, как атрибут .flat у ndarray. Обычно его приводят к PyArrayIterObject*, чтобы получить доступ к членам структуры. Для работы нужны iter->size — общее число элементов, iter->index — текущий линейный индекс, и iter->dataptr — указатель на данные текущего элемента. Иногда полезен также iter->ao — указатель на исходный ndarray.

После обработки текущего элемента перейти к следующему можно макросом PyArray_ITER_NEXT(iter). Обход всегда идёт в порядке C: быстрее всего меняется последний индекс. Для перехода к определённой точке массива используется PyArray_ITER_GOTO(iter, destination), где destination — массив npy_intp длины не меньше числа измерений исходного массива. Иногда полезен PyArray_ITER_GOTO1D(iter, index), переходящий к плоскому индексу index. Наиболее типичное использование показано в следующем примере.

PyObject *obj; /* assumed to be some ndarray object */
PyArrayIterObject *iter;
...
iter = (PyArrayIterObject *)PyArray_IterNew(obj);
if (iter == NULL) goto fail;   /* Assume fail has clean-up code */
while (iter->index < iter->size) {
    /* do something with the data at it->dataptr */
    PyArray_ITER_NEXT(it);
}
...
Комментарии к примеру на русском
  • Предполагается некоторый объект ndarray
  • Предполагается, что fail содержит код очистки
  • Работаем с данными по адресу it->dataptr

Вы также можете использовать PyArrayIter_Check (obj), чтобы убедиться, что у вас есть объект итератора и PyArray_ITER_RESET (iter) для сброса объекта итератора обратно в начало массива.

Если массив уже непрерывен, итератор может быть не нужен: он будет работать, но окажется медленнее наиболее эффективного кода для такого случая. Основное назначение итераторов — скрыть детали обхода N-мерных массивов с произвольными шагами. Сам NumPy широко использует их в исходном коде. Если известно, что массив непрерывен в порядке C или Fortran, для эффективного обхода достаточно каждый раз увеличивать указатель на размер элемента. Поэтому следующий код для непрерывного массива, вероятно, будет быстрее; предполагается тип double:

npy_intp size;
double *dptr;  /* could make this any variable type */
size = PyArray_SIZE(obj);
dptr = PyArray_DATA(obj);
while(size--) {
   /* do something with the data at dptr */
   dptr++;
}
Комментарии к примеру на русском
  • Здесь можно использовать любой тип переменной
  • Работаем с данными по адресу dptr

Обход по всем осям, кроме одной#

Распространённый алгоритм обходит все элементы массива, вызывая функцию для каждого. Вызовы могут занимать заметное время. Для ускорения можно написать функцию, принимающую вектор данных, и вызывать её сразу для всего измерения. Это увеличивает объём работы за вызов и уменьшает долю накладных расходов. Даже без вызова функции внутри цикла бывает выгодно выполнять внутренний цикл по самому длинному измерению, используя ускорение, которое современные микропроцессоры получают за счёт конвейерного выполнения базовых операций.

PyArray_IterAllButAxis(array, &dim) создаёт итератор, настроенный так, чтобы не обходить измерение dim. Единственное ограничение: с этим итератором нельзя использовать макрос PyArray_ITER_GOTO1D(it, ind). Поэтому плоская индексация также не сработает при передаче объекта обратно в Python, чего делать не следует. Возвращаемый объект обычно по-прежнему приводится к PyArrayIterObject *. Меняются только шаги и размеры итератора, чтобы имитировать обход array[…,0,…], где 0 стоит в измерении \(\textrm{dim}^{\textrm{th}}\). Если dim отрицателен, выбирается самое длинное измерение.

Одновременный обход нескольких массивов#

Часто нужно одновременно обходить несколько массивов; так работают, например, универсальные функции. Для массивов одинаковой формы обычно достаточно создать несколько итераторов. Следующий код обходит два массива, предполагая, что их форма и размер совпадают. В действительности достаточно, чтобы общее число элементов obj1 было не меньше, чем у obj2:

/* It is already assumed that obj1 and obj2
   are ndarrays of the same shape and size.
*/
iter1 = (PyArrayIterObject *)PyArray_IterNew(obj1);
if (iter1 == NULL) goto fail;
iter2 = (PyArrayIterObject *)PyArray_IterNew(obj2);
if (iter2 == NULL) goto fail;  /* assume iter1 is DECREF'd at fail */
while (iter2->index < iter2->size)  {
    /* process with iter1->dataptr and iter2->dataptr */
    PyArray_ITER_NEXT(iter1);
    PyArray_ITER_NEXT(iter2);
}
Комментарии к примеру на русском
  • Предполагается, что obj1 и obj2 — ndarray одинаковых формы и размера.
  • Предполагается, что при переходе к fail для iter1 вызывается DECREF
  • Обрабатываем данные через iter1->dataptr и iter2->dataptr

Трансляция нескольких массивов#

Когда в операции участвует несколько массивов, могут понадобиться те же правила трансляции массивов, что и в математических операциях (то есть в универсальных функциях). Это легко сделать с помощью PyArrayMultiIterObject. Такой объект возвращает команда Python numpy.broadcast; из C им пользоваться почти так же просто. Используется функция PyArray_MultiIterNew(n, ...), где передаётся n входных объектов вместо .... Входами могут быть массивы или любые объекты, преобразуемые в массив. Возвращается указатель на PyArrayMultiIterObject. Трансляция уже выполнена, а итераторы настроены так, что для перехода к следующему элементу каждого массива достаточно вызвать PyArray_ITER_NEXT для каждого входа. Макрос PyArray_MultiIter_NEXT(obj) автоматически выполняет этот переход; он принимает мультиитератор obj как в виде PyArrayMultiIterObject*, так и в виде PyObject*. Данные входа с номером i доступны через PyArray_MultiIter_DATA(obj, i). Далее приведён пример использования.

mobj = PyArray_MultiIterNew(2, obj1, obj2);
size = mobj->size;
while(size--) {
    ptr1 = PyArray_MultiIter_DATA(mobj, 0);
    ptr2 = PyArray_MultiIter_DATA(mobj, 1);
    /* code using contents of ptr1 and ptr2 */
    PyArray_MultiIter_NEXT(mobj);
}
Комментарии к примеру на русском
  • Код, использующий содержимое ptr1 и ptr2

Функция PyArray_RemoveSmallest(multi) настраивает все итераторы составного итератора так, чтобы обход не выполнялся по самому длинному измерению: его размер устанавливается в 1. Коду цикла, использующему указатели, скорее всего, также потребуются шаги каждого итератора. Они хранятся в multi->iters[i]->strides.

В исходном коде NumPy есть несколько примеров использования мультиитератора: он сильно упрощает написание N-мерного кода с трансляцией массивов. Дополнительные примеры можно найти, изучив исходный код.

Пользовательские типы данных#

NumPy предоставляет 24 встроенных типа данных. Они покрывают подавляющее большинство задач, но пользователю может понадобиться дополнительный тип. NumPy в некоторой степени поддерживает добавление таких типов. Новый тип будет вести себя почти как обычный, однако для универсальных функций нужно отдельно зарегистрировать одномерные циклы его обработки. Кроме того, проверки безопасного приведения других типов к новому и обратно всегда будут отвечать «приведение возможно», если дополнительно не зарегистрировать допустимые направления преобразования.

В тестах NumPy есть пример собственного типа данных: файл _rational_tests.c.src в каталоге исходников numpy/_core/src/umath/ реализует рациональное число как отношение двух 32-битных целых чисел.

Добавление нового типа данных #

Чтобы использовать новый тип данных, сначала нужно определить тип Python для хранения его скаляров. Если новый тип имеет двоично совместимое расположение данных, можно унаследовать его от одного из скалярных типов массива. Тогда он получит методы и атрибуты скаляров массива. Новые типы данных должны занимать фиксированный объём памяти. Если требуется гибкое представление, например для числа переменной точности, используйте в качестве типа данных указатель на объект. Структура объекта нового типа Python должна начинаться с PyObject_HEAD, за которым следует область фиксированного размера для данных типа. Например, подойдёт такая структура:

typedef struct {
   PyObject_HEAD;
   some_data_type obval;
   /* the name can be whatever you want */
} PySomeDataTypeObject;
Комментарии к примеру на русском
  • Имя может быть любым

После определения нового объекта типа Python нужно определить новую структуру PyArray_Descr, поле typeobject которой содержит указатель на только что определённый тип данных. Также необходимо определить обязательные функции в поле «.f»: nonzero, copyswap, copyswapn, setitem, getitem и cast. Чем больше функций в «.f» реализовано, тем полезнее новый тип данных. Неиспользуемые функции обязательно нужно инициализировать значением NULL; для этого можно вызвать PyArray_InitArrFuncs(f).

После создания структуры PyArray_Descr с нужными сведениями и функциями вызывают PyArray_RegisterDataType(new_descr). Примечание переводчика: описание структуры в оригинале устарело; в NumPy 2.5 эта функция принимает PyArray_DescrProto*, а не PyArray_Descr*. Возвращаемое целое число — уникальный type_number нового типа. Модуль должен сохранить и предоставить этот номер, чтобы другие модули могли распознавать ваш тип данных.

Этот API по своей природе небезопасен при работе из нескольких потоков. Подробнее см. Безопасность потоков.

Регистрация функции приведения типов#

Можно разрешить автоматическое приведение встроенных и других пользовательских типов данных к вашему типу. Для этого нужно зарегистрировать функцию приведения у типа, из которого выполняется преобразование. Требуется написать низкоуровневую функцию для каждого поддерживаемого преобразования и зарегистрировать её в дескрипторе типа данных. Низкоуровневая функция приведения имеет следующую сигнатуру.

void castfunc(void *from, void *to, npy_intp n, void *fromarr, void *toarr)#

Преобразует n элементов из буфера from с одним типом данных в буфер to с другим. Исходные данные находятся в непрерывном, выровненном участке памяти с правильным порядком байтов, на который указывает from. Выходной буфер также непрерывен, выровнен и имеет правильный порядок байтов. Аргументы fromarr и toarr следует использовать только для массивов с настраиваемым размером элемента: string, unicode и void.

Пример castfunc:

static void
double_to_float(double *from, float* to, npy_intp n,
                void* ignore1, void* ignore2) {
    while (n--) {
          (*to++) = (double) *(from++);
    }
}

Затем эту функцию можно зарегистрировать для преобразования double в float следующим кодом:

doub = PyArray_DescrFromType(NPY_DOUBLE);
PyArray_RegisterCastFunc(doub, NPY_FLOAT,
     (PyArray_VectorUnaryFunc *)double_to_float);
Py_DECREF(doub);

Регистрация правил преобразования типов#

По умолчанию пользовательские типы данных не считаются безопасно приводимыми к встроенным, и наоборот. Это ограничивает участие пользовательских типов в автоматическом приведении, выполняемом универсальными функциями и другими средствами NumPy. Ситуацию можно изменить, зарегистрировав безопасное приведение из конкретного объекта типа данных. Функция PyArray_RegisterCanCast(from_descr, totype_number, scalarkind) задаёт возможность приведения из from_descr к типу с номером totype_number. Если правила приведения скаляров менять не требуется, передайте NPY_NOSCALAR как аргумент scalarkind.

Чтобы новый тип данных участвовал в правилах приведения скаляров, в поле «.f» объекта типа данных нужно задать функцию scalarkind. Она должна возвращать категорию скаляра, к которой следует относить новый тип; значение скаляра доступно этой функции. Затем для каждой категории скаляров, которую может возвращать пользовательский тип, можно отдельно зарегистрировать целевые типы приведения. Если обработка приведения скаляров не зарегистрирована, все пользовательские типы данных будут рассматриваться как NPY_NOSCALAR.

Регистрация цикла универсальной функции#

Для своего типа данных можно также зарегистрировать низкоуровневые циклы ufunc. Тогда математические операции будут естественно работать с ndarray этого типа. Регистрация нового цикла с той же сигнатурой arg_types без предупреждения заменяет ранее зарегистрированный цикл для этого типа.

Сначала нужно создать ufunc, а затем зарегистрировать её одномерный цикл. Для регистрации вызывают PyUFunc_RegisterLoopForType(…) с нужными сведениями. При успехе возвращается 0; при неудаче — -1 и устанавливается исключение.

Создание подкласса ndarray на C#

Одна из редко используемых возможностей, присутствующих в Python с версии 2.2, — создание подклассов типов на C. Это одна из важных причин, по которым NumPy основан на коде Numeric, уже написанном на C. Подтип на C даёт гораздо большую гибкость управления памятью. Создать его несложно даже при базовом понимании того, как создавать новые типы для Python. Проще всего наследоваться от одного родительского типа, но возможно и множественное наследование. На C оно обычно менее полезно, чем в Python: подтипы Python должны иметь двоично совместимое расположение данных в памяти. Возможно, именно поэтому наследование от одного родительского типа несколько проще.

Каждая C-структура, представляющая объект Python, должна начинаться с PyObject_HEAD или PyObject_VAR_HEAD. Аналогично, начало структуры подтипа должно совпадать по расположению в памяти со структурой родительского типа. При множественном наследовании ограничения совместимости расположения должны соблюдаться для всех базовых типов; произвольное объединение их структур недопустимо. Python может обращаться к члену структуры подтипа как к члену родительской структуры — то есть привести указатель к указателю на родительскую структуру и разыменовать его член. При несовместимом расположении результат непредсказуем и может закончиться нарушением доступа к памяти и аварийным завершением программы.

Один из элементов PyObject_HEAD — указатель на структуру объекта типа. Чтобы создать новый тип Python, создают такую структуру и заполняют её функциями и указателями, описывающими нужное поведение типа. Обычно также создают структуру C для хранения данных каждого экземпляра. Например, &PyArray_Type указывает на структуру объекта типа ndarray, а переменная типа PyArrayObject* — на отдельный экземпляр ndarray. Одно из полей структуры ndarray, в свою очередь, содержит указатель &PyArray_Type на структуру объекта типа. Наконец, для каждого нового типа Python необходимо вызвать PyType_Ready(<pointer_to_type_object>).

Создание подтипов #

Создание подтипа выполняется аналогично, но в структуре объекта типа нужно задавать лишь поля, отвечающие за отличающееся поведение. Остальные могут быть NULL: PyType_Ready заполнит их соответствующими функциями родительских типов. Чтобы создать подтип на C, выполните следующие действия:

  1. При необходимости создайте новую C-структуру для обработки каждого экземпляра вашего типа. Типичная C-структура будет такой:

    typedef _new_struct {
    PyArrayObject base;
    /* new things here */
} NewArrayObject;
    Комментарии к примеру на русском
    • Новые моменты

    Полная структура PyArrayObject используется в качестве первого поля, чтобы двоичное расположение данных экземпляров нового типа совпадало с PyArrayObject.

  2. Заполните новую структуру объекта типа Python указателями на функции, переопределяющие стандартное поведение. Поля функций, которые должны остаться прежними, оставьте незаполненными (или NULL). Значение tp_name должно отличаться.

  3. Запишите указатель на объект основного родительского типа в поле tp_base структуры нового объекта типа. Для множественного наследования также заполните поле tp_bases кортежем всех родительских объектов в порядке наследования. Помните: для корректного множественного наследования все родительские типы должны иметь одинаковую структуру C.

  4. Вызовите PyType_Ready (<pointer_to_new_type>). Отрицательное возвращаемое число означает ошибку: тип не инициализирован. Иначе он готов к использованию. Обычно важно поместить ссылку на новый тип в словарь модуля, чтобы сделать его доступным из Python.

Подробнее о создании подтипов на C см. PEP 253: https://www.python.org/dev/peps/pep-0253.

Особенности создания подтипов ndarray#

Некоторые специальные методы и атрибуты используются массивами для облегчения взаимодействия подтипов с базовым типом ndarray.

Метод __array_finalize__ #

ndarray.__array_finalize__#

Некоторые функции создания массивов ndarray позволяют указать конкретный подтип результата. Благодаря этому многие процедуры могут работать с подтипами без дополнительных действий. Однако при таком создании экземпляра подтипа не вызываются ни __new__, ни __init__. Вместо этого выделяется память для экземпляра и заполняются соответствующие поля его структуры. Затем в словаре объекта ищется атрибут __array_finalize__. Если он есть и не равен None, он может быть либо объектом PyCapsule с указателем на PyArray_FinalizeFunc, либо методом с одним аргументом, который может быть None.

Если атрибут __array_finalize__ является объектом PyCapsule, указатель должен указывать на функцию со следующей сигнатурой:

(int) (PyArrayObject *, PyObject *)

Первый аргумент — вновь созданный подтип. Второй аргумент, если он не NULL, — «родительский» массив: он передаётся, если массив получен срезом или иной операцией с явно определяемым родителем. Эта процедура может выполнять любые действия. При ошибке она должна вернуть -1, в остальных случаях — 0.

Если атрибут __array_finalize__ не равен None и не является PyCapsule, он должен быть методом Python, принимающим родительский массив (или None при его отсутствии) и ничего не возвращающим. Ошибки в этом методе будут перехвачены и обработаны.

Атрибут __array_priority__#

ndarray.__array_priority__#

Этот атрибут позволяет просто и гибко определить, какой подтип считать главным в операции с двумя или более подтипами. Если подтипы различаются, подтип результата или результатов определяется наибольшим значением атрибута __array_priority__. При одинаковом __array_priority__ результат определяется подтипом первого аргумента. По умолчанию __array_priority__ возвращает 0.0 для базового ndarray и 1.0 для подтипа. Этот атрибут можно определить и у объектов, не являющихся подклассами ndarray; с его помощью выбирается метод __array_wrap__ для формирования результата. Примечание переводчика: утверждение оригинала о приоритете 1.0 у любого подтипа не соответствует современному поведению. Подкласс ndarray без собственного __array_priority__ наследует значение 0.0.

Метод __array_wrap__ #

ndarray.__array_wrap__#

Любой класс или тип может определить этот метод: он должен принимать аргумент ndarray и возвращать экземпляр соответствующего типа. Его можно рассматривать как противоположность методу __array__. Универсальные функции и другие функции NumPy используют его для поддержки работы с другими объектами. В Python >2.4 с его помощью также можно написать декоратор, который превращает функцию, работающую только с ndarray, в функцию, работающую с любым типом, имеющим методы __array__ и __array_wrap__.
