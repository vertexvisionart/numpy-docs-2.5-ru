Написание модуля расширения #

Объект ndarray позволяет быстро выполнять вычисления в Python, но при этом рассчитан на самые разные вычислительные задачи. Поэтому, если нужна максимальная скорость, хорошо написанный скомпилированный цикл, учитывающий конкретное приложение и оборудование, незаменим. Это одна из причин включения f2py в NumPy: он предоставляет удобные средства непосредственного подключения простого кода C/C++ и произвольного кода Fortran к Python. Мы рекомендуем использовать и совершенствовать этот механизм. В этом разделе описывается не сам инструмент, а лежащие в его основе базовые шаги написания модуля расширения.

После написания, компиляции и установки модуля расширения в каталог из пути поиска Python (sys.path) его можно импортировать как обычный файл Python. Он содержит объекты и методы, определённые и скомпилированные в коде C. Основные шаги хорошо документированы; подробности доступны в документации Python на www.python.org.

Помимо C API Python, существует обширный C API NumPy для сложных операций на уровне C. Однако большинству приложений обычно требуется лишь несколько вызовов. Например, для извлечения указателя на память и сведений о форме с передачей их другой вычислительной процедуре нужны совсем другие вызовы, чем для создания нового типа объектов, подобных массивам, или нового типа данных ndarray. В этой главе описаны наиболее употребительные вызовы API и макросы.

Необходимая подпрограмма#

Чтобы Python мог использовать ваш код C как модуль расширения, в нём необходимо определить одну функцию инициализации. Она должна называться init{name}, где {name} — имя модуля в Python, и быть объявлена так, чтобы быть доступной извне. Помимо добавления нужных методов и констант, эта функция должна вызывать import_array() и/или import_ufunc() в зависимости от используемого C-API. Если забыть эти вызовы, обращение к любой подпрограмме C-API приведёт к ошибке сегментации и аварийному завершению. В одном файле можно определить несколько функций init{name}, чтобы предоставить несколько модулей. Для их корректной работы необходимы дополнительные приёмы, которые здесь не рассматриваются. Примечание переводчика: в оригинале описана схема инициализации Python 2. В Python 3 функция называется PyInit_{name}; следующий пример с init{name} и Py_InitModule также относится к Python 2.

Минимальный исторический метод init{name} выглядит так:

PyMODINIT_FUNC
init{name}(void)
{
   (void)Py_InitModule({name}, mymethods);
   import_array();
}

mymethods должен быть массивом (обычно объявленным статически) структур PyMethodDef, содержащих имена методов, соответствующие функции C, переменную, указывающую, принимает ли метод именованные аргументы, и строки документации. Они описаны в следующем разделе. Чтобы добавить в модуль константы, сохраните возвращаемое значение Py_InitModule — объект модуля. Наиболее общий способ добавления элементов в модуль — получить его словарь с помощью PyModule_GetDict(module). Через этот словарь можно вручную добавить в модуль что угодно. Более простой способ добавить объекты — использовать один из трёх дополнительных вызовов C API Python, не требующих отдельно получать словарь модуля. Они описаны в документации Python, но для удобства приведены и здесь:

int PyModule_AddObject(PyObject *module, char *name, PyObject *value)#
int PyModule_AddIntConstant(PyObject *module, char *name, long value)#
int PyModule_AddStringConstant(PyObject *module, char *name, char *value)#

Все три функции требуют объект module — возвращаемое значение Py_InitModule. name — строка, задающая имя значения в модуле. В зависимости от вызываемой функции аргумент value представляет собой произвольный объект (PyModule_AddObject забирает владение ссылкой на него), целочисленную константу или строковую константу.

Определение функций #

Второй аргумент функции Py_InitModule — структура, упрощающая определение функций модуля. В примере выше структура mymethods должна быть определена ранее в файле (обычно непосредственно перед подпрограммой init{name}) следующим образом:

static PyMethodDef mymethods[] = {
    { nokeywordfunc,nokeyword_cfunc,
      METH_VARARGS,
      Doc string},
    { keywordfunc, keyword_cfunc,
      METH_VARARGS|METH_KEYWORDS,
      Doc string},
    {NULL, NULL, 0, NULL} /* Sentinel */
}
Комментарии к примеру на русском
  • Сторожевое значение

Каждый элемент массива mymethods представляет собой структуру PyMethodDef, содержащую: 1) имя функции в Python; 2) реализующую её функцию C; 3) флаги, указывающие, принимает ли функция именованные аргументы; 4) строку документации функции. Добавляя записи в эту таблицу, в одном модуле можно определить любое число функций. Все поля последней записи должны быть NULL, как показано в примере: эта запись служит признаком конца таблицы. По ней Python определяет, что перечислены все функции модуля.

Для завершения модуля расширения остаётся написать код, выполняющий нужные функции. Функции бывают двух видов: принимающие именованные аргументы и не принимающие их.

Функции без именованных аргументов#

Функции, не принимающие именованные аргументы, следует записывать так:

static PyObject*
nokeyword_cfunc (PyObject *dummy, PyObject *args)
{
    /* convert Python arguments */
    /* do function */
    /* return something */
}
Комментарии к примеру на русском
  • Преобразуем аргументы Python
  • Выполняем функцию
  • Возвращаем результат

Фиктивный аргумент в этом контексте не используется, и его можно игнорировать. Аргумент args содержит кортеж всех аргументов, переданных функции. Здесь можно выполнять любые действия, но обычно проще всего обработать входные аргументы вызовом PyArg_ParseTuple (args, format_string, addresses_to_C_variables…) или PyArg_UnpackTuple (tuple, “name”, min, max, …). Первая функция подробно описана в разделе 5.5 справочника C API Python (Parsing arguments and building values). Особое внимание стоит уделить формату «O&»: он использует функции преобразования для перехода между объектом Python и объектом C. Остальные форматы можно в основном считать частными случаями этого общего правила. В C API NumPy определено несколько полезных функций преобразования. В частности, PyArray_DescrConverter удобна для поддержки произвольного задания типа данных. Она преобразует любой допустимый объект Python, задающий тип данных, в объект PyArray_Descr*. Не забудьте передать адреса переменных C, которые нужно заполнить.

В исходном коде NumPy много примеров PyArg_ParseTuple. Обычное использование выглядит так:

PyObject *input;
PyArray_Descr *dtype;
if (!PyArg_ParseTuple(args, "OO&", &input,
                      PyArray_DescrConverter,
                      &dtype)) return NULL;

Помните, что строка формата «O» возвращает заимствованную ссылку на объект. Однако функции преобразования обычно требуют управления памятью. В этом примере при успешном преобразовании dtype содержит новую ссылку на объект PyArray_Descr*, а input — заимствованную ссылку. Поэтому, если это преобразование совмещено с другим (например, в целое число), причём преобразование типа данных прошло успешно, а преобразование в целое завершилось ошибкой, перед возвратом необходимо уменьшить счётчик ссылок объекта типа данных. Обычно для этого dtype присваивают NULL до вызова PyArg_ParseTuple, а перед возвратом вызывают Py_XDECREF для dtype.

После обработки аргументов выполняется основной код, при необходимости вызывающий другие функции. Последний шаг функции C — вернуть результат. При ошибке возвращается NULL; прежде нужно убедиться, что ошибка Python действительно установлена. Если возвращать нечего, увеличьте счётчик ссылок Py_None и верните этот объект. При возврате одного объекта нужно владеть ссылкой на него. Несколько объектов возвращаются кортежем. Функция Py_BuildValue(format_string, c_variables…) упрощает создание кортежей объектов Python из переменных C. Обратите внимание на разницу между «N» и «O» в строке формата, иначе возможны утечки памяти. «O» увеличивает счётчик ссылок объекта в соответствующей переменной C типа PyObject*, а «N» забирает владение ссылкой из переменной PyObject*. Используйте «N», если уже владеете ссылкой и хотите передать её кортежу; «O» — если имеете лишь заимствованную ссылку и нужно создать новую для кортежа.

Функции с именованными аргументами#

Эти функции очень похожи на функции без аргументов-ключевых слов. Единственное отличие состоит в том, что сигнатура функции:

static PyObject*
keyword_cfunc (PyObject *dummy, PyObject *args, PyObject *kwds)
{
...
}

Аргумент kwds содержит словарь Python: его ключи — имена переданных именованных аргументов, значения — соответствующие значения аргументов. Его можно обработать любым подходящим способом. Проще всего заменить PyArg_ParseTuple(args, format_string, addresses…) вызовом PyArg_ParseTupleAndKeywords(args, kwds, format_string, char *kwlist[], addresses…). Параметр kwlist — массив строк с ожидаемыми именами аргументов, завершающийся NULL. Каждому элементу format_string должна соответствовать строка. При передаче недопустимых именованных аргументов функция вызывает TypeError.

Для получения дополнительной помощи по этой функции см. раздел 1.8 (Параметры ключевых слов для функций расширения) учебника по расширению и встраиванию в документации Python.

Подсчёт ссылок#

Самая большая трудность при написании модулей расширения — подсчёт ссылок. Во многом этим объясняется популярность f2py, weave, Cython, ctypes и других средств. Ошибки управления ссылками могут приводить к чему угодно — от утечек памяти до ошибок сегментации. Единственная известная мне стратегия правильной работы со счётчиками ссылок — кровь, пот и слёзы. Сначала нужно твёрдо усвоить, что у каждого объекта Python есть счётчик ссылок. Затем — точно понять, как каждая функция меняет счётчики ссылок на ваши объекты, чтобы правильно использовать DECREF и INCREF. Это серьёзное испытание терпения и внимательности программиста. Несмотря на такое мрачное описание, в большинстве случаев подсчёт ссылок довольно прост. Чаще всего забывают вызвать DECREF для объектов перед досрочным выходом из подпрограммы из-за ошибки. На втором месте — передача ссылки, которой вызывающий код не владеет, в функцию или макрос, забирающий владение этой ссылкой (например, PyTuple_SET_ITEM и большинство функций, принимающих объекты PyArray_Descr). Примечание переводчика: в оригинале счётчик приписан переменной Python; точнее, он принадлежит объекту, на который могут ссылаться несколько переменных.

Обычно новая ссылка на объект получается при его создании или возврате из функции. Есть важные исключения, например получение элемента кортежа или словаря. Владея ссылкой, вы обязаны вызвать Py_DECREF(var), когда объект больше не нужен, если владение ссылкой не было передано другой функции. Передавая объект Python функции, которая принимает владение ссылкой, убедитесь, что ссылка принадлежит вам, либо получите собственную ссылку с помощью Py_INCREF. Существует также понятие заимствованной ссылки. Функция, заимствующая ссылку, не меняет счётчик ссылок объекта и не собирается сохранять её: объект используется временно. При вызове PyArg_ParseTuple или PyArg_UnpackTuple вы получаете заимствованные ссылки на объекты в кортеже и не должны менять их счётчики ссылок внутри своей функции. Правильное управление ссылками приходит с практикой, хотя поначалу оно может вызывать затруднения.

Функция Py_BuildValue — частый источник ошибок управления счётчиками ссылок. Обратите внимание на различие кодов формата ‘N’ и ‘O’. Если вы создаёте в подпрограмме новый объект, например выходной массив, и возвращаете его внутри кортежа результатов, то в Py_BuildValue, скорее всего, следует использовать ‘N’. Код ‘O’ увеличивает счётчик ссылок на 1, поэтому у совершенно нового массива останутся две ссылки. При удалении переменной счётчик уменьшится на 1, но лишняя ссылка останется, и память массива никогда не будет освобождена. Возникнет утечка памяти из-за неверного подсчёта ссылок. Код ‘N’ позволяет этого избежать: вызывающий код получит объект внутри кортежа с единственной учитываемой ссылкой.

Работа с объектами массивов#

Большинству модулей расширения NumPy нужен доступ к памяти ndarray или экземпляра его подкласса. Простейший способ не требует подробного знания внутреннего устройства NumPy. Он состоит в следующем:

  1. Убедитесь, что массив имеет нужный тип и число измерений, а его данные выровнены, хранятся в машинном порядке байтов и занимают один непрерывный сегмент памяти.

    1. Преобразовав его из какого-нибудь объекта Python с помощью PyArray_FromAny или построенного на нем макроса.

    2. Создать новый ndarray нужной формы и типа с помощью PyArray_NewFromDescr либо более простого макроса или функции на её основе.

  2. Получает форму массива и указатель на его данные.

  3. Передать данные и сведения о форме в подпрограмму или другой участок кода, выполняющий само вычисление.

  4. При написании алгоритма рекомендуется обращаться к элементам массива с учётом его шагов: макросы PyArray_GetPtr упрощают это. Тогда можно ослабить требования, не настаивая на односегментном массиве и избегая возможного копирования данных.

Каждая из этих подтем рассматривается в следующих подразделах.

Преобразование объекта произвольной последовательности #

Основная функция получения массива из преобразуемого в массив объекта Python — PyArray_FromAny. Она очень гибкая и имеет много аргументов. Несколько макросов упрощают её использование; для распространённых задач особенно полезен PyArray_FROM_OTF. Он преобразует произвольный объект Python в массив заданного встроенного типа данных — например, float — с указанными требованиями, например к непрерывности, выравниванию и возможности записи. Синтаксис:

PyArray_FROM_OTF

Возвращает ndarray, полученный из преобразуемого в массив объекта Python obj. Число измерений результата определяется объектом. Нужный тип данных задаётся в typenum одним из значений перечисления типов. Параметр requirements допускает комбинацию стандартных флагов массива. Аргументы подробнее описаны ниже. При успехе возвращается новая ссылка на массив; при неудаче возвращается NULL и устанавливается исключение.

obj

Допускается любой объект Python, преобразуемый в ndarray. Если это уже ndarray или экземпляр его подкласса, удовлетворяющий требованиям, возвращается новая ссылка на него. Иначе создаётся новый массив. Содержимое obj копируется в него, кроме случаев, когда интерфейс массива позволяет обойтись без копирования данных. В массив можно преобразовать: 1) любую вложенную последовательность; 2) любой объект, предоставляющий интерфейс массива; 3) любой объект с методом __array__, который должен возвращать ndarray; 4) любой скаляр, который становится нульмерным массивом. Экземпляры подклассов ndarray, удовлетворяющие требованиям, передаются без изменений. Чтобы гарантировать результат базового класса ndarray, включите NPY_ARRAY_ENSUREARRAY в флаги требований. Копия создаётся только при необходимости. Чтобы гарантировать копирование, включите NPY_ARRAY_ENSURECOPY в флаги требований.

typenum

Одно из значений перечисления типов либо NPY_NOTYPE, если тип данных нужно определить по самому объекту. Можно использовать имена типов C:

NPY_BOOL, NPY_BYTE, NPY_UBYTE, NPY_SHORT, NPY_USHORT, NPY_INT, NPY_UINT, NPY_LONG, NPY_ULONG, NPY_LONGLONG, NPY_ULONGLONG, NPY_DOUBLE, NPY_LONGDOUBLE, NPY_CFLOAT, NPY_CDOUBLE, NPY_CLONGDOUBLE, NPY_OBJECT.

Можно также использовать поддерживаемые платформой имена типов с явно указанной разрядностью. Например:

NPY_INT8, NPY_INT16, NPY_INT32, NPY_INT64, NPY_UINT8, NPY_UINT16, NPY_UINT32, NPY_UINT64, NPY_FLOAT32, NPY_FLOAT64, NPY_COMPLEX64, NPY_COMPLEX128.

Объект преобразуется к нужному типу только без потери точности. Иначе возвращается NULL и устанавливается ошибка. Чтобы изменить это поведение, добавьте NPY_ARRAY_FORCECAST к флагам требований.

requirements

Модель памяти ndarray допускает произвольный шаг по каждому измерению для перехода к следующему элементу массива. Однако часто нужно взаимодействовать с кодом, ожидающим непрерывного расположения данных в порядке C или Fortran. Кроме того, ndarray может быть не выровнен; в оригинале это поясняется как некратность адреса элемента размеру элемента. Разыменование указателя на данные такого массива может привести к аварийному завершению программы или как минимум замедлить её работу. Обе проблемы решаются преобразованием объекта Python в массив, удовлетворяющий требованиям конкретного применения. Примечание переводчика: требуемая кратность адреса определяется выравниванием типа dtype.alignment, которое не всегда совпадает с размером элемента itemsize. Например, complex128 может иметь размер 16 байт при требуемом выравнивании 8 байт.

Флаг requirements позволяет указать, какие массивы допустимы. Если переданный объект не удовлетворяет требованиям, создаётся копия, чтобы возвращаемый объект им соответствовал. Такие ndarray могут использовать указатель на произвольную область памяти. Этот флаг задаёт желаемые свойства возвращаемого объекта массива. Все флаги описаны в главе с подробным описанием API. Чаще всего требуются NPY_ARRAY_IN_ARRAY, NPY_ARRAY_OUT_ARRAY и NPY_ARRAY_INOUT_ARRAY:

NPY_ARRAY_IN_ARRAY

Этот флаг подходит для массивов, которым нужны непрерывное расположение в порядке C и выравнивание. Обычно это входные массивы алгоритма.

NPY_ARRAY_OUT_ARRAY

Этот флаг задаёт массив с данными, непрерывно расположенными в памяти в порядке C, с выравниванием и возможностью записи. Такой массив обычно используется как выходной, хотя выходные массивы чаще создаются с нуля.

NPY_ARRAY_INOUT_ARRAY

Этот флаг позволяет указать массив, используемый и для ввода, и для вывода. В конце интерфейсной процедуры необходимо вызвать PyArray_ResolveWritebackIfCopy перед Py_DECREF, чтобы записать временные данные обратно в исходный переданный массив. Флаг NPY_ARRAY_WRITEBACKIFCOPY требует, чтобы входной объект уже был массивом: другие объекты нельзя автоматически обновить таким способом. При ошибке вызовите PyArray_DiscardWritebackIfCopy (obj) для массива с этими флагами. Это разрешит запись в базовый массив, не копируя содержимое обратно в исходный массив.

Следующие полезные флаги можно добавить к требованиям побитовым ИЛИ:

NPY_ARRAY_FORCECAST

Привести к нужному типу, даже если это невозможно сделать без потери информации.

NPY_ARRAY_ENSURECOPY

Убедитесь, что полученный массив является копией оригинала.

NPY_ARRAY_ENSUREARRAY

Обеспечить, чтобы результат был именно ndarray, а не экземпляром его подкласса.

Примечание

Порядок байтов массива определяется его типом данных. PyArray_FROM_OTF всегда запрашивает массивы с родным порядком байтов, поэтому флаг NPY_ARRAY_NOTSWAPPED в аргументе требований не нужен. Получить с помощью этой функции массив с обратным порядком байтов также невозможно.

Создание нового ndarray с нуля#

Довольно часто новые массивы нужно создавать в коде модуля расширения. Например, нужен выходной массив, который вы не хотите требовать от вызывающего кода, или временный массив для промежуточных вычислений. В любом случае есть простые способы получить объект ndarray нужного типа данных. Самая универсальная функция для этого — PyArray_NewFromDescr. Через этот многократно используемый код проходят все функции создания массивов. Его гибкость может усложнять использование, поэтому предусмотрены более простые варианты. Они входят в семейство функций PyArray_SimpleNew и упрощают интерфейс за счёт стандартных значений для распространённых случаев.

Получение доступа к памяти ndarray и элементам ndarray #

Если obj — ndarray (PyArrayObject*), на его область данных указывает указатель void* PyArray_DATA (obj) или char* PyArray_BYTES (obj). Помните, что в общем случае эта область может быть не выровнена согласно типу данных, иметь несистемный порядок байтов и/или быть недоступна для записи. Если данные выровнены и имеют системный порядок байтов, доступ к конкретному элементу определяется только массивом переменных npy_intp PyArray_STRIDES (obj). Этот массив целых чисел C показывает, сколько байтов нужно прибавить к указателю текущего элемента, чтобы перейти к следующему элементу по каждому измерению. Для массивов с числом измерений меньше 4 предусмотрены макросы PyArray_GETPTR{k} (obj, …), где {k} — 1, 2, 3 или 4, упрощающие использование шагов массива. Аргументы … представляют собой {k} неотрицательных целочисленных индексов массива. Например, пусть E — трёхмерный ndarray. Указатель (void*) на элемент E[i,j,k] получают как PyArray_GETPTR3 (E, i, j, k).

Как объяснялось выше, непрерывным массивам в порядке C и Fortran соответствуют определённые шаги по осям. Флаги NPY_ARRAY_C_CONTIGUOUS и NPY_ARRAY_F_CONTIGUOUS показывают, соответствует ли расположение элементов одному из этих порядков; возможны оба флага или ни одного. Для проверок в оригинале приведены PyArray_IS_C_CONTIGUOUS(obj) и PyArray_ISFORTRAN(obj). Примечание переводчика: второй макрос проверяет F-непрерывность при отсутствии C-непрерывности. Для проверки самого флага F, включая массивы, непрерывные в обоих порядках, используйте PyArray_IS_F_CONTIGUOUS. Большинство сторонних библиотек ожидают непрерывные массивы, но поддержать произвольные шаги часто несложно. По возможности учитывайте шаги в собственном коде, оставляя требование единого непрерывного участка памяти для обёрток сторонних библиотек. Это сокращает копирование по сравнению с обязательным преобразованием в непрерывный массив.

Примеры #

В следующем примере показано, как можно написать оболочку, которая принимает два входных аргумента (которые будут преобразованы в массив) и выходной аргумент (который должен быть массивом). Функция возвращает None и обновляет выходной массив. Обратите внимание на обновленное использование семантики WRITEBACKIFCOPY для NumPy v1.14 и выше.

static PyObject *
example_wrapper(PyObject *dummy, PyObject *args)
{
    PyObject *arg1=NULL, *arg2=NULL, *out=NULL;
    PyObject *arr1=NULL, *arr2=NULL, *oarr=NULL;

    if (!PyArg_ParseTuple(args, "OOO!", &arg1, &arg2,
        &PyArray_Type, &out)) return NULL;

    arr1 = PyArray_FROM_OTF(arg1, NPY_DOUBLE, NPY_ARRAY_IN_ARRAY);
    if (arr1 == NULL) return NULL;
    arr2 = PyArray_FROM_OTF(arg2, NPY_DOUBLE, NPY_ARRAY_IN_ARRAY);
    if (arr2 == NULL) goto fail;
#if NPY_API_VERSION >= 0x0000000c
    oarr = PyArray_FROM_OTF(out, NPY_DOUBLE, NPY_ARRAY_INOUT_ARRAY2);
#else
    oarr = PyArray_FROM_OTF(out, NPY_DOUBLE, NPY_ARRAY_INOUT_ARRAY);
#endif
    if (oarr == NULL) goto fail;

    /* code that makes use of arguments */
    /* You will probably need at least
       nd = PyArray_NDIM(<..>)    -- number of dimensions
       dims = PyArray_DIMS(<..>)  -- npy_intp array of length nd
                                     showing length in each dim.
       dptr = (double *)PyArray_DATA(<..>) -- pointer to data.

       If an error occurs goto fail.
     */

    Py_DECREF(arr1);
    Py_DECREF(arr2);
#if NPY_API_VERSION >= 0x0000000c
    PyArray_ResolveWritebackIfCopy(oarr);
#endif
    Py_DECREF(oarr);
    Py_INCREF(Py_None);
    return Py_None;

 fail:
    Py_XDECREF(arr1);
    Py_XDECREF(arr2);
#if NPY_API_VERSION >= 0x0000000c
    PyArray_DiscardWritebackIfCopy(oarr);
#endif
    Py_XDECREF(oarr);
    return NULL;
}
Комментарии к примеру на русском
  • Код, использующий аргументы
  • Вероятно, понадобятся как минимум nd = PyArray_NDIM(<..>) — число измерений; dims = PyArray_DIMS(<..>) — массив npy_intp длины nd с размерами измерений; dptr = (double *)PyArray_DATA(<..>) — указатель на данные. При ошибке выполняется goto fail.
