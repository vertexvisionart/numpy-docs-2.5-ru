Использование Python для связывания компонентов#

Предупреждение

Этот текст написан в 2008 году для первоначальной книги Трэвиса Э. Олифанта Guide to NumPy и устарел.

Нет более скучного разговора, чем тот, в котором все
согласен.
— Мишель де Монтень
Клейкая лента похожа на Силу. У неё есть светлая сторона, тёмная сторона, и
Он держит Вселенную вместе.
— Carl Zwanzig

Python часто называют замечательным языком для объединения компонентов. Надеемся, эта глава убедит вас в справедливости такой оценки. Первые пользователи Python в науке обычно связывали с его помощью крупные прикладные программы, работавшие на суперкомпьютерах. Писать на Python было гораздо удобнее, чем сценарии оболочки или код на Perl. Кроме того, простота расширения Python позволяла сравнительно легко создавать новые классы и типы, приспособленные к конкретным задачам. Благодаря совместной работе этих первых участников появился Numeric — объект, подобный массиву, который можно было использовать для передачи данных между такими приложениями.

По мере развития Numeric и его превращения в NumPy стало возможным писать больше кода непосредственно с помощью NumPy. Зачастую этот код достаточно быстр для практического применения, однако иногда всё же требуется обращаться к скомпилированному коду: чтобы добиться максимальной эффективности алгоритма или упростить использование распространённых программ на C/C++ или Fortran.

В этой главе рассматриваются многие инструменты для обращения к коду на других компилируемых языках. Существует много материалов о вызове скомпилированных библиотек из Python, и эта глава не ставит целью сделать вас экспертом. Её основная задача — познакомить с некоторыми возможностями, чтобы вы знали, что искать в Google для дальнейшего изучения.

Вызов других скомпилированных библиотек из Python#

Python — удобный язык, на котором приятно писать, но его динамическая природа создаёт накладные расходы. Из-за них некоторые вычисления (то есть непосредственные вычисления внутри циклов for) могут быть в 10–100 раз медленнее эквивалентного кода на статическом компилируемом языке. Расход памяти также может быть избыточным из-за создания и удаления временных массивов. Во многих вычислительных задачах такое замедление и потребление памяти неприемлемы, по крайней мере в критических участках кода. Поэтому часто требуется вызывать из Python быструю подпрограмму в машинном коде, например скомпилированную из C/C++ или Fortran. Относительная простота таких вызовов — одна из основных причин, по которым Python хорошо подходит как высокоуровневый язык научного и инженерного программирования.

Есть два основных способа вызвать скомпилированный код: написать модуль расширения и импортировать его в Python инструкцией import либо вызвать подпрограмму разделяемой библиотеки напрямую из Python через модуль ctypes. Наиболее распространён первый способ.

Предупреждение

Неосторожный вызов кода C из Python может привести к аварийному завершению Python. Ни один из подходов в этой главе не исключает такой риск. Необходимо понимать, как данные обрабатываются и в NumPy, и в используемой сторонней библиотеке.

Обёртки, написанные вручную#

Модули расширения рассмотрены в разделе Написание модуля расширения. Самый простой способ взаимодействия со скомпилированным кодом — написать модуль расширения с методом, вызывающим этот код. Для удобства чтения кода метод должен использовать PyArg_ParseTuple для преобразования объектов Python в типы данных C. Для стандартных типов C, скорее всего, уже существует встроенный преобразователь. Для остальных может потребоваться собственный преобразователь и строка формата "O&": она позволяет указать функцию, преобразующую объект Python в нужные структуры C.

После преобразования в соответствующие структуры и типы данных C обёртка вызывает базовую функцию. Для функции на C или C++ это просто. Однако для вызова кода Fortran нужно знать, как ваш компилятор и платформа вызывают подпрограммы Fortran из C/C++. Это несколько различается между платформами и компиляторами (ещё одна причина, по которой f2py значительно упрощает взаимодействие с Fortran), но обычно включает добавление подчёркивания к имени и передачу всех переменных по ссылке, то есть все аргументы являются указателями.

Написанная вручную обёртка даёт полный контроль над использованием и вызовом библиотеки C, что позволяет сделать компактный интерфейс с минимальными накладными расходами. Недостаток — необходимость писать, отлаживать и сопровождать код C, хотя большую его часть можно адаптировать из других модулей расширения проверенным способом: скопировать и изменить. Поскольку вызовы дополнительного кода C устроены довольно однотипно, разработаны средства генерации, упрощающие этот процесс. Одно из них поставляется с NumPy и легко интегрирует Fortran и простой код C. Этот пакет, f2py, кратко рассматривается в следующем разделе.

F2PY#

F2PY позволяет автоматически создать модуль расширения для вызова подпрограмм на Fortran 77/90/95. Он умеет разбирать код Fortran 77/90/95 и автоматически генерировать сигнатуры Python для найденных подпрограмм. Также можно самостоятельно задать их интерфейс с Python, создав файл определения интерфейса или изменив файл, сгенерированный f2py.

Подробнее и примеры см. в документации F2PY.

Связывание скомпилированного кода через f2py сейчас наиболее развито и тесно интегрировано. Этот подход чётко отделяет Python от скомпилированного кода, позволяя распространять модуль расширения отдельно. Единственный недостаток — для установки кода пользователю нужен компилятор Fortran. Однако наличие свободных g77, gfortran и g95, а также качественных коммерческих компиляторов делает это ограничение необременительным. По нашему мнению, Fortran всё ещё проще всего подходит для быстрого и понятного кода научных вычислений. Он наиболее непосредственно поддерживает комплексные числа и многомерную индексацию. Однако некоторые компиляторы Fortran не оптимизируют код так же хорошо, как качественный код C, написанный вручную.

Cython#

Cython — компилятор диалекта Python с необязательной статической типизацией для ускорения работы и возможностью включать код C или C++ в модули. Он генерирует расширения на C или C++, которые можно скомпилировать и импортировать в Python.

Cython хорошо подходит для модуля расширения, который будет содержать значительный объём вашего собственного алгоритмического кода. Среди его возможностей — удобная и быстрая работа с многомерными массивами.

Cython только генерирует модули расширения. В отличие от f2py, он не предоставляет автоматических средств для их компиляции и компоновки. Однако многие инструменты сборки Python поддерживают Cython.

Ниже показана настройка проекта Python с расширением Cython. В примере используются бэкенд сборки Python meson-python и система сборки Meson. Эту же систему сборки использует сам NumPy.

Сначала создайте файл под названием my_extension.pyx.

cimport numpy as np

def say_hello():
    print("Hello!")

Этот файл находится рядом с файлом __init__.py со следующим содержимым:

from .my_extension import say_hello

Теперь вам нужно создать еще два файла, чтобы настроить систему сборки. Во-первых, файл meson.build:

project(
   'module_with_extension',
   'c', 'cython',
   version: '0.0.1',
   license: 'MIT',
)

cython = find_program('cython')
py = import('python').find_installation(pure: false)

numpy_nodepr_api = ['-DNPY_NO_DEPRECATED_API=NPY_2_0_API_VERSION']

np_dep = declare_dependency(dependencies: dependency('numpy'),
                            compile_args: numpy_nodepr_api)

py.extension_module(
  'my_extension',
  'my_extension.pyx',
  dependencies: [np_dep],
  install: true,
  subdir: 'my_module_with_extension',
)

py.install_sources(
  '__init__.py',
  subdir: 'my_module_with_extension',
)

А также файл pyproject.toml со следующим содержимым:

[build-system]
build-backend = "mesonpy"
requires = [
    "meson-python",
    "Cython>=3.0.0",
    "numpy",
]

[project]
name = "my_module_with_extension"
version = "0.0.1"
license = "MIT"
dependencies = ["numpy"]

Затем вы можете выполнить следующую команду для создания, установки и вызова функции, определенной в расширении от Python:

$ pip install .
$ python -c "from my_module_with_extension import say_hello; say_hello()"
"Hello!"

Добавление зависимости NumPy в вашу конфигурацию Meson необходимо только в том случае, если вы используете C API NumPy в модуле расширения через cimport numpy (мы предполагаем, что для этого вы используете Cython). Если вы просто используете Cython для компиляции стандартного модуля Python, вы получите модуль расширения C, который обычно работает немного быстрее, чем эквивалентный модуль Python. Дальнейшего увеличения скорости можно добиться, используя ключевое слово cdef для статического определения переменных C.

Подробнее о сборке более сложных расширений см. в документации Meson и meson-python.

Давайте рассмотрим два примера, которые мы видели раньше, чтобы увидеть, как они могут быть реализованы с помощью Cython.

Комплексное сложение в Cython #

Ниже приведена часть модуля Cython add.pyx, реализующего функции сложения комплексных чисел, ранее реализованные с помощью f2py:

cimport cython
cimport numpy as np
import numpy as np

# We need to initialize NumPy.
np.import_array()

#@cython.boundscheck(False)
def zadd(in1, in2):
    cdef double complex[:] a = in1.ravel()
    cdef double complex[:] b = in2.ravel()

    out = np.empty(a.shape[0], np.complex64)
    cdef double complex[:] c = out.ravel()

    for i in range(c.shape[0]):
        c[i].real = a[i].real + b[i].real
        c[i].imag = a[i].imag + b[i].imag

    return out
Комментарии к примеру на русском
  • Нужно инициализировать NumPy.
  • @cython.boundscheck(False)

В этом модуле оператор cimport загружает определения из файла numpy.pxd, поставляемого с Cython. Кажется, будто NumPy импортируется дважды, но роли разные: cimport лишь делает доступным C API NumPy, а обычный import выполняет импорт Python во время работы программы и позволяет обращаться к привычному Python API NumPy.

Пример также показывает типизированные представления памяти Cython (typed memoryviews). На уровне C они похожи на массивы NumPy: хранят форму и шаги и знают свои размеры, в отличие от массива C, доступного через обычный указатель. Запись double complex[:] обозначает одномерный массив (вектор) double с произвольными шагами. Непрерывно расположенный в памяти массив int обозначается int[::1], а матрица float — float[:, :]. Примечание переводчика: в первой записи указан double complex, то есть комплексный тип двойной точности.

В закомментированном виде показан декоратор cython.boundscheck, включающий или отключающий проверку границ при доступе к представлениям памяти для отдельной функции. Его можно использовать для дополнительного ускорения кода, пожертвовав безопасностью или выполнив проверку вручную перед входом в цикл.

За исключением синтаксиса представлений, функция сразу понятна программисту Python. Статический тип переменной i выводится неявно. Вместо синтаксиса представлений можно было бы использовать специальный синтаксис массивов NumPy в Cython, но представления предпочтительнее.

Фильтр изображений на Cython#

Двумерный пример, который мы создали с помощью Fortran, так же легко написать на Cython:

cimport numpy as np
import numpy as np

np.import_array()

def filter(img):
    cdef double[:, :] a = np.asarray(img, dtype=np.double)
    out = np.zeros(img.shape, dtype=np.double)
    cdef double[:, ::1] b = out

    cdef np.npy_intp i, j

    for i in range(1, a.shape[0] - 1):
        for j in range(1, a.shape[1] - 1):
            b[i, j] = (a[i, j]
                       + .5 * (  a[i-1, j] + a[i+1, j]
                               + a[i, j-1] + a[i, j+1])
                       + .25 * (  a[i-1, j-1] + a[i-1, j+1]
                                + a[i+1, j-1] + a[i+1, j+1]))

    return out

Этот двумерный усредняющий фильтр работает быстро, поскольку цикл выполняется на C, а вычисления с указателями — только по мере необходимости. Если приведённый выше код скомпилировать в модуль image, двумерное изображение img можно быстро отфильтровать так:

import image
out = image.filter(img)

В коде важны два момента. Во-первых, представление памяти нельзя вернуть в Python. Поэтому сначала создаётся массив NumPy out, а для вычислений используется его представление b. Во-вторых, b имеет тип double[:, ::1]: двумерный массив с непрерывными строками, то есть с порядком C. Явное указание порядка может ускорить некоторые алгоритмы, позволяя не вычислять шаги.

Заключение#

Cython используют для расширений многие научные библиотеки Python, включая SciPy, pandas, SageMath, scikit-image и scikit-learn, а также библиотека обработки XML lxml. Язык и компилятор активно сопровождаются.

Есть несколько недостатков использования Cython:

  1. Для написания собственных алгоритмов, а иногда и обёрток над существующими библиотеками C нужно некоторое знание C. В частности, при управлении памятью средствами C, такими как malloc и аналогичные функции, легко допустить утечку памяти. Однако даже простая компиляция модуля Python, переименованного в .pyx, может ускорить его работу, а добавление нескольких объявлений типов иногда даёт существенное ускорение.

  2. Чёткую границу между Python и C легко потерять; тогда повторно использовать код C в проектах, не связанных с Python, становится сложнее.

  3. C-код, сгенерированный Cython, трудно читать и модифицировать (и обычно он компилируется с раздражающими, но безобидными предупреждениями).

Важное преимущество расширений, созданных Cython, — простота распространения. Cython подходит и для связывания с кодом C, и для быстрого создания расширений. Он особенно полезен тем, кто не умеет или не хочет писать код на C или Fortran.

ctypes#

ctypes — модуль расширения Python из стандартной библиотеки, позволяющий вызывать произвольные функции из разделяемых библиотек непосредственно из Python. Так можно напрямую взаимодействовать с кодом C, что открывает доступ к огромному числу библиотек. Недостаток этого подхода в том, что ошибки в коде легко приводят к серьёзным сбоям программы, как и в C: типы параметров и допустимые границы почти не проверяются. Это особенно важно, когда данные массива передаются как указатель на область памяти. В таком случае вы отвечаете за то, чтобы подпрограмма не обращалась к памяти за пределами массива. Если этот риск вас не смущает, ctypes может стать эффективным средством для быстрого использования большой разделяемой библиотеки или расширения возможностей собственной библиотеки.

Поскольку ctypes предоставляет прямой низкоуровневый доступ к скомпилированному коду, ошибки пользователя не всегда обрабатываются безопасно. Для надёжного использования обычно нужен дополнительный слой Python, проверяющий типы данных и границы массивов перед передачей объектов в подпрограмму. Эти проверки, а также преобразования объектов ctypes в типы C, выполняемые самим ctypes, делают интерфейс медленнее написанного вручную расширения. Однако если функция C выполняет существенный объём работы, накладные расходы обычно незначительны. Для сильного программиста Python с небольшим опытом C ctypes — простой способ создать полезный интерфейс к скомпилированной разделяемой библиотеке.

Чтобы использовать ctypes, вы должны

  1. Иметь разделяемую библиотеку.

  2. Загрузить разделяемую библиотеку.

  3. Преобразовать объекты Python в аргументы, понятные ctypes.

  4. Вызовите функцию библиотеки с аргументами ctypes.

Наличие разделяемой библиотеки#

Требования к разделяемым библиотекам, используемым через ctypes, зависят от платформы. Предполагается, что вы умеете создавать такую библиотеку в своей системе или уже располагаете готовой. Важно помнить следующее:

  • Разделяемую библиотеку нужно компилировать особым образом (например, с флагом -shared в gcc).

  • На некоторых платформах (например Windows) разделяемой библиотеке нужен файл .def со списком экспортируемых функций. Например, mylib.def может содержать:

    LIBRARY mylib.dll
EXPORTS
cool_function1
cool_function2

    В качестве альтернативы, вы можете использовать спецификатор класса хранения __declspec(dllexport) в C-определении функции, чтобы избежать необходимости в этом файле .def.

В distutils Python нет стандартного переносимого способа создать обычную разделяемую библиотеку (модуль расширения — особая разделяемая библиотека, понятная Python). Поэтому на момент написания книги существенный недостаток ctypes — сложность переносимого распространения расширения Python, которое использует ctypes и содержит собственный код, требующий компиляции в разделяемую библиотеку на компьютере пользователя.

Загрузка разделяемой библиотеки#

Простой и надёжный способ загрузить разделяемую библиотеку — получить её абсолютный путь и загрузить её с помощью объекта cdll из ctypes:

lib = ctypes.cdll[<full_path_name>]

Однако в Windows обращение к атрибуту cdll загружает первую DLL с таким именем, найденную в текущем каталоге или в PATH. Для кроссплатформенной загрузки библиотеки по абсолютному пути нужны дополнительные меры, поскольку расширения разделяемых библиотек различаются. Утилита ctypes.util.find_library может упростить поиск загружаемой библиотеки, но не гарантирует успеха во всех случаях. Дополнительная сложность в том, что на разных платформах используются разные стандартные расширения разделяемых библиотек: например, .dll в Windows, .so в Linux и .dylib в Mac OS X. Это тоже необходимо учитывать, если вы создаёте с помощью ctypes обёртку для кода, который должен работать на нескольких платформах.

NumPy предоставляет вспомогательную функцию ctypeslib.load_library(name, path). Она принимает имя разделяемой библиотеки (включая префикс вроде «lib», но без расширения) и путь, по которому её следует искать. Функция возвращает объект библиотеки ctypes; если библиотека не найдена, вызывает OSError, а если модуль ctypes недоступен — ImportError. Пользователям Windows: load_library всегда загружает объект библиотеки ctypes с соглашением о вызовах cdecl. О загрузке библиотек с другими соглашениями см. документацию ctypes для ctypes.windll и/или ctypes.oledll.

Функции разделяемой библиотеки доступны как атрибуты объекта библиотеки ctypes, возвращённого ctypeslib.load_library, либо через синтаксис lib['func_name']. Второй вариант особенно полезен, если имя функции содержит символы, недопустимые в именах переменных Python.

Преобразование аргументов#

Объекты Python типов int/long, строки и Unicode-строки автоматически преобразуются по мере необходимости в эквивалентные аргументы ctypes. Объект None также автоматически преобразуется в указатель NULL. Все остальные объекты Python необходимо преобразовать в специальные типы ctypes. Есть два способа обойти это ограничение, позволяющих ctypes взаимодействовать с другими объектами.

  1. Не задавайте атрибут argtypes объекта функции; вместо этого определите метод _as_parameter_ у передаваемого объекта. Метод _as_parameter_ должен возвращать int Python, который будет передан функции напрямую.

  2. Присвойте атрибуту argtypes список объектов, у каждого из которых есть метод класса from_param. Этот метод должен уметь преобразовать ваш объект в то, что понимает ctypes: целое int/long, строку, unicode или объект с атрибутом _as_parameter_. Обозначения int/long и unicode здесь отражают терминологию исторического примера.

NumPy использует оба способа, предпочитая второй как потенциально более безопасный. Атрибут ctypes массива ndarray возвращает объект с атрибутом _as_parameter_, который, согласно оригиналу, возвращает целое число с адресом связанного ndarray. Поэтому объект ctypes можно непосредственно передать функции, ожидающей указатель на данные ndarray. Вызывающий код должен проверить тип, форму и флаги массива: передача указателя на неподходящие данные может привести к тяжёлым сбоям. Примечание переводчика: в современных версиях NumPy _as_parameter_ возвращает объект ctypes.c_void_p с адресом данных массива; само целое значение адреса доступно через его атрибут value.

Для реализации второго способа NumPy предоставляет функцию — фабрику классов ndpointer в модуле numpy.ctypeslib. Она создаёт подходящий класс, который можно включить в атрибут argtypes функции ctypes. Класс содержит метод from_param, с помощью которого ctypes преобразует переданный ndarray в понятный ей объект. При преобразовании проверяются свойства ndarray, указанные пользователем при вызове ndpointer: тип данных, число измерений, форма и/или состояние флагов переданного массива. Метод from_param возвращает атрибут ctypes массива. Поскольку он содержит атрибут _as_parameter_, указывающий на область данных массива, ctypes может использовать его напрямую.

У атрибута ctypes объекта ndarray есть дополнительные атрибуты, удобные для передачи сведений о массиве в функцию ctypes. Атрибуты data, shape и strides предоставляют совместимые с ctypes объекты, соответствующие области данных, форме и шагам массива. Атрибут data возвращает c_void_p — указатель на область данных. Атрибуты shape и strides возвращают массивы целых чисел ctypes (либо None, представляющее указатель NULL, для нульмерного массива). Базовый тип такого массива — целочисленный тип ctypes, размер которого совпадает с размером указателя на данной платформе. Также доступны методы data_as({ctype}), shape_as(<base ctype>) и strides_as(<base ctype>). Они возвращают данные в виде объекта ctypes выбранного типа, а массивы формы и шагов — с выбранным базовым типом. Для удобства модуль ctypeslib содержит c_intp — целочисленный тип данных ctypes, размер которого совпадает с размером c_void_p на данной платформе (если ctypes не установлен, его значение равно None).

Вызов функции#

К функции загруженной разделяемой библиотеки можно обратиться как к атрибуту или элементу. Например, если ./mylib.so содержит функцию cool_function1, доступны следующие способы:

lib = numpy.ctypeslib.load_library('mylib','.')
func1 = lib.cool_function1  # or equivalently
func1 = lib['cool_function1']
Комментарии к примеру на русском
  • Или, что эквивалентно,

В ctypes возвращаемое значение функции по умолчанию имеет тип int. Это можно изменить, задав атрибут restype функции. Если функция ничего не возвращает (void), установите restype в None:

func1.restype = None

Как обсуждалось выше, можно задать атрибут argtypes функции, чтобы ctypes проверяла типы входных аргументов при вызове. Фабричная функция ndpointer создаёт готовый класс для проверки типа данных, формы и флагов в новой функции. Сигнатура ndpointer:

ndpointer(dtype=None, ndim=None, shape=None, flags=None)#

Именованные аргументы со значением None не проверяются. Задание аргумента включает проверку соответствующего свойства ndarray при преобразовании в объект, совместимый с ctypes. dtype может быть любым объектом, интерпретируемым как тип данных. ndim должен быть целым числом, а shape — целым числом или последовательностью целых чисел. flags задаёт минимальный набор флагов для любого передаваемого массива. Его можно указать строкой требований, разделённых запятыми; целым числом, объединяющим биты требований операцией ИЛИ; либо объектом flags, полученным из атрибута flags массива с нужными свойствами.

Использование класса ndpointer в argtypes значительно повышает безопасность вызова функции C через ctypes с областью данных ndarray. Для удобства можно добавить ещё одну обёртку на Python, скрыв очевидные аргументы и сделав некоторые из них выходными. При этом функция NumPy requires может помочь получить массив нужного вида из заданных входных данных.

Полный пример#

В этом примере мы продемонстрируем, как функция сложения и функция фильтра, реализованные ранее с использованием других подходов, могут быть реализованы с использованием ctypes. Во-первых, код C, реализующий алгоритмы, содержит функции zadd, dadd, sadd, cadd и dfilter2d. Функция zadd:

/* Add arrays of contiguous data */
typedef struct {double real; double imag;} cdouble;
typedef struct {float real; float imag;} cfloat;
void zadd(cdouble *a, cdouble *b, cdouble *c, long n)
{
    while (n--) {
        c->real = a->real + b->real;
        c->imag = a->imag + b->imag;
        a++; b++; c++;
    }
}
Комментарии к примеру на русском
  • Складываем массивы непрерывно расположенных данных

с аналогичным кодом для cadd, dadd и sadd, обрабатывающим соответственно типы данных complex float, double и float:

void cadd(cfloat *a, cfloat *b, cfloat *c, long n)
{
        while (n--) {
                c->real = a->real + b->real;
                c->imag = a->imag + b->imag;
                a++; b++; c++;
        }
}
void dadd(double *a, double *b, double *c, long n)
{
        while (n--) {
                *c++ = *a++ + *b++;
        }
}
void sadd(float *a, float *b, float *c, long n)
{
        while (n--) {
                *c++ = *a++ + *b++;
        }
}

Файл code.c также содержит функцию dfilter2d :

/*
 * Assumes b is contiguous and has strides that are multiples of
 * sizeof(double)
 */
void
dfilter2d(double *a, double *b, ssize_t *astrides, ssize_t *dims)
{
    ssize_t i, j, M, N, S0, S1;
    ssize_t r, c, rm1, rp1, cp1, cm1;

    M = dims[0]; N = dims[1];
    S0 = astrides[0]/sizeof(double);
    S1 = astrides[1]/sizeof(double);
    for (i = 1; i < M - 1; i++) {
        r = i*S0;
        rp1 = r + S0;
        rm1 = r - S0;
        for (j = 1; j < N - 1; j++) {
            c = j*S1;
            cp1 = j + S1;
            cm1 = j - S1;
            b[i*N + j] = a[r + c] +
                (a[rp1 + c] + a[rm1 + c] +
                 a[r + cp1] + a[r + cm1])*0.5 +
                (a[rp1 + cp1] + a[rp1 + cm1] +
                 a[rm1 + cp1] + a[rm1 + cp1])*0.25;
        }
    }
}
Комментарии к примеру на русском
  • Предполагается, что b непрерывно расположен в памяти, а его шаги кратны sizeof(double)

Возможное преимущество этого кода перед эквивалентом на Fortran — поддержка произвольных шагов, то есть массивов с данными, расположенными в памяти не непрерывно. Он также может работать быстрее в зависимости от возможностей оптимизации компилятора. Однако он явно сложнее простого кода в filter.f. Его нужно скомпилировать в разделяемую библиотеку. В моей системе Linux это делается так:

gcc -o code.so -shared code.c

В текущем каталоге будет создана разделяемая библиотека code.so. В Windows не забудьте добавить __declspec(dllexport) перед void в строке определения каждой функции либо создать файл code.def с именами экспортируемых функций.

Создадим интерфейс Python для этой разделяемой библиотеки. Для этого создайте файл interface.py со следующими строками в начале:

__all__ = ['add', 'filter2d']

import numpy as np
import os

_path = os.path.dirname('__file__')
lib = np.ctypeslib.load_library('code', _path)
_typedict = {'zadd' : complex, 'sadd' : np.single,
             'cadd' : np.csingle, 'dadd' : float}
for name in _typedict.keys():
    val = getattr(lib, name)
    val.restype = None
    _type = _typedict[name]
    val.argtypes = [np.ctypeslib.ndpointer(_type,
                      flags='aligned, contiguous'),
                    np.ctypeslib.ndpointer(_type,
                      flags='aligned, contiguous'),
                    np.ctypeslib.ndpointer(_type,
                      flags='aligned, contiguous,'\
                            'writeable'),
                    np.ctypeslib.c_intp]

Этот код загружает разделяемую библиотеку с именем code.{ext} из каталога, в котором находится этот файл. Затем для функций библиотеки задаётся тип возвращаемого значения void и добавляется проверка аргументов. Это позволяет передавать ndarray в качестве первых трёх аргументов, а четвёртым — целое число достаточной разрядности для хранения указателя на данной платформе.

Аналогичным образом настраивается функция фильтрации: её первые два аргумента — ndarray, а последние два — указатели на целые числа достаточной разрядности для представления шагов и формы ndarray:

lib.dfilter2d.restype=None
lib.dfilter2d.argtypes = [np.ctypeslib.ndpointer(float, ndim=2,
                                       flags='aligned'),
                          np.ctypeslib.ndpointer(float, ndim=2,
                                 flags='aligned, contiguous,'\
                                       'writeable'),
                          ctypes.POINTER(np.ctypeslib.c_intp),
                          ctypes.POINTER(np.ctypeslib.c_intp)]

Затем определите простую функцию, выбирающую по типу данных нужную функцию сложения в разделяемой библиотеке:

def select(dtype):
    if dtype.char in ['?bBhHf']:
        return lib.sadd, single
    elif dtype.char in ['F']:
        return lib.cadd, csingle
    elif dtype.char in ['DG']:
        return lib.zadd, complex
    else:
        return lib.dadd, float
    return func, ntype

Наконец, две функции, экспортируемые интерфейсом, могут быть записаны просто:

def add(a, b):
    requires = ['CONTIGUOUS', 'ALIGNED']
    a = np.asanyarray(a)
    func, dtype = select(a.dtype)
    a = np.require(a, dtype, requires)
    b = np.require(b, dtype, requires)
    c = np.empty_like(a)
    func(a,b,c,a.size)
    return c

и:

def filter2d(a):
    a = np.require(a, float, ['ALIGNED'])
    b = np.zeros_like(a)
    lib.dfilter2d(a, b, a.ctypes.strides, a.ctypes.shape)
    return b

Заключение#

ctypes — мощное средство связи Python с произвольным кодом C. Его преимущества при расширении Python:

  • чёткое разделение кода C и кода Python

  • Не нужно изучать новый синтаксис помимо Python и C.

  • Позволяет повторно использовать код C

  • Возможности разделяемых библиотек, написанных для других задач, можно использовать, найдя библиотеку и создав простую обёртку Python.

  • Удобная интеграция с NumPy через атрибут ctypes.

  • полная проверка аргументов с помощью фабрики классов ndpointer

К его недостаткам относятся

  • Модуль расширения, использующий ctypes, трудно распространять из-за отсутствия в distutils поддержки сборки разделяемых библиотек.

  • Код должен быть собран в виде разделяемых библиотек; статические библиотеки не подходят.

  • Очень слабая поддержка кода C++ и различных соглашений о вызове библиотек. Вероятно, вам понадобится оболочка C для кода C++ для использования с ctypes (или вместо этого просто используйте Boost.Python).

Поскольку распространять модуль расширения, созданный с ctypes, сложно, f2py и Cython по-прежнему остаются самыми простыми способами расширить Python при создании пакетов. Однако в некоторых случаях ctypes — полезная альтернатива. Это должно расширить возможности ctypes и устранить сложности разработки и распространения расширений Python с её помощью.

Другие полезные инструменты#

Эти инструменты оказались полезны другим пользователям Python, поэтому включены сюда. Они рассмотрены отдельно, поскольку либо представляют старые способы решения задач, теперь выполняемых f2py, Cython или ctypes (SWIG, PyFort), либо недостаточно документированы (SIP, Boost). Ссылки не приведены: актуальные легко найти через Google или другую поисковую систему, а здесь они быстро устарели бы. Само включение в список не означает рекомендации пакета. Мы собрали сведения, поскольку многим эти инструменты помогли и мы хотим дать вам как можно больше вариантов интеграции вашего кода.

SWIG#

Simplified Wrapper and Interface Generator (SWIG) — давно существующее и достаточно стабильное средство создания обёрток библиотек C/C++ для множества других языков. Оно не поддерживает массивы NumPy напрямую, но может работать с ними через правила преобразования типов (typemap). Примеры таких правил находятся в файле numpy.i каталога numpy/tools/swig вместе с примером использующего их модуля. SWIG хорошо подходит для больших библиотек C/C++: он способен почти полностью разобрать их заголовки и автоматически создать интерфейс. Формально требуется файл .i с описанием интерфейса, но часто файл .i может состоять из частей самого заголовка. Обычно интерфейс нужно немного доработать, чтобы им было удобно пользоваться. Способность разбирать заголовки C/C++ и автоматически создавать интерфейс делает SWIG полезным средством расширения Python кодом C/C++, несмотря на появление других способов, более ориентированных на Python. SWIG может создавать расширения для нескольких языков, но typemap обычно привязаны к конкретному языку. Тем не менее, изменив правила для Python, можно использовать SWIG для доступа к библиотеке из других языков, например Perl, Tcl и Ruby.

Мой опыт работы с SWIG в целом положительный: этот инструмент относительно прост и достаточно мощен. Я часто использовал его, пока не освоил написание расширений на C. Однако создавать собственные интерфейсы с SWIG нередко сложно: для этого нужны отображения типов (typemaps), которые не привязаны к Python и записываются в синтаксисе, похожем на C. Поэтому я предпочитаю другие способы связывания и, вероятно, рассматривал бы SWIG только для создания обёртки над очень большой библиотекой C/C++. Тем не менее многие вполне довольны работой с SWIG.

SIP#

SIP — ещё один инструмент для создания обёрток над библиотеками C/C++, предназначенный специально для Python и, по-видимому, хорошо поддерживающий C++. Компания Riverbank Computing разработала SIP для создания привязок Python к библиотеке QT. Для генерации привязок нужно написать файл интерфейса, во многом похожий на заголовочный файл C/C++. SIP не является полноценным синтаксическим анализатором C++, но понимает значительную часть его синтаксиса, а также собственные специальные директивы, управляющие созданием привязок Python. Он также позволяет задавать соответствия между типами Python и структурами и классами C/C++.

Boost Python#

Boost — набор библиотек C++. Одна из них, Boost.Python, предоставляет компактный интерфейс для доступа к классам и функциям C++ из Python. Её особенность в том, что она целиком работает на чистом C++, не вводя нового синтаксиса. Многие разработчики C++ отмечают, что Boost.Python позволяет удобно сочетать сильные стороны обоих языков. Для обёрток простых подпрограмм C Boost обычно избыточен: его основная задача — сделать классы C++ доступными в Python. Поэтому, если нужно аккуратно интегрировать набор классов C++ в Python, стоит изучить Boost.Python.

Pyfort #

Pyfort — удобный инструмент для создания Python-обёрток над Fortran и кодом C, написанным в стиле Fortran, с поддержкой массивов Numeric. Его автор — Paul Dubois, известный специалист по информатике и первый сопровождающий Numeric, ныне отошедший от этой работы. Мы упоминаем Pyfort в надежде, что кто-нибудь добавит в него поддержку массивов NumPy, которые теперь могут быть непрерывно расположены в памяти как в порядке Fortran, так и в порядке C.
