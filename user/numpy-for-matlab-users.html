NumPy Для пользователей MATLAB #

Введение#

MATLAB® и NumPy имеют много общего, но NumPy был создан для работы с Python, а не для того, чтобы быть клоном MATLAB. Это руководство поможет пользователям MATLAB начать работу с NumPy.

Основные отличия #

В MATLAB базовый тип, даже для скаляров, — многомерный массив. При присваивании массивы сохраняются как двумерные массивы чисел с плавающей точкой двойной точности, если число измерений и тип не заданы явно. Операции над такими двумерными массивами соответствуют матричным операциям линейной алгебры.

В NumPy основной тип — многомерный array. Массивы NumPy обычно хранятся как N-мерные массивы с минимальным типом, достаточным для представления объектов последовательности, если число измерений и тип не заданы явно. NumPy выполняет операции поэлементно: умножение двумерных массивов через * — поэлементное, а не матричное. Для обычного матричного умножения можно использовать оператор @, доступный с Python 3.5.

В MATLAB индексы начинаются с 1: a(1) — первый элемент. См. примечание «Индексация» (INDEXING).

NumPy, как и Python, нумерует индексы с 0; a[0] — первый элемент.

Скриптовый язык MATLAB создавался для линейной алгебры, поэтому синтаксис некоторых операций с массивами компактнее, чем в NumPy. При этом API для графических интерфейсов и полноценных приложений добавлялся уже как дополнение к исходным возможностям.

NumPy основан на Python, языке общего назначения. Одно из преимуществ NumPy — доступ к библиотекам Python, включая SciPy, Matplotlib, Pandas, OpenCV и другим. Кроме того, Python часто встраивается в другие программы как язык сценариев, что позволяет использовать в них и NumPy.

Срезы массивов MATLAB используют семантику передачи по значению с отложенным копированием при записи: копии создаются лишь по необходимости. Операции среза копируют части массива.

Срезы массивов NumPy используют передачу по ссылке: аргументы не копируются. Результаты операций взятия среза представляют собой представления массива.

Примечания#

Подматрица: присваивать значения подматрице можно с помощью списков индексов и команды ix_. Например, для двумерного массива a: ind=[1, 3]; a[np.ix_(ind, ind)] += 100.

СПРАВКА: прямого аналога MATLAB-команды which нет, но help обычно показывает имя файла функции. В Python также есть модуль inspect (выполните import inspect) с функцией getfile, которая часто помогает.

ИНДЕКСИРОВАНИЕ: в MATLAB индексы начинаются с единицы, поэтому первый элемент последовательности имеет индекс 1. В Python индексы начинаются с нуля, поэтому первый элемент имеет индекс 0. У обоих подходов есть достоинства и недостатки, что порождает путаницу и жаркие споры. Индексирование с единицы соответствует обычной речи: «первый» элемент последовательности имеет индекс 1. Индексирование с нуля упрощает работу с индексами. См. также текст профессора Эдсгера В. Дейкстры.

ДИАПАЗОНЫ: в MATLAB 0:5 может служить и литералом диапазона, и индексом среза внутри круглых скобок. В Python конструкции вида 0:5 допускаются только как индексы срезов внутри квадратных скобок. Поэтому создан несколько необычный объект r_, обеспечивающий NumPy столь же краткий способ построения диапазонов. Обратите внимание: r_ не вызывают как функцию или конструктор, а индексируют с помощью квадратных скобок. Это позволяет использовать в аргументах синтаксис срезов Python.

LOGICOPS: & и | в NumPy — побитовые И/ИЛИ, а & и | в MATLAB — логические И/ИЛИ. Их действие может казаться одинаковым, но есть существенные различия. Вместо операторов MATLAB & и | используйте ufunc NumPy logical_and/logical_or. Основные различия операторов & и | в MATLAB и NumPy:

  • Для входных данных, не ограниченных логическими значениями {0,1}, NumPy возвращает результат побитового И. MATLAB трактует любое ненулевое значение как 1 и возвращает результат логического И. Например, (3 & 4) в NumPy даёт 0, тогда как в MATLAB и 3, и 4 считаются логической истиной, а (3 & 4) возвращает 1.

  • Приоритет: оператор & в NumPy имеет более высокий приоритет, чем логические операторы < и >; в MATLAB — наоборот.

Если аргументы заведомо логические, можно использовать побитовые операторы NumPy, внимательно расставляя скобки: z = (x > 1) & (x < 2). Отсутствие операторных форм NumPy для logical_and и logical_or — досадное следствие устройства Python.

ИЗМЕНЕНИЕ ФОРМЫ И ЛИНЕЙНАЯ ИНДЕКСАЦИЯ: MATLAB всегда разрешает обращаться к многомерным массивам по скалярным или линейным индексам; NumPy — нет. Линейные индексы часто используются в программах MATLAB: например, find() для матрицы возвращает именно их, тогда как find в NumPy ведёт себя иначе. При переносе кода MATLAB может понадобиться сначала изменить форму матрицы в линейную последовательность, выполнить индексацию, а затем восстановить форму. Поскольку reshape обычно создаёт представления тех же данных, это можно сделать достаточно эффективно. По умолчанию reshape в NumPy использует порядок обхода «C», а MATLAB — порядок Fortran. При простом преобразовании в линейную последовательность и обратно это неважно. Но если исходный код MATLAB зависит от порядка обхода, выражение z = reshape(x,3,4); нужно заменить в NumPy на z = x.reshape(3,4,order='F').copy().

array или matrix: что выбрать?#

Исторически NumPy предоставляет специальный матричный тип np.matrix — подкласс ndarray, в котором бинарные операции трактуются как операции линейной алгебры. В существующем коде он иногда используется вместо np.array. Какой же вариант выбрать?

Краткий ответ#

Используйте массивы.

  • Они поддерживают ту же алгебру многомерных массивов, что и MATLAB

  • Это стандартный тип NumPy для представления векторов, матриц и тензоров. Многие функции NumPy возвращают массивы, а не объекты matrix.

  • Поэлементные операции чётко отделены от операций линейной алгебры.

  • Можно использовать как обычные векторы, так и векторы-строки или векторы-столбцы.

До Python 3.5 единственным недостатком массивов была необходимость использовать dot вместо * для умножения (свёртки) двух тензоров: скалярного произведения, умножения матрицы на вектор и т. д. Начиная с Python 3.5 можно использовать оператор матричного умножения @.

По этим причинам мы намерены в будущем объявить matrix устаревшим.

Подробный ответ#

NumPy содержит классы array и matrix. Класс array представляет универсальный n-мерный массив для различных численных вычислений, а matrix специально упрощает вычисления линейной алгебры. На практике между ними лишь несколько ключевых различий.

  • Операторы * и @, функции dot() и multiply():

    • Для array оператор * означает поэлементное умножение, а @ означает матричное умножение; им соответствуют функции multiply() и dot().

    • Для matrix оператор * означает матричное умножение, а для поэлементного умножения нужно вызывать multiply().

  • Обработка векторов — одномерных массивов

    • Для array формы векторов 1×N, N×1 и N различаются. Операции вроде A[:,1] возвращают одномерный массив формы N, а не двумерный формы N×1. Транспонирование одномерного array ничего не меняет.

    • В случае matrix одномерные массивы всегда преобразуются в матрицы 1×N или N×1, то есть векторы-строки или векторы-столбцы. Выражение A[:,1] возвращает двумерную матрицу формы N×1.

  • Обработка массивов с более чем двумя измерениями (ndim > 2)

    • Объекты array могут иметь более двух измерений.

    • Объекты matrix всегда имеют ровно два измерения.

  • Удобные атрибуты

    • array имеет атрибут .T, возвращающий транспонированные данные.

    • У matrix также есть атрибуты .H, .I и .A, возвращающие соответственно эрмитово сопряжение, обратную матрицу и результат asarray() для матрицы.

  • Вспомогательный конструктор

    • Конструктор array принимает вложенные последовательности Python для инициализации. Например, array([[1,2,3],[4,5,6]]).

    • Конструктор matrix также принимает удобный строковый инициализатор, например matrix("[1 2 3; 4 5 6]").

У обоих вариантов есть преимущества и недостатки:

  • array

    • :) Поэлементное умножение выполняется легко: A*B .

    • :( Помните, что для матричного умножения предусмотрен отдельный оператор — @.

    • :) Одномерные массивы можно рассматривать как векторы-строки или векторы-столбцы. A @ v трактует v как вектор-столбец, а v @ A трактует v как вектор-строку. Это позволяет избежать множества явных транспонирований.

    • :) Тип array — стандартный тип NumPy, поэтому он проверяется тщательнее всего и чаще всего возвращается сторонним кодом, использующим NumPy.

    • :) легко справляется с данными любого числа измерений.

    • :) По смыслу это ближе к тензорной алгебре, если вы с ней знакомы.

    • :) Все операции (*, /, +, - и т. д.) выполняются поэлементно.

    • :( Отмечаемый в оригинале недостаток: разреженные матрицы из scipy.sparse хуже взаимодействуют с обычными массивами.

  • matrix

    • :\\ Поведение ближе к матрицам MATLAB.

    • <:( Не более двух измерений. Для хранения трёхмерных данных нужен array или, возможно, список Python из объектов matrix.

    • <:( Не менее двух измерений. Векторы недопустимы: их нужно представлять матрицами из одного столбца или одной строки.

    • <:( Поскольку array используется в NumPy по умолчанию, некоторые функции могут возвращать array, даже если передать им matrix. Для функций NumPy этого происходить не должно (если происходит, это ошибка), но сторонний код на основе NumPy может не сохранять тип так, как это делает сам NumPy.

    • :) A*B означает умножение матриц, поэтому запись выглядит так же, как в линейной алгебре (в Python >= 3.5 для обычных массивов столь же удобную запись обеспечивает оператор @).

    • <:( Для поэлементного умножения нужно вызывать функцию multiply(A,B).

    • <:( Перегрузка операторов несколько нелогична: * работает не поэлементно, а / — поэлементно.

    • Взаимодействие с scipy.sparse стало немного проще.

Поэтому рекомендуется array. Авторы NumPy планируют со временем вывести matrix из употребления.

Настройка среды #

В MATLAB основной способ настройки среды — добавление в путь поиска каталогов с нужными функциями. Такие настройки можно поместить в стартовый скрипт, который MATLAB выполняет при запуске.

NumPy, или, вернее, Python, имеет аналогичные возможности.

  • Чтобы изменить путь поиска Python, включив в него расположение собственных модулей, определите переменную среды PYTHONPATH.

  • Чтобы определённый скрипт выполнялся при запуске интерактивного интерпретатора Python, задайте его имя в переменной окружения PYTHONSTARTUP.

В MATLAB доступное через путь поиска можно вызвать сразу, а в Python сначала нужно выполнить import, чтобы получить доступ к функциям соответствующего файла.

Например, вы можете создать сценарий запуска, который выглядит так (Примечание: это просто пример, а не утверждение «лучших практик»):

# Make all numpy available via shorter 'np' prefix
import numpy as np
#
# Make the SciPy linear algebra functions available as linalg.func()
# e.g. linalg.lu, linalg.eig (for general l*B@u==A@u solution)
from scipy import linalg
#
# Define a Hermitian function
def hermitian(A, **kwargs):
    return np.conj(A,**kwargs).T
# Make a shortcut for hermitian:
#    hermitian(A) --> H(A)
H = hermitian
Комментарии к примеру на русском
  • Делаем весь NumPy доступным через короткий префикс np
  • Делаем функции линейной алгебры SciPy доступными как linalg.func()
  • Например, linalg.lu, linalg.eig для общей задачи l*B@u==A@u
  • Определяем функцию эрмитова сопряжения
  • Создаём короткое имя для hermitian:
  • hermitian(A) --> H(A)

Для использования устаревающего matrix и других функций matlib:

# Make all matlib functions accessible at the top level via M.func()
import numpy.matlib as M
# Make some matlib functions accessible directly at the top level via, e.g. rand(3,3)
from numpy.matlib import matrix,rand,zeros,ones,empty,eye
Комментарии к примеру на русском
  • Делаем все функции matlib доступными на верхнем уровне через M.func()
  • Делаем некоторые функции matlib доступными напрямую, например rand(3,3)
