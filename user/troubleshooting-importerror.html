Устранение неполадок#

Примечание

Эта информация может регулярно обновляться, поэтому убедитесь, что читаете самую актуальную версию.

ImportError#

В некоторых случаях из-за неудачной установки или настройки вы можете увидеть следующее сообщение об ошибке:

IMPORTANT: PLEASE READ THIS FOR ADVICE ON HOW TO SOLVE THIS ISSUE!

Importing the numpy c-extensions failed. This error can happen for
different reasons, often due to issues with your setup.

Ошибка также содержит дополнительную информацию, которая поможет вам устранить неполадку:

  • Ваша версия Python

  • Ваша версия NumPy

Внимательно проверьте оба значения на соответствие ожиданиям. Возможно, потребуется проверить переменные окружения PATH или PYTHONPATH (см. ниже Проверка переменных окружения).

Ниже перечислены распространённые проблемы для разных конфигураций. Если знаете проблему и решение, которые стоит добавить, создайте сообщение об ошибке в NumPy.

Есть несколько часто встречающихся проблем, зависящих от вашей системы/настройки. Если ни один из следующих советов вам не помог, обратите внимание на следующее:

  • Как установлен Python.

  • как вы установили NumPy

  • ваша операционная система

  • Установлено ли несколько версий Python.

  • если вы собирали из исходного кода, версии вашего компилятора и, в идеале, журнал сборки.

При дальнейшем исследовании проблемы и обращении за помощью.

Использование Python из conda (Anaconda)#

Убедитесь, что окружение conda активировано. См. также руководство пользователя conda. Внешний редактор или среду разработки тоже нужно настроить правильно. Ниже приведены решения для распространённых конфигураций.

Использование PyCharm с Anaconda Python #

При совместном использовании PyCharm и Anaconda довольно часто возникают проблемы; см. поддержку PyCharm.

Использование VS Code с Python из Anaconda или отдельного окружения#

Частая причина проблем — активация окружения в VS Code. О правильной настройке виртуальных окружений и conda см. документацию поддержки VS Code.

Использование Eclipse/PyDev с Anaconda Python или окружениями Anaconda#

О правильной настройке Eclipse/PyDev для использования Anaconda Python с определёнными окружениями conda см. документацию Anaconda.

Отладочная сборка в Windows#

Вместо того, чтобы собирать проект в режиме DEBUG в Windows, попробуйте собрать его в режиме RELEASE с символами отладки и без оптимизации. Полный режим DEBUG в Windows меняет имена DLL, которые Python ожидает найти, поэтому, если вы хотите по-настоящему работать в режиме DEBUG, вам нужно будет перекомпилировать весь стек модулей Python, с которыми вы работаете, включая NumPy.

Все настройки #

Иногда могут возникнуть простые проблемы со старой или плохой установкой NumPy. В этом случае вы можете просто попытаться удалить и переустановить NumPy. Убедитесь, что NumPy не найден после удаления.

Настройка среды разработки#

При разработке обязательно выполните git clean -xdf, чтобы удалить файлы, не находящиеся под контролем версий. Будьте осторожны: не потеряйте собственные изменения, например site.cfg. Файлы от прежних сборок часто приводят к неправильной сборке.

Проверьте переменные среды #

Способ задания и проверки переменных окружения зависит от системы. Если вы можете открыть сеанс нужного интерпретатора Python, выполните в нём:

import os
print("PYTHONPATH:", os.environ.get('PYTHONPATH'))
print("PATH:", os.environ.get('PATH'))

Это может в основном помочь вам, если вы не используете версию python и / или NumPy, которую вы ожидаете запустить.

ImportError, AttributeError или несовместимость C-API/ABI в зависимых пакетах#

Если вы видите такое сообщение, как:

A module that was compiled using NumPy 1.x cannot be run in
NumPy 2.0.0 as it may crash. To support both 1.x and 2.x
versions of NumPy, modules must be compiled with NumPy 2.0.
Some module may need to rebuild instead e.g. with 'pybind11>=2.12'.

либо как ImportError, либо с помощью:

AttributeError: _ARRAY_API not found

или другие ошибки, такие как:

RuntimeError: module compiled against API version v1 but this version of numpy is v2

или когда пакет реализован с помощью Cython:

ValueError: numpy.dtype size changed, may indicate binary incompatibility. Expected 96 from C header, got 88 from PyObject

Это означает, что пакет, зависящий от NumPy, был собран способом, несовместимым с найденной версией NumPy. Если эта ошибка вызвана недавним обновлением до NumPy 2, самым простым решением может быть просто понизить версию NumPy до 'numpy<2'.

Чтобы найти причину, просмотрите трассировку с конца и найдите первую строку вне NumPy: она укажет несовместимый пакет. Запишите версии NumPy и этого пакета — это поможет подобрать решение.

Могут быть различные причины несовместимости:

  • Вы недавно обновили NumPy, вероятнее всего до версии 2, и теперь нужно обновить другой модуль. NumPy 2 вышел в июне 2024 года.

  • У вас есть ограничения по версии, и pip, возможно, установил комбинацию несовместимых пакетов.

  • Вы выполнили локальную компиляцию либо скопировали готовое скомпилированное расширение из другого места, что обычно нежелательно.

Лучшим решением обычно будет обновление неисправного пакета:

  • Если пакет установлен, например, через pip, попробуйте обновить его командой pip install package_name --upgrade.

  • Если это ваш пакет или он собран локально, его нужно перекомпилировать для новой версии NumPy (подробнее см. Добавление зависимости от NumPy). Возможно, проблему решит простая переустановка пакета.

Если эти действия не помогли, сообщите сопровождающим пакета: вероятно, им нужно выпустить новую совместимую версию.

Однако обновление не всегда возможно: совместимая версия может ещё не существовать или её нельзя установить по другим причинам. В таком случае:

  • Установите совместимую версию NumPy:

    • Попробуйте установить более раннюю версию NumPy командой pip install 'numpy<2' (NumPy 2 вышла в июне 2024 года).

    • Если NumPy устарел, попробуйте обновить его, например командой pip install numpy --upgrade.

  • Добавьте ограничения версий для пакета, с которым возникла ошибка, чтобы pip мог подобрать совместимые версии NumPy и этого пакета.

Ошибки сегментации и аварийные завершения#

NumPy пытается ускорять операции с помощью расширенных возможностей процессора (SIMD). Если возникает ошибка «illegal instruction» или ошибка сегментации, возможная причина — среда сообщает о поддержке одной или нескольких возможностей, которых на самом деле не поддерживает. Это может происходить внутри образа Docker или виртуальной машины (qemu, VMWare и т. д.).

Вывод np.show_runtime() показывает, какие возможности SIMD обнаружены. Например:

>>> np.show_runtime()
WARNING: `threadpoolctl` not found in system! Install it by `pip install \
threadpoolctl`. Once installed, try `np.show_runtime` again for more detailed
build information
[{'simd_extensions': {'baseline': ['SSE', 'SSE2', 'SSE3'],
                      'found': ['SSSE3',
                                'SSE41',
                                'POPCNT',
                                'SSE42',
                                'AVX',
                                'F16C',
                                'FMA3',
                                'AVX2'],
                      'not_found': ['AVX512F',
                                    'AVX512CD',
                                    'AVX512_KNL',
                                    'AVX512_KNM',
                                    'AVX512_SKX',
                                    'AVX512_CLX',
                                    'AVX512_CNL',
                                    'AVX512_ICL']}}]

В этом случае AVX2 и FMA3 перечислены в разделе found. Можно попробовать отключить их, задав переменную окружения NPY_DISABLE_CPU_FEATURES="AVX2,FMA3" перед запуском Python; ниже пример для cmd.exe в Windows:

>SET NPY_DISABLE_CPU_FEATURES="AVX2,FMA3"
>python <myprogram.py>

После установки threadpoolctl вызов np.show_runtime() выводит дополнительные сведения:

...
{'architecture': 'Zen',
  'filepath': '/tmp/venv3/lib/python3.9/site-packages/numpy.libs/libopenblas64_p-r0-15028c96.3.21.so',
  'internal_api': 'openblas',
  'num_threads': 24,
  'prefix': 'libopenblas',
  'threading_layer': 'pthreads',
  'user_api': 'blas',
  'version': '0.3.21'}]

Пакет wheel с PyPI содержит код OpenBLAS для ускорения матричных операций. Этот код также может использовать SIMD, но выбирает инструкции другим механизмом, исходя из архитектуры процессора. Архитектуру можно переопределить через OPENBLAS_CORETYPE: минимальное значение для x86_64 — OPENBLAS_CORETYPE=Haswell. Эту переменную тоже нужно задать до запуска Python; пример для POSIX:

$ OPENBLAS_CORETYPE=Haswell python <myprogram.py>
